# 靜態 ES Module 發佈版本策略（CDN 舊資源修復）

日期：2026-10-21（Asia/Shanghai）。

狀態：已由 root 審查，提交 `bb835345d4760ac60e202105d4834706eab10c7c` 已推送並部署至 149；公網 36 項驗收及 237 個瀏覽器模組雜湊比對全部通過。完整證據見[正式部署記錄](20261021010801023_文章閱讀檔案與統一標記正式部署記錄.md)。

## 問題

正式站 `https://bdc.a4a4.qzz.io` 由 Cloudflare 快取靜態檔案。前端修復提交 `01365d2`（article-store 同 scope 保留正文）及 `4e1c7c0`（reading-panel 同 scope 恢復標記）已部署到 149，但公網瀏覽器仍取得舊模組：

- `modules/article-store.js`：舊 SHA256 `d3499a81…`、`CF-Cache-Status: HIT`、`age: 1346`。
- `features/article/reading-panel.js`：舊 SHA256 `f79e460b…`，同樣命中 CDN 快取。
- 149 本機及一般 HTTP 請求已是新檔 `66069b70…`。
- Wrangler OAuth 無 Cache Purge 權限，目前憑證亦未能查出此 zone；不能依賴強制刷新。

只替 `main.js` 加 `?v=` 不足以修復：`main.js` 內部的相對 import 仍會解析到無 query 的舊 URL。因此需要讓**整張模組圖**一起換版本。

## 方案

在 `index.html` 的 `<head>`、任何 module script 之前內嵌 generated import map：

- 由 `scripts/update-release-map.mjs` 從 `main.js` 遞迴解析所有本機 ES Module，包含：
  - `features/`、`modules/` 的靜態 import 與字面量動態 `import()`；
  - `shared/article-protocol.mjs`、`shared/reading-protocol.mjs`；
  - `locales/zh-CN.js`、`locales/zh-HK.js`。
- 每個模組都映射到同一個 `/path?v=<release>`。
- `<script type="module" src="main.js?v=<release>">` 與 `<link rel="stylesheet" href="styles.css?v=<release>">` 同步版本化。
- `release` 是「所有可達模組內容 + `styles.css` 內容」的 SHA-256 前 12 碼；任一檔案變更即產生新 URL。
- `ai-config.js` 明確排除：不進 import map、不進雜湊，避免把執行期私人設定鎖在舊版本。AI profile／managed catalog 等執行期資料本來就不在這張靜態模組圖內。
- 沒有 bundler、沒有新增 runtime dependency。

本次 release：`19bbe739949c`（80 個模組）。

同一模組不論用 `/modules/x.js` 或 `/modules/x.js?v=19bbe739949c` 匯入，import map 都解析到同一個 URL，因此只有一個 module instance。回歸測試會直接比較 namespace 物件。

## 每次更新與部署流程

1. 修改任何 `main.js` 可達的 ES Module、`shared/*.mjs`、`locales/*` 或 `styles.css`。
2. 產生新的 release map：
   ```bash
   node scripts/update-release-map.mjs
   ```
3. 部署前確認 map 沒有忘記更新：
   ```bash
   node scripts/update-release-map.mjs --check
   ```
4. 執行相關測試（至少）：
   ```bash
   PORT=8313 PLAYWRIGHT_MODULE=<path-to-playwright> node tests/release-asset-versioning.cjs
   PORT=8313 PLAYWRIGHT_MODULE=<path-to-playwright> node tests/article-refresh-scope.cjs
   PORT=8313 PLAYWRIGHT_MODULE=<path-to-playwright> node tests/reading-panel-scope-refresh.cjs
   ```
5. 提交並更新 149 工作副本。
6. 公網驗證：
   - 首頁 HTML 應含新的 `release-assets:importmap` 及新 release。
   - `main.js`、`styles.css` 與實際載入的模組 URL 都應帶同一個 `?v=`。
   - 未預熱的新 query 通常先回應 `CF-Cache-Status: MISS`（或 `DYNAMIC`）；已由其他請求預熱時亦可為 HIT。驗收以實際回應 SHA256 相符為準，不應再取得舊檔。

`index.html` 目前由 Cloudflare 以 `cf-cache-status: DYNAMIC` 回應，沒有被 edge 快取；新版本上線後 HTML 必須取得新內容。若日後調整快取規則，需確保 HTML 不快取或能即時失效，否則任何前端版本策略都無法被瀏覽器發現。

## 限制與後續

- import map 只處理 `main.js` 可達的 ES Module。以傳統 `<script>` 載入的 jsPDF、字型資料，以及非 module 的 JSON／圖片，不在這次 import map 範圍；若這些資產需要避免 CDN 舊版，應另在載入點加版本或調整快取，不應把它們硬塞進 module map。
- `phonetics.html` 等其他 HTML 入口目前沒有這張 map；本次修改範圍是主 SPA。若日後要一併版本化，應擴充腳本支援多個 entry，而不是手動複製 map。
- import map 需要現代瀏覽器（Chrome 89+／Safari 16.4+／Firefox 108+）。專案原本已依賴 ES Modules，未另加 polyfill。
- 不可手動編輯 `release-assets:importmap` 區塊；重新執行 `scripts/update-release-map.mjs` 即可。
