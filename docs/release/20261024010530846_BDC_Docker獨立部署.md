切換前：`https://bdc.a4a4.qzz.io` → `bdc-cloudflared-tunnel` → `10.10.10.149:8000` → qinglong 的 port mapping／network namespace → `bdc-static-nginx`。

## 新增檔案

| 檔案 | 職責 |
| --- | --- |
| `Dockerfile` | 沿用 `nginx:stable-alpine`，只加入 nginx 設定與兩個啟動腳本 |

| 本文件 | 部署、驗證、更新及回滾紀錄 |

## 直接啟動與更新

在原有 BDC 根目錄執行，不需建立 `.env` 或重新設定 AI：

```sh
docker compose up -d --build
docker compose ps
docker exec bdc nginx -t
```

預設 `BDC_ROOT=.`、`BDC_PORT=8001`；149 根目錄為 `/Users/linus/Documents/code/qinglong/ql/data/scripts/bdc`，新部署的 LAN 網址為 `http://10.10.10.149:8001`。`8000` 仍由 qinglong 佔用，不更動它的映射。本次回滾後新容器已停止，8001 暫不提供服務；正式 LAN 仍使用 8000。

日後正常更新應用程式：

```sh
git pull
docker compose restart bdc
```

每次容器啟動或 restart 都會重新同步並清除過期檔案；掛載內容變動不會即時反映至 web root。若改了 Dockerfile、nginx 設定或啟動腳本，改用 `docker compose up -d --build`；若改了 `.env`、port 或掛載設定，使用 `docker compose up -d --force-recreate`。

此次沒有 commit、push 或 git pull；新增檔案由本機複製至 149，兩邊均保留為 untracked。149 非互動 SSH 使用 Docker 前需 `export PATH=/usr/local/bin:$PATH`。

## 限制

- 正式採用新部署後 LAN 將由 8000 改至 8001。localStorage／IndexedDB 依 origin 隔離，原 LAN 網址的本機資料不會自動出現在新 port；公開 HTTPS 網址不變。本輪已回滾，現行 LAN 仍是 8000。
- nginx 僅提供靜態檔案，不提供 `scripts/serve.py` 的同源代理或文章抓取後端。
- 重新啟動時會先複製資源，期間有短暫中斷；沒有熱更新或零停機切換保證。
- 掛載中的設定檔仍會供瀏覽器讀取；`Cache-Control: no-store` 控制快取，並不構成存取認證。
- qinglong 重建不會影響新容器的網絡，但若刪除其 host 上的原 repo 資料夾，BDC 掛載來源仍會遺失；原資料夾必須保留。
- 基底使用可變的 `nginx:stable-alpine` 標籤。本次使用 149 現有 arm64 image；一般未快取的環境首次建置需取得此 image。
