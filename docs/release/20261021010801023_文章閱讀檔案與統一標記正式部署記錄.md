## 發佈驗收發現與修復

首輪公網測試發現：`marked: true` 已保存，但原文沒有下劃線。檢查確認新記錄使用空正文的 `contentVersion`，`anchor.start/end` 為 `-1`。等待 30 秒後仍未恢復，並非單純等待不足。

原因是 `articleStore.refreshScope()` 在同一範圍仍執行 `reloadScope()`，清除全文快取及已載入記錄，將正在閱讀的文章變為僅有摘要。畫面保留正文，但後續標記定位取不到記憶體中的正文。初始化同步或正常同步均可能觸發。

已交由使用者指定的「代碼執行」（assistant_id: 1）修復，主代理另準備包含主動 `refreshScope()`／`reloadScope()` 的獨立公網測試，驗證正文、版本、精確位置、筆記及取消標記。正文修復為 `01365d2`，閱讀面板修復為 `4e1c7c0`；本地回歸及局域網獨立 UI 驗證均已通過。

補測亦發現 `reloadReadingScope()` 清空學習資料的記憶體視圖後，閱讀面板直接套用空列表，導致已有劃線消失，重新點詞才恢復。資料本身仍在 IndexedDB。修復方向是在同範圍重載事件後，按需補讀目前文章再重畫，並保護帳戶／文章切換及正在編輯的筆記草稿。

## CDN 發佈一致性

149 檔案與 Python HTTP 檢查均為最新版本，但 Chromium 載入的 `article-store.js` 仍是舊版：SHA256 `d3499a81bdfa65783a31f7399c4cc96ee007883f0e4d9d6b42a2d1af88197cb4`，`Last-Modified` 為 17:07:35 UTC，`CF-Cache-Status: HIT`，壓縮格式 zstd；新檔 SHA256 為 `66069b709f414085a4e8931c8d39e6d849d2e5108dadc2534aaa45918ce742c9`、修改時間 17:27:46 UTC。這證明只比對另一個 HTTP 客戶端不足以確認瀏覽器實際版本。見[診斷證據](assets/20261021010801023/cdn-stale-diagnostic.json)。

現有 Wrangler OAuth 沒有此域名的 Cache Purge 能力。已以提交 `bb83534` 加入靜態 import map，讓主入口、80 個可達本地模組及 CSS 使用共同版本 `19bbe739949c`；私人 `ai-config.js` 不納入版本。產生與檢查指令為 `node scripts/update-release-map.mjs` 及 `node scripts/update-release-map.mjs --check`。詳見[發佈版本策略](20261021054436216_靜態ESModule發佈版本策略.md)。

使用普通公網首頁（沒有臨時 cache-busting 頁面參數）重新驗收，36 項全部通過，237 個瀏覽器實際模組回應均與本地源碼相符，確認沒有再執行舊版。最終[桌面標記畫面](assets/20261021010801023/final-public/zh-CN-1440-marked.png)及[香港繁體手機筆記畫面](assets/20261021010801023/final-public/zh-HK-390-retained-note.png)已檢視；精確詞位劃線正常，取消標記後筆記仍保留。
