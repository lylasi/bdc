### 4.1 什麼時候會用到

伺服器自動使用，不需要人工介入：

| 場景 | 是否使用 pepper |
| --- | --- |
| 使用者以「使用者名稱＋密碼」登入（`POST /login`） | 是 |
| 管理員建立使用者並設定初始密碼（`POST /admin/users`） | 是 |
| 管理員修改使用者密碼（`PUT /admin/users/:id` 的 `newPassword`） | 是 |
| 使用者自行修改密碼（`POST /change-password`） | 是 |
| `GET /auth-capabilities` 檢查是否已設定 | 只檢查長度，不使用內容 |
| 通行碼登入、一次性登入碼 | 否 |
| 同步學習資料、AI 功能 | 否 |
| `npx wrangler deploy` | 否；部署不會刪除或改變 secret |

需要人工取出備份的情況：

1. 刪除並重建 Worker、更換 Cloudflare 帳號或 Worker 名稱。
2. 災難復原：Cloudflare secret 遺失或誤刪。
3. 遷移到自建後端，且該後端實作相同的密碼方案。
4. 懷疑 pepper 洩露，需要更換並重設所有密碼。
5. 將 BDC 交接給其他人維護。

### 4.2 注意事項

- **不要無故重新執行 `wrangler secret put PASSWORD_PEPPER`。** 覆蓋成不同值會讓所有既有密碼立即失效。
- **D1 備份不包含 pepper。** 只還原資料庫無法恢復密碼登入，必須同時保有 pepper。
- **`wrangler deploy` 會保留 secret。** 只有刪除 Worker 或手動覆蓋才會影響。
- **遺失 pepper：** 通行碼與一次性登入碼仍可用；管理員需為每個使用者重設密碼。
- **洩露 pepper：** 立即更換並重設所有密碼；目前版本沒有平滑輪換機制。
