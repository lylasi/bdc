## 需求與成因

- 短語只能「先加進詞書」：沒有加入前的預覽，使用者要先加、再去詞書刪掉，才知道 AI 的翻譯合不合用。
- 短語直加入詞書時沒有任何分析，`addItemToVocabulary()` 取不到 `explanation.result.analysis.meaning`，條目就沒有中文意思；單詞因為有查詞彈窗才會有。

## 修改

- `features/article/phrase-picker.js`：新增「查詞」按鈕與釋義區塊（`#phrase-picker-lookup`／`#phrase-picker-analysis`）；查詞先讀同一 occurrence 已存的解釋，沒有才請求 AI；成功後按鈕改「重新查詞」；範圍一改即收回舊釋義；`openPhrasePicker({ autoLookup })` 供工具條直接帶出釋義；切語言重建面板後讀回同一份釋義。
- `features/article/article.js`：選取工具條新增 `data-act="lookup"`，只對多詞短語顯示（單詞仍走點詞查詞彈窗）。
- `styles.css`：釋義區樣式；手機 `#phrase-picker-lookup`、`#phrase-picker-add` 各佔整列；`.phrase-picker-actions > button` 取代原本失效的 `.btn` 選擇器。
- `locales/zh-CN.js`、`locales/zh-HK.js`：新增 `article.lookupPhrase`、`lookupLoading`、`lookupFailed`、`lookupEmpty`、`lookupRedo`；面板提示改為「可以先查詞，再決定是否加入詞書」。
- 短語面板按鈕由 `class="btn primary"` 改為 `btn-primary`／`btn-secondary`／`btn-tertiary`：原寫法會被 `button.btn` 基礎樣式按特異性蓋掉，整個面板的按鈕都退化成純文字。
- `tests/reading-phrase-lookup.cjs`：新增驗收腳本（同時支援 `PORT` 與 `BASE_URL`）。
- `index.html`：重跑 release map 產生 `a9b46f8b9680`。

3. 149 確認工作副本乾淨、`HEAD` 為 `7c8d79c` 後 `git pull --ff-only origin master`，fast-forward 至 `31dd345`。
4. `docker compose restart bdc`；容器重新複製白名單資源至 `/srv/bdc`。`docker compose ps` 為 `Up (healthy)`，`nginx -t` 通過。
