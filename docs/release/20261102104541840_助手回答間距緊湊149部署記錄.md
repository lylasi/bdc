## 成因

`.assistant-msg` 為了串流時的純文字保留換行而設了 `white-space: pre-wrap`。`markdownToHtml()` 的輸出用 `\n` 串接區塊，於是最終渲染時每個區塊之間都有換行字元被當成真正換行印出來，再疊上區塊自身的 margin，就變成 54–63px 的空白（手機上像斷成好幾段）。

## 修改

- `styles.css`：新增 `.assistant-answer { white-space: normal }` 與 `.assistant-answer.is-streaming { white-space: pre-wrap }`；標題邊距 `12px/6px → 8px/4px`、清單 `3px/6px → 2px/4px`、`li 3px → 1px`、引用與表格 `6px → 4px`、儲存格內距 `8px/10px → 5px/8px`；首尾區塊多餘邊距歸零。
- `styles.css`：全域 `ul, ol { list-style: none }` 是給導覽清單的，助手回答裡的清單另補 `disc`／`decimal`，否則只剩縮排。
- `features/assistant/assistant.js`：正文一律經過 `.assistant-answer` 節點；新增 `renderAnswerMarkdown()`，渲染 markdown 前移除 `is-streaming`。歷史訊息也走同一條路徑，重開會話間距一致；「保留為 AI 資料」的內文取樣只看正文節點。
- `features/sync/sync.js`：AI 會話預覽的助手訊息改為 `white-space: normal`（使用者訊息仍保留換行）。
- `index.html`：重跑 release map 產生 `1f40e0ec9b6c`。

## 部署流程
