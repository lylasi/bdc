## 成因

第一版把釋義塞進短語面板：候選詞列表、選取預覽、釋義區與一整排按鈕擠在同一個滿屏 sheet 裡，而且載入中會同時出現兩個「查詞中…」（釋義區與按鈕）。與單詞查詞的輕量浮框相比，資訊密度與操作路徑都不一致。

## 修改

- `features/article/article.js`
  - 新增 `showSelectionLookupTooltip()`：直接渲染 `#word-analysis-tooltip`（同一節點、同一套 CSS 與按鈕），標題＝短語＋音標／詞性，內容＝意思／用法／例句；動作按鈕沿用既有委派處理器（`data-*` 屬性齊備即可用）。
  - 定位沿用「觸發詞」機制：`wordTooltipTrigger` 設為選取範圍的**起詞**，`ui.repositionTooltip()`、捲動跟隨、窄屏底部 sheet、locale 重畫全部走單詞查詞同一條路徑。
  - `analyzePhraseWithSaved()`：新增 `force`（重新查詞，同時 `noCache`）；**沒有 meaning 時不寫入解釋**，閱讀記錄不再出現空白解析。
  - 選取工具條：「查詞」不再開短語面板，改呼叫上面的彈窗；`captureSelection()` 額外回傳起詞元素作錨點。
- `features/article/phrase-picker.js`：回到原結構（只保留 `btn-primary`／`btn-secondary`／`btn-tertiary` 樣式修正）。
- `styles.css`：新增 `.tooltip-examples`（例句清單，補回全域清掉的項目符號）與 `.tooltip-error`；移除短語面板的釋義區樣式。
- `locales/zh-CN.js`、`locales/zh-HK.js`：只保留 `article.lookupPhrase`、`article.lookupFailed`；短語面板提示文案還原。
- `tests/reading-phrase-lookup.cjs`：改寫驗收（開彈窗而非面板、釋義／用法／例句、加詞本、標記、關閉、缺模型說明與重試、短語面板已無查詞、單詞不顯示查詞）。
- `index.html`：release map `8a6f86360d51`。

## 部署流程

1. 本機 `node scripts/update-release-map.mjs`，`--check` 確認最新。
2. 提交並推送 `1c83be5..11d9683`。
3. 149 工作副本乾淨後 `git pull --ff-only origin master`，fast-forward 至 `11d9683`。
4. `docker compose restart bdc`；`docker compose ps` 為 `Up (healthy)`，`nginx -t` 通過（非互動 SSH 需先 `export PATH=/usr/local/bin:$PATH`）。

## 實測界限

- 驗收以合成文章 + 預先寫入的解釋驗證「已存釋義」與「缺模型」兩條離線路徑；真實模型的輸出品質、逾時與配額錯誤只在程式路徑上處理。
- 查詞卡錨點是選取範圍的起詞（沿用單詞彈窗的捲動跟隨與底部 sheet）；長短語時卡片對齊起詞而非整段選區。
- 詞卡「問 AI」在助手內退回時會以起詞重開單詞卡片，而不是短語卡片；目前未另做處理。
- 版面只在 390×844 與 1440×960 視口檢查；未以真機 WeChat WebView 重新截圖（使用者回報的 `bdc.eigui.cn` 本機仍不可達，與 149 同一容器）。
