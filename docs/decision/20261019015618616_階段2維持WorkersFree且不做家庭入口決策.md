# 階段 2：維持 Workers Free 且不做家庭入口

- 日期：2026-10-19
- 狀態：已決定
- 相關文件：`docs/plan/20261019014836940_階段2使用者名稱密碼登入與入口連結方案探討.md`

## 決策

1. 繼續使用 Cloudflare Workers Free，不升級 Workers Paid。
2. **不做家庭組入口**：不新增 `groups`／`group_members`、不做 `#group=<entryCode>`、不做家庭成員選擇、家庭 owner 與入口碼輪換。
3. 階段 2 範圍收窄為「使用者名稱＋密碼登入」；既有一次性登入碼 `#login=CODE` 保留。
4. **不做個人入口 `#u=<username>`**：主站登入即可，避免多一組入口文案與行為。

## 原因

- Workers Free 的 CPU 限制是密碼雜湊的主要取捨；家庭入口本身不解決這個問題，反而增加產品與權限複雜度。
- 家庭入口若沒有共享資料，价值主要是「一個連結看到全家人」；目前優先解決登入體驗。
- 共享詞書／文章／QA 是獨立的資料模型專案，不與登入混做。

## 影響

- 不做群組層權限；資料仍按 `user_id` 隔離。
- 不做家长管理成員、代發成員登入碼的家庭面板。
- 登入相關連結只保留：
  - `#login=<one-time code>`：一次性、自動登入（階段 1）。
  - 不再提供 `#u=<username>` 個人入口。

## 最終確認（2026-10-19）

1. Free 方案密碼雜湊：**PBKDF2-SHA256 50,000 次＋服務端 pepper**（`PASSWORD_PEPPER` Worker secret）。
2. 一般使用者密碼最低長度：**10** 字元。
3. 管理員：支援使用者名稱＋密碼，密碼最低 **12** 字元；保留 32 字元通行碼作為緊急入口。
4. 既有使用者：由**管理員**在用戶管理設定使用者名稱與初始密碼；使用者登入後可自行修改密碼。
5. 實作與驗證結果見計劃文件的「實作結果」章節；部署步驟見 `docs/release/20261019021846980_階段2A使用者名稱密碼登入部署說明.md`。
