# 助手「思考過程」：分離、折疊與不落盤

- 時間：2026-11-02 10:06
- 影響範圍：`modules/api.js`、`modules/ai-protocols/*`、`features/assistant/*`、`locales/*`、`styles.css`
- 相關：助手串流（`streamAIResponse`）、詞卡問答（`word-chat.js`）

## 1. 現象

推理模型（DeepSeek-R1、Qwen、GLM、Gemini thinking 等）回答時，模型的內部思考會直接混進答案正文，
在文字氣泡裡先出現一大段英文自語（「broken, be stolen… Not necessary.」「Need not use IPA…」），
之後才接真正的答案。使用者無法分辨哪段是答案。

## 2. 根因

協議層把「思考」和「正文」當成同一個輸出通道：

- `modules/ai-protocols/chat-completions.js` 的 `parseStreamEvent`：
  `delta.content || delta.reasoning_content` → 思考片段被當成正文串進畫面，並在結束時寫入訊息內容。
- `modules/ai-protocols/gemini.js`：`thought: true` 的 parts 與正文混在同一個 parts 陣列，沒有區分。
- `modules/ai-protocols/anthropic.js`：`thinking_delta` 直接被丟掉（不會顯示，但也不回報）。
- `modules/api.js` 的 `streamAIResponse`：只有 `onDelta` 一條回調，呼叫端無從分開處理。

因為思考是和正文拼在同一個字串裡存進 `reading-store` 的訊息 `content`，
重新開啟會話或同步到雲端後，思考仍會重現在答案上方。

## 3. 方案比較

| 方案 | 優點 | 缺點 |
| --- | --- | --- |
| A. 完全過濾 | 畫面最乾淨、實作最小 | 模型長時間思考時畫面完全空白，看不出是否卡住；出問題時無法回看模型在想什麼 |
| B. 折疊（採用） | 正文乾淨；等待時有「正在思考…」回饋；需要時可展開查證 | 多一行標題；實作稍多 |
| C. 折疊＋全域設定開關 | 使用者可徹底關掉 | 多一個設定項與持久化分支，收益有限 |

選擇 **B**：折疊預設收起，對不想看的人等同過濾（一行灰色標題），
同時保留等待回饋與可查證性。若日後要極簡，只需在 `onReasoning` 不回填內容即可降級為 A。

## 4. 實作

協議層（每個協議只維護一套邏輯）：

- `chat-completions.js`：`text` 只取 `delta.content`；`reasoning_content` / `reasoning` 走 `reasoning`。
  非串流的 `parseResponse` 同理；`content` 為空、整段在 `reasoning_content` 的供應商仍以它當正文（不回歸空白）。
- `gemini.js`：`splitThoughtParts()` 依 `thought: true` 拆成 `{ text, reasoning }`。
- `anthropic.js`：`thinking_delta` → `reasoning`；`parseResponse` 一併回報 `thinking` block。
- `modules/api.js`：`streamAIResponse` 新增 `onReasoning`，回傳 `{ text, reasoning, ... }`。

助手層：

- 正文寫進 `.assistant-answer` 子節點，`.assistant-reasoning`（`<details>`）是它的兄弟節點，
  因此重畫 markdown、補「已停止／錯誤／保留為 AI 資料」都不會把思考沖回正文。
- 標題三態：`正在思考…`（帶脈動點）→ `思考过程（N 秒）` → 完成後維持收起。
  秒數存在 `dataset.reasoningSeconds`，切換介面語言時只重算標題（`refreshReasoningSummary`）。
- **不落盤**：`reading-store` 的訊息 `content` 只存正文，思考僅存在當前 DOM。
  理由：思考長度常是答案數倍，寫進本地／同步快照會明顯放大資料量，而回看時幾乎不需要它。
- 詞卡問答（`word-chat.js`）共用同一批節點，切換語言時透過注入的 `refreshReasoning` 重算標題。
- 文案（`locales/zh-CN.js`、`zh-HK.js`）：`assistant.reasoning`、`assistant.reasoningPending`、`assistant.reasoningDone`。

樣式（`styles.css`）：虛線框、`--surface-3` 底色、`--ink-500` 字色、`--fs-xs` 字級，
沿用既有 `pulse` 動畫（已受 `prefers-reduced-motion` 保護），展開後限制 `40vh` 內捲動。

## 6. 已知邊界

- 供應商若把思考直接寫進 `content`（部分代理轉發會這樣做），協議層無從分辨，仍會顯示為正文。
- 思考不落盤，因此重新開啟會話或換裝置後只會看到答案；若日後要保留，需要 `reading-store`／同步快照一起加欄位並評估容量。
- 非串流模式（設定關閉「流式響應」）同樣支援折疊，但整段思考一次到達，看不到「正在思考」的過程。
