# serve 啟動命令與 AI 同源代理逐項說明

日期：2026-11-02（Asia/Shanghai）。依據目前 `scripts/serve.py` 實作及 `--help` 輸出核對。本次僅解釋命令及保存說明，沒有啟動新的長期服務或修改 149 部署。

## 1. 這條命令的完整意思

```bash
python3 scripts/serve.py --lan --ai-proxy http://127.0.0.1:3425
```

在執行命令的電腦上，啟動一個 Python 服務；它以預設埠 `8313` 提供 BDC 網頁，同時把這個入口收到的 `/v1/*` GET／POST 請求，轉送到同一台電腦的 `3425` 埠。前面已確認該埠由 Magpie 使用。

此服務同時負責「送出網頁檔案」與「代轉 AI 請求」，毋須另外開第二個 Python 程序。

## 2. 每一部分的意思

| 部分 | 實際作用 |
| --- | --- |
| `python3` | 使用電腦已安裝的 Python 3 執行後面的程式 |
| `scripts/serve.py` | 執行 BDC 專案自帶的本機服務腳本；檔案根目錄依腳本位置指向 BDC 專案根目錄 |
| `--lan` | 把服務監聽地址由預設 `127.0.0.1` 改為 `0.0.0.0`，讓能連到這台電腦的其他裝置亦可訪問 |
| `--ai-proxy` | 設定 `/v1/*` 請求的固定上游地址，讓 Python 代轉 AI API 請求 |
| `http://127.0.0.1:3425` | 上游為 HTTP，主機是 Python 所在電腦本身，埠為 `3425`，在目前環境對應 Magpie |

`8313` 沒有出現在命令中，是因為腳本的 `--port` 預設值就是 `8313`。

目前電腦的區網 IP 已再核對為 `10.10.10.5`；Magpie 程序正在監聽 `3425`。在此環境執行後，網頁入口會是 `http://10.10.10.5:8313/`。`0.0.0.0` 是服務監聽設定，其他裝置應使用實際 IP `10.10.10.5` 訪問。

## 3. 啟動位置與生命週期

在目前這台 Mac Studio 的終端機執行：

```bash
cd /Users/linus/CODE/bdc
python3 scripts/serve.py --lan --ai-proxy http://127.0.0.1:3425
```

這個腳本使用 Python 標準庫，這條命令本身不會安裝依賴、不會啟動 AI 模型，也不會啟動 Magpie。Magpie 與所用供應商服務須各自已在運行。

啟動後，終端機會保持前台運行並顯示服務網址與 HTTP 請求紀錄。停止時在該終端機按 `Control+C`，本次 Python 服務就會結束；這不會停止獨立運行的 Magpie 或模型服務。此命令沒有設定開機自動啟動。

若 `8313` 被其他程序佔用，腳本會啟動失敗。可透過 `--port` 另選埠，但瀏覽器網頁與 BDC 供應商地址的埠必須一起修改。

## 4. Python 收到請求後怎樣處理

| 瀏覽器請求 | Python 的處理 |
| --- | --- |
| `GET /` | 提供專案的 `index.html` |
| `GET /main.js`、`GET /styles.css` | 提供相應的 BDC 靜態檔案 |
| `GET /v1/models` | 代轉到 `http://127.0.0.1:3425/v1/models` |
| `POST /v1/chat/completions` | 把請求內容代轉到 `http://127.0.0.1:3425/v1/chat/completions` |

轉送方式是把 `--ai-proxy` 指定的上游，與原請求路徑相接，並把上游回應傳回瀏覽器。上游 HTTP 錯誤會保留相應狀態；無法連接等代理錯誤會回 502。

所以命令裡的上游地址應填 `http://127.0.0.1:3425`，不要再加 `/v1`，否則容易接成 `/v1/v1/models`。

## 5. 瀏覽器與設定頁分別使用甚麼地址

```text
瀏覽器開啟： http://10.10.10.5:8313/
供應商地址： http://10.10.10.5:8313/v1
Python 上游：http://127.0.0.1:3425
```

供應商地址填 `8313/v1`，表示「瀏覽器先把 AI 請求交給 BDC 自己」。上游的 `3425` 是告訴 Python 接著去哪裡取結果。

```mermaid
flowchart LR
    browser["瀏覽器<br/>10.10.10.5:8313"] --> python["BDC / Python<br/>提供網頁與 /v1"]
    python --> magpie["本機 Magpie<br/>127.0.0.1:3425"]
    magpie --> provider["模型供應商"]
```

Magpie 收到請求後，才按模型識別及它已有的供應商設定選擇實際模型接口。此 Python 腳本不負責挑模型或轉換 AI 協議。

## 6. 為何稱為「同源代理」

網頁與瀏覽器看到的 API 都使用 `http`、`10.10.10.5`、`8313`，只有路徑不同，因此是同一來源。瀏覽器無須直接訪問 `3425`，它面對的是自己載入 BDC 的那個服務。

Python 到 Magpie 的後半段屬伺服器請求，不受瀏覽器 CORS 政策約束。腳本亦不轉送 `Origin` 標頭，避免上游把這段當作由外部網頁來源直接發出的請求。

若原網頁仍開在 `10.10.10.149:8001` 或原公網網址，而供應商填 `10.10.10.5:8313/v1`，兩者就不是同源。單獨在 Mac Studio 執行此命令，不會自動改變原網站的 AI 請求路徑。

## 7. `--lan` 與 `127.0.0.1` 並不衝突

兩者分別設定不同方向：

- `--lan`：誰可以連進 Python／BDC 服務。
- 上游 `127.0.0.1:3425`：Python 接到 AI 請求後，往哪裡轉送。

手機與 Mac 能互通時，手機亦可開 `http://10.10.10.5:8313/`，供應商填同一地址的 `/v1`。終端機中的 `127.0.0.1:3425` 維持原樣：這段請求由 Mac 上的 Python 發出，故回環地址仍指向 Mac。

`--lan` 讓服務監聽網絡介面，不會自動配置路由器公網映射、Tunnel、HTTPS 或防火牆。

## 8. 認證實際如何處理

腳本只轉送 `Content-Type`、`Authorization`、`Accept`。若 BDC 供應商有 Bearer Key，它會隨 `Authorization` 轉送給上游；腳本本身不會尋找、保存或補上 Key。

前次已驗證本機 `127.0.0.1:3425/v1/models` 不帶 Key 能取得模型列表，而 `10.10.10.5:3425/v1/models` 不帶 Key 回 401。因此，前述本機 Magpie 的留空 Key 配置，不能直接套用到跨裝置的 Magpie 連接。

要直接代理至另一個需要 Key 的上游，仍應在 BDC 供應商中配置相應認證。代理解決請求通道，不會取消上游認證。

## 9. 與 149 主環境的關係

此命令在哪台電腦執行，就在那台電腦開新的服務。`127.0.0.1` 也跟隨該電腦：

| 執行位置 | `127.0.0.1:3425` 指向 |
| --- | --- |
| Mac Studio，`10.10.10.5` | Mac Studio 自己的 Magpie |
| 149 主機 | 149 自己的 `3425`，不會連到 Mac Studio |

如果日後在 149 上用同類服務轉接 Mac Studio 的 Magpie，上游應改為 `http://10.10.10.5:3425`，並處理跨裝置認證及連通性。但以預設埠啟動仍會得到 149 的新 `8313` 入口，原有 `8001` Nginx 與公網入口不會自行改變。

要保留 149 既有主要網址，較直接的落點是在其現有 Nginx／服務端增加固定上游 API 代理。此 Python 命令主要用於理解及驗證相同的轉送原理，不代表必須改用本機網址作為主環境。

## 10. 現有實作的範圍

- 每次啟動只指定一個固定上游。多個實際供應商可由 Magpie 依模型路由。
- AI 代理只匹配 `/v1/*` 的 GET／POST；不是通用的系統或瀏覽器網絡代理。
- 只轉送上述三個標頭，不完整支援其他協議需要的所有認證標頭。
- 上游回應使用 `response.read()` 完整讀取後才傳回，SSE 會緩衝，不能逐段即時顯示。
- 上游代理逾時設定為 300 秒；前端 AI 任務可能有更短的逾時。
- 腳本亦預設提供文章抓取 `/fetch`、`/extract` 並停用 HTTP 快取，這是其他既有能力；可用 `--no-article-fetch` 關閉文章抓取。
- 啟動參數只作用於這次程序，不會把 AI 網址寫進 `ai-config.js`、BDC profile 或 D1；BDC 供應商地址仍須在設定介面另行填寫。

主要程式依據：`scripts/serve.py:581`（代理）、`:636`（路由）、`:659`（參數與啟動）。
