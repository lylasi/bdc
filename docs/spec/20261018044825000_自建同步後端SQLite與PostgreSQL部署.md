# 自建同步後端（SQLite / PostgreSQL）部署記錄

日期：2026-10-18。本文記錄新增的自建同步後端與教程入口；完整逐步操作見根目錄 `README.md` 及 `selfhost/README.md`。

## 目的

除了 Cloudflare Worker + D1，提供一個可部署在 NAS、VPS 或家用電腦的 Node.js 同步後端，支援 SQLite 與 PostgreSQL。前端仍以 localStorage／IndexedDB 為主，雲端只同步學習資料快照。

## 入口

- `README.md`：〈自建同步後端（PostgreSQL / SQLite）〉快速教程。
- `selfhost/README.md`：完整部署、備份、systemd、Caddy 與疑難排解。
- `selfhost/server.mjs`：零框架 HTTP 伺服器。
- `selfhost/schema.sql`：SQLite／PostgreSQL 共用 schema。
- `selfhost/add-user.mjs`：產生建立使用者與重設通行碼的 SQL。

## 支援範圍

支援 `/health`、`/me`、`/version`、`/snapshot`、`/change-token`、`/reset-token`，沿用樂觀鎖與 SHA-256 通行碼雜湊。`/ai-credentials`、`/ai-catalog`、`/admin/*` 回 `501 not_supported`；AI 供應商雲端同步仍使用 Cloudflare Worker。

## 驗證

- SQLite：啟動、建立使用者、`/me`、快照讀寫、版本衝突、修改通行碼、恢復碼重設、CORS 允許與拒絕。
- PostgreSQL 16（Docker）：同一組 API 與 token 流程通過。
- `node --check` 通過 `server.mjs`、`add-user.mjs`、`snapshot-sanitize.js`。

## 限制

- 未實作即時推送，前端以 `/version` 輪詢。
- 限流為單一行程記憶體計數，公開部署需在反向代理加强。
- `selfhost/snapshot-sanitize.js` 與 `cloudflare-worker/src/snapshot-sanitize.js` 內容同步，修改時需兩處一起更新。
