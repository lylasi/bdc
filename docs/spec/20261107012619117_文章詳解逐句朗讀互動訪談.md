# 文章詳解逐句朗讀互動訪談

狀態：三輪 grilling 已完成並由使用者確認；方案已實作，驗證記錄見 `docs/report/20261107021459019_文章逐句朗讀實作與驗證.md`。

## 使用者目標

使用者希望在文章詳解內方便地朗讀指定句子，並盡量節省畫面空間。提出的候選入口包括手機長按、電腦右鍵、選取文字後朗讀，以及佔位盡量小的朗讀圖示。

本輪依使用者指定的 `grill-me` 所指向的 `grilling` 技能，先釐清設計決策。本文記錄訪談及查證事實，候選方案均未視為使用者已確認的需求。

## 第 1 輪問題

### Q1：最常用的操作

主要需要聽完整一句英文，還是自己選取的詞組／片段？

- A：整句為主，選中片段為輔（建議）。
- B：只需要整句朗讀。
- C：主要朗讀選中的片段。

建議理由：常用的整句操作應盡量一步完成；精確選取的操作可作補充。

### Q2：讀到哪裏停止

觸發一句後，讀完這一句就停止，還是從這一句開始繼續往後讀？

- A：只讀這一句（建議）。
- B：從這一句繼續往後讀。
- C：兩種都要，可以多一步選擇。

建議理由：單句朗讀便於反覆聆聽；連續朗讀需要明確區分，避免使用者預期不一致。

### Q3：節省空間的底線

可否接受英文旁邊一個小朗讀圖示，只要不新增一行、盡量不增加卡片高度？還是平時完全不能有新增控制？

- A：允許小圖示，盡量不增加高度（建議）。
- B：電腦懸停才顯示，手機可以常顯。
- C：平時完全不顯示新增控制。

建議理由：可見入口有助手機使用者發現功能，也有利於保留清楚的點擊區域。

### 第 1 輪回答

使用者回覆「都按推荐」，並補充「其实手机端，我也想尽量不占空间，因为本来就窄占了不好看」。

已確認整句為主、選取片段為輔，單句讀完停止，電腦以懸停顯示朗讀入口。手機雖初步接受可見入口，但節省寬度與視覺空間是明確要求；不能把「再加一個常顯圖示」當成已最終確認的配置。

## 第 2 輪問題

### Q4：手機零新增按鈕與操作步數

手機是否接受把既有句尾 `ⓘ` 改為同位置的 `⋯`，輕點後顯示「朗讀本句／解析句子」的小選單？

- A：復用句尾位置，以輕量操作選單兼顧朗讀及解析（建議）。手機正文不增加按鈕數量，但經此入口朗讀和解析都需要兩次點擊；電腦仍提供懸停後的直接朗讀操作。
- B：手機也要一點即播，接受新增一個小朗讀圖示。

建議沿用原生長按選字及右鍵選單；選取英文片段後，可透過現有選字浮動工具列的新朗讀動作播放。此項為本輪完整候選方案的一部分，仍待使用者確認。

先前提問描述了「先開既有句子卡再朗讀」的兩步構想。查證發現現有卡片無快取時會立即呼叫 AI，故具體建議調整為先開獨立輕量操作選單，只有主動選「解析句子」才呼叫 AI；不可把朗讀按鈕綁在解析完成後才出現的動作列。

### Q5：播放時再次操作與全文朗讀協調

- A：同句再點就停止，另一句則立即切換；全文朗讀先暫停，單句結束後由使用者手動恢復（建議）。
- B：同句再點從頭重讀，換句立即切換，全文手動恢復。
- C：單句結束後自動恢復原來的全文朗讀。

### Q6：首期內容範圍

- A：英文原句與同一句內選取的英文片段（建議）。
- B：英文還需支援跨句選取。
- C：中文譯文也需支援朗讀。

建議沿用既有選字範圍，先讓英文整句及句內片段的操作清楚且穩定。

### 第 2 輪回答

使用者採納 Q4 的句尾輕量選單，並明確新增兩個動作：

- 「從這裏開始讀」：讀完指定句，接着朗讀下一句。
- 「循環讀本句」：讀完後繼續重複本句。

使用者要求 Q5 根據新的 Q4 調整，並採納 Q6 建議：英文原句及同一句內選取的英文片段。

第 1 輪的「單句讀完停止」現明確對應「朗讀本句」這個動作；不限制新加入的連續及循環動作。

## 本輪整合方案

手機沿用既有句尾圖示的位置，以 `⋯` 開啟輕量選單；不並排增加常駐圖示。電腦保留懸停後直接朗讀本句的入口，鍵盤焦點亦須可操作。完整選單共四項：

| 動作 | 播放行為 |
| --- | --- |
| 朗讀本句 | 本句讀一次即停止 |
| 從這裏開始讀 | 從本句起，按文章次序逐句讀至結尾 |
| 循環讀本句 | 持續重複本句，直至手動停止或切換 |
| 解析句子 | 使用者選取此項後，才進入既有解析流程 |

選中英文片段後，既有浮動工具列新增「朗讀選中內容」：只讀選中的片段一次。句子三種播放模式設於句尾選單，片段工具列不另外新增連續及循環選項。

### Q5 的調整建議

依使用者「根據 Q4 調整」的指示，整合以下行為供定稿：

- 同一句、同一個正在執行的播放動作再次操作時停止；選單對應動作顯示停止狀態，避免用相同靜態文字暗示會再開新播放。
- 選另一句或另一種模式，立即停止目前播放並切換，不疊加音訊。
- 單句、連續及循環共用既有播放列的暫停／繼續／停止控制，不新增另一套浮動控制列。暫停後繼續沿用既有行為，由本句開頭重播。
- 前後句保留目前播放模式：單句模式只讀相鄰句一次，連續模式由相鄰句往後讀，循環模式改為循環相鄰句。沒有相鄰句時停留在原句。
- 新動作會取代目前全文播放；單句或循環結束後不自動恢復舊播放。使用者可透過全文朗讀入口重新開始。
- 關閉輕量選單不停止播放；既有播放列的停止操作可隨時結束連續或循環。
- 循環過程仍允許立即停止或切換，不因等待下一次音訊而失去控制；播放失敗不能無限自動重試。

上述行為為本輪提出的整合方案，並非已完成的產品功能。

## 第 3 輪問題

### Q7：三個動作是否嚴格按名稱執行

即使側欄設為「按段落朗讀、重複 3 次」，是否仍讓句尾動作各自固定為本句一次、從本句逐句各讀一次、無限循環本句？

- A：各動作嚴格按名稱執行，聲音及語速沿用目前選擇（建議）。
- B：仍受側欄的分段方式與重複次數影響。

建議只在本次播放採用對應行為，不改寫側欄原有選項，避免使用者下次點全文朗讀時發現設定被更改。

### Q8：循環之間的停頓

文章播放器目前沒有句間停頓設定，讀完後直接接下一次呼叫。先前進度說明曾提及沿用句間停頓，查證後更正為：聲音及語速可沿用，但停頓不是目前已有的設定。

- A：循環兩次之間留 0.5 秒停頓，首期使用固定值（建議）。
- B：讀完立即重讀。

停頓只適用於「循環讀本句」；「從這裏開始讀」沿用現有接續速度。

### 第 3 輪回答及定稿

使用者回覆「按推荐」，採納 Q7、Q8 及本輪整合方案。三種句子操作固定依名稱執行，聲音及語速沿用目前選擇；循環間隔固定 0.5 秒。設計樹已沒有未回答的產品決策，依確認方案進入實作。

實作沒有新增持久化設定：播放模式與循環計時器僅保留於本次頁面工作階段。手機沿用單一句尾入口，電腦的懸停朗讀按鈕浮在正文排版之外，並保留原有句子譯文提示。

## 查證事實

- 句末現有小圖示用途為句子解析，不是朗讀。現有樣式是 12px 圖示、16px 行內按鈕，點擊區以偽元素擴大至 28px，粗指標裝置為 32px（`styles.css:4035` 起）。
- 英文詞語已有點擊查詞，句子其他區域與句末圖示可開啟句卡。
- 已有選字浮動工具列；目前選區限於同一英文句子。
- 中文翻譯已有按住顯示遮罩的互動（`features/article/article.js:1050` 附近）。
- 應用的 `features/`、`modules/`、`main.js` 及 `index.html` 初查未找到自訂 `contextmenu` 或英文長按朗讀處理。
- 句子及譯文以段落和句子索引配對；句末解析圖示會與最後一詞綁在一起，避免圖示單獨換行（`features/article/article.js:2524`、`:8885`）。
- 選字浮動工具列目前提供查詞、加詞書、標記、筆記、選短語與關閉，尚未提供朗讀。選區快照可供新增動作使用；跨句、跨段、中文翻譯選區目前不適用（`features/article/article.js:7811`、`:7930`）。
- 現有全文朗讀建立句子／段落佇列，由索引 0 起播；播放邏輯會在讀完後前進，目前沒有直接對指定句起播／只讀該句的入口（`features/article/article.js:5345`、`:5385`、`:5471`）。
- 共用 `audio.speakText()` 可朗讀任意文本；文章已有浮動播放列、前後句、停止及高亮。文章的暫停會停止音訊，恢復時由本句開頭重播；其他 owner 開始朗讀時會讓文章暫停，且不會自動恢復（`modules/audio.js:281` 及上述文章播放邏輯）。
- 卡片使用 `overflow: hidden`，若把新圖示放到卡片外側，需處理被裁切的可能（`styles.css:3771`）。
- 句尾圖示連同 margin 的排版寬度約 19px，而手機點擊區為 32px。若直接並排複製圖示，點擊區可能重疊；增加間距則會進一步佔用行寬。末詞及圖示使用 `white-space: nowrap`，增加圖示會擴大末尾整組寬度，可能令手機換行提早發生。這是按 CSS 推算，尚未做裝置實測（`styles.css:4050`、`:4096`、`features/article/article.js:8885`）。
- 英文區左右 padding 16px，字體 16px，line-height 1.95；同一段可以有多句，並非每句獨立一張卡。右側沒有可保證用作逐句按鈕的空白欄，絕對定位也必須處理文字遮擋及句子對應（`styles.css:3771`、`features/article/article.js:3944`）。
- 句子解析目前使用 modal；開啟入口後，無已保存解析即呼叫 AI。成功後標題動作列才有逐詞／重新整理／關閉，載入及失敗畫面沒有同一列。因此朗讀必須獨立於解析載入狀態（`features/article/article.js:2117`、`:8311`、`:8328`、`:8465`）。
- 側欄現有全文／段落／句子模式與 1–10 次重複控制。重複控制在全文模式隱藏，但播放函數仍無條件讀取其值，因此先選 3 次再切全文，仍會逐句各讀 3 次。這是程式碼查閱發現的既有行為，尚未另行修正（`index.html:1254`、`features/article/article.js:924`、`:5396`）。
- `buildReadingChunks('paragraph')` 會建立段落片段；sentence／full 才逐句建立佇列。新「從這裏開始讀」必須使用句子定位及句子佇列，不能直接沿用側欄當前分段方式；畫面分析若過期，不能把舊 DOM 句子位置套用到重新切分後的輸入（`features/article/article.js:5134`、`:5150`、`:5160`）。
- 播放完成後目前直接呼叫下一次播放，重複與接續之間未見句間停頓設定（`features/article/article.js:5385`）。
- 浮動播放列目前提供前後句、播放／暫停、顯示英文、跟隨捲動、停止、收起，尚未有模式或循環提示；收起不會停止音訊（`features/article/article.js:5207`、`:5233`、`:5429`、`:5471`）。
- 切文章、匯入、清空與換帳戶會停止音訊；目前離開文章 route 不會自動停止朗讀，背景化也未自動暫停文章播放。本輪不因新增播放模式而擅自更改既有背景播放策略（`features/article/article.js:898`、`:4007`、`:4346`）。

## 外部參考

- [MDN：contextmenu event](https://developer.mozilla.org/en-US/docs/Web/API/Element/contextmenu_event)：右鍵通常會觸發瀏覽器選單事件；自訂選單需要處理預設行為，Firefox 的 Shift + 右鍵另有差異。右鍵朗讀需考慮使用者保留原生選單的需要。
- [W3C：Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：指標目標尺寸以 24 × 24 CSS px 為基準並列出例外；顯示圖示的尺寸與實際點擊區域可分開設計。較小的視覺圖示不代表點擊區域也應同樣縮小。

## 發布前獨立審查細化

根據 DSH 的實測，發布版本補足中文原文段落的停用說明、可見句尾錨點的捲動跟隨、Tab／Shift+Tab 的正文導航，以及香港繁體「朗讀選取內容」用詞。這些修正沒有改變三種播放模式及手機單一句尾入口的定稿；跨模組背景播放沿用原有策略，浮動列可隨時停止。
