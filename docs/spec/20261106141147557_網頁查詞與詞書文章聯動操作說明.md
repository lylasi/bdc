# 網頁查詞與詞書文章聯動操作說明

擴充套件 0.3.0。原網頁選詞後按浮動查詞按鈕，可在原頁查詢、收藏、新增詞書及導入文章。帳戶與 AI 設定沿用原同步服務；初次登入在擴充套件工具列的設定頁完成。

## 安裝與另一部電腦

在 repository 的 master 執行 `git pull --ff-only origin master`，再於專案根目錄執行：

```bash
node scripts/package-extension.mjs
```

Git 只追蹤手寫原始檔；共用模組、字典和安全的範例設定由此命令生成。完成後在 `chrome://extensions`／`edge://extensions` 開啟開發人員模式並載入根目錄的 `extension/`。已安裝者按重新載入，確認 0.3.0；原有網頁重新整理一次，或從擴充套件按「啟用目前網頁查詞」。不用另開本機伺服器。

## 在原網頁查詞與收藏

1. 用滑鼠選取普通網頁上的單詞或短語，再點旁邊的查詞按鈕。
2. 原頁浮窗會顯示語境釋義、音標及詞性。「編輯選詞」可修改原句與語境；「帳戶設定」開啟可信設定頁。
3. 選擇詞書後加入；也可直接「建立本頁詞書」、輸入名稱新增自訂詞書，或在沒有預設時「建立預設生詞本」。
4. 明確按「設為預設詞書」會保存到目前帳戶；新頁可沿用預設。同頁曾選的詞書優先沿用，其次為已存在的本頁詞書及明確預設。不以名稱或排序猜測預設。
5. 已加入提示代表收到保存回執；沒有成功的操作保留本機待傳，重新開啟或重試會沿用原操作。取消待傳不會刪除雲端已保存的資料。

收藏直接使用已展示的結果，不再次呼叫 AI。同書同詞保留既有釋義，追加原句、當時意思及網頁來源。查詞本身不會自動加入詞書。

## 整篇導入文章詳解

1. 在浮窗或工具列頁按「AI 擷取本頁文章」。擴充套件只在這次操作讀取目前網頁正文，移除表單、導覽等區塊後沿用共用 AI 清理流程。
2. 檢查並按需要修改標題與正文。原語言和 Markdown 章節保留；截斷、空結果或超限會明確提示。
3. 按「保存到文章詳解」。如勾選「保存前同時逐段 AI 分析」，會先逐段生成譯文再保存；未勾選則保存正文，稍後在 BDC 分析。
4. 成功後可按「在 BDC 開啟」。首次如使用自建主站，可在帳戶設定填寫 BDC 主站網址。主站須登入同一帳戶，必要時按立即同步。

同一來源網址已有文章時沿用現有記錄，保留已編輯的原文與分析。重試不建立第二篇，也不默默覆寫內容。一般段落錨點會歸到同頁；`#/...`／`#!/...` 路由保留區分。

本頁詞書先建立或文章先導入，兩種順序都可補上關聯。主站文章詳解可繼續使用已關聯的本頁詞書。刪除後明確重新建立頁書會分配新 ID，舊操作重播不會復活舊詞書。

待傳的文章以首次提交內容為準；其預覽會鎖定，避免重試時換了內容。可先取消該待傳，再修改；取消並不撤回伺服器可能已完成的保存。

## 服務端更新

原 Worker 套用 `cloudflare-worker/migrations/008_capture_preferences.sql` 後發布新程式；selfhost 全新 schema 已包含偏好表，既有服務使用 `selfhost/migrations/004_capture_preferences.sql`。新偏好表保存帳戶的預設詞書；詞書與文章仍走既有 reading／articles 協議，無需另建服務。

新增端點：`POST /vocabulary/books`、`PUT /vocabulary/default`、`POST /vocabulary/page-link`；GET 詞書清單增回本頁及關聯 metadata。原 API 和登入方式沿用。

網頁腳本只處理選取和浮窗外殼，AI 與保存使用可信擴充套件頁面；普通網頁不取得登入 token 或 AI Key。瀏覽器的受保護頁面不能注入，仍可在工具列頁手動查詢。

開發時已參照 Chrome 官方的[擴充套件儲存邊界](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)及[Web Accessible Resources](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources)，並以實際 MV3 驗證嵌入流程。
