# UI 雙語開發與維護規範

## 1. 目的

本專案介面支援：

- `zh-CN`：中國大陸簡體中文，為預設介面。
- `zh-HK`：香港繁體中文，使用香港正式書面中文及香港常用詞。

日後新增功能或修改現有功能時，只要變更涉及 UI 層，就必須同步考慮兩種介面語言。本規範用於避免簡體介面混入繁體文字，或香港繁體介面混入簡體、台灣慣用詞及不必要的粵語口語。

## 2. 核心原則

### 2.1 功能程式碼只維護一套

不要建立簡體版功能及繁體版功能兩套程式碼。功能邏輯、資料結構、事件處理及 API 呼叫只維護一套，差異只放在語言資源及 AI 語言規則中。

```js
button.textContent = t('common.save');
```

```js
// locales/zh-CN.js
save: '保存'

// locales/zh-HK.js
save: '儲存'
```

### 2.2 UI 文案必須經過 i18n

以下內容都屬於 UI 文案：

- 導航、標題、按鈕、標籤及表單說明。
- placeholder、title、aria-label 及輔助功能文字。
- 彈窗、選單、Tooltip、Toast 及確認提示。
- 「載入中」「處理中」「已完成」等非同步狀態。
- 錯誤、警告、成功提示及空狀態。
- JavaScript 動態拼接的 HTML。
- PDF 中由系統產生的標題、說明、頁尾及狀態文字。

禁止直接寫：

```js
button.textContent = '加入生詞本';
container.innerHTML = '<p>載入中...</p>';
```

必須寫成：

```js
button.textContent = t('article.addToWordbook');
container.innerHTML = `<p>${t('article.loading')}</p>`;
```

## 3. 靜態 HTML 規則

靜態 HTML 優先使用：

```html
<button data-i18n="common.save">保存</button>
<input data-i18n-placeholder="article.inputPlaceholder">
<button data-i18n-title="article.refresh" title="重新获取"></button>
<button data-i18n-aria-label="article.close" aria-label="关闭"></button>
```

可使用的現有屬性包括：

- `data-i18n`
- `data-i18n-title`
- `data-i18n-placeholder`
- `data-i18n-aria-label`
- `data-i18n-value`
- 導航專用的 `data-i18n-full` 及 `data-i18n-short`

## 4. JavaScript 動態 UI 規則

動態建立 DOM 時，所有使用者可見文字必須在產生時呼叫 `t()`：

```js
modalTitle.textContent = t('qa.previewTitle', { name: qaSet.name });
status.textContent = t('ocr.recognizing', { done, total });
```

需要特別檢查的高風險位置：

1. `innerHTML` 模板字串。
2. `textContent`、`title`、`placeholder`、`aria-label`。
3. `alert()`、`confirm()`、`prompt()`。
4. `displayMessage()`、Toast 及錯誤處理分支。
5. 請求開始、成功、失敗及重試狀態。
6. 動態 Modal、Tooltip、選單及列表空狀態。
7. 按鈕按下後暫時改變的文字，例如「產生中」「加入中」「重試中」。

## 5. Locale 維護規則

- 翻譯資源位於 `locales/zh-CN.js` 及 `locales/zh-HK.js`。
- 每次新增翻譯鍵時，必須同時更新兩份檔案。
- 兩份檔案使用完全相同的鍵名及插值參數。
- 不要在簡體版及香港繁體版使用不同的資料 schema。
- 可共用的文字放入合適的公共或現有模組分組，避免建立大量重複鍵。

常見用詞：

| 大陸簡體 | 香港繁體 |
| --- | --- |
| 单词本 | 生字簿 |
| 加载 | 載入 |
| 上传 | 上載 |
| 网络 | 網絡 |
| 链接 | 連結 |
| 设置 | 設定 |
| 保存 | 儲存 |

香港繁體採用正式書面中文，不預設寫成粵語口語，也不直接套用台灣慣用詞。

## 6. 學習內容不得自動轉換

介面語言與學習內容互相獨立。切換語言時不得修改：

- 詞書名稱及詞書內容。
- 教材、文章及新聞原文。
- OCR 識別原文。
- QA 問題、標準答案及使用者答案。
- 使用者輸入、自訂提示詞及歷史訊息。
- 已經產生並儲存的舊 AI 內容。

只翻譯明確屬於應用 UI 的系統文字。

## 7. AI 提示詞規則

- AI 任務模板及 JSON schema 只維護一套。
- 提示詞集中在 `modules/prompts/`。
- 語言差異由 `modules/prompts/language-rules.js` 按目前 locale 注入。
- `zh-CN` 要求解釋、翻譯、回饋及建議使用大陸簡體中文。
- `zh-HK` 要求使用香港繁體正式書面中文。
- 提示詞不得要求模型轉換使用者原文的簡繁體。
- AI 快取鍵必須包含 locale，避免不同語言互相命中舊快取。

## 8. 開發完成檢查清單

新增或修改 UI 功能後必須確認：

- [ ] 靜態 HTML 文案已使用 i18n 屬性。
- [ ] 動態 JavaScript 文案已使用 `t()`。
- [ ] `zh-CN.js` 及 `zh-HK.js` 同時包含新鍵。
- [ ] 簡體介面沒有出現 `載入、詞、簿、詳、關閉` 等繁體殘留。
- [ ] 香港繁體介面沒有出現不合適的簡體或台灣用詞。
- [ ] 載入、成功、失敗、重試及空狀態已全部檢查。
- [ ] 彈窗、Tooltip、選單及流動版介面已全部檢查。
- [ ] 切換語言不會改變教材及使用者資料。
- [ ] 產生中文的 AI 功能已分別驗證簡體及香港繁體輸出。
- [ ] 兩份 locale 鍵集合一致，程式碼沒有引用缺失鍵。

## 9. 建議驗證方式

專案沒有正式測試 runner，可先執行：

```bash
node --check features/<module>/<file>.js
node --check locales/zh-CN.js
node --check locales/zh-HK.js
git diff --check
```

然後透過瀏覽器或 Playwright 分別切換 `zh-CN`、`zh-HK`，巡檢本次修改涉及的完整互動流程，不能只檢查初始頁面。

## 10. Code Review 阻擋條件

出現以下任一情況時，UI 修改不應視為完成：

1. 新增使用者可見中文但沒有使用 i18n。
2. 只新增 `zh-CN` 或只新增 `zh-HK`。
3. 初始按鈕已翻譯，但載入、錯誤或完成狀態仍然硬編碼。
4. 為兩種語言複製兩套功能邏輯。
5. 切換語言時改寫使用者內容或教材內容。
6. AI 輸出語言沒有跟隨目前介面語言。
