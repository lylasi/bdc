## 已核對事實

- 短語提示詞目前同時要求音標、意思、用法及中英例句，見 [article.js](../../modules/prompts/article.js:131)。單字提示詞沒有要求例句。
- 查詞走非串流 AI，全部完成後才顯示，見 [api.js](../../modules/api.js:674)、[lookup.js](../../extension/lookup.js:699)。因此短語例句的生成時間會增加首次詞義出現前的等待。
- 首次查新詞在本機快取未命中後會等待帳戶 AI 設定同步；該同步也等待 TTS 完成，見 [lookup.js](../../extension/lookup.js:691)、[extension-ai-runtime.js](../../modules/extension-ai-runtime.js:195)。需要核對可否將與文字查詢無關的等待移至背景，同時保留帳戶驗證、401 清理、最新 AI 設定套用及帳戶切換防護。
- 詞卡已有 `ext-result-details` 的展開入口，見 [lookup.html](../../extension/lookup.html:114)，但沒有點開才請求的處理；CSS 目前會隱藏尚無例句的整個區塊，需配合新狀態調整。
- 既有 `generateExamplesForWord()` 會生成三句及逐詞對齊，沒有查詞釋義或原文語境，不宜直接用於精簡的按需例句，見 [api.js](../../modules/api.js:1066)、[learning.js](../../modules/prompts/learning.js:9)。
- 擴充套件已有按帳戶保存的模型與思考控制；預設查詞思考為 none，不能假定慢是深思造成，也不能未經決定就更換模型。

## 具體實作提案

1. 共用 AI 層支援精簡查詞，讓 extension 首輪不請求例句；沿用共用協議及語言規則，並保留主站文章詳解原有的例句需求。
2. 在共用 AI 層新增依本次詞語、釋義及原文語境生成精簡例句的入口，由可信任的 extension runtime 呼叫。
3. 詞義顯示後保留「例句」展開入口；首次展開時讀取可用例句或另發 AI 請求，顯示載入狀態，失敗可重試。沒有點開時例句請求應為零。
4. 例句有獨立快取，依帳戶、同步端點、供應商連線、模型、思考、語言、詞語、釋義、原句／語境及提示詞版本隔離。收合再展開及同時點擊不重複請求。
5. 更換詞語、語言、帳戶、端點或重新查詞時取消或丟棄過期例句，防止舊結果覆蓋新詞卡；例句失敗保留原有詞義。
6. 同時完成 zh-CN、zh-HK 的載入、錯誤及重試文案，維持香港正式書面中文，教材與歷史內容不隨 UI 語言轉換。
7. 核對文字查詞是否需要等待 TTS；若可分離，保留完整帳戶與設定保護，將該等待移至背景。
