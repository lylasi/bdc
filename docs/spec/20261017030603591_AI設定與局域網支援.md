# AI 設定與局域網支援

更新：2026-10-18。原建議稿的多數項目已落地，本文改記現行行為與仍受限的連線條件。

## 現行設定方式

- 供應商只有兩個來源：管理員在「設定 → 管理預設供應商」發布到 Cloudflare D1 的共享清單；使用者在「設定 → 我的供應商」建立的帳戶／裝置 profile。`ai-config.js` 不再保存 AI 網址、Key 或模型。
- 新增供應商只需「服務網址 + API Key」（無 Key 可留空）→ 連接 → 選模型 → 儲存。系統會自動辨識協議及取得模型；協議、API／模型端點、認證方式及模型名稱可在進階設定手動覆寫。
- 支援 OpenAI Chat Completions 相容、Anthropic Messages、Gemini 原生（文字／圖片／JSON／串流）。未實作的協議會明確提示，不會猜測。
- 日常任務沿用預設模型；文章分析、QA 校對、OCR、助手等可在任務設定逐項覆寫。OCR 需選支援圖片的模型。
- 可建立多個具名供應商並手動切換；目前沒有「局域網失敗自動改走雲端」的後備，避免教材在未確認下送出。
- 個人 Key 預設只存目前裝置；登入後可逐供應商選擇是否同步到 D1（AES-GCM）。同步快照只含非秘密設定，不含 Key。
- 無 Key 服務須選「無需金鑰」，此時不送 `Authorization`，也不會繼承其他供應商的 Key。

## 局域網連線條件

- 手機上的 `localhost` 指向手機本身；連接電腦上的 AI 服務時，要填電腦的區網 IP，例如 `http://192.168.1.100:11434/v1`。服務須監聽區網介面、防火牆放行，並正確回應 CORS（含預檢）。
- `python3 scripts/serve.py --lan` 只改變前端綁定位址，讓同網段裝置載入頁面；AI 仍由瀏覽器直連，除非另加 `--ai-proxy` 走同源 `/v1`。同網段可讀 `ai-config.js`，僅應在可信網絡使用。
- HTTPS 頁面直連 HTTP 區網服務受瀏覽器混合內容與本地網路權限限制。Chrome 142 起可經使用者授權放寬，但各瀏覽器不一致；需要穩定跨瀏覽器使用時，應在同一入口提供網頁與 API 反向代理。
- 公網 Worker／代理無法直接連到家中私有 IP；D1 只保存設定，不會代理局域網請求。
- `scripts/serve.py` 的 `/v1/*` 是舊式同源代理，現行供應商設定要填完整絕對網址；不同裝置的 origin 可能不同，同步前請確認 binding。

## 診斷

- 分開測試模型列表與實際推理；列表成功不代表推理可用。推理測試應顯示成功狀態與耗時。
- 401／403、404／405、429、5xx 及超時按實際狀態提示。`Failed to fetch` 可能是 CORS、權限、混合內容或服務未啟動，不能只斷定為 CORS。
- 驗證至少涵蓋：無 Key 服務、HTTP 區網端點、雲端端點、失敗與重試，以及 zh-CN／zh-HK 兩種介面。
- 部署與發布步驟見 `docs/release/20261018025155000_AI供應商逐步部署與維護手冊.md`。
