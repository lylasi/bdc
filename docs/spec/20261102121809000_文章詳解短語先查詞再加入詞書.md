# 文章詳解：短語先查詞、再決定加入詞書

- 時間：2026-11-02 12:18（2026-11-02 13:0x 修訂：查詞改用單詞詳解彈窗）
- 狀態：已實作
- 涉及模組：`features/article/`、`locales/`、`styles.css`

## 1. 問題

文章詳解區選取多個詞（短語）後，浮動工具條只有「加入單詞本」，短語面板（選短語）也只有「加入詞書／標記／寫筆記／問 AI／重新選」。

結果是：

1. 使用者無法在加入前先看到 AI 對這個短語的釋義、用法與例句，只能先加進去再回頭刪；
2. 短語沒有走過任何分析，加入詞書的條目往往沒有中文意思（單詞因為有查詞彈窗，釋義會一併寫入）。

需求：短語也要能「先查詞 → 看 AI 釋義適不適合 → 再決定是否加入單詞本」，而且**畫面要跟單詞查詞一樣**（同一個彈出框），不要另一個滿屏面板。

## 2. 方案

### 第一次修訂（已廢棄）

曾在短語面板內加「查詞」與釋義區。實際使用時面板內容過多（候選詞列表＋預覽＋釋義＋一排按鈕），與單詞查詞的輕量彈窗體驗不一致，使用者明確要求改回「像查單詞那樣那個彈出的框」。

### 現行方案

查詞直接複用單詞詳解的彈窗 `#word-analysis-tooltip`（同一個節點、同一套 CSS、同一組按鈕）：

- 選取工具條對多詞短語顯示「查詞」（`data-act="lookup"`）；點下去開的就是單詞查詞那個框。
- 彈窗標題＝短語（有音標/詞性時附上）；內容＝**意思／用法／例句**；右上角是「重新查詞」與關閉。
- 底部動作列與單詞查詞一致：發音、加詞本、標記、問 AI、更多（寫筆記）——都走 `#word-analysis-tooltip` 既有的委派處理器，資料用 `data-*` 屬性傳遞。
- 定位沿用「觸發詞」機制：以選取範圍的**起詞**作為錨點，視窗捲動、縮放、窄屏轉底部 sheet 都跟單詞查詞同一條路徑。
- 短語面板（選短語）**回到原本樣式**，不再負責查詞；它只負責挑範圍、加入詞書、標記、寫筆記、問 AI。

## 3. 行為細節

| 情境 | 行為 |
| --- | --- |
| 同一 occurrence 已有解釋 | 直接顯示（`analyzePhraseWithSaved` 先查 `findSavedItem`），不請求模型，並更新查閱時間 |
| 沒有解釋、有可用模型 | `api.analyzeSelection()` → 顯示 → `recordExplanation()` 寫回條目（`markViewed` 僅在畫面真的顯示時為 true） |
| 沒有釋義（AI 失敗／沒有可用模型） | 彈窗內顯示原因（缺模型時用 `article.aiNotConfigured`），提供「重試」；**不寫入空解釋**（`analyzePhraseWithSaved` 已改為只在有 meaning 時才落盤） |
| 「重新查詞」 | `force: true` 跳過已存解釋、繞過快取重新請求 |
| 請求期間換選取／關彈窗／切帳戶 | 以 `wordTooltipSession` + 凍結的 `actionContext`／`contentVersion` 判定，舊回應不改畫面、不寫錯帳戶 |
| 加到詞書 | 按鈕的 `data-meaning` 來自目前釋義，`addItemToVocabulary()` 亦會讀條目的 `explanation.result.analysis.meaning`，所以條目一定帶中文意思 |
| 介面語言切換 | 卡片沿用 `wordTooltipRender`／`wordTooltipLastPayload`，直接以新語言重畫 |
| 單詞選取 | 工具條不顯示「查詞」，維持原本點詞開查詞彈窗 |

## 4. 變更檔案

- `features/article/article.js`
  - 新增 `showSelectionLookupTooltip()`：組出與單詞詳解相同的彈窗（標題／內容／動作列），沿用 `ui.repositionTooltip`、`syncWordTooltipSheetMode()`、`initWordTooltipMenu()` 與既有按鈕委派。
  - `analyzePhraseWithSaved()`：支援 `force`（重新查詞）與 `noCache`；**沒有 meaning 時不寫入解釋**（避免閱讀記錄出現空白解析）。
  - 選取工具條：新增 `data-act="lookup"`（僅多詞短語顯示），`captureSelection()` 額外回傳起詞元素作錨點。
- `features/article/phrase-picker.js`：回到原本結構（只保留 `btn-primary`／`btn-secondary`／`btn-tertiary` 的樣式修正）。
- `styles.css`：`.tooltip-examples`（例句清單，補回全域清掉的项目符號）與 `.tooltip-error`；短語面板恢復原樣。
- `locales/zh-CN.js`、`locales/zh-HK.js`：新增 `article.lookupPhrase`、`article.lookupFailed`。
- `tests/reading-phrase-lookup.cjs`：驗收腳本（支援 `PORT` 與 `BASE_URL`）。

## 6. 已知取捨

- 查詞卡的錨點是「選取範圍的起詞」而不是整個選區：好處是沿用單詞彈窗的捲動跟隨與底部 sheet 行為，代價是長短語時卡片會對齊起詞。
- 詞卡「問 AI」回上層時（助手 `onReturn`）會以起詞重開單詞卡片，而不是短語卡片；目前只在助手內退回時出現，未另做處理。
- 「加入單詞本」按鈕在工具條上仍是直接加入（不先分析）；需要先看釋義就走「查詞」。
