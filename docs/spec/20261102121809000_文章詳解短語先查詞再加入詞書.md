# 文章詳解：短語先查詞、再決定加入詞書

- 時間：2026-11-02 12:18
- 狀態：已實作
- 涉及模組：`features/article/`、`locales/`、`styles.css`

## 1. 問題

文章詳解區選取多個詞（短語）後，浮動工具條只有「加入單詞本」，短語面板（選短語）也只有「加入詞書／標記／寫筆記／問 AI／重新選」。

結果是：

1. 使用者無法在加入前先看到 AI 對這個短語的釋義、用法與例句，只能先加進去再回頭刪；
2. 短語沒有走過任何分析，加入詞書的條目往往沒有中文意思（單詞因為有查詞彈窗，釋義會一併寫入）。

需求：短語也要能「先查詞 → 看 AI 釋義適不適合 → 再決定是否加入單詞本」。

## 2. 方案

沿用既有的短語面板（`features/article/phrase-picker.js`，手機底部面板／桌面面板同一個），新增一個「查詞」動作與釋義區塊，而不是再造一個新的彈窗：

- 面板動作列最前面加「查詞」（`#phrase-picker-lookup`），下方新增釋義區塊（`#phrase-picker-analysis`）；
- 釋義區顯示：意思（單詞另有音標）、用法、最多 3 條例句；
- 「查詞」成功後按鈕改為「重新查詞」，可重查；
- 「加入單詞本」維持原行為，但因為查詞結果已寫回同一條學習條目，加入詞書時會自動帶上這份釋義。

浮動選取工具條（`features/article/article.js` → `initArticleSelectionToWordbook`）：

- 選取範圍含空白（多詞短語）時，工具條多一個「查詞」；
- 點它會直接開短語面板並自動執行一次查詞（`openPhrasePicker({ autoLookup: true })`）；
- 單詞選取不顯示「查詞」，維持原本「點單詞開查詞彈窗」的路徑，避免多餘入口。

## 3. 行為細節

| 情境 | 行為 |
| --- | --- |
| 同一 occurrence 已有解釋 | 直接顯示（`readingActions.findSavedItem` + `explanationFromItem`），不請求模型，並更新查閱時間 |
| 沒有解釋、有可用模型 | `api.analyzeSelection()` → 顯示 → `readingActions.recordExplanation()` 寫回條目（`markViewed` 僅在畫面真的顯示時為 true） |
| 沒有任何可用模型 | 查詞前先以 `ai-models.getPreferredTaskSpec()` 判斷，直接顯示「尚未配置可用的 AI 供應商與模型」，不送出必定失敗的請求 |
| AI 回應為空釋義 | 視為失敗（`lookup_empty`），不寫入條目，顯示失敗文案 |
| 請求期間改了選取範圍或關閉面板 | 回應不改寫畫面；仍保存解釋但不記為查閱 |
| 帳戶／文章 scope 在請求期間切換 | 凍結 `actionContext`，`recordExplanation` 會以 `stale_scope` 拒絕寫入 |
| 查詞失敗 | 釋義區顯示原因（已本地化的 AI／網路錯誤直接顯示），按鈕可重試，「加入單詞本」不受影響 |
| 介面語言切換 | 面板重建後（`bdc:locale-change`）以已存解釋讀回同一份釋義（`captureSheetState.lookupShown`） |
| 加到詞書 | `addItemToVocabulary()` 從條目的 `explanation.result.analysis.meaning` 取釋義，因此查過詞再加的條目會帶中文意思 |

同時修正短語面板按鈕樣式：原本寫成 `class="btn primary"`，會被 `button.btn` 基礎樣式蓋掉（`.primary` 特異性較低），整個面板的按鈕都退化成純文字。改為專案慣用的 `btn-primary` / `btn-secondary` / `btn-tertiary`，讓「查詞」與「加入單詞本」有可見的按鈕層級（`加入單詞本` 為主行動）。

## 4. 變更檔案

- `features/article/phrase-picker.js`
  - 新增 `#phrase-picker-lookup`、`#phrase-picker-analysis`
  - 新增 `selectionKey()`、`resetLookup()`、`renderLookup()`、`runLookup()`
  - `openPhrasePicker({ autoLookup })`；`captureSheetState()/restoreSheetState()` 保留釋義
  - `updatePreview()`／`setBusy()` 反映查詞狀態；範圍改變即收回釋義
- `features/article/article.js`
  - 選取工具條新增 `data-act="lookup"`（僅多詞短語顯示），沿用 `openPhrasePicker(..., autoLookup: true)`
- `styles.css`
  - `.phrase-picker-analysis*` 樣式；`.phrase-picker-actions > button` 取代 `.phrase-picker-actions .btn`
  - 手機（≤767px）`#phrase-picker-lookup` 與 `#phrase-picker-add` 各佔整列
- `locales/zh-CN.js`、`locales/zh-HK.js`
  - 新增 `article.lookupPhrase`、`lookupLoading`、`lookupFailed`、`lookupEmpty`、`lookupRedo`
  - `article.phrasePickerSelected` 文案改為「可以先查詞，再決定是否加入詞書」
- `tests/reading-phrase-lookup.cjs`（新增）
