# AI 思考開關品質與速度對照 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 對本機可用 AI 模型實際比較關閉／開啟思考的答案品質、首段正文時間、總耗時及完整性，提供 BDC 任務設定建議。

**Architecture:** 所有新增內容放在獨立的調研附件目錄，沿用 BDC 提示詞，以固定供應商模型直接呼叫本機 Magpie 網關。先核對參數的實際作用，再以交錯次序重複對照，保存答案與統計，不更改產品程式或帳戶設定。

**Tech Stack:** Node.js 原生 fetch、node:test、現有 modules/prompts、Python 標準庫、現行 Magpie 與 grok2api 的唯讀協議資料。

**Spec:** 使用者本輪要求「測試加思考和不加思考，得到結果的品質還有速度的區別，綜合分析」；現況依 `docs/research/20261102120957540_AI查詞文章翻譯與助手思考強度核對.md`。

## Global Constraints

- 供應商使用本機已配置的 Magpie；不輸出、持久化或改動金鑰。
- 不修改工作區既有產品變更，也不改動使用者模型選擇或代理設定。
- 所有計劃、原始測試資料與報告落在 `docs`，文件名包含 `yyyyMMddHHmmssfff`。
- 同一模型、同一提示詞、同一生成預算及 temperature 對照；只改思考欄位。
- 使用自行撰寫的公開性質英文測例，沒有使用者私人文章或歷史對話。
- 思考內容僅記錄是否出現、字數與可用 token 用量，不保存或展示推理原文。
- 無完整用量資料時不估造費用；模型名按網關回傳記錄，不將其等同於獨立驗證過的官方型號。

## Review Focus

- 參數被忽略、被改寫或只隱藏思考輸出：先核對實際路由，不將此類結果當有效推理開關。
- 首個 SSE 事件只有角色或思考：正文首字時間須單獨計算，不能把 HTTP 標頭時間當作答案到達時間。
- HTTP 200 後 SSE 發生錯誤、串流提前結束或 JSON 被截斷：保留失敗記錄，不能混進成功延遲統計。
- 網絡抖動、暖機與先後次序影響：交錯模式、重複測量，呈現中位數及樣本數。
- 品質評估偏好較長答案：先寫答案要點，按正確性、完整性、指令與格式評估，再對匿名答案逐項覆核（模型評審加執行代理覆核）。
