# AI 方案 C 服務端憑證接入實施建議

建議沿用 BDC 現有 Cloudflare Worker 與 D1 使用者認證，增加受保護的 AI API。供應商金鑰留在服務端；前端使用自身的 BDC 登入憑證。這是一份實施建議，尚未修改程式或部署。

## 現有基礎

features/sync/sync.js 已使用 modules/sync-cloudflare.js；cloudflare-worker/src/worker.js 以 Bearer 通行碼查詢 D1 users 表。可沿用此身份，再增加 AI 權限，不需要新增 Supabase JWT 登入。

現有認證是長效通行碼，並非短效登入會話。第一版可沿用高熵隨機通行碼並加入認證失敗限流、AI 權限及用量限制；若擴展多人使用，再改為通行碼換取可撤銷、短效的會話。瀏覽器仍有 BDC 登入憑證，並非沒有任何秘密。

## 請求與保存位置

瀏覽器 → BDC Worker 驗證身份與權限 → magpie 受保護入口 → magpie → 上游供應商。

- 瀏覽器：模型選擇及 BDC 登入憑證，不持有 magpie 或上游供應商金鑰。
- Worker Secrets：magpie 專用 gateway key、Cloudflare Access service token 的 Client ID 和 Client Secret。
- magpie：HAPI 等上游供應商金鑰與路由設定。
- D1：使用者身份、AI 權限、模型白名單與必要用量資料。第一版不把供應商金鑰放進可同步的快照。

若只使用 HAPI，可以先採用瀏覽器 → Worker → HAPI，將 HAPI 金鑰直接保存在 Worker Secrets，省去 magpie 隧道；往後增加 magpie 接入。需要 magpie 模型時則完成下述隧道配置。

## 部署步驟

1. 在 magpie 建立 BDC 專用 gateway key，限定可用模型和總額度。保留上游金鑰於 magpie 的管理設定。
2. 讓可連上 magpie 的 cloudflared 建立專用 HTTPS hostname，例如 ai-origin.example.com，轉到 magpie 的內網服務；只有 cloudflared 跑在 magpie 同機時才用 127.0.0.1:3425。
3. 為該 hostname 建立 Cloudflare Access 自託管應用，以 Service Auth 策略只允許指定 service token，不設公開 Bypass。Worker 呼叫時帶 CF-Access-Client-Id 與 CF-Access-Client-Secret。Worker 不能只填家庭私有 IP 就直接連回家中。
4. 在 Worker Secrets 設定 MAGPIE_GATEWAY_KEY、CF_ACCESS_CLIENT_ID、CF_ACCESS_CLIENT_SECRET。上游網址用普通環境設定；所有金鑰均不放 ai-config.js、Wrangler vars、Git 或網址查詢參數。
5. 擴充既有 Worker，新增 GET /api/ai/models 及 POST /api/ai/chat/completions。先驗證 BDC 使用者和 AI 權限，再以新的服務端標頭呼叫固定上游。不要把 BDC 使用者的 Authorization 轉送到上游。
6. 將受 Cloudflare 代理的正式網站 hostname 之 /api/ai/* Route 指向 Worker，使網頁與 AI 同源。若先沿用獨立 workers.dev 網址，必須正確設定前端來源的 CORS；憑證仍在服務端，但不是同源。原路由器的 :5000 入口不會自動獲得 Cloudflare Route，需另作路由或使用完整 Worker URL。
7. BDC 增加受管理的 AI 服務類型：登入後取得可用模型，不顯示供應商 Key 欄位。此模式透過共用的請求抽象帶上 BDC 憑證，且只發往受信任的 BDC API，避免將通行碼發往使用者任意填寫的 provider URL。

Secrets 官方說明：https://developers.cloudflare.com/workers/configuration/secrets/
Access service token 官方說明：https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/
Worker Routes 前提與配置：https://developers.cloudflare.com/workers/configuration/routing/routes/

## 程式變更範圍

cloudflare-worker/src/worker.js 增加 AI 路由、權限與上游轉送；獨立模組維護轉送邏輯，避免同步處理與 AI 混雜。用 schema migration 新增使用者 AI 授權，預設不授權所有同步帳戶。

modules/api.js 與 modules/ai-models.js 統一管理模式下的請求及模型列表；features/assistant/assistant.js 目前有直接 fetch 的串流路徑，也須改接共用入口。前端設定和文案同時覆蓋 zh-CN、zh-HK。

後端只開放必要路徑與方法、固定上游 hostname，禁止客戶端指定任意轉送 URL；限制模型、輸出 token、請求大小和請求頻率。總預算以 magpie 硬限制兜底；若要每人硬額度，需服務端具備原子預留及結算，不能僅用 Worker 記憶體計數。限制亦應涵蓋認證失敗與既有通行碼重置入口。

串流回覆應透傳，不把整段回覆緩衝成 JSON。錯誤輸出與日誌不含 secrets，AI 回覆不進共享快取。相同驗證應適用於 Worker 所有可達入口。

## 驗收與交付順序

先本地完成 Worker、前端及雙語介面，再部署測試環境驗證。涵蓋未登入 401、無權限 403、非法模型與任意上游被拒、限流、模型列表、一般推理、助手串流、OCR 圖片請求、超時與取消，以及同步功能回歸。

透過手機網絡驗證 BDC 登入後可用 magpie，瀏覽器請求、靜態檔案及一般設定匯出均無上游金鑰。沒有 service token 的隧道請求必須被 Access 拒絕。

確認秘密已從公開設定移除後，輪換任何曾公開的金鑰；正式切換前驗證實際網域及所有現用入口。使用家中 magpie 時，電腦、magpie 與隧道須持續運作；經雲端 Worker 的請求內容會通過 Cloudflare。
