# 文章唯讀分享與獨立副本 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 同一同步服務內的帳戶能分享唯讀文章，接收者可建立自己的副本，但不能修改或刪除分享者原文。

**Architecture:** 分享使用獨立的不可修改快照，與私人文章 ID／outbox 分離。伺服器按登入身份檢查分享者／接收者，複製時以新文章 ID 寫入接收者的 articles，再沿用既有同步。UI 以唯讀分享預覽顯示內容，只有複製成功後才進入可編輯文章功能。

**Tech Stack:** ES2022、原生 ES Modules、Cloudflare Worker／D1、共用 selfhost SQLite／PostgreSQL handler、node:test、Playwright。

**Spec:** [既有文章獨立儲存與指定用戶分享設計](../spec/20261018184206963_文章獨立儲存與指定用戶分享建議.md)、本次使用者要求「它可以複製一份，但是不能刪除別人的」。本輪以單一接收者每筆分享實作上述設計。

## Global Constraints

- 使用 ES2022、4 空白縮排、單引號；延用檔案既有格式。
- 使用者可見文字同時支援 `zh-CN`（預設）及 `zh-HK`；動態 UI 必須呼叫 `t()`。
- 純前端靜態 SPA，沒有 bundler，也沒有既定的 npm scripts 工作流。
- 分享僅適用於同一同步服務的兩個不同帳戶，輸入穩定的「帳戶 ID」，不以 label 或登入通行碼授權。
- 唯讀固定快照只含原文、標題與白名單翻譯。個人單字／句子詳解、筆記、收藏、詞書、助手訊息不分享；來源 URL 不隨分享送出。
- 接收者移除分享僅修改自己的收件狀態；分享者撤回或刪除原文後停止服務端讀取。已建立的副本獨立保留。
- 不修改本機私有 `ai-config.js`、不提交、不部署、不操作正式帳戶。

API 契約：

```text
POST   /article-shares
       { articleId, recipientUserId, expectedRevision, clientMutationId }
       -> { share: { id, title, ownerUserId, ownerLabel, recipientUserId, sourceRevision, createdAt } }
GET    /article-shares?direction=received|sent&limit=50&offset=0
       -> { shares: [metadata], hasMore, offset }
GET    /article-shares/:shareId
       -> { share: metadata, article: { title, body, analysis, sourceType, sourceUrl: '' } }
DELETE /article-shares/:shareId
       -> owner: { revoked: true }; recipient: { removed: true }
POST   /article-shares/:shareId/copy
       { clientMutationId }
       -> { article: ownArticleDocument, created, idempotent? }
```

分享建立與複製必須有非空 mutation ID，重試不得產生重複分享／副本。副本 ID 由登入接收者、share ID、mutation ID 的 SHA-256 推導；永遠不接受客戶端指定 owner 或覆寫原文 ID。

### Task 1: 分享協議與後端權限

**Files:** 上表 shared、Worker／selfhost handler、schema／migration，以及 `tests/article-shares.test.mjs`。

**Interfaces:** `handleArticleSharesRoute({ request, env, url, user, rest }) -> Response`；`sanitizeSharedArticle(document) -> ArticleDocument`；文章建立允許僅供內部使用的分享授權條件，普通 `/articles` 請求不可設定該條件。

- [ ] **Step 1: 加入並執行失敗測試**

```js
const shared = await api('alice', '/article-shares', 'POST', {
    articleId: original.id, recipientUserId: 'bob', expectedRevision: 1, clientMutationId: 'share-1'
});
assert.equal(shared.status, 201);
const copy = await api('bob', `/article-shares/${shared.body.share.id}/copy`, 'POST', { clientMutationId: 'copy-1' });
assert.equal(copy.status, 201);
assert.notEqual(copy.body.article.id, original.id);
assert.equal((await api('bob', `/articles/${original.id}`, 'DELETE', { expectedRevision: 1 })).status, 404);
assert.equal((await api('alice', `/articles/${original.id}`)).body.article.deletedAt, '');
```

Run: `node --test tests/article-shares.test.mjs`；初次預期分享端點尚不存在而失敗。

- [ ] **Step 2: 實作 schema 與共用 handler**

```sql
CREATE TABLE IF NOT EXISTS article_shares (
    id TEXT PRIMARY KEY,
    owner_user_id TEXT NOT NULL,
    article_id TEXT NOT NULL,
    recipient_user_id TEXT NOT NULL,
    source_revision INTEGER NOT NULL,
    snapshot_json TEXT,
    size_bytes INTEGER NOT NULL,
    created_at TEXT NOT NULL,
    revoked_at TEXT,
    dismissed_at TEXT,
    client_mutation_id TEXT NOT NULL,
    UNIQUE (owner_user_id, client_mutation_id)
);
```

使用 `INSERT ... SELECT FROM articles WHERE owner_user_id = ? AND id = ? AND revision = ? AND deleted_at IS NULL` 固定快照版本；SQL 同時限制有效分享數量及總 bytes。PostgreSQL 在 batch 中鎖定分享者及來源文章，避免配額與版本競態。單一分享 800 KiB、每位分享者有效分享最多 100 筆、合計 50 MiB。

- [ ] **Step 3: 複製與撤回**

```js
const id = `art_${sha256(recipientUserId + '\0' + shareId + '\0' + mutationId).slice(0, 40)}`;
```

副本沿用文章建立的配額／change／cursor 交易，INSERT 加入有效分享、recipient 及原文未刪除的條件。撤回清除 snapshot；原文 DELETE 同交易撤回該文章全部分享。刪除復原不自動重開舊分享。

- [ ] **Step 4: 協議測試通過**

Run: `node --test tests/article-shares.test.mjs tests/articles-protocol.test.mjs tests/reading-protocol.test.mjs`。

驗證：匿名 401、第三人與不存在對象 404、非擁有人不可分享、舊版本 409、無私人內容、分享不跟隨改文、相同 mutation 重試不新增、接收者移除不改原文、撤回阻止未複製者、已複製副本可改／刪且原文不變、配額、原文刪除後分享撤回且復原不再有效。

### Task 2: 雙語分享 UI 與私人資料隔離

**Files:** 上表 frontend、HTML／CSS、locales、`tests/article-sharing.cjs`。

**Interfaces:** UI 消費 Task 1 API；`initArticleSharing()` 綁定入口、`showSharedArticle(shareId)` 顯示唯讀預覽。副本接收後以既有文章 store 的遠端文件套用方法保存，再導覽到 `#a/<newId>`。

- [ ] **Step 1: 建立雙帳戶瀏覽器案例**

```js
await alice.locator('#article-share-btn').click();
await alice.locator('#article-share-recipient').fill('bob');
await alice.locator('#article-share-create').click();
await bob.locator('#article-shared-inbox-btn').click();
await bob.locator('[data-share-open]').first().click();
await bob.locator('#article-share-copy').click();
assert.notEqual(await currentId(bob), await currentId(alice));
```

- [ ] **Step 2: 分享與收件視窗**

以集中 DOM 綁定兩個工具列按鈕；建立分享前要求登入、文章已同步、沒有尚未保存的修改或衝突。未保存修改提供明確提示，不能靜默分享錯版本。收件／已分享清單提供重新載入、分頁、空狀態、失敗重試；唯讀預覽用文字節點顯示標題、原文與翻譯，不把外來內容寫入可編輯的全域 article state。

- [ ] **Step 3: 帳戶與請求隔離**

每次請求捕捉 endpoint、userId、token；回應後檢查一致，過期回應丟棄。登出／401／帳戶與同步服務切換關閉分享內容，複製不得在身份改變後寫入新帳戶。快照只保存在目前視窗記憶體；複製成功後的個人文章走現有儲存／同步／備份。

- [ ] **Step 4: 雙語完整驗證**

Run: `PORT=8313 PLAYWRIGHT_MODULE=<path> node tests/article-sharing.cjs`。

完整跑 `zh-CN`、`zh-HK`，含載入／分享成功／收件／複製／移除／撤回／錯誤重試／帳戶切換與手機寬度。驗證唯讀預覽沒有文章刪除或修改操作。
