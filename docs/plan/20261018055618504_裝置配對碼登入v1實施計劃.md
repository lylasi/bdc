# 裝置配對碼登入 v1 實施計劃

- 時間：2026-10-18 05:56:18 CST
- 狀態：已完成並部署後端與前端（2026-10-18；部署記錄見 `docs/release/20261018161115856_裝置配對碼登入v1部署記錄.md`）
- 關聯：`cloudflare-worker/`、`modules/sync-cloudflare.js`、`features/sync/sync.js`、`features/admin-users/`
- 前置評估：`docs/research/20261018054804004_普通用戶通行碼強度與登入方式評估.md` 方案 A

## 1. 目標

保留現有 43 字元高強度通行碼，不降低帳戶憑證強度；讓使用者在**新裝置**上
不必手動輸入 43 字元通行碼，改由管理員產生短效一次性配對碼，新裝置用
「用戶代號 + 配對碼」換取長期 session token。

同時補上可撤銷的裝置 session，讓重設通行碼時能一次撤銷所有已配對裝置。

## 2. 範圍

- 管理員可為非管理員用戶產生配對碼：
  - 12 字元、排除易混淆字元、10 分鐘有效、只能使用一次。
  - 資料庫只存 SHA-256 雜湊，不存明文。
- 新裝置配對：
  - `POST /pair` 接受 `{ userId, code }`。
  - 成功後建立 180 天有效的隨機 session token（43 字元），回傳一次。
  - 不影響原本的 `users.token_hash`，既有裝置不會被登出。
- Worker `authenticate()` 同時接受：
  - 原本的通行碼（`users.token_hash`）。
  - 配對產生的 session token（`user_sessions.token_hash`，需未過期）。
- 登入彈窗新增「使用裝置配對碼」表單與「本機會記住登入」提示。
- 管理員用戶面板新增「產生配對碼」按鈕與一次性配對碼卡片。
- 重設通行碼（自助恢復、登入後修改、管理員重設）時：
  - 刪除該用戶所有 `user_sessions`。
  - 刪除該用戶所有未使用的 `pairing_codes`。
- 管理員帳戶不允許產生配對碼；仍使用高強度通行碼或部署者流程。

## 3. 非範圍

- 不把通行碼改成短密碼，也不降低 `MIN_AI_PASSCODE_LENGTH`。
- 不提供公開註冊、電郵 OAuth 或電郵驗證碼。
- 不提供 session 列表／單一裝置撤銷介面；目前以重設通行碼撤銷全部裝置。
- 不提供用戶自助產生配對碼（第一版由管理員產生）。

## 4. 資料模型

新增 `cloudflare-worker/migrations/003_device_pairing.sql`：

### `user_sessions`

| 欄位 | 說明 |
| --- | --- |
| `token_hash` | SHA-256(session token)，主鍵 |
| `user_id` | 所屬用戶 |
| `created_at` | 建立時間 |
| `expires_at` | 到期時間（180 天） |
| `device_label` | 可選裝置標籤 |

### `pairing_codes`

| 欄位 | 說明 |
| --- | --- |
| `code_hash` | SHA-256(正規化配對碼)，主鍵 |
| `user_id` | 目標用戶 |
| `created_by` | 產生配對碼的管理員 |
| `created_at` | 建立時間 |
| `expires_at` | 10 分鐘後到期 |
| `used_at` | 使用時間；非空代表已用 |

同時更新 `schema.sql`，讓全新安裝具備相同結構。

## 5. Worker API

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| POST | `/pair` | 未登入；`{ userId, code }` → `{ token, user_id, label, role, expires_at }` |
| POST | `/admin/users/:id/pairing-code` | 管理員；產生一次性配對碼，回傳 `{ userId, code, expiresAt }` |

配對碼規則：

- 字母表排除 `0/O/1/I`，長度 12，約 60 bits。
- 輸入時轉大寫並移除空白／連字號。
- 查詢與標記使用採條件更新 `WHERE code_hash=? AND used_at IS NULL`，
  避免同一組配對碼被兩台裝置同時使用。
- 所有失敗（不存在、過期、已用、帳戶不符、管理員帳戶）一律回
  `403 pairing_invalid`，避免洩漏帳戶是否存在。

## 7. 安全與邊界

- 配對碼是 10 分鐘有效的臨時憑證，等同學一次登入機會；管理員需以安全渠道交付。
- 配對碼只存雜湊，回應後不再可查。
- 管理員帳戶不可產生配對碼，避免擴大管理權限的臨時憑證面。
- 重設通行碼會撤銷所有 session 與未使用配對碼，可用於遺失裝置的補救。
- Session token 與通行碼同為 Bearer，兩者都受既有 Origin 白名單與 32 字元
  AI／管理接口門檻保護。
- `/pair` 有 IP 速率限制；配對碼本身有 60 bits 熵與 10 分鐘有效期。

```bash

node tests/audit-i18n.mjs
PORT=8313 PLAYWRIGHT_MODULE=<path-to-playwright> node tests/admin-users.cjs
```

需涵蓋：

1. 管理員產生配對碼，普通用戶可交換為 session token。
2. 配對碼不可重複使用；錯誤、過期、管理員帳戶均被拒絕。
3. 配對不影響原本通行碼與其他裝置。
4. 重設通行碼後，session token 立即失效，未使用配對碼也失效。
5. 登入彈窗與管理面板的 `zh-CN`／`zh-HK` 流程。
6. 管理員面板仍不可重設管理員通行碼。
