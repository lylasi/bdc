# 多模型與 HAPI Grok 思考控制擴展實測 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 擴充既有思考測試至多個模型家族與使用者指定的 HAPI Grok，量測速度、品質、完整性、預設行為及關閉是否有效，並說明設定面板應如何呈現。

**Architecture:** 沿用既有8題與量測原則，新增片語、較長翻譯、歧義句及多輪助手題；每個渠道獨立核驗。測試附件存於新的獨立目錄，憑證只在記憶體內傳給原有供應商；不更改 BDC 或代理設定。

**Tech Stack:** Node.js原生fetch與node:test、現有提示詞、Python／Matplotlib，以及已配置的Magpie與HAPI。

**Spec:** 使用者要求「再測更多模型，包含HAPI渠道的Grok，有更完整分析」，並詢問將來能否在設定中控制思考等級或關閉。參照前次 `docs/research/20261102123519885_AI思考開關品質與速度實測.md`；本輪目標是擴展實測與設定方案說明，沒有要求部署或立即更改產品。

## Global Constraints

- 使用者已授權真實模型實測；沿用既有渠道的設定與憑證，不輸出憑證、不把它寫進附件或命令列。
- 現有未提交的產品工作保持獨立，本輪只新增docs附件、計劃、執行記錄與報告。
- 省略參數、明確關閉、最低強度及高強度分別記錄；不把成功HTTP或沒有思考文字當成關閉生效。
- 固定相同渠道與模型路由做檔位對照；模型名稱本身不同的非推理／推理路由另列比較，不混成同模型開關。
- 相同題目固定messages、語言、temperature與生成預算；有效思考參數以供應商實際支援為準。
- 保存正文、時間、上報用量、思考字數及失敗；不保存模型推理原文。
- 文件以時間戳命名，資料落在 `docs/research/assets/20261102125618427/`。

## Review Focus

- HAPI與本機grok2api是不同渠道：分別測量並標明可驗證範圍，不能沿用上一輪對本機代理的結論。
- none請求被映射至low、參數被忽略、只關閉顯示：以能力資訊、實際用量及可取得的協議證據判別，不能提供虛假的關閉選項。
- 200後SSE錯誤、截斷、超時與用量缺失：保留原始狀態，不將失敗混進成功延遲中位數。
- 模型家族差異、渠道網絡、服務端排隊及首輪暖機：先做pilot，交錯模式，重要測例重測；不宣稱小樣本顯著性。
- 品質評分偏好長答案或自身模型風格：固定題目要點，匿名化標籤，檢查數字、否定、歧義與多輪約束，保留原評分及覆核。
