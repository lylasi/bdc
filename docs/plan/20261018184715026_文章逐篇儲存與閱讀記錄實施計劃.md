# 文章逐篇儲存與閱讀記錄實施計劃

日期：2026-10-18。狀態：使用者已確認架構方向，交由 DeepSeek Harness 實作第一階段。

本計劃為本次實作的主要依據，優先於先前文章身份／blob 擴展計劃及其配額決策中的衝突內容。目標是每篇文章獨立保存、以穩定 user_id 關聯擁有人，完成逐篇同步和閱讀記錄改善，並為第二階段的指定用戶分享預留邊界。

依據：[獨立儲存與分享規格](../spec/20261018184206963_文章獨立儲存與指定用戶分享建議.md)、[計劃複核](../report/20261018183612102_文章閱讀記錄與同步計劃複核.md)、[原閱讀記錄交互設計](20261018174933864_文章詳解閱讀記錄互動優化計劃.md)。

**交付範圍與優先規則**

- 第一階段現在實作：文章獨立資料表、帳戶範圍本機儲存、逐篇接口與同步、舊資料遷移、備份還原，以及閱讀記錄搜尋／排序／改名／刪除復原與切換安全。
- 第二階段另行實作：指定用戶唯讀分享、固定分享版本、收到的文章、儲存個人副本及撤回；本次完成穩定 ID、擁有人及私人資料邊界即可，不顯示尚未可用的分享入口。
- 不採用整包文章索引作為文章同步的權威來源，不實作原計劃的內容 hash blob API／GC。現有 snapshot 僅繼續同步其他群組。
- 本次不必進行相似文章演算法、破壞性結果精簡、手動備份限額淘汰或全文多版本歷史。保留既有單字、句子、片語詳解，避免把交互改造變成有損資料遷移。
- 沿用專案 ES Modules、共用 API、DOM、狀態與雙語規範。不可改寫 ai-config.js 的私有內容；不可混入登入功能計劃。

**資料庫與接口**

Worker D1 與 selfhost SQLite／PostgreSQL 實作一致的文章協議，新增適用於現有安裝的遷移流程，不能只更新 fresh-install schema。

`articles` 每篇一筆，至少包含全域唯一 `id`、`owner_user_id`、標題、原文、分析 JSON、來源、遞增 `revision`、建立／修改時間與刪除標記。`owner_user_id` 關聯 `users.user_id`，從登入身份取得；查詢、寫入、刪除及同步均限制在登入帳戶。`label`、登入 token 及內文 hash 不作擁有人或文章主鍵。

提供列表／單篇讀取／新增／更新／刪除接口；列表不傳完整正文。修改與刪除以 `expected_revision` 作原子版本檢查，同篇衝突保留本機修改並提供重試或另存副本，不靜默覆蓋。新增和重試具冪等性；刪除復原也是有版本的明確操作。

增量同步使用伺服器游標及變更記錄，文章寫入與變更記錄保持原子一致。分頁、刪除事件及失效游標的完整重同步均需有明確語義，不依裝置時鐘判定有無變更。其他 snapshot 沒有變更時仍需檢查文章同步，不可共用舊版版本判斷而漏同步。

容量可先沿用先前選定的產品限制：每位使用者文章資料 50 MB、單篇文件 800 KB、400 篇提示／1,000 篇上限、原文 20k 字元提示／100k 字元上限。明確採 UTF-8 序列化位元組計算文件大小；超限不丟棄現有資料或分析結果。舊資料超限需保全並提示處理，不自動截斷。這些是產品限制，不再引用錯誤的 D1 1 MB 資料列上限。未授權讀取／跨帳戶寫入必須被服務端拒絕。

**本機儲存與文章身份**

IndexedDB 逐篇存文件、必要列表 metadata、待同步操作及同步游標；以同步端點和 user_id 隔離，訪客獨立範圍。儲存服務保持功能模組的統一入口，必要時提供相容讀取介面逐步銜接現有 state。登入／登出／換帳戶時不得把前帳戶文章或待同步操作套給後帳戶；訪客資料轉入帳戶需明確流程，不能隱式歸屬。

區分「編輯載入的記錄」與「匯入另一篇」。文章庫、網址、OCR、全文匯入等入口先切換編輯上下文，再決定是否命中既有來源；目前文章 ID 不能直接套到新內容。重新分析同一篇沿用 ID 及生詞本，另存新篇建立新 ID。同網址在不同帳戶中仍是各自的文章。

所有非同步主分析、重試、單字、句子及片語工作在啟動時固定文章 ID、內容版本、runId 和 controller；回應、儲存、DOM 更新及 finally 清理均驗證所屬工作。不得在回應時才讀目前文章 ID 決定寫入歸屬，亦不得重新排程已取消的工作。

持久化失敗與分析失敗分開呈現；結果及草稿保留，提供儲存重試或匯出。不可先宣告已儲存再靜默吞掉寫入失敗。個人學習資訊不成為未來分享 payload 的預設內容，規格中的分享欄位清單為後續邊界。

**閱讀記錄介面**

採單一閱讀記錄入口及清單彈窗，取代原下拉與分散的管理／刪除按鈕。提供標題／可用內文搜尋、來源篩選、最近閱讀／最近更新／標題排序、目前文章標示和改名。雲端尚未下載的文章不可被誤稱已完成全文搜尋；明確標示搜尋範圍或提供對應後端搜尋能力。

預設最近閱讀，以本機 `lastOpenedAt` 排序，不因每次瀏覽就修改文章版本；未開啟記錄採穩定回退時間。日期分組只適用於時間排序。標題只有一個權威欄位，改名後列表、來源列和儲存內容一致。

切換前保存可恢復的草稿及來源／文章綁定，提供再次找到草稿的入口。刪除無關記錄不清空目前畫面；刪除目前記錄保護未儲存修改。每次刪除獨立保存復原狀態，連續刪除不覆蓋前次復原資訊。刪除文章保留已有生詞，保留或重定向其來源關聯，避免孤立連結。

列內開啟按鈕與更多按鈕平行，禁止巢狀 button；Delete 僅在列焦點觸發，搜尋框內維持文字編輯。處理焦點還原、手機彈層及所有 zh-CN／zh-HK 動態文案。

**遷移與備份**

先完成可驗證的完整備份，再逐篇遷移並核對原文、詳解及關聯，最後切換資料版本。保留 user_id 與 legacy article ID 的冪等映射；缺 ID／重複 ID 使用穩定的遷移記錄鍵，不能只靠內容相同自動合併。中斷或 IDB 失敗不刪原資料、不提前標記遷移成功。

雲端舊 snapshot 與裝置補傳使用同一遷移規則；明確保留各裝置尚未同步的修改。帳戶啟用新文章存儲後，服務端封鎖舊格式文章寫入，舊 snapshot 的其他群組更新不得重複匯入文章。區分版本衝突、需升級及容量錯誤；不要把所有 409 都當一般重試衝突。回滾須保全遷移後新增內容，不能僅關掉格式閘門。

備份／匯出含完整文章文件及必要個人關聯，從空白本機在離線狀態可以恢復。保留舊備份讀取能力，不因本次升級自動清除手動備份。同步狀態、文章數量與儲存用量應反映新儲存來源。

**驗收與完成條件**

1. 文章庫／OCR／網址匯入 B 不覆蓋之前開啟的 A；同篇修改後分析不換 ID、不裂出生詞本。
2. 切換或刪除文章後延遲回來的主分析與詞句片語詳解不污染其他文章、不復活刪除資料。
3. 帳戶 A/B 及訪客隔離，API 無法越權；多裝置新增不同文章都保留，同篇衝突不丟本機修改。
4. 刪除、復原、增量分頁及過期游標重新同步符合協議；重試和遷移不重複新增。
5. 既有頂層單字詳解及句子／片語資料遷移後仍可讀，詞書及來源關聯完整。
6. 備份 → 清空 → 離線還原能開啟全部文章；寫入失敗及超限時畫面和結果仍可恢復。
7. 閱讀記錄在手機及桌面、zh-CN／zh-HK 完成搜尋、排序、改名、草稿恢復及連續刪除復原巡檢。
8. Worker 與 selfhost 以測試證明協議及權限一致，對原同步其他群組做回歸。

依 AGENTS.md 執行適用的 node:test、i18n 與 Playwright 檢查；修改 AI 呼叫歸屬時執行其規定的 AI 回歸。根目錄沒有 npm scripts，不虛構 build／lint。若環境缺依賴或瀏覽器無法啟動，記錄實際阻礙及替代驗證，不能宣稱測試通過。

完成後在 docs/report 保存含時間戳的實作報告，列出變更檔案、資料遷移、實際執行的測試及結果、部署注意事項和未完成項。本次授權工作區實作及本機驗證；生產資料遷移／部署另外處理，不自行執行。
