# 文章詳解易用性改進實施計劃

- 文件日期：2026-10-22（Asia/Shanghai）
- 依據調研：`docs/research/20261022002549733_文章詳解易用性調研.md`
- 程式基準：`5839aa7`（沿用調研基準）
- 性質：只讀規劃。本文件只新增計劃，未修改任何程式碼、設定或資料。
- 適用範圍：`features/article/`、`features/assistant/`、`features/learning/`、`features/qa/` 的既有能力邊界，以及 `modules/` 共享層。
- 撰寫原則：先修可靠性和版本一致性，再做高頻互動；長文效能先量測，不先承諾虛擬化；所有新 UI 文案同時完成 `zh-CN` 與 `zh-HK`。

## 一、目標與非目標

### 1.1 目標

1. **分析結果可信**：段落失敗、重試、保存、重新開啟的狀態一致；空回應不再被當成成功，單段與批次重試不會空轉或寫錯文章。
2. **同一個閱讀版本**：畫面、朗讀、助手、單詞／句子詳解對「目前是哪一篇、哪一版」有明確共識；修改或匯入原文時不再靜默混用新舊內容。
3. **助手行為可預期**：串流錯誤、停止、重試、切換文章各有明確狀態；停止不會被存成完整答案，重試使用原請求快照。
4. **高頻入口好用**：查詞詳解在鍵盤、小螢幕、軟鍵盤、縮放與載入中都可完成；朗讀與單詞發音不再互相拆台。
5. **可續作與可治理**：長文分析有逐段 checkpoint；快取有明確身份、失敗不進快取、可清理；locale 切換不丟操作狀態。
6. **先量測再優化**：建立可重複的長文量測方式，以數據決定是否進入虛擬化、分塊或上下文預算工程。

### 1.2 非目標（本次明確不做）

- **不重寫 `features/article/article.js`**：只做局部函式抽離與狀態收斂，不把 5,700 行一次拆成新架構。
- **不改文章翻譯 prompt 的產品 schema、模型選擇策略或翻譯品質**。本計劃只處理狀態、保存、互動與成本可觀測性。
- **不新增 AI 供應商、金鑰、目錄或同步後端協定**；不碰 `ai-config.js` 的 AI 設定邊界。
- **不新增同步後端 schema 或 migration**。文章分析仍放在既有 `analysis_json`；閱讀訊息仍走既有實體與 patch 白名單。
- **不做長文虛擬化、懶渲染或自動分段**。Phase 3 只量測；是否進入 Phase 4 由數據與產品決策決定。
- **不建「文章 → QA」完整產品流程**。F14 只做匯出／複習入口的產品驗證；文章轉 QA 若要落地，另案參照既有 `features/qa/` 入口，不新增平行資料系統。
- **不改 TTS 後端協定**。若需要 POST、分段合成、合併、可驗證下載或真正 pause/resume，必須先確認服務端能力；本期只把前端能力與限制說清楚。
- **不把文章、OCR、QA、使用者輸入、歷史訊息或已保存詳解轉成目前介面語言**。locale 只影響控制文字與後續生成。
- **不新增 npm scripts、build、lint 或 typecheck 流程**；驗證仍用既有 `node --test`、`tests/*.cjs` 與手動巡檢。
- **不刪除永久學習記錄、舊原文版本、筆記、chat 或已收藏詳解**。TTL／容量清理只針對可重建快取。
- **不在本規劃任務中呼叫真實 AI／TTS、跑真機或宣稱已完成瀏覽器重現**。

### 1.3 成功判準（整體驗收）

- 失敗矩陣（401／429／500／timeout／空 JSON／空譯文／取消）每一種都有明確、可重試、可保存的結果。
- 單段與批次重試成功後重新載入頁面，結果仍在；空結果不閃成功。
- 助手停止後不再被標成 `complete`；錯誤提示在串流 finally 後仍可見；跨文章重試不換正文。
- 修改／匯入原文後，朗讀與助手使用的內容與畫面提示一致，不出現「畫面 A、助手 B」的靜默混用。
- 朗讀中點單詞發音，文章播放 UI 與實際聲音一致；「繼續」的語義在 UI 上可預期（本計劃採明示重播本句）。
- 只用鍵盤可從句子進入解析、進入逐詞模式、開啟與關閉單詞詳解並返回原句。
- locale 切換時助手草稿、閱讀面板狀態、片語筆記不丟；靜態與動態文案都完成兩語。
- 10k／50k 字文章有可重複的量測報告；未達門檻前不投入虛擬化。

### 2.2 必須先驗證的假設

以下不是本次可直接當成事實的結論；相關任務開始前先以 mock 或樣本確認。

1. **A1 失敗矩陣可重現**：以 Playwright route mock 401／429／500／timeout／空 JSON／空譯文，能穩定重現 F01 的空結果與按鈕不同步。
2. **A2 分詞器可用性**：目標瀏覽器支援 `Intl.Segmenter`；不支援時 fallback 的行為與歷史錨點仍一致。
3. **A3 音訊後端能力**：本期不假設 HTMLAudio、系統語音、第三方 TTS 支援一致的 pause/resume；先以「明示重播本句」設計，真支援再升級。
4. **A4 原文修改後的政策**：使用者在編輯原文時，朗讀與助手應跟「最新輸入」還是「已分析版本」？本計劃推薦最新輸入＋明確提示；需產品拍板（見 D1）。
5. **A5 checkpoint 成本**：每 1–2 秒寫入一次完整分析 JSON 對 IndexedDB、outbox 與同步的實際成本可接受；需以 10k／50k 字樣本量測。
6. **A6 文章容量**：`ARTICLE_LIMITS.maxArticleBytes` 對「分析結果＋analysis_run」仍足夠；需以最大樣本確認。
7. **A7 版面回歸**：tooltip 改成手機底部面板、句解析鍵放大，不破壞既有段落、表格、圖片、朗讀高亮。
8. **A8 助手訊息狀態**：`status: 'cancelled'` 雖符合現有資料形狀，仍需確認 Worker／selfhost／匯出／閱讀面板都不把它當成錯誤或完整回答。
9. **A9 既有測試覆蓋**：`tests/article-analysis-ownership.cjs`、`tests/article-version-ownership.cjs` 的斷言足以守住本次改動；不足處以新腳本補，不修改測試期望來遷就實作。
10. **A10 缺失文件**：調研指出 `docs/storage-architecture.md` 不存在。checkpoint 與快取治理落地前，應先確認是否有外部版本，或另寫一份現況文件。

## 五、Phase 1：可靠性與版本一致

> 階段原則：先建立單一狀態來源，再讓所有入口共用同一條請求、驗證、歸屬與保存流程。不要先改 UI 外觀。

### P1-T1｜建立段落狀態模型，空結果不再算成功

- **對應發現**：F01；為 F08 的「失敗不進快取」鋪路。
- **改動**：
  - 新增純函式模組 `features/article/analysis-state.js`（不碰 DOM、不碰網路）：
    - `PARAGRAPH_STATUS = { pending, done, skipped, failed, cancelled }`。
    - `classifyParagraphResult(item, { sourceText, isImageParagraph })`：回傳 `{ status, errorCode }`；中文原文與純圖片回 `skipped`；有 `failed === true` 或空譯文回 `failed`；其餘 `done`。
    - `isUsableParagraphResult(item, context)`：供重試與快取使用，避免把空結果當成功。
    - `failedIndicesFromResult(result, paragraphs)`、`resumeIndicesFromResult(result, paragraphs)`。
    - `paragraphStatusLabelKey(status)` 與 `paragraphErrorLabelKey(errorCode)`，只回傳翻譯鍵，不拼使用者文字。
  - `modules/api.js:analyzeParagraph`：最終兜底回傳物件加上 `failed: true`、`errorCode: lastErr?.code || (lastErr ? 'provider_error' : 'empty_response')`。這是 additive 欄位，不改既有 `chinese_translation`／`word_alignment`／`detailed_analysis` 形狀。
  - `features/article/article.js`：
    - `buildChineseSourceResult` 回傳加 `skipped: true`、`skipReason: 'source_zh'`。
    - 主分析中純圖片結果加 `status: 'skipped'`、`skipReason: 'image'`。
    - `renderParagraph` 改用 `classifyParagraphResult` 決定 `.para-status` 的 done／failed／skipped，不再只以「譯文是否空」猜測；失敗時在狀態列顯示可翻譯的錯誤原因。
    - `recordFailedParagraphs` 改呼叫 `failedIndicesFromResult(...).length`，刪除重複的 filter 規則。
- **預期行為**：
  - 空譯文段落顯示「失敗」與原因，不再進入成功狀態。
  - 純圖片、原文已是中文的段落顯示「已跳過」，不算失敗，也不顯示重試本段。
  - 歷史清單的「N 段未完成」與畫面上的失敗段數一致。
- **驗收**：
  - [ ] mock 回傳空 JSON／空 `chinese_translation`：段落狀態為 failed，顯示原因，該段不閃成功。
  - [ ] 原文為中文的段落：狀態 skipped，`recordFailedParagraphs` 不計入。
  - [ ] 純 Markdown 圖片段：狀態 skipped，朗讀跳過，不計失敗。
  - [ ] 同一篇有 2 段失敗時，歷史列顯示「2 段未完成」，與畫面失敗數相同。
- **風險／降級**：舊記錄沒有 `status` 欄位；`classifyParagraphResult` 必須以「`skipped`／`failed` 旗標＋空譯文」推導，不能要求資料已升級。若新狀態判斷造成既有成功段變失敗，先以 `isUsableParagraphResult` 的單元測試與歷史樣本回歸，不急著改寫入格式。
- **依賴**：P0-T1。工作量：M（約 2 人日）。

### P1-T2｜單段與批次重試共用請求、有效性與保存流程

- **對應發現**：F01。
- **改動**：

## 八、雙語（zh-CN／zh-HK）與 i18n 處理清單

### 8.1 強制規則

1. 功能邏輯只維護一套；不得為簡體與繁體複製流程。
2. 靜態 HTML 用 `data-i18n`、`data-i18n-title`、`data-i18n-placeholder`、`data-i18n-aria-label`；動態 DOM 一律 `t()`。
3. 每個新鍵同時加入 `locales/zh-CN.js` 與 `locales/zh-HK.js`；鍵集合與插值參數必須完全一致。
4. 香港文案使用香港正式書面中文與常用詞，不使用台灣慣用詞，也不預設粵語口語。
5. 不翻譯教材、文章、OCR、QA、詞書、使用者輸入、歷史訊息與已保存詳解；只翻譯控制文字與後續 AI 回覆的語言規則。
6. 動態插入的詞、句、錯誤訊息必須 `escapeHtml`／`escapeAttr`；不得把使用者內容拼進未轉義 HTML。
7. 狀態按鈕（朗讀、下載、重試）若 `aria-label` 會隨狀態改變，移除其 `data-i18n-aria-label`，改由 JS 在 `update*UI()` 設定，避免 locale 套用時被靜態值蓋回。

## 九、持久化欄位與同步影響

### 9.1 原則

- **能不加欄位就不加**。Phase 1／2 主要用記憶體狀態與既有 `paragraph_analysis`、`message.status`。

### 9.3 同步與版本檢查清單

- **文章**：`articleStore.saveAnalysis` 的 `expectContentVersion` 必須由請求開始時凍結；checkpoint 也必須帶同一版本。`article-sync.js` 的 outbox 已按文章合併，checkpoint 不應產生多筆 op；若新增 `silent`，確認 `pending`／`dirty` 與 `markOpDone` 仍正確。

- **AI profile**：本計劃不新增 AI 設定；若未來要把助手上下文範圍存成 profile，才檢查 `modules/ai-profile-storage.js`、`modules/ai-credential-sync.js`、`modules/ai-settings-sanitize.js` 與登出／401 清理路徑。文章內容不得寫進 profile。

### 12.1 一般原則

- ** additive data**：`analysis_run`、段落 `status`／`errorCode`、`message.status='cancelled'` 都是新增欄位；舊版忽略即可，不需要 migration。
- **單一入口**：每個任務盡量把新行為收在一個函式或新模組，出問題可只 revert 該 PR，不必回退整個 Phase。
- **預設安全**：新 UI 若失敗，退回既有滑鼠／既有重試流程；不得讓文章無法閱讀或無法保存。
- **不刪資料**：清理只針對 `bdc:cache:v1:*`；永久記錄、舊原文版本、筆記、chat、詳解一律不動。

### 12.2 Kill switch 與降級路徑

| 功能 | Kill switch／降級 | 行為 |
| --- | --- | --- |
| 段落 pipeline | `localStorage['bdc:flags']` 的 `paragraphPipeline: false`（若實作 flags；否則 revert PR-3） | 回到舊的單段／批次請求；Phase 1 的其他狀態修正仍可用 |
| Checkpoint | `settings.reading.analysisCheckpoint = false` 或 flags `checkpoint:false` | 只在最後保存；不顯示續作 banner；不影響已保存資料 |
| 逐詞鍵盤 | flags `wordKeyboard:false` | 句子不加 tabindex；保留滑鼠查詞與片語選取器鍵盤路徑 |
| 分詞 | flags `tokenizer:'legacy'` | 使用舊 regex；仍保留「跳過連結／code」的安全修正 |
| 助手快照重試 | flags `assistantRetry:'legacy'` | 回到舊重試（仍不得標 complete）；作為緊急降級，不建議長期 |
| 音訊 true pause | 無後端支援時 | 一律「重播本句」，不承諾續播 |
| 下載 | 無遠端 TTS | 播放可用本機語音；下載明確停用／提示 |
| 匯出對話框 | `showOptionsModal` 不可用時 | 回到既有兩個入口，但保留範圍文案與 flush 草稿 |
| 長文量測 | `?perf=1` 關閉 | 不安裝 observer、不影響產品 |

### 12.3 資料回滾

- 若 Phase 3 checkpoint 造成容量或同步問題：停止寫入 `analysis_run`、保留既有 `paragraph_analysis`；使用者仍可批次重試；不需要清除已寫入欄位。
- 若 `status:'cancelled'` 造成舊客戶端顯示異常：停止寫入新 status，改為不保存半段（只留畫面），但不得改回 complete。
- 若分詞造成錨點錯位：切回 legacy tokenizer，並以既有 `contentVersion`／anchor 檢查回復；不重寫歷史記錄。

## 十三、跨階段風險與取捨

1. **版本一致 vs 編輯自由**：若每次改字都禁用朗讀／助手，會很煩；若完全不管，會混用。本計劃採「畫面標舊版、朗讀／助手用最新輸入、重試需先重新分析」的折衷，仍需 D1 確認。
2. **永久記錄 vs 可再生快取**：checkpoint 與 prune 都可能誤傷永久資料；以 store 前綴與 `articleStore`／`readingStore` 邊界隔離，並用測試確認 prune 不動 `bdc-articles`／`bdc-reading`。
3. **checkpoint 寫入頻率**：越即時越安全，但增加 IDB、outbox、同步與多裝置衝突；1.2 秒 debounce 是起點，需用 10k／50k 樣本與慢速裝置驗證。
4. **可及性 vs DOM 成本**：把每個詞都設 tabindex 會讓長文 Tab 爆炸；本計劃用「句 → 逐詞模式」控制 Tab 順序，需螢幕閱讀器實測。
5. **音訊後端差異**：HTMLAudio、SpeechSynthesis、第三方 TTS 的 pause／resume／error 事件不一致；本計劃只承諾「明示重播本句」，不假裝真正續播。
6. **下載安全與能力**：GET URL 含文字與 key 是既有設計；本計劃只避免 UI 暴露與誤導，真正移除需後端支援（D4）。
7. **locale 與教材完整**：locale 只改控制文字與後續生成；不得把文章、OCR、QA、使用者輸入或歷史回答轉語言。已保存詳解若需新語言，另做「按目前語言重新生成」，不在本計劃。
8. **長文優化範圍蔓延**：F09 只量測；若沒有數據就做虛擬化，可能破壞瀏覽器搜尋、選取、標記、朗讀跟隨與螢幕閱讀器。以 D8 門檻控制。
9. **測試穩定性**：串流、音訊、動畫與計時器容易 flaky；優先使用 mock 與可觀察狀態，不用固定 sleep 當唯一斷言。
10. **文件缺口**：`docs/storage-architecture.md` 缺失；checkpoint／快取治理落地前，應補一份現況文件或確認外部版本（D10），避免用舊印象設計。

## 十六、摘要

本計劃把「文章詳解更好用」拆成三條主線：

1. **先讓結果可信**：統一失敗／成功／跳過／取消狀態，單段與批次重試共用請求、驗證、保存；這是 F01 的核心，也是後續所有 UX 的地基。
2. **再讓上下文一致**：畫面、朗讀、助手、詳解共享 `articleId + contentVersion`；匯入／編輯不再靜默混用；助手錯誤、停止、重試有明確狀態。
3. **最後才做增量與治理**：逐步 checkpoint、快取身份與清理、locale 狀態保留、分詞與無障礙；長文只先量測，不在沒有數據前投入虛擬化。

最重要的五條實作建議：

1. **先建失敗矩陣與段落狀態模型，再改任何 UI**；不要用「畫面有沒有文字」猜成功。
2. **所有段落請求收斂到 `paragraph-pipeline.js`**，保存前用 `contentVersion`／scope 守門；失敗或保存失敗不得閃成功。
3. **助手重試使用原請求快照**（正文、文章 ID、會話、歷史），停止以 `cancelled` 保存半段，錯誤節點在 finally 之後仍保留。
4. **原文版本只認一個來源**：`contentVersionOf`；畫面標舊版、朗讀／助手用最新輸入、重試需先重新分析（待 D1 拍板）。
5. **音訊先做 owner 與中斷通知，再做 UI**；不承諾跨後端真續播，明示「重播本句」比假裝續播可靠。

最後，**不要先重構 5,700 行的 `article.js`**。以新純函式模組（`analysis-state.js`、`paragraph-pipeline.js`、`tokenize.js`）包住可測試的規則，讓 `article.js` 只負責接線與 DOM；這樣才能在不擴大風險的前提下，逐段改善可靠性與易用性。
