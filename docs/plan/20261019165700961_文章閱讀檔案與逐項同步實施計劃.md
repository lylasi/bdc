## 1. 交付目標與依據

依據 [目標規格](../spec/20261019164259740_文章閱讀檔案與學習記錄目標方案.md) 及 [現況評估](../research/20261019043905937_文章學習資料儲存與手機短語操作評估.md)。本次交付可操作版本，不以示意頁代替功能。

一篇文章能串起已查詞、短語、句子、詞書收藏、理解狀態、個人筆記與 AI 資料；已下載內容優先本機讀取，操作立即可靠保存，背景逐項同步。手機可點首詞和末詞選短語，離線可匯出閱讀筆記。

沿用現有靜態 SPA、文章 ID、登入與同步排程，不引入框架或打包流程。PDF、高階熟練度評分、完整點擊事件日誌及知識圖譜不屬本次範圍。以下階段是實作順序，不代表可自行省略後段。

## 2. 資料契約與程式邊界

### 2.1 永久儲存

優先升級現有 `bdc-articles` IndexedDB，抽出共同開庫／交易入口，避免兩模組用不同版本開同一庫。文章仍一篇一筆；新增以下實體，可採共用 record store＋類型欄位，或具索引的獨立 stores，保持相同對外契約：

| 實體 | 關鍵欄位／規則 |
| --- | --- |
| learningItem | id、scope、articleId、contentVersion、kind、anchor(start/end/quote/prefix/suffix)、sentence、explanation、firstViewedAt、lastViewedAt、understanding、note、revision、deletedAt |
| vocabularyBook / vocabularyEntry | 穩定 ID；詞條逐項修改；保留既有複習欄位，功能層可保留原介面 |
| vocabularyLink | itemId、bookId、entryId、addedAt、removedAt；收藏狀態只從有效關聯推導 |
| articleDocument | articleId、kind(note/ai)、title、content、sourceItemIds、sourceMessageIds、引用版本、revision |
| conversation / message | 穩定 articleId、conversationId、messageId；消息逐條保存，選配 learningItemId 與引用 |
| articleVersion | 僅原文真的變更且被記錄引用時保存必要舊版本；重分析不複製原文 |
| outbox / syncState / conflict | scope、entityType、entityId、mutationId、expectedRevision、base、patch、游標及衝突副本 |

新增或更新永久實體及 outbox 必須在同一 IndexedDB transaction 中提交；transaction 完成後才能顯示已保存。收藏的詞條、來源關聯及待同步操作同交易完成。不可用跨庫先後寫入假裝原子操作。

`scope` 固定為端點＋帳戶，訪客獨立。非同步操作一開始捕捉 scope、articleId、contentVersion、anchor、conversationId；完成後驗證作用域，禁止寫入當前切換後的文章或帳戶。

學習條目以同文章版本＋類型＋精確引用範圍唯一。再查更新原條目；全文預先生成的解釋不偽造已查歷史。理解狀態只有 unmarked / needs_review / understood，與查閱及收藏獨立。更新解析不能覆蓋個人筆記。

### 2.2 主要檔案責任

- `modules/article-store.js`：保留文章 API；共同 DB、原文版本、按需全文載入、文章摘要索引；修正現有文章寫入與 outbox 原子性及舊回應誤清新操作。
- 新增 `modules/reading-store.js`（或同責任命名）：學習條目、文件、來源關聯、會話及消息 CRUD、遷移、查詢、備份與交易；介面至少提供按文章列舉、按 anchor upsert、欄位 patch、保存文件、追加消息、匯出/還原。
- 新增 `shared/reading-protocol.mjs`：實體與 patch 白名單、ID/容量/字串驗證、冪等規則、三方欄位合併及快照閘門；兩後端共用。
- 新增 `modules/reading-sync.js`：逐項 push/pull，掛接現有同步協調入口；功能按鈕不直接 fetch。
- `modules/storage.js`、`modules/vocab.js`：詞書讀寫改由共同永久層負責，記憶體只是視圖；保留功能相容 API，移除舊 snapshot 權威寫入。
- `modules/sync-core.js`、`modules/sync-cloudflare.js`、`features/sync/sync.js`：同步協調、舊 snapshot 保護、狀態／衝突處理；清快取只清可重建結果。
- `features/article/article.js`：所有查詞／句／短語入口統一保存與讀取；新閱讀面板及選短語邏輯抽至獨立功能檔，避免繼續擴大主檔。
- `features/assistant/assistant.js`：消息永久儲存、會話 ID 固定、文章／條目來源、保留 AI 資料及主動分析。
- `modules/local-backup.js`：完整資料、消息、來源與原文版本備份還原；不沿用 50 條上限。
- `modules/dom.js`、`index.html`、`styles.css`、`locales/zh-CN.js`、`locales/zh-HK.js`：新介面、可達性、雙語與響應式版面。
- `main.js`：等待必要遷移與作用域初始化，整合新模組；不先 hydrate 全部長會話。

具體命名可按既有抽象調整，但不得留下兩個永久權威來源或只有 demo 可用的路徑。

## 3. 實作順序與每段驗收

### A. 先修正現有資料可靠性並完成遷移

1. 聊天從 `bdc-cache` 遷入永久資料；索引、完整消息、會話文章關聯一起遷移。原文 hash 只有唯一匹配才轉 articleId；無法匹配仍保留為未關聯會話。
2. 備份使用完整永久資料，與 AI 上下文裁剪分開；超過 50 條消息也須完整還原。
3. 重分析保留既有句子及短語內容；取消每句僅保留最近三個短語的資料刪除。
4. 遷移前保存可恢復副本；遷移具版本、冪等標記、數量／ID 核對。失敗不切換權威讀寫；重啟可重試。不要刪除無法識別的舊資料。
5. 舊解析按需導入條目，viewed 時間留空；舊詞書能確定文章與引用才建精確關聯，否則留原句及位置未知。
6. 舊資料移交完成後禁止舊 snapshot 覆蓋新詞書／聊天；只有確認遷移成功才設遠端閘門。新後端能力尚未部署時顯示待同步／需更新服務端，本機功能仍可使用。

驗收：清 AI 快取後聊天／筆記仍在；大於 50 條的會話往返備份相同；遷移重跑不重複；失敗可恢復；訪客、帳戶 A/B 不串資料。

### B. 按項目同步（Cloudflare 與 selfhost 同步完成）

1. 新增共用路由處理器與 SQL migration，兩後端均接入；selfhost 沿用現有共用 Worker 路由模式及 SQLite/PostgreSQL 相容層。
2. 建議 API：`GET /reading/changes?cursor=`、`POST /reading/batch`、`POST /reading/mutations`、能力／遷移閘門。名稱可配合現有 conventions；認證 owner 由服務端取，禁止接受客戶端任意 owner。
3. 寫入用 mutationId 冪等、expectedRevision 樂觀並行控制、服務端序號游標、刪除標記。每次遠端提交的實體、change、冪等憑據同交易，兩後端一致。
4. 基於已知 base 做欄位三方合併：不同條目直接合併；同條目改不同欄位可合併；同欄位矛盾保留雙方版本供選擇。firstViewedAt 取最早、lastViewedAt 取最晚。使用者文字與理解狀態不能盲用裝置時間取代。
5. 已有本機 pending 不被拉取覆蓋；ack 僅移除匹配 mutationId 的操作。上傳期間再編輯，保留新 patch 並重設基準。進行中的拉取和 ack 都檢查捕捉作用域。
6. 共用協調排程同帳戶單次在途：先文章依賴，再其條目／文件／消息。網絡錯誤可重試，舊後端不回退成整組覆蓋。
7. 衝突在 UI 能檢視本機與雲端，選本機／雲端／保留副本；使用者未處理時保留資料且不顯示已同步。

驗收：雙客戶端不同條目、同條目不同欄位、同欄位衝突、重送、刪除與離線復活、舊 ack、切帳戶、舊 snapshot 保護都有實際測試。不可只 mock 呼叫次數。

### C. 快速讀取與主動學習記錄

1. 列表讀文章摘要；開文章並行讀該篇原文與學習標記，長文件／消息按需讀。避免每字一次 DB／網絡查詢。
2. 詞／句／短語所有入口使用：當前文章永久記錄 → 共用快取 → AI。命中快取也將使用者實際打開的解釋保存到文章記錄。
3. 成功呈現解釋才更新 viewed；失敗、預取及切走後的結果不計查閱。非同步任務持有原 articleId/anchor，不以當前全域文章寫入。
4. 收藏先保存詞條及來源，再補 AI 解釋。去重不能丟新語境；移出收藏保留學習條目和筆記。
5. 原文編輯保留引用版本；唯一匹配才重新定位，歧義顯示位置待確認，不貼到第一個同詞。
6. 任何保存失敗保留編輯內容並顯示可重試錯誤，不能只 console 或提示成功。

驗收：重開已查詞／句零多餘 AI 請求；同 anchor 不增生；同詞不同位置可獨立標記；慢請求時切文章不串資料；重分析不丟筆記或短語。

### D. 正文標記、本文記錄及手機短語

1. 新增「本文學習記錄」入口：桌面側欄，手機底部面板。篩選全部、詞與短語、句子、待弄懂、筆記、AI 資料；可顯示收藏。
2. 條目含引用／原句、解釋、詞書來源、理解狀態、筆記、回原文、問 AI。個人筆記自動保存，標示保存狀態；同步更新不覆蓋正在輸入的草稿。
3. 已查淡底線、待弄懂暖色線型、收藏在面板顯示圖示；同範圍單一主要標記，待弄懂優先。提供顯示標記開關；不只靠顏色表達。
4. 手機：點詞 →「選短語」→ 點同句末詞，面板立即顯示固定短語與原句；可調整起止、取消、加入詞書、仍不懂、筆記、問 AI。相反方向點選需有明確規則；長短語可見完整預覽。
5. 保留原生拖選作替代。監聽 selectionchange，按鈕操作使用已捕捉的 Range/anchor，不重讀已失焦的 Selection。只選原文，翻譯與跨句不誤收。
6. 底部面板支援 safe-area、鍵盤、內部滾動、焦點返回、Escape／關閉、至少 44px 觸控目標；不攔截正常頁面滾動和朗讀。

驗收：桌面 1440 寬與手機 390×844/窄屏；zh-CN、zh-HK；短語不靠拖手柄也可保存；刷新後標記和筆記保留；同步不整篇跳動。

### E. AI 資料與閱讀筆記匯出

1. 助手新消息逐條持久化並固定 conversationId，按穩定 articleId 與可選 learningItemId 關聯；流式處理不得串會話。
2. AI 回答加入「保留為 AI 資料」，保存內容快照、來源消息與條目／版本。原聊天後來變化不改已保留文件。
3. 「分析本文難點」「整理閱讀筆記」先選範圍，再經既有 `modules/api.js` 請求；結果保存為新文件，不改理解狀態或個人筆記。未配置 AI 時明確提示，普通記錄與匯出照常。
4. Markdown 匯出完全在本機生成：標題來源／版本、生詞短語、重點句子、個人筆記、待弄懂、選擇保留的 AI 資料；可附全文和完整聊天附錄。記錄多分類引用避免大段重複。
5. 匯出抓取一致資料快照；有未保存、未下載、待同步或衝突時說清範圍。JSON 備份包含全部永久資料及關聯，還原核對引用、消息與版本。

驗收：離線 Markdown 可下載且內容正確；AI 文件可追溯；70 條以上消息備份還原完整；沒有 AI Key 仍能完成選詞、收藏、筆記及匯出。
