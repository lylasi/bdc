# AI 思考強度按任務設定實施計劃

日期：2026-11-02。狀態：待實作。依據：

- [AI 查詞、文章翻譯與助手的思考強度核對](../research/20261102120957540_AI查詞文章翻譯與助手思考強度核對.md)

- [多模型與 HAPI Grok 思考控制實測](../research/20261102140712993_多模型與HAPIGrok思考控制實測.md)

## 一、現況結論

目前 BDC 對查詞、文章翻譯、句子分析與 AI 助手都沒有傳送任何思考強度參數：

- `modules/api.js` 的 `requestAI()` 與 `streamAIResponse()` 只傳 `temperature`、`maxTokens`。
- 三個協議適配器都沒有輸出 `reasoning_effort`、`thinking`、`thinkingConfig` 等欄位。
- 因此實際思考程度完全由供應商／模型／網關預設決定，不能稱為「低／中／高」，也不能視為已關閉。
- 對已實測的 Magpie `workbuddy/deepseek-v4.1-flash`，省略參數仍有推理用量；明確傳 `reasoning_effort: "none"` 才能驗證為 0。

## 二、實施目標

1. 在帳戶範圍 AI profile 增加非秘密的「按任務思考模式」設定，跟隨現有同步流程。
2. 由共用請求層解析有效模式，`requestAI()` 與 `streamAIResponse()` 使用同一套映射；協議適配器負責輸出各協議欄位。
3. 設定介面提供四個實際有差異的任務群組：
   - 查詞／一般釋義（`wordAnalysis`，並套用到 `articleWordTranslation`、`articlePhraseTranslation`）
   - 文章段落翻譯（`articleParagraphTranslation`）
   - 句子詳解（`articleSentenceTranslation`）
   - AI 助手（`assistant`）
4. 助手面板提供本次提問的臨時覆寫，重試沿用同一模式。
5. 快速模式不得讓 JSON／正文被推理耗盡而截斷；深入模式要有足夠生成預算。
6. 快取鍵納入有效模式，避免快速與深入結果互相命中。
7. 渠道不支援該參數時不得讓整個功能失敗：重試一次不含思考參數的請求，並留下可觀測訊號。
8. 所有新增 UI 文案同時提供 `zh-CN` 與 `zh-HK`。

## 三、模式與預設

模式值固定為：`auto`、`none`、`low`、`medium`、`high`。

| 值 | 介面文案（zh-CN／zh-HK） | 出站含義 |
| --- | --- | --- |
| `auto` | 跟随服务端／跟隨服務端 | 完全省略思考參數 |
| `none` | 关闭思考／關閉思考 | 盡量明確關閉；協議支援度不同 |
| `low` | 低强度／低強度 | 最低可用推理檔位 |
| `medium` | 中强度／中強度 | 中等推理檔位 |
| `high` | 高强度／高強度 | 最高推理檔位 |

應用程式任務預設（使用者未設定時）：

| 任務 | 預設 | 理由 |
| --- | --- | --- |
| `wordAnalysis` | `none` | 查詞優先速度，實測高強度收益小 |
| `articleWordTranslation` | 跟隨 `wordAnalysis` | 句中釋義屬查詞群組 |
| `articlePhraseTranslation` | 跟隨 `wordAnalysis` | 一般片語釋義屬查詞群組 |
| `articleParagraphTranslation` | `none` | 普通文章翻譯，長文高強度等待成本高 |
| `articleSentenceTranslation` | `low` | 句法與結構分析需要少量推理 |
| `assistant` | `medium` | 一般問答保留推理空間，可本次切換快速／深入 |
| 其他任務 | `auto` | 未充分實測，不擅自改變行為 |

優先次序：本次手動覆寫 → 個人任務設定 → 應用程式任務預設。

## 四、協議映射

### Chat Completions（OpenAI 相容）

- `auto`：不送欄位。
- 其他：送 `reasoning_effort: "<level>"`。
- 部分相容服務不支援或只接受特定值；由共用層的 400／422 降級重試處理。

### Anthropic Messages

- `auto`／`none`：省略 `thinking`（不啟用 extended thinking）。
- `low`／`medium`／`high`：送
  `thinking: { type: "enabled", budget_tokens: <budget> }`。
- 啟用時 `temperature` 必須為 `1`，且 `max_tokens` 必須大於 `budget_tokens`。
- 預算：`low = 1024`、`medium = 4096`、`high = 8192`；適配器把 `max_tokens` 提高到至少 `budget + 1024`。

### Gemini

- 2.5 系列：`generationConfig.thinkingConfig = { thinkingBudget: n }`。
  - `none = 0`、`low = 1024`、`medium = 4096`、`high = 16384`。
- Gemini 3 系列：`generationConfig.thinkingConfig = { thinkingLevel: "low" | "high" }`。
  - `none`／`low = "low"`，`medium`／`high = "high"`。
  - Gemini 3 未必能真正關閉，介面提示需說明可能被降為最低檔。
- `auto`：不送 `thinkingConfig`。

### 生成預算

`requestAI()` 對非 `auto` 模式套用最低 `maxTokens`：

| 模式 | 最低生成預算 |
| --- | ---: |
| `none` | 不變 |
| `low` | 1200 |
| `medium` | 2500 |
| `high` | 5000 |

只在呼叫端已提供 `maxTokens` 時向上調整；未提供（例如助手串流）維持供應商預設。Anthropic 適配器另外保證 `max_tokens > budget_tokens`。

## 五、程式落點

### 新增 `modules/ai-thinking.js`

集中定義，避免循環依賴：

- `THINKING_LEVELS`
- `normalizeThinkingLevel(value, fallback = 'auto')`
- `THINKING_BUDGETS`
- `THINKING_TOKEN_FLOORS`
- `appThinkingDefault(taskName)`
- `resolveThinkingLookupKeys(taskName)`（含查詞群組與文章任務回退）

此模組不得 import `ai-profile-storage.js` 或 `ai-models.js`。

### `modules/ai-profile-storage.js`

- profile 增加 `taskThinking: {}`。
- `normalizeProfile()` 正規化 `taskThinking`，只保留合法任務名與合法模式。
- `getAIViewFromProfile()` 輸出 `thinking: { ...profile.taskThinking }`。
- `applyRemoteAISettings()` 讀取 `remote.thinking`。
- `applyAISettingsPatch()` 支援 `ai.thinking`。
- `importGuestProviders()` 可選擇性帶入訪客思考設定（不覆蓋既有值）。

### `modules/ai-models.js`

- 增加 `resolveThinkingLevel(taskName, { override } = {})`：回傳有效模式與來源。
- 增加 `getTaskThinkingLevel(taskName)`、`saveTaskThinkingLevel(taskName, level)`。
- 儲存後 `syncTouch('aiSettings')`。
- 任務查找順序：自身 key → 群組回退 key → 應用程式預設。

### `modules/ai-settings-sanitize.js`

- `sanitizeAISettings()` 保留合法的 `thinking` 映射，非法值丟棄。
- 保持舊 snapshot 沒有此欄位時不強制寫入。

### `cloudflare-worker/src/snapshot-sanitize.js` 與 `selfhost/snapshot-sanitize.js`

- 兩份保持同步，新增 `sanitizeSnapshotThinkingMappings()`，只接受合法任務名與五個模式值。
- `sanitizeSnapshotAISettings()` 輸出 `thinking`。

### `modules/sync-core.js`

- `hasSyncableAISettings()` 把 `ai.thinking` 視為可同步內容。

### `modules/api.js`

- `requestAI()`、`streamAIResponse()` 增加可選 `thinking` 參數（本次覆寫）。
- 解析有效模式，套用生成預算下限。
- 傳給 `adapter.buildRequest({ thinking })`。
- 400／422 且錯誤訊息與 reasoning／thinking／effort 相關時，重試一次 `auto`（不含參數）；成功後 `console.warn` 並 dispatch `bdc:ai-thinking-fallback`（detail：task、level、provider、model）。
- 串流路徑也要有同樣的一次降級重試。
- 快取相關函式把有效模式加入 `cacheOptions`；`getWordAnalysis()` 的字典快取 key 也加入模式。

### 協議適配器

- `chat-completions.js`：輸出 `reasoning_effort`。
- `anthropic.js`：輸出 `thinking`、必要時 `temperature = 1`、提高 `max_tokens`。
- `gemini.js`：依模型輸出 `thinkingConfig.thinkingBudget` 或 `thinkingLevel`。
- 三者 `auto` 都不得輸出任何思考欄位。

### 設定 UI：`features/sync/ai-provider-settings.js`

- 在「按功能指定模型」區塊，為四個群組顯示「思考模式」下拉：
  - `wordAnalysis`
  - `articleParagraphTranslation`
  - `articleSentenceTranslation`
  - `assistant`
- 只顯示四個群組，避免介面過度膨脹；其他任務維持 `auto`。
- 新增 `AI_TASK_FIELDS` 的段落翻譯與句子詳解列（含模型與思考兩個下拉），讓兩個任務可獨立選模型。
- 即時儲存：`change` 時直接呼叫 `saveTaskThinkingLevel()`，不加「儲存」按鈕。
- 群組下方加誠實提示：部分渠道會把「關閉」降為最低強度，實際效果取決於模型。

### 助手：`features/assistant/assistant.js`

- 面板底部增加思考模式下拉：跟隨設定、關閉、低、中、高。
- 記憶最後選擇（localStorage `assistantThinkingLevel`），不寫入同步。
- 送出時把模式寫入 `requestSnapshot`；重試沿用 snapshot 的模式。
- `onceCompletions()`、`streamCompletions()` 把 `thinking` 傳給 `requestAI()`／`streamAIResponse()`。

### 樣式：`styles.css`

- 調整 `.gs-ai-task-row` 支援模型＋思考兩個下拉（桌面兩個欄位、窄螢幕單欄）。
- 助手 `.assistant-sub` 容納新增下拉，避免擠壓。

### i18n

`locales/zh-CN.js`、`locales/zh-HK.js` 同時新增：

- `settings.aiThinkingLabel`
- `settings.aiThinkingAuto`
- `settings.aiThinkingNone`
- `settings.aiThinkingLow`
- `settings.aiThinkingMedium`
- `settings.aiThinkingHigh`
- `settings.aiThinkingHint`
- `settings.taskArticleParagraph`
- `settings.taskArticleSentence`
- `assistant.thinking`
- `assistant.thinkingFollow`

兩個字典鍵集合與插值參數必須一致。

## 六、測試與驗收

### 自動測試

新增／擴充 `tests/ai-units.test.mjs`：

1. 三個適配器在 `auto` 時不輸出任何思考欄位。
2. Chat Completions 在 `none/low/medium/high` 時輸出正確 `reasoning_effort`。
3. Anthropic 在 `low` 時輸出 `thinking`、`temperature = 1`、`max_tokens > budget_tokens`；`none` 不輸出。
4. Gemini 2.5 輸出 `thinkingBudget`；Gemini 3 輸出 `thinkingLevel`。
5. `normalizeThinkingLevel()` 與非法值回退。
6. profile 正規化保留合法 `taskThinking`、丟棄非法值。
7. `sanitizeAISettings()` 與 snapshot sanitizer 保留合法 thinking 映射。

執行：

```bash
node --test tests/ai-units.test.mjs tests/ai-worker.test.mjs tests/ai-sync-regressions.test.mjs
node tests/audit-i18n.mjs
```

### 手動驗收

1. 設定頁四個群組可切換模式並即時保存，重新載入後保留。
2. `zh-CN` 與 `zh-HK` 文案一致、無硬編中文。
3. 查詞請求出站為 `reasoning_effort`（或對應協議欄位），設為跟隨服務端時完全沒有該欄位。
4. 助手選擇「高」後本次請求使用高檔；重試仍為高檔。
5. 文稿翻譯 JSON 不被推理耗盡截斷；`high` 模式有足夠 `maxTokens`。
6. 帳戶同步：一端修改思考模式，另一端拉取後生效；舊 snapshot 不會把新欄位清空。
7. 選一個不支援該參數的 OpenAI 相容供應商，確認 400 後自動降級重試成功，功能不中斷。
