# 快速模型切換與完整思考模式入口實施計劃

日期：2026-11-02。狀態：已實作。2026-11-03 追加：快速模型選單加入一行緊湊的思考模式下拉，預設「跟隨應用預設（目前檔位）」，可選跟隨服務端／關閉／低／中／高；模型與思考模式在同一次 profile revision 寫入，只寫實際改動的欄位以避免覆蓋其他分頁的並行更新，桌面與手機共用同一版面。

使用者回饋兩點：

1. 為什麼設定裡只有少數任務能選思考強度？全文翻譯是不是不能選？
2. 希望在查詞、文章等 AI 介面加一個極簡圖示，點擊彈出模型選單，確認後關閉，並自動同步到全局設定。

## 一、現況與結論

- 設定頁目前只為 `wordAnalysis`、`articleParagraphTranslation`、`articleSentenceTranslation`、`assistant` 四個群組顯示思考模式；其他任務固定使用應用程式預設（多數為跟隨服務端）。
- 全文翻譯不是獨立任務：文章「分析文章」與逐段翻譯都走 `features/article/paragraph-pipeline.js` → `api.analyzeParagraph()`，`taskType` 是 `articleParagraphTranslation`。因此「文章段落翻譯」的思考模式實際上已套用到全文翻譯。
- 目前缺少的是：
  1. 設定頁沒有把這個對應關係寫清楚，也沒有為其他任務提供思考模式入口。
  2. 查詞彈窗、文章閱讀頁沒有快速切換模型的入口，只能進全局設定。

## 二、實作目標

### A. 思考模式入口補齊

- 在「設定 → AI 供應商 → 按功能指定模型」中，為所有任務列顯示思考模式下拉，不再只限四個。
- 仍然保留即時儲存與現有預設值；未設定的任務維持「跟隨服務端」。
- 將 `settings.taskArticleParagraph` 文案改為「文章翻译（段落 / 全文）」／「文章翻譯（段落／全文）」，明確表示全文翻譯共用此設定。
- 更新 `settings.aiThinkingHint`，說明每個任務可獨立設定，且部分渠道會把關閉降為最低強度。

### B. 極簡快速模型圖示

新增共用模組 `modules/quick-model-picker.js`：

- `openQuickModelPicker({ tasks, initialTask, title })` 開啟輕量彈窗。
- 多任務時頂部顯示任務切換（文章圖示支援文章翻譯、句子詳解、文章詳解、文章清洗）。
- 下方列出該任務目前可用的模型，單選；最上方提供「跟隨全局預設」選項，可清除任務層級覆寫。
- 確認後呼叫 `saveTaskModelSelection(task, value)`，立即寫入 AI profile 並透過既有 `syncTouch('aiSettings')` 同步；關閉彈窗並顯示簡短提示。
- 沒有可用模型時顯示「尚未配置可用模型」與前往設定的說明，不寫入任何值。
- 沿用現有 modal / radio-card 樣式與無障礙焦點管理。

放置位置：

1. **單詞／短語查詞彈窗**：在 `#word-analysis-tooltip` 的 `.tooltip-head-actions` 增加模型圖示（`#ic-model`），點擊開啟 `wordAnalysis` 的模型選單。單詞與短語兩條 render 路徑都要有。
2. **文章閱讀頁**：在 `#article-reader-actions` 增加一個模型圖示按鈕，點擊開啟文章任務群組的模型選單，預設停在「文章翻譯」。
3. **助手面板**：已有模型下拉，本次不重複加入圖示；保留現有行為。

圖示使用新增的 `ic-model` SVG symbol（晶片造型），沿用 `.article-reader-action` 與 `.btn-refresh-word` 的尺寸與 hover 樣式。

- 新增 `tests/quick-model-picker.cjs`（Playwright，沿用 `tests/helpers/article-mock.cjs`）：

  5. 設定頁每個任務列都有思考模式下拉，段落翻譯列文案包含「全文」。
- 既有測試：`node tests/audit-i18n.mjs`、四個 AI node:test 檔、`tests/settings-autosave.cjs`（若環境可跑）。

手動驗收：

- `zh-CN`／`zh-HK` 兩個語系的圖示 title、彈窗文案、任務名稱。
- 桌面與 390px 寬的手機版：文章工具列圖示不擠壓、彈窗可滾動、確認後關閉。
