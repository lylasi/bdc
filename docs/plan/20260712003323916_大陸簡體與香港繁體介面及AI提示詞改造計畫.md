# 大陸簡體與香港繁體介面及 AI 提示詞改造計畫

## 1. 文件目的

本文件依據目前 BDC 專案的實際程式結構，制定「大陸簡體中文／香港繁體中文」雙語改造計畫。改造重點只有兩條主線：

1. 使用者介面可在大陸簡體中文與香港繁體中文之間切換，網站預設使用大陸簡體中文。
2. 所有會產生中文內容的 AI 功能，必須依目前介面語言輸出對應的大陸簡體或香港繁體中文。

學習內容與介面語言保持獨立：簡體介面可以閱讀及學習繁體內容，香港繁體介面也可以閱讀及學習簡體內容。切換語言不得自動改寫文章、詞書、OCR 原文、QA 資料、對話紀錄或其他使用者資料。

本文件只描述修改方案，不修改產品程式碼。

## 2. 需求結論

### 2.1 第一版支援範圍

第一版只提供兩個選項，避免設定過度複雜：

| 設定值 | 顯示名稱 | 用途 |
| --- | --- | --- |
| `zh-CN` | 大陸簡體中文 | 簡體介面及大陸常用書面詞彙的 AI 回覆 |
| `zh-HK` | 香港繁體中文 | 香港繁體介面及香港常用書面詞彙的 AI 回覆 |

預設值為 `zh-CN`。

第一版不提供「跟隨瀏覽器」「AI 語言獨立選擇」或「粵語口語」選項。這些能力可保留擴充空間，但不應增加目前介面的理解成本。

### 2.2 語言行為

使用者切換語言後：

- 導航、按鈕、標籤、提示、錯誤訊息、模態框及設定頁改為對應語言。
- 後續 AI 請求使用對應的語言規則。
- 已顯示的 AI 舊結果不自動重寫；重新分析或重新請求後才取得另一語言版本。
- 原始教材及使用者輸入保持不變。
- TTS 的中文朗讀偏好仍是獨立設定，不與介面語言強制綁定。

### 2.3 香港繁體定義

`zh-HK` 指香港常用的正式書面中文，不代表粵語口語。

香港繁體 AI 規則應明確要求：

- 使用香港繁體字及香港常用書面詞彙。
- 可使用「軟件、網絡、網上、上載、電郵、巴士、的士、單車、連結、相片」等香港用詞。
- 除非使用者要求，不使用「喺、嘅、唔、冇」等粵語口語。
- 不使用臺灣地區特有的詞彙作為預設，例如應避免將軟件固定寫成「軟體」。

## 3. 現況盤點

### 3.1 全域設定現況

目前全域設定位於 `modules/settings.js`：

- 使用 localStorage 鍵 `pen_global_settings`。
- 已有 `ai`、`tts`、`reading`、`assistant` 分區。
- `reading.chineseVariant` 預設為 `zh-CN`，但它目前代表中文朗讀 voice 偏好，不是介面語言。
- `mergeSettings()` 已提供兼容舊資料的合併機制，適合新增語言欄位。

全域設定 UI 位於 `features/sync/sync.js` 的 `showGlobalSettingsModal()`：

- 設定頁由 JavaScript 動態產生。
- 已提供中文朗讀 `zh-CN`／`zh-HK` 選擇，但只影響朗讀。
- 新的介面語言選項應放在設定頁最上方，與 TTS 語言明確分開。

### 3.2 提示詞現況

專案雖已在 `ai-config.example.js` 中提供 `AI_PROMPTS`，但仍未真正集中：

- `ai-config.example.js` 同時承擔 API、Provider、模型、限流、TTS、OCR 及提示詞等多種責任。
- `modules/api.js` 為多數任務保留硬編碼後備提示詞。
- `features/assistant/assistant.js` 內有獨立的 `SYSTEM_PROMPT`。
- `features/dictation/dictation-grader.js` 內有獨立的 `defaultAIMarkdownPrompt()`。
- `features/qa/qa-checker.js` 內有獨立後備 system prompt 及 user prompt。
- 部分 OCR 提示詞允許使用者自行修改，需區分「使用者補充提示」與「系統語言規則」。

目前提示詞與香港繁體要求直接混在任務內容中，因此若增加簡體版本，直接複製兩套完整提示詞會造成長期維護風險。

### 3.3 AI 快取現況

`modules/cache.js` 的文章、單字、句子及片語快取鍵目前包含輸入內容、模型及 schema，但未包含：

- AI 輸出語言。
- 提示詞版本。

若不修改快取鍵，簡體介面可能取得先前的香港繁體結果，反之亦然。

### 3.4 UI 文案現況

目前靜態 HTML 及多個 JavaScript 模組含有大量硬編碼繁體文案。主要集中於：

- `index.html`
- `main.js`
- `modules/`
- `features/vocabulary/`
- `features/learning/`
- `features/dictation/`
- `features/quiz/`
- `features/article/`
- `features/ocr/`
- `features/qa/`
- `features/sync/`
- `features/assistant/`

其中 QA、Article、Sync 及 Dictation 的動態文案較多，應分批遷移，不能只轉換 `index.html`。

## 4. 目標架構總覽

建議新增以下結構：

```text
modules/
├── i18n.js
├── i18n-config.js
└── prompts/
    ├── index.js
    ├── language-rules.js
    ├── dictionary.js
    ├── learning.js
    ├── article.js
    ├── qa.js
    ├── ocr.js
    ├── dictation.js
    ├── assistant.js
    └── import.js

locales/
├── zh-CN.js
└── zh-HK.js
```

職責分配：

- `modules/i18n-config.js`：支援語言、預設語言及顯示名稱。
- `modules/i18n.js`：載入設定、翻譯查找、參數插值、DOM 更新及語言變更事件。
- `locales/*.js`：只存放使用者介面文案。
- `modules/prompts/`：唯一的產品 AI 提示詞維護位置。
- `modules/prompts/language-rules.js`：大陸簡體與香港繁體的 AI 語言規則。
- `modules/prompts/index.js`：提示詞查找、模板變數套用、語言規則組裝及版本管理。

## 5. 介面語言設計

### 5.1 公開語言配置

`modules/i18n-config.js` 建議保持簡單：

```js
export const DEFAULT_LOCALE = 'zh-CN';

export const SUPPORTED_LOCALES = {
    'zh-CN': {
        label: '大陆简体中文',
        htmlLang: 'zh-CN'
    },
    'zh-HK': {
        label: '香港繁體中文',
        htmlLang: 'zh-HK'
    }
};
```

網站維護者可在此修改預設語言，不必進入私有的 `ai-config.js`。語言配置不包含秘密資料，也不應與 API Key 放在一起。

### 5.2 設定資料模型

在 `modules/settings.js` 的 defaults 新增：

```js
language: {
    interfaceLocale: 'zh-CN'
}
```

`mergeSettings()` 同步加入：

```js
language: mergeRecord(base.language, override.language)
```

第一版 AI 回覆語言直接跟隨 `language.interfaceLocale`，不新增第二個可見設定。這樣使用者只需理解一個語言選項。

保留未來擴充方式：

```js
language: {
    interfaceLocale: 'zh-CN',
    aiResponseLocale: 'follow-interface'
}
```

第一版不必顯示 `aiResponseLocale`。

### 5.3 設定頁 UI

在 `features/sync/sync.js` 的全域設定面板頂部增加一個簡潔區塊：

```text
顯示語言
[ 大陸簡體中文 ▼ ]
介面及 AI 回覆會使用所選語言；學習內容保持原樣。
```

建議使用單一 `<select>`，而不是再增加一組複雜開關：

```html
<select id="gs-interface-locale">
    <option value="zh-CN">大陆简体中文</option>
    <option value="zh-HK">香港繁體中文</option>
</select>
```

儲存時：

1. 呼叫 `saveGlobalSettings({ language: { interfaceLocale } })`。
2. 呼叫 `setLocale(interfaceLocale)` 即時更新介面。
3. 發出 `bdc:locale-change` 事件，讓動態模組刷新必要文字。
4. 顯示已儲存訊息，不強制重新整理頁面。

### 5.4 `modules/i18n.js` API

建議提供：

```js
getLocale()
setLocale(locale)
t(key, params)
applyTranslations(root = document)
subscribeLocaleChange(handler)
```

必要行為：

- 不合法 locale 回退到 `zh-CN`。
- 缺少簡體或香港繁體翻譯鍵時回退預設語言。
- 開發環境以 `console.warn` 顯示缺少的翻譯鍵。
- 更新 `<html lang>`。
- `setLocale()` 只更新 UI，不改寫頁面中的學習內容。

### 5.5 靜態與動態文案

靜態 DOM 使用：

```html
<button data-i18n="common.save">保存</button>
<input data-i18n-placeholder="vocabulary.searchPlaceholder">
```

導航的長短文案建議由目前的：

```text
data-full-text
data-short-text
```

調整為：

```text
data-i18n-full
data-i18n-short
```

`main.js` 的 `responsiveNavLabels()` 應使用 `t()` 取得目前語言的長短文案。

動態文案使用：

```js
showMessage(t('common.saved'));
confirm(t('quiz.leaveConfirmation'));
```

禁止在語言切換時掃描所有文字節點並機械轉換，避免改寫文章、題目、使用者輸入及 AI 舊回覆。

## 6. 提示詞集中維護設計

### 6.1 為何使用目錄而非單一大檔案

使用 `modules/prompts/` 作為唯一入口，但按功能分檔，原因如下：

- 所有提示詞都在一個固定目錄中，容易搜尋及審查。
- 避免單一檔案快速超過 300 行。
- 功能負責人可只修改對應檔案。
- `index.js` 對外提供一致 API，呼叫端不需要知道實際檔案位置。

### 6.2 每個提示詞必須包含的備註

每個提示詞 export 前加入固定格式註解：

```js
/**
 * Prompt ID: learning.exampleGeneration
 * 對應功能：學習模組 → 產生 AI 例句
 * 呼叫位置：modules/api.js → generateExamplesForWord()
 * 任務模型：exampleGeneration
 * 輸出格式：JSON array
 * 語言策略：跟隨介面語言
 * 注意事項：英文例句保持英文，只翻譯及說明使用目標中文
 */
```

備註欄位統一為：

- Prompt ID
- 對應功能
- 呼叫位置
- AI taskType
- 輸出格式
- 語言策略
- 特別注意事項

### 6.3 提示詞資料格式

建議每個提示詞定義為帶 metadata 的物件：

```js
export const exampleGenerationPrompt = {
    id: 'learning.exampleGeneration',
    version: '1.0.0',
    feature: 'learning',
    caller: 'modules/api.js#generateExamplesForWord',
    taskType: 'exampleGeneration',
    responseType: 'json',
    languagePolicy: 'follow-interface',
    system: '...',
    user: '...'
};
```

`version` 必須在會影響 AI 輸出的提示詞修改時更新，並加入快取鍵。

### 6.4 語言策略類型

不要對所有提示詞強制加入翻譯語言。建議定義三種策略：

| 策略 | 用途 | 範例 |
| --- | --- | --- |
| `follow-interface` | AI 產生給使用者閱讀的中文內容 | 單字解釋、文章翻譯、QA 回饋、Assistant |
| `preserve-source` | 嚴格保留來源文字，不翻譯 | OCR 純文字擷取、網頁文章清理 |
| `custom` | 功能自行決定或使用者可補充 | OCR 自訂提示、特殊匯入流程 |

### 6.5 語言規則

`modules/prompts/language-rules.js` 建議集中維護：

```js
export const AI_LANGUAGE_RULES = {
    'zh-CN': `
所有中文解释、翻译、反馈和建议使用简体中文。
采用中国大陆常用的现代书面中文。
优先使用软件、网络、在线、上传、电子邮件、公交、地铁、用户等大陆常用词。
不得擅自转换用户原文的简繁体。
`,
    'zh-HK': `
所有中文解釋、翻譯、回饋及建議使用香港繁體中文。
採用香港常用的正式書面中文。
優先使用軟件、網絡、網上、上載、電郵、巴士、港鐵、用戶等香港常用詞。
除非使用者明確要求，否則不要使用粵語口語或臺灣地區特有用詞。
不得擅自轉換使用者原文的簡繁體。
`
};
```

此規則只描述語言，不包含任務邏輯、JSON schema 或評分標準。

### 6.6 提示詞組裝 API

`modules/prompts/index.js` 建議提供：

```js
getPromptDefinition(promptId)
buildPrompt(promptId, params, options)
buildMessages(promptId, params, options)
getPromptVersion(promptId)
```

組裝順序：

1. 共用 system 任務規則。
2. 功能專屬任務規則。
3. 依 `languagePolicy` 決定是否注入語言規則。
4. 套用 `${variable}` 模板參數。
5. 加入使用者輸入，並以清晰分隔符包裹。

呼叫範例：

```js
const messages = buildMessages('article.paragraphTranslation', {
    paragraph
}, {
    locale: getLocale()
});
```

### 6.7 `ai-config.js` 的調整

`ai-config.js` 與 `ai-config.example.js` 應只保留：

- API URL、Key 及 Provider。
- AI 任務與模型映射。
- 限流設定。
- TTS、OCR 及文章匯入服務配置。

應將 `AI_PROMPTS` 移出私有設定檔。原因：

- 提示詞是產品邏輯，不是秘密設定。
- 私有 `ai-config.js` 不適合成為團隊唯一的提示詞來源。
- 示例檔與真實本機檔可能逐漸不同步。
- 提示詞修改應能正常進入版本控制及 code review。

## 8. 逐檔修改計畫

### 8.1 新增檔案

#### `modules/i18n-config.js`

- 定義 `DEFAULT_LOCALE = 'zh-CN'`。
- 定義 `SUPPORTED_LOCALES`。
- 提供 locale 合法性檢查。

#### `modules/i18n.js`

- 從全域設定讀取目前 locale。
- 提供 `t()`、`setLocale()`、`applyTranslations()`。
- 管理 `<html lang>`。
- 發出語言變更事件。
- 提供缺少翻譯鍵回退。

#### `locales/zh-CN.js`、`locales/zh-HK.js`

- 使用相同鍵結構。
- 先覆蓋主導航、共用 UI、設定頁及 AI 狀態。
- 再按功能逐步遷移。
- 不存放 AI 提示詞。

#### `modules/prompts/*`

- 建立提示詞 registry。
- 按功能分檔。
- 每個提示詞包含固定格式備註與版本。
- 集中維護 fallback。
- 統一注入語言規則。

### 8.2 修改 `modules/settings.js`

- 新增 `language.interfaceLocale`。
- 預設 `zh-CN`。

## 9. 提示詞整理規則

### 9.1 任務規則只維護一份

禁止建立完整的 `zh-CN prompt` 與 `zh-HK prompt` 副本。以下內容共用：

- AI 角色。
- 任務步驟。
- JSON schema。
- Markdown 保留規則。
- 評分標準。
- 安全與錯誤處理。

只有 `language-rules.js` 維護地區語言差異。

### 9.2 JSON 欄位固定英文

例如：

```json
{
  "translation": "...",
  "teacherFeedback": "...",
  "improvementSuggestions": []
}
```

禁止簡體版使用中文鍵、香港繁體版使用另一組中文鍵。UI 顯示標題由 i18n 處理。

### 9.3 原文保留規則

所有 `follow-interface` 提示詞也要包含：

```text
只將解釋、翻譯、回饋及建議寫成目標語言。
引用的使用者原文、題目、答案及文章片段保持原樣。
```

### 9.4 使用者自訂提示詞

OCR 與手寫批改目前允許使用者編輯提示詞。應將其視為補充要求：

- UI 標籤由「AI 提示詞」改為「補充要求」或增加說明。
- 系統必要規則不放在可被完全覆蓋的 textarea 中。
- 使用者內容插入 `<user_instructions>` 等明確邊界。
- 系統語言與輸出格式規則具有較高優先級。

## 11. 測試與驗收案例

### 11.1 語言設定

1. 清除 `pen_global_settings` 後開啟網站，介面應為大陸簡體。
2. 切換香港繁體並儲存，介面立即更新。
3. 重新整理後保持香港繁體。
4. 將 locale 人工設為非法值，應回退大陸簡體。
5. 確認中文朗讀 voice 不因介面切換被強制改變。

### 11.2 跨語言學習內容

1. 簡體介面載入香港繁體文章，文章原文保持繁體，AI 解釋使用簡體。
2. 香港繁體介面載入簡體文章，文章原文保持簡體，AI 解釋使用香港繁體。
3. 切換介面後，詞書、QA 題目及 OCR 原文不產生 localStorage 寫入變更。
4. 匯出資料時內容保持原始簡繁，不跟隨介面轉換。

### 11.3 AI 功能

每個 AI 任務至少測試一次 `zh-CN` 與 `zh-HK`：

- 單字分析。
- 例句生成。
- 造句檢查。
- 段落翻譯。
- 句子分析。
- 單字 tooltip。
- 片語分析。
- QA 判題。
- OCR 手寫批改。
- Dictation Markdown 批改。
- Article Assistant。

驗收標準：

- 簡體模式使用大陸簡體書面中文。
- 香港繁體模式使用香港正式書面中文，不自動使用粵語口語。
- JSON 欄位與陣列結構完全一致。
- 英文原句及使用者中文原文保持不變。
- Markdown 結構沒有被翻譯或破壞。

### 11.4 快取

1. 在簡體模式分析同一段落並記錄結果。
2. 切換香港繁體後分析同一段落，必須重新請求或讀取香港繁體快取。
3. 切回簡體後可讀取原簡體快取。
4. 更新 prompt version 後不得繼續使用舊版本結果。

### 11.5 UI 人工巡檢

- Vocabulary：詞書 CRUD、匯入、匯出及 URL 導入。
- Learning：單字分析、例句、造句及播放。
- Dictation：設定、暫停、恢復、評分、AI 手寫批改。
- Quiz：題數、倒數、計分及離開確認。
- Article：載入、分析、翻譯遮罩、朗讀及片語分析。
- OCR：拖放、相機、提示補充、結果及 Markdown 預覽。
- QA：題集、訓練、AI 校對、回饋及 PDF。
- Sync：登入、全域設定、備份及同步狀態。
- Assistant：開關、串流、歷史對話及語言切換後的新回覆。
- `test-floating-statusbar.html`：確認語言設定持久化改造沒有破壞浮動控制。

## 12. 風險與控制

| 風險 | 控制方式 |
| --- | --- |
| 直接維護兩套完整提示詞導致規則分叉 | 共用任務提示詞，只拆分語言規則 |
| 簡繁 AI 快取互相污染 | locale、prompt version、schema 一起加入 key |
| 語言切換改寫學習內容 | 只翻譯有明確 i18n 標記的 UI 節點 |
| 香港繁體被模型寫成臺灣用詞 | `zh-HK` 規則列明香港詞彙及禁止預設臺灣詞彙 |
| 香港繁體被模型寫成粵語口語 | 明確要求正式書面中文，除非使用者主動要求 |
| 動態模組切換後仍顯示舊語言 | 統一 locale change 事件，模組重建或刷新文案 |
| 使用者自訂提示覆蓋 JSON 規則 | 自訂內容只作補充，固定 system 規則不可覆蓋 |
| `ai-config.js` 與示例提示詞不一致 | 將提示詞移出私有設定檔並納入版本控制 |
| 一次翻譯全部 UI 範圍過大 | 按模組分批遷移，每批獨立驗收 |

## 13. 完成定義

此改造只有在下列條件全部達成後才算完成：

- 網站預設顯示大陸簡體中文。
- 使用者可在全域設定切換大陸簡體與香港繁體。
- 語言設定可保存並在重新整理後恢復。
- 所有產品 AI 提示詞集中在 `modules/prompts/`。
- 每個提示詞都有功能、呼叫位置、輸出格式及語言策略備註。
- `modules/api.js`、Assistant、QA、Dictation 不再保留獨立完整提示詞。
- AI 回覆跟隨介面語言。
- 香港繁體輸出符合香港正式書面中文，而非臺灣中文或粵語口語。
- AI 快取區分 locale 與提示詞版本。
- 切換語言不修改原始學習內容及使用者資料。
- 九大模組的主要流程完成雙語人工巡檢。

## 14. 建議實作順序摘要

1. 先建立 `modules/i18n-config.js`、`modules/i18n.js` 及 locale 資源。
2. 在 `modules/settings.js` 加入預設 `zh-CN` 的介面語言設定。
3. 在全域設定加入兩選項語言切換。
4. 建立 `modules/prompts/` 並搬移所有提示詞。
5. 讓 AI prompt builder 自動注入 `zh-CN` 或 `zh-HK` 規則。
6. 更新 AI 快取鍵。
7. 按功能模組逐步遷移 UI 文案。
8. 完成雙語、跨語言教材、快取及同步巡檢。

此順序先解決語言與提示詞的底層機制，再處理大量 UI 文案，可降低重工及回歸風險。
