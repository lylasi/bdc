# 備份容量與文章同步失敗修復計劃

使用者提供的截圖確認本機備份 `localStorage.setItem` 超出容量，另有文章同步失敗。上一輪閱讀逐項同步修復仍保留；本次完成備份儲存與文章同步錯誤追蹤，依既有授權驗證後提交並部署 149。

1. 新增獨立的 IndexedDB 備份資料庫；備份內容與列表中繼資料同交易寫入，保留所有手動備份、最近兩份自動備份。
2. 舊 localStorage 備份逐一搬移、讀回確認後才移除舊內容；失敗保留原備份。不清除文章、筆記、登入及供應商設定。IndexedDB 不可用時維持 localStorage 後備，但錯誤清楚顯示。
3. 備份讀寫與面板改為 async，保留匯出、匯入、刪除及還原。啟動及同步前準備備份儲存，釋放舊備份佔用的 localStorage。
4. 文章同步顯示具體錯誤碼及可行處理提示；以本機容量滿及服務失敗情境重現，避免再次只顯示籠統失敗。
5. 驗證容量、搬移交易失敗、完整資料保留、保留份數、後備路徑、雙語面板及跨裝置同步；重跑相關既有測試及資源版本檢查。
6. 按 Git 推送、149 fast-forward、容器重啟及內外網資源核對流程發布；記錄實際驗證範圍。

只讀雲端中繼資料顯示該帳戶有 21 篇文章，最大約 40 KB，低於單篇及帳戶文章容量上限；沒有取得手機本機 outbox，因此不把文章同步原因直接斷定為容量不足。
