# IndexTTS 2.5 部署環境與 Mac 可行性

- 核對日期：2026-10-28。
- 問題：IndexTTS 2.5 需要甚麼環境；能否使用現有 Apple Silicon 電腦、本地 Docker 或 Cloudflare。
- 方法：核對官方 README、2.5 模型卡、`pyproject.toml`、`infer_v2_5.py`、WebUI 及授權；以 Hugging Face metadata 唯讀統計模型檔案大小。
- 驗證邊界：沒有下載或執行 IndexTTS，沒有安裝依賴、啟動容器或量測合成效能。資源建議不代表已驗證的最低需求。

## 一、結論

**IndexTTS 2.5 可以本地部署，但比 Kokoro 重；要穩定提供服務，優先選 Linux＋NVIDIA GPU。現有 36 GiB Apple Silicon Mac 可考慮原生 MPS 試驗，Mac 上的 Linux Docker 則只能走 CPU，並非首選。**

官方 2.5 模型卡明列 **Python 3.10–3.11、NVIDIA GPU、推理約 6 GB VRAM**。這個數字是單次推理的文件要求，不是長文本、情緒模型、所有精度或多人併發的保證配置。

官方程式另有 MPS／CPU 路徑，所以不能把 NVIDIA 說成程式唯一可選裝置；但有程式分支不代表官方已驗證 Mac 的完整流程、速度和穩定性。

## 二、先確認版本

- 官方倉庫記錄 **2026-08-10** 發布 IndexTTS-2.5。
- 官方 checkpoint：`IndexTeam/IndexTTS-2.5`。
- 2.5 推理入口為 `indextts.infer_v2_5.IndexTTS2`，不是舊版 `indextts.infer_v2`。
- WebUI 現行 `--version` 預設為 `2.5`，可選 `2` 或 `2.5`。
- 倉庫的 Python 套件 metadata 仍寫 `version = "2.0.0"`，但同一份主線程式碼包含並載入 2.5。不能只憑套件版本欄就判斷取到舊版，也不能把舊版教學的參數直接套到新版本。
- 2.5 使用 `use_bf16`；舊 2.0 常見的 Python 參數 `use_fp16` 不是同一個介面。

## 三、官方要求與部署預算

| 項目 | 已核對的官方資料 | 建議如何理解 |
| --- | --- | --- |
| Python | `>=3.10,<3.12`，即 3.10／3.11 | 使用 uv 管理相符版本及隔離環境 |
| PyTorch | 主線依賴 `torch==2.8.*`、`torchaudio==2.8.*` | 優先跟隨鎖定依賴，不任意混裝版本 |
| NVIDIA 路徑 | Linux／Windows 使用 PyTorch CUDA 12.8 index | 需要匹配驅動；需要編譯可選 CUDA 元件時，再準備相符 Toolkit |
| GPU VRAM | 模型卡列推理約 6 GB | 6 GB 屬緊湊起點，不宜作長文或併發服務保證 |
| 系統 RAM | 已查官方資料未列確切最低量 | 可先預算 16 GB，32 GB 較有餘裕；屬規劃建議 |
| 磁碟 | 主 checkpoint 倉庫檔案合計約 5.49 GB 十進位 | 尚有輔助模型、Python／PyTorch、快取；建議先留 20–30 GB，屬規劃預算 |
| 參考聲音 | 以一段 reference audio 做零樣本聲音克隆 | 需要先準備聲線參考音訊，與 Kokoro 直接選固定 voice ID 不同 |

### GPU 如何選

個人單工作可先比較 8 GB 與 12 GB 以上配置；若打算持續供 BDC 使用，**12–16 GB VRAM 的 NVIDIA 卡較有規劃餘裕**，例如 RTX 3060 12 GB 或 RTX 4060 Ti 16 GB 等級。這是部署建議，不是上游對這些卡、特定片段長度或併發數的效能認證。

2.5 原始碼在 CUDA 裝置少於 **10 GB VRAM** 時啟用低顯示記憶體模式：非串流推理遇到超過 40 字符的文字會再分塊。WebUI 亦會在低 VRAM 時啟用半精度，並預設跳過 QwenEmotion。這些節省機制不等於所有 6 GB 顯示卡都能無條件跑所有功能。

官方速度表是在 **RTX 4090、kv_cache=True** 的條件測得：2.5 BF16 overall RTF 為 **0.2065**。RTF 是生成耗時除以音訊時長；它不是首字延遲，亦不能外推為 Mac 或一般 CPU 的速度。

### 磁碟數字的範圍

本次模型倉庫 metadata 的 revision 為：

```text
c39ce5ba981572cb187443877ff559dfb246ce63
```

所有已列檔案的大小合計 **5,491,182,363 bytes**，其中包括約 3.26 GB 的 GPT 權重及約 1.19 GB 的 Qwen 情緒模型權重。這不代表運行時記憶體只需同樣大小。

## 四、現有 Apple Silicon Mac 的可行性

沿用前一輪已核對環境：Apple Silicon、36 GiB 統一記憶體，Docker 為 Linux aarch64，分配約 15.66 GiB RAM。

### 原生 macOS：適合試驗

`infer_v2_5.py` 明確包含裝置選擇順序：

```text
CUDA → Intel XPU → Apple MPS → CPU
```

自動選擇 MPS／CPU 時，程式停用 BF16；非 CUDA 裝置亦不使用自訂 CUDA kernel。這表示 Mac 有原生 MPS 路徑，但仍須實際檢查所有依賴和算子的相容性。

建議初次試驗：

- 使用 Python 3.10／3.11 及獨立 uv 環境。
- 先安裝基本推理或 WebUI 所需依賴，避免照抄 `--all-extras` 安裝 NVIDIA 專用加速套件。
- 先關閉 DeepSpeed、FlashAttention、自訂 CUDA kernel、`torch.compile`；確認基本輸出後再個別評估加速。
- 首次透過 Python API 試驗時，可先保持 `use_qwen_emo=False`，避免載入額外的文字情緒模型；此時不能使用 `use_emo_text=True`，但參考音訊及情緒向量等控制仍可選。
- 現行 WebUI 的 QwenEmotion 載入預設與 Python API 不同：在未判定為低 VRAM 時會載入，不能以 Python API 預設推斷 WebUI 的實際用量。

**判斷：36 GiB 是合理的試驗條件，但本次沒有證明這台 Mac 能即時合成或長時間穩定服務。**

### macOS 上 Docker：CPU 可試，Apple GPU 不可直接使用

一般 Docker Desktop 的 Linux 容器不能直接使用 Apple MPS／Metal。因此把 IndexTTS 放進這台 Mac 的 Linux 容器，不會自動取得 Apple GPU 加速。

CPU 分支存在，程式亦提示 CPU 模式可能耗時。若重視 BDC 點擊後迅速播放，Mac Docker CPU 版不是本次推薦的第一條路線；不能把 Kokoro CPU 版的可用體驗套到 IndexTTS。

本次查核沒有找到主倉庫維護的正式 Docker 映像／Compose 快速部署入口，因此不提供未核實的第三方 `docker run` 指令。

## 五、Linux／Windows NVIDIA 與 Docker

- **Linux＋NVIDIA**：最值得作服務部署的路線；若採 Docker，主機要有 NVIDIA 驅動和 NVIDIA Container Toolkit，容器內提供 PyTorch／CUDA 使用者空間依賴及模型。
- **Windows＋NVIDIA**：主線依賴包含 Windows 路徑，可評估原生或 WSL2；若經 Docker 使用 GPU，仍需相符的 WSL2／Docker GPU 支援。
- CUDA 版 PyTorch 不代表每個安裝情境都需主機完整 Toolkit；只有編譯可選 kernel／加速套件時，才另外核對 Toolkit、編譯器與相關版本。
- 生產部署可參考官方連結的 vLLM recipe；它屬另一個服務化方案，不應把主線約 6 GB 的推理要求直接當作 vLLM 全配置的最低資源保證。

## 六、Cloudflare 是否適合

- **一般 Workers**：128 MB 記憶體及執行模型不適合這套 PyTorch、多模型推理服務。
- **Containers**：可考慮 CPU 容器的工程路徑，但目前公開配置沒有 GPU 選項，且需要付費；本次沒有在 Cloudflare 部署 IndexTTS，不能保證 CPU 速度或特定配置能裝下完整模型組合。
- **本地推理＋Tunnel**：可行方向與 Kokoro 相同；模型在 Mac 原生或 NVIDIA 主機執行，Cloudflare 提供外部 HTTPS 入口。Tunnel 不會加速模型或代替本地 GPU。

若只是要 BDC 快速、免費或低成本地讀單字與文章，仍優先驗證 Kokoro；若特別需要聲音克隆、情緒控制或指定發音，才值得承擔 IndexTTS 較重的部署成本。

## 七、功能與授權注意點

- 官方明列語言為中文、英語、日語、西班牙語及阿拉伯語；未以詞表檔名中出現 `yue` 來推論已正式支援粵語。
- 英語 CMU 音素及中文拼音控制對學習場景有價值，但需在 BDC 逐詞核對，不能直接視為發音零錯誤。
- 參考音訊的品質、口音與內容會影響聲線；使用者也需要有權使用該音源。
- 授權為 **bilibili Model Use License Agreement**，不是 Apache／MIT。條款提供受條件約束的研究及商用權利；達到超過 1 億月活或上一年度超過人民幣 10 億元年收入等門檻時，須另取得明確書面授權。
