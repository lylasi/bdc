# 擴充查詞預設不生成例句的速度評估

就目前程式流程推斷，像「Board of Directors」這類短語在未命中快取時，預設不生成例句通常可以縮短首次結果的等待時間。實際幅度仍需用相同模型、語境與思考設定進行對照量測；本次沒有呼叫真實供應商做延遲測試。

已核對的行為：

- 短語提示詞的同一份 JSON 同時要求音標、意思、用法及中英例句，見 [article.js](../../modules/prompts/article.js:131)。例句沒有獨立延後載入。
- `analyzeSelection()` 使用共用 `requestAI()`，請求為非串流；extension 在查詢完成後才執行 `renderResult()`，見 [api.js](../../modules/api.js:1438)、[lookup.js](../../extension/lookup.js:691)。因此例句的生成時間會計入詞義出現之前的等待。
- 單字查詢使用的 `article.wordTooltip` 和 `dictionary.wordAnalysis` 提示詞目前沒有要求例句，見 [article.js](../../modules/prompts/article.js:51)、[dictionary.js](../../modules/prompts/dictionary.js:9)。此次預期收益主要落在短語查詢。
- extension 已優先讀取本機快取；命中快取時不需要重新生成例句，因此這種情況預期差別很小，見 [lookup.js](../../extension/lookup.js:691)。

建議預設查音標、詞義及必要用法；使用者點擊「例句」後才另外生成並快取。只將現有例句區塊摺疊或隱藏，仍會等待原本的完整 AI 回覆，無法省下例句生成時間。

若後續實作，應讓共用 AI 層明確支援是否生成例句及對應快取，維持文章詳解既有需求，並同時完成 zh-CN、zh-HK 的按需載入與錯誤文案。本次完成程式核對與建議記錄，尚未修改查詞行為。
