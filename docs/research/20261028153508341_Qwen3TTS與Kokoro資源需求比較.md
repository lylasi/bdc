# Qwen3-TTS 與 Kokoro 資源需求比較

- 核對日期：2026-10-28。
- 問題：Qwen3-TTS 需要多少資源；與 Kokoro、IndexTTS 2.5 相比，是否 Kokoro 最省資源。
- 方法：官方 README、模型卡、模型倉庫檔案 metadata、官方載入程式，以及 MLX-Audio 的社群實作文件。
- 驗證邊界：本次沒有下載權重、安裝依賴或執行推理。所有建議配置屬單人、單個合成工作的試驗預算，不是官方最低值或本機實測結果。

## 一、結論

**在 Kokoro、Qwen3-TTS、IndexTTS 2.5 這三組候選中，Kokoro 是明顯較輕量、適合先用 CPU／Docker 驗證的選擇。**

Qwen3-TTS 有 0.6B 及 1.7B 系列，資源負擔較大，但可提供中英等十種語言、固定音色、聲音克隆或聲音設計。若需要在現有 Apple Silicon Mac 上試 Qwen，優先評估原生 MLX-Audio，而不是希望 Linux Docker 使用 Apple GPU。

這個結論不能擴張為「Kokoro 是所有 TTS 中最小」。例如 Kitten TTS Nano 0.8 int8 為 15M、約 25 MB，比 Kokoro 更小；較小也不代表聲線、發音及語言能力更符合 BDC。

## 二、可核實的模型下載量

以下 Qwen 數字來自模型倉庫檔案 metadata，統計該 revision 所有已列檔案；Kokoro 數字是單一 ONNX 模型檔案，尚未計入聲線及執行引擎。因此此表用於理解量級，不是相同封裝邊界的精準比較。

| 模型／封裝 | 本次核對的下載大小 | 包含範圍 |
| --- | ---: | --- |
| Kokoro-82M 量化 ONNX | 約 92.4 MB | `model_quantized.onnx`，不含完整服務環境 |
| Kokoro-82M FP32 ONNX | 約 326 MB | `model.onnx`，不含完整服務環境 |
| Qwen3-TTS-12Hz-0.6B-CustomVoice | 約 2.50 GB 十進位 | 整個倉庫，包含語音 tokenizer；主要生成權重約 1.81 GB |
| Qwen3-TTS-12Hz-1.7B-CustomVoice | 約 4.52 GB 十進位 | 整個倉庫，包含語音 tokenizer；主要生成權重約 3.83 GB |
| IndexTTS-2.5 | 約 5.49 GB 十進位 | 先前核對的主倉庫，另需輔助模型；不是全部安裝大小 |

Qwen 的語音 tokenizer 權重約 **682 MB**。官方生成模型倉庫已包含 `speech_tokenizer/`，官方載入程式亦從該子目錄載入，因此不能再無條件將獨立 tokenizer 倉庫的同一份大小重複加上去。

本次 Qwen metadata：

- `Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice`，revision `85e237c12c027371202489a0ec509ded67b5e4b5`，合計 **2,498,388,392 bytes**。
- `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`，revision `0c0e3051f131929182e2c023b9537f8b1c68adfe`，合計 **4,520,218,951 bytes**。
- `Qwen/Qwen3-TTS-Tokenizer-12Hz`，revision `7dd38ad4e9bad454aae9cd937d0cd577604fe229`，合計 **682,300,739 bytes**；已打包在上述生成模型內的主要權重為相同量級。

官方以 0.6B／1.7B 命名系列；Hugging Face 的生成權重 metadata 分別顯示約 0.906B／1.917B 參數，且另有語音 tokenizer。系列名稱並不等於整個執行鏈的全部參數或記憶體需求。

## 三、NVIDIA 部署的資源預算

**官方 README 沒有公布 0.6B／1.7B 的確切最低或推薦 VRAM。** 網上不同整合專案的數字會受精度、推理引擎、是否串流、生成長度及併發數影響，不能當作 Qwen 官方最低值。

可先按以下保守預算作個人、單工作試驗：

| 模型 | 建議試驗配置 | 性質 |
| --- | --- | --- |
| Kokoro CPU | 2–4 vCPU、4–8 GiB 系統 RAM，不要求獨立 GPU | 沿用本專案前一輪部署預算，不是最低要求 |
| Qwen3-TTS 0.6B | NVIDIA 6–8 GB VRAM、系統 RAM 約 16 GB | 單工作規劃預算，未實測；更小 VRAM 是否可用需按精度及推理實作測試 |
| Qwen3-TTS 1.7B | NVIDIA 8–12 GB VRAM、系統 RAM 約 16–32 GB | 單工作規劃預算，未實測；長文與併發需另測峰值 |

上述 GPU 預算假設使用適當半精度等推理配置，不代表預設 FP32 或任何生成長度均適用。權重大小之外，還要容納 tokenizer／decoder、KV cache、activation、框架和工作緩衝區。

不對 Qwen3-TTS 1.7B 與 IndexTTS 2.5 作固定的峰值記憶體或速度排序：IndexTTS 官方列約 6 GB 推理要求，但與 Qwen 不同實作及功能無法直接對比。能確定的是 Kokoro 的模型量級與 CPU 部署負擔較小。

## 四、Qwen 官方軟件環境

- 官方建議新建 **Python 3.12** 環境。
- 官方 Python 範例使用 CUDA、BF16；沒有在 README 列出一個通用最低 CUDA／VRAM 組合。
- `qwen-tts` 基本依賴包括 Transformers、Accelerate、torchaudio、librosa、soundfile、sox、onnxruntime 等。
- FlashAttention 2 是額外、可選的加速／節省 GPU 記憶體措施，不是基本安裝必需依賴。需使用相容 GPU 和 FP16／BF16。
- README 出現的 **96 GB RAM** 是編譯 FlashAttention 時限制多核心編譯並行度的提示，**不是 Qwen3-TTS 的推理 RAM 或 VRAM 最低要求**。

## 五、現有 36 GiB Apple Silicon Mac

### 優先看原生 MLX 路徑

社群 **MLX-Audio** 已有 Qwen3-TTS 0.6B／1.7B 的 Base／CustomVoice，以及 1.7B VoiceDesign 支援和量化模型。這不是 Qwen 官方 PyTorch 實作，安裝、相容性和量化效果需分開驗證。

MLX-Audio 文件的基本環境為 Apple Silicon Mac、Python 3.10+、MLX；MP3 等編碼另需 ffmpeg。MLX 直接使用 Apple GPU／統一記憶體，不能透過一般 Mac 上的 Linux Docker 取得相同加速。

專案對 **1.7B CustomVoice 6-bit、短輸入、batch=1** 的公開表格列出 **3.88 GB Memory**，batch=8 為 4.10 GB；表格沒有明列測試 CPU／Mac 型號或完整記憶體量測口徑。這是特定實作的基準數字，不是整台 Mac 只需 4 GB RAM，也不能套到官方 BF16、長文或其他功能。

**判斷：這台 36 GiB Mac 具備合理的 Qwen 0.6B／量化 1.7B 試驗條件，不必先購買 NVIDIA 卡；速度、峰值及發音仍需本機實測。**

### Docker 的定位

- Kokoro：CPU Docker 適合作為第一個可部署候選。
- Qwen3-TTS：Linux＋NVIDIA Docker 是可考慮的服務路線；Mac Linux Docker 不能直接使用 Apple MPS／Metal／MLX GPU，CPU 速度不宜事先保證。
- 若希望手機使用 Mac 上的原生 MLX 服務，可在確認服務與 BDC 協議相容後，再以 Cloudflare Tunnel 提供 HTTPS；模型仍留在 Mac 運算。

## 六、對 BDC 的選型建議

1. **英語單字、例句及文章，重視低成本與部署簡單：先 Kokoro。** 保留現有微軟聲線作短文本及發音對照。
2. **需要中英等多語種及固定聲線：試 Qwen3-TTS 0.6B CustomVoice。** 不必為一般朗讀先部署所有模型。
3. **需要文字控制聲音風格或設計新聲音：再考慮 1.7B CustomVoice／VoiceDesign。** 官方功能表沒有把 1.7B 的完整 instruction control 記在 0.6B CustomVoice 上，不能假設兩者功能完全相同。
4. **需要聲音克隆：選對應 Base。** CustomVoice 提供九個預設音色，不是所有用途都需要參考聲音。

Kokoro 的小模型不代表任何輸入都更準確；官方短輸入限制仍應納入 BDC 單字與聽寫驗證。量化 Qwen 也應對比發音、聲線一致性和首段等待，不能僅因記憶體較少就換成預設。
