# 文章詳解：小標題、清單、加粗的識別與翻譯保留

- 時間：2026-10-15
- 範圍：`features/article/article.js`、`modules/prompts/article.js`、`styles.css`
- 觸發：導入的新聞（例：RT、The Conversation）在「文章詳解」裡，`## 小標題` 顯示成字面文字、`**加粗**` 翻譯後消失，整篇看起來很亂

## 一、先量化，再動手

### 1. 抽取層沒問題（11 個來源 × 2 篇實測）

拿線上 worker 逐源抓真實文章，對比 `contentHtml`（Readability 的結果）與 `markdown`（我們的渲染器）：

| 檢查 | 結果 |
| --- | --- |
| contentHtml → markdown 的結構損失 | 幾乎為 0（只有零星 `strong`/`em`，1 個 `ul`） |
| RT 那篇 | 正文 `<div class="article__text">` 裡**本來就只有** 11 個 `<p>`、7 個 `<em>`、1 個空 `<strong>`，沒有 h2/ul；先前看到的 h2/ul 全在側欄與推薦區 → Readability 忠實保留了正文 |

結論：**不是抽取或渲染丟的**，`##`、`**` 都好好地在 markdown 裡。

### 2. 真正的位置：文章詳解只做「行內」渲染

`features/article/article.js` 的分析流程是：

1. `parseTitleAndParagraphs()` 只把第一個 `#` 行當標題，其餘 `## / ###` 行按空行切成**普通段落**；
2. 每段用 `inlineMarkdownToHtml()` 渲染 —— 這個函式**只認行內語法**，沒有 `#` 規則，於是 `## What the bill changes` 原樣顯示；
3. 送 AI 前呼叫 `stripInlineMarkdown()`，它把 `**粗體**`、`~~刪除線~~`、連結全部剝掉 → **譯文自然沒有加粗**（提示詞卻寫著「保留 Markdown 標記」，等於沒東西可保留）；
4. 中文側用 `esc(z)` 純文字渲染，就算模型回了 `**粗體**` 也只會顯示成星號。

## 二、修復

| 位置 | 改動 |
| --- | --- |
| 新增 `splitMarkdownHeading()` | 認出 `## ～ ######`，回傳層級與去掉標記的文字 |
| 新增 `isMarkdownListBlock()` / `normalizeListMarkersForDisplay()` | 整段都是 `- x` / `1. x` 時標記為清單，顯示時把 `- ` 換成 `• `（有序清單保留編號） |
| 新增 `prepareParagraphForTranslation()` | 取代 `stripInlineMarkdown()`：圖片只留 alt、連結只留文字，**保留粗體／斜體標記** |
| 兩條渲染路徑（即時分析 + 還原快取結果） | 標題段落去掉 `##` 後顯示，加上 `is-heading` / `data-heading-level`；清單段落加 `is-list` |
| 中文側渲染 | `esc(z)` → `inlineMarkdownToHtml(...)`，`**粗體**` 才會變成 `<strong>` |
| `styles.css` | `.paragraph-pair.is-heading`（左側色條＋字級，h3 以下縮小）、`.paragraph-pair.is-list`（縮排） |
| `paragraphTranslationPrompt` | 版本 1.0.0 → 1.1.0，明確要求 `**bold**`／`*italic*`／`` `code` `` 原樣保留（含按句翻譯變體） |

## 三、驗證

1. **Node 單元驗證**（把函式抽出來跑）：`## x`→h2、`### x`→h3、`###### x`→h6、`####### x` 與句中 `##` 不誤判；`**Bold** text` 送翻後仍是 `**Bold** text`，連結／圖片仍被簡化；`inlineMarkdownToHtml('**重要** 内容')` → `<strong>重要</strong> 内容`。
2. **瀏覽器端到端**（本機 `scripts/serve.py` + 樁替換 `fetch`，繞過不通的 AI 端點）：7 段文章 → 3 個標題（h2/h3/h2，`##` 已剝除）、1 個清單（`• Families with a family trust`，無殘留 `- `）、英文側 3 處 `<strong>`、**中文側 14 處 `<strong>`**，截圖確認標題樣式正確。
3. **UI 回歸**：`tests/ui-regression.cjs` 91/92；唯一失敗是既有的 5 條「內部錯誤訊息寫死中文」（`qa-pdf.js`、`word-sheet.js`），與本次改動無關（我新增的那條已改成 `//` 註解而不再觸發）。

## 五、遺留

1. **preview.py 那份（LAN 預覽 8318）沒動**：它走 `EXTRACT_URL: '/extract?url='`（Python 抽取，RT 沒有 `<article>`/`<main>` → 取整個 `<body>` 交給 AI 轉 Markdown → 導航湯）。要讓它跟線上一致，最省事是把該份 `ai-config.js` 的 `EXTRACT_URL`／`PROXY_URL` 指向 CF worker，而不是改 preview.py。
2. 清單目前只是「符號替換＋縮排」，沒有真正的 `<ul>/<ol>` 結構；表格與圖片段落已有專門渲染，若之後要更完整可再補。
3. `qa-pdf.js` / `word-sheet.js` 的內部錯誤訊息仍是寫死中文（UI 回歸的老問題），不影響顯示但會被檢查點名。
