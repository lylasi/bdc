## 二、關鍵發現：倉庫 HEAD 比線上落後

先前幾次部署是走 Dashboard／Script API，倉庫這份沒跟上。以線上 bundle 逐模組比對後，**只有一個檔案有實質差異**：

| 檔案 | 倉庫 HEAD | 線上實際在跑 |
| --- | --- | --- |
| `src/lib/markdown.js` | turndown 版（46 行） | linkedom 手寫版（237 行） |
| 其他模組 | 一致（`http.js` 倉庫還多一個未使用的 `textResponse`） | — |

後果：用倉庫程式碼 `wrangler deploy` 之後，**線上每個 `/extract`、`/feeds/:id/article` 都回 500**：

```
ReferenceError: document is not defined
    at Parser3.parseFromString → new RootNode → TurndownService.turndown → htmlToMarkdown
```

turndown 在 Worker 裡會走 Node 分支去要 `document`。這是為什麼先前所有修正我都只能打在 bundle 上——源碼根本跑不起來。

排查過程中值得一提的坑：這個例外被 `handleExtract` 的 `try/catch` 接住轉成 500，所以 **`wrangler tail` 顯示 `outcome: ok`、`exceptions: []`**，完全看不出原因；最後是在 catch 裡補 `logger.error` 才看到堆疊。這行日誌已保留。

## 五、Docker / 本地部署方案

專案本來就有 `Dockerfile` 與 Node 入口（`@hono/node-server`），本次補強：

- `Dockerfile`：`npm ci --omit=dev`、只複製 `src`、加 `HEALTHCHECK`、基礎映像參數化
  `docker build --build-arg NODE_IMAGE=node:22-alpine ...`（Docker Hub 拉不動或本地已有映像時很方便）。
- 新增 `docker-compose.yml`：**宿主 8788 → 容器 8787**（8787 已被你的 2FA 看碼器佔用），`REFRESH_ON_BOOT=true` 啟動先抓一輪 feed。
- 新增 `.dockerignore`。
- Node 版沒有 KV：`FEEDS_CACHE` 不存在時 feed 快取退回行程內記憶體，重啟即失效。
- 對外抓取走伺服器自身 IP，站點封鎖行為可能與 Cloudflare 出口不同，仍要按實際部署環境驗收。

```bash
cd /Users/linus/CODE/article-import-service
docker compose up -d --build        # http://localhost:8788
```

前端接法（`bdc` 的 `ai-config.js`）把 `PROXY_URL`／`EXTRACT_URL`／`FEED_URL` 指向自架位址即可，詳見該專案 `docs/deployment.md`。
