## 12 個核心檢查點
1. **分析並行與保序**：modules/extension-ai-runtime.js:610 起預分配結果，按原索引回填；最多兩個 runner。相同正文合併工作後仍填回每個位置，不依回應先後拼接。
2. **內容失敗隔離**：同檔:635 起記錄失敗索引並繼續其他內容工作；最終有失敗即拋錯，沒有將稀疏結果當完整分析交給保存。
3. **致命錯誤取消兄弟工作**：同檔:651 起捕捉失敗、abort 共用 controller，並等待 allSettled 收尾；不會提早返回而留下未收尾 runner。
4. **上下文快照**：同檔:574–604 使用 scope、session、locale、公開 profile 與 catalog 內容比對；去掉 generation 後，同版同內容 refresh 不因計數器改變而中止。入口、段落回來及返回前均有門禁。
5. **快取隔離**：modules/api.js:1098–1134 捕捉 scope，擴充路徑帶 scope 與 context；快取回讀後再次檢查。成功寫入使用固定舊 scope/context 的鍵，即使寫入期間切帳戶，也不會寫到新帳戶的擴充快取鍵。
6. **成功快取／失敗不快取**：modules/api.js:1163–1189、1207–1229 驗證非空及 schema 後才寫快取；fallback 成功也寫入。失敗重試可復用已成功段落。
7. **連續 length**：modules/api.js:1164、1208 在結構化與 fallback 回應均檢查 finish reason；截斷不能經過成功快取及完整文章保存。最後錯誤碼可能保留前一候選錯誤，屬診斷精度問題，不是截斷內容被保存。
8. **queue 取消**：modules/api.js:142–181 待排隊項目可移除；已領槽的間隔等待可 abort，finally 釋放 active 並推進下一項。未發現取消造成永久佔槽的新路徑。
9. **退避取消**：modules/api.js:109–125、811 使用可取消等待，requestAI 在解析設定後及讀取回應後再檢查 signal。取消不必等完整 backoff。
10. **清洗 partial 完整性**：modules/api.js:2098–2135 以索引保存各塊；空、截斷或一般內容失敗使用完整原塊；fatal／abort 不作成功返回。2194–2210 將 cleanupIncomplete 帶給預覽；extension/workspace-ui.js:209–212 顯示 partial 提示。此檢查不等於能識別模型以正常 stop 靜默刪文，後者不是此次並行引入的可確認回歸。
11. **確認與凍結重試**：extension/workspace-ui.js:215–240 分析完成後才 enqueue；currentJob 存在時不重跑分析或替換其 payload，saving 隱藏停止按鈕。modules/extension-workspace.js:31–51 預設只 GET，顯式 link 才 POST。shared/workspace-client.mjs 的前置 GET 按要求保留，不建議改以穩定 ID 取代舊 ID 相容與確認期間查重。
