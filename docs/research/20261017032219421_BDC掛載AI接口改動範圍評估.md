# BDC 掛載 AI 接口改動範圍評估

結論：第一版屬中等規模改動，主要工作在服務端。前端已有多供應商、模型列表及任務分配，可沿用，不需要逐一重寫功能模組。具體檔案數與工時須在選定後端運行方式及認證策略後確認。

## 已有可用基礎

scripts/serve.py 已有靜態服務和 /v1 同源代理，但目前是單一上游，轉送瀏覽器 Authorization，且以 response.read() 讀完再回傳。因此它不等於服務端保管憑證的方案 C，也未提供即時串流轉送。可參考既有路由，不應直接把 --ai-proxy 當成可公開部署的完整實作。

modules/ai-models.js 已接受相對 API 路徑並提供模型列表讀取。modules/api.js 集中大部分推理請求。features/assistant/assistant.js 另有直接 fetch 的串流路徑，必須一起調整。

## 第一版建議範圍

服務端提供固定供應商的 GET models 與 POST chat/completions，支援普通 JSON、圖片請求與 SSE 串流。路徑可用 /api/ai/hapi/v1 與 /api/ai/magpie/v1，對應前端既有供應商，避免一開始增加聚合模型命名和複雜路由。

供應商網址及金鑰由管理者在靜態目錄之外的私有設定檔維護。後端只按已設定的供應商 ID 選取上游，注入金鑰，限制模型、請求大小、逾時及併發，不接受任意上游網址。

加入本地驗證與基本存取限制。既有登入依賴 Cloudflare D1，不能直接宣稱本地後端已有可獨立運作的登入能力；若目標是雲端同步故障不影響 AI，這部分是主要新增工作之一。使用同源 cookie 時需一併處理 session 屬性與 CSRF，會話亦須支援撤銷。

前端主要調整 modules/api.js、modules/ai-models.js、features/assistant/assistant.js，並在 features/sync/sync.js 的現有設定介面區分服務端管理與個人直連來源。服務端管理來源不再要求填供應商 Key。必要的設定欄位及雙語提示同步更新 modules/settings.js、ai-config.example.js、locales/zh-CN.js、locales/zh-HK.js。

部署將現有靜態服務替換為能同時提供網頁與 API 的單一服務，沿用 HTTPS 入口，配置私有設定掛載、重啟與備份。正式運行方式須在實作前確定，不能將開發用 Python 代理直接當作完成。

## 規模邊界

僅做能轉送一次請求的原型改動小；可公開使用且支援驗證、金鑰隔離、串流、圖片及錯誤處理的第一版屬中等改動。若再加入網頁管理金鑰、多使用者精細配額、自動後備和審計，範圍將明顯增加，建議後續分批。

第一版保留既有模型選擇與任務映射，用私有設定檔管理供應商、手動切換故障來源。驗收需包括模型列表、文字推理、OCR、助手即時串流、登入失效、未授權請求、上游故障、秘密不出現在靜態檔案或回覆，以及 zh-CN 和 zh-HK。

本次為源碼層面的工作量評估，未修改功能或部署服務。
