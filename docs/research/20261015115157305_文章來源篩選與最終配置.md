## 一、NYT 改走 RSS 有用嗎？沒有

1. **NYT 的 RSS 只有摘要**（`<description>` 一兩句），worker 的正文一律走 `/extract` 抓文章頁，沒有任何「用 RSS 內文當正文」的模式。走 RSS 只會得到一兩句話的「文章」。
2. **文章頁是 NYT 端在擋**：worker 回 `Upstream responded with status 403`；我用**同一個 Chrome UA 從本機另一條網路直連 `www.nytimes.com` 也是 403**。所以不是 worker 的 header/UA 問題，換 feed 也救不了。
3. 結論：**已從來源清單移除 NYT**（連同 `*.nytimes.com` 一起從 `ALLOW_HOSTS` 拿掉，不留開放代理的餘地）。想留美國視角就用 NPR／The Conversation。

## 二、怎麼篩的

1. 用**線上同一份 worker bundle 在本機跑**（`/feeds` + `/extract`），先淘汰 feed 解析不了、或抓不到正文的。
2. 再把候選主機加進 `ALLOW_HOSTS`，**從 Cloudflare 出口 IP 實測一次**（本機 IP 過得了、CF 出口不一定過得了）。
3. 最後看三個指標：正文 Markdown 字數、圖片數、**連結數（導覽噪音指標）**。

## 四、v11 的最終變數

```
ALLOW_HOSTS = www.rt.com,rt-english.com,*.rt.com,*.bbc.com,*.bbc.co.uk,feeds.bbci.co.uk,
              edition.cnn.com,www.cnn.com,*.cnn.com,www.timeforkids.com,www.snexplores.org,
              www.sciencedaily.com,theconversation.com,www.theguardian.com,www.npr.org,
              text.npr.org,www.abc.net.au
FEED_CACHE_TTL = 300
MAX_BYTES = 8000000
SOURCES_JSON = { bbc, timeforkids, snexplores, sciencedaily, conversation, guardian, npr, abcau, cnn, rt }
FEEDS_CACHE = <KV namespace 2da90f96c5624b1aa980f505ea313800>
```

每個源的欄位：`{ label, type:'rss'|'json', rss|url|json, description, allowHosts[], maxItems }`。

**注意兩個坑**：

1. `SOURCES_JSON` 一旦非空就**完全取代**內建 `DEFAULT_SOURCES`（`parseSources()`），所以它必須包含**所有**要保留的來源。
2. 各源的 `allowHosts` 是**額外限制**、不是放行（`handleFeedArticle` 用它擋，然後 `handleExtract` 再過一次全域 `ALLOW_HOSTS`）。新來源的**文章主機一定要進 `ALLOW_HOSTS`**，否則導入會回 `Host ... is not allowed`。feed 主機不用（抓 feed 時會自動臨時加白）。

## 六、遺留

1. 伺服器 `bdc.eigui.cn:5000` 上的 `ai-config.js` 仍是舊的後備 `SOURCES`（guardian/techcrunch/cna/rt）。因為來源是動態讀 `/feeds`，不影響正常使用；但 `/feeds` 掛掉時會掉進這份舊清單，建議一併更新。
2. `MAX_BYTES=8MB` 是為了 CNN 這種 6MB 頁面；Worker 記憶體上限 128MB，實測 CNN 解析峰值 +77MB，還在安全範圍，但同時多個大頁面請求時要留意。
3. 速率限制是寫死的 40 次/分鐘/IP（`src/utils/rate-limit.js`），超過回 429。多裝置同時導入大頁面時可能撞到。
4. 若要把 BNE／VOA 這類站點接好，需要**按站點的抽取規則**（或改成走 AI 清洗），不是通用 readability 能解決的。
