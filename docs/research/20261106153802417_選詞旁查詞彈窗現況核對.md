## 2. 定位與尺寸（現況）

### 2.1 宿主外殼

- 建立 `<bdc-page-lookup>` 自訂元素，內聯樣式 `all:initial;position:fixed;inset:0;z-index:2147483647;pointer-events:none`，掛在 `document.documentElement`（`extension/page-lookup.js:12-14,34`）。
- 使用 **closed shadow root**，頁面世界無法讀取內容（同檔 `:14`；測試斷言 `tests/extension-inline-security-deepseek.cjs:318`）。
- 外殼本身不攔截指標（`pointer-events:none`），只有按鈕與 iframe 個別設 `pointer-events:auto`（`extension/page-lookup.js:16`）。

### 2.2 查詞按鈕

- 樣式：`font:13px system-ui;padding:7px 12px;background:#2563eb;…;position:fixed`（`extension/page-lookup.js:16`）。
- 位置計算：`left = max(8, min(innerWidth - 100, rect.left))`、`top = max(8, min(innerHeight - 48, rect.bottom + 5))`（同檔 `:44-45`）。
  - 以選取範圍矩形 `getRangeAt(0).getBoundingClientRect()` 的**左緣**對齊、**下緣**再留 5px。
  - 內含硬編碼的寬 100px、高 48px 假設；只做「夾在視窗內」，**沒有**向上翻轉、左右避讓或碰撞偵測。
- 按鈕文字由 background 提供的字典決定（`BDC_INLINE_LABELS`，只回三個鍵：`inlineLookup`／`inlineClose`／`inlineTitle`）（`extension/background.js:15-20`；`extension/page-lookup.js:8-9,43`）。

### 2.3 結果面板 iframe（目前形態：右側全高）

- `iframe{border:1px solid #cbd5e1;border-radius:12px;…;position:fixed;right:12px;top:12px;width:min(420px,calc(100vw - 24px));height:calc(100vh - 24px);pointer-events:auto}`（`extension/page-lookup.js:16`）。
- **與選詞位置完全無關**：固定貼右邊、滿高，選詞在左或在右都一樣。
- iframe 文件樣式：`body{min-width:400px;max-width:760px;padding:14px}`；內嵌模式 `.ext-inline{min-width:0;width:100%;max-width:none;padding:10px}`（`extension/lookup.css:4-15`）。
- 沒有監聽 `resize`／`visualViewport`／`scroll` 去重算位置或尺寸。

## 3. 選詞觸發

- 監聽 `document` 的 `mouseup`（bubble 階段）。以下情況直接略過：`!event.isTrusted`、`event.composedPath().includes(host)`（點在自己面板上）、`event.target.closest('input,textarea,[contenteditable="true"]')`（`extension/page-lookup.js:37`）。
- 取 `getSelection().toString().trim()`；**空字串、超過 400 字、沒有 range** 都只是隱藏按鈕（同檔 `:39-41`）。
- 沒有監聽 `selectionchange`、`keyup`、`touchend`：
  - 鍵盤選取（Shift＋方向鍵／Ctrl+A）不會出現按鈕；
  - 觸控選取行為未處理；
  - 頁面在 `mouseup` 做 `stopPropagation` 時按鈕不會出現；
  - 子 iframe 內的選取不屬於頂層 document 的 selection，不會觸發。
- 按鈕上有 `mousedown` → `preventDefault()`，避免點按鈕時清掉頁面選取（同檔 `:20`）。
- 面板開啟後仍在同一監聽器上：**再選新詞會再現按鈕**，點下去會 `panel?.remove()` 後重建（單一實例，不疊加）。

## 4. 開啟與一次性票據（ticket）流程

1. 按鈕 click（要求 `event.isTrusted`）→ 先 `button.hidden = true` → 送 `BDC_OPEN_INLINE`（`extension/page-lookup.js:21-24`）。
2. 取不到結果或 `result.ok !== true` 就 `return`（`:25`）——**目前沒有錯誤提示**，表現為「按了沒反應」。
3. background 收到 `BDC_OPEN_INLINE`（`extension/background.js:21-30`）：
   - 要求 `sender.id === chrome.runtime.id`、`sender.tab?.id`、`sender.url` 為 `http(s)`、`sender.frameId === 0`；
   - 以 `chrome.scripting.executeScript(extractActivePageSelectionInTab)` **重新抽取當下頁面選取**（isolated world），空或 >400 字丟 `empty_selection`；
   - 清除同 tab 舊票據；簽發 `crypto.randomUUID()`，TTL 1 小時。
4. iframe 以 `lookup.html?embedded=1&ticket=…` 載入（`extension/page-lookup.js:27-31`）。
5. iframe 內 `BDC_INLINE_CONTEXT`（`extension/background.js:31-36`）：sender 必須是 `extensionOrigin + '/lookup.html'` 前綴、tab 相同、未過期、**未被 claim**；claim 時記錄 `sender.documentId`，因此同 tab 重播、跨 tab 重播都會被拒。
6. 後續 `BDC_READ_PAGE`（`:37-52`）帶 ticket 時比對 `record.claimed === sender.documentId`；不帶 ticket（popup／options 頁）才退回「當前 active 的 http(s) tab」。
7. tab 關閉或 URL 變更即清票據（`:67-70`）。

**重要事實**：`page-lookup.js` 內的 `selection` 變數只用於長度判斷，**不會**隨訊息送出；真正查的字是背景在開啟瞬間重新抽取的。因此「選詞後立刻自動開卡」在資料面上不需要另造通道。

## 5. 關閉路徑（現況）

| 觸發 | 位置 |
| --- | --- |
| 頁面 `keydown` Escape | `extension/page-lookup.js:49` |
| iframe 內 Escape → `parent.postMessage({type:'BDC_CLOSE_INLINE', ticket})` | `extension/lookup.js:532-534` |
| iframe 工具列「關閉」按鈕 → 同一 postMessage | `extension/lookup.js:531` |
| 父頁驗 `event.source === panel.contentWindow` 且 `event.data.ticket === ticket` 後關閉 | `extension/page-lookup.js:50-52` |
| `popstate`／`hashchange` | `extension/page-lookup.js:53-54` |
| 點新選詞的按鈕（舊面板被移除重建） | `extension/page-lookup.js:27` |

**沒有**：點頁面空白處關閉、捲動時關閉、iframe 載入失敗提示、縮放／resize 重算。

## 6. iframe 內訊息與帳戶邊界

- 頁面世界與 content script 讀不到 `chrome.storage`：background 啟動即 `setAccessLevel({accessLevel:'TRUSTED_CONTEXTS'})`（`extension/background.js:6`）；測試斷言 denied（`tests/extension-inline-security-deepseek.cjs:324-339`）。
- 帳戶登入、AI Key、詞書寫入、文章寫入全部發生在 extension-origin iframe 內；頁面只看到 closed shadow root，也列不出 iframe URL（同測試 `:318-321`）。
- `web_accessible_resources` 只放行 `http/https` 頁面嵌入（`extension/manifest.json:40-58`）。
- `lookup.html` 只用 `<script type="module" src="./lookup.js">`，不載外部腳本（`extension/lookup.html:216`）。
- **邊界結論（事實）**：只要新卡片仍是 extension-origin iframe，ticket／claim／storage 這整套邊界完全不變；若改成 content script 直接在頁面世界畫 UI，就等於把帳戶與 AI 憑證帶進頁面世界，與現有邊界相反。

## 7. 內嵌模式顯示什麼（決定卡片高度的來源）

`lookup.js` 開頭：`isEmbedded = window.parent !== window`，必須成功取得 `BDC_INLINE_CONTEXT`，否則整頁替換成 `extension.inlineUnavailable` 文字並中止（`extension/lookup.js:24-38`）。

內嵌時以 CSS 收掉：頁首（含語言選擇、開獨立分頁）與「帳戶」整張卡（`extension/lookup.css:16`）、查詞欄位與「從本頁取詞」（`:17`）；工具列改為「編輯選詞／帳戶設定／關閉」（`extension/lookup.html:10-15`）。

內嵌時**仍然顯示**（也就是卡片內的高度需求）：

1. 查詞結果卡：詞、音標、詞性、意思、角色、例句清單、provider／model／task 標註（`lookup.html:136-151`；`lookup.js:190-236`）。
2. 收藏卡：詞書下拉、來源網址、加入按鈕、重新整理、本頁詞書／新增詞書／建立預設／設為預設、**新增詞書表單**（名稱＋兩個 checkbox）、**待傳清單**（每筆「重試／取消」）（`lookup.html:153-186`；`capture-ui.js:54-107`）。
3. 文章卡：AI 擷取、**預覽**（標題 input＋正文 `textarea rows="8"`＋逐段分析 checkbox＋保存）、在 BDC 開啟、待傳清單（`lookup.html:188-214`；`workspace-ui.js:132-177`）。

登入狀態下載入即自動查一次（`lookup.js:567-579`）；未登入則顯示 `extension.inlineLoginRequired`，只能按「帳戶設定」跳 options 頁（`lookup.js:529`）。

查詞本身不因內嵌而走別條路：`runExtensionLookup` → `modules/api.js:2258 lookupSelection`（含 AI 快取、任務鏈、短語判定 `/\s/`）。

## 9. 改成「選詞附近、自動避讓的小卡片」的可行性核對

**可以保留、不需改動的（事實層面）**

- 一次性 ticket、`documentId` claim、同 tab／跨 tab 重播拒絕（`background.js:21-36`）。
- `BDC_READ_PAGE` 與文章擷取；`page-extractor.js:6` 已把 `bdc-page-lookup` 從正文中剔除，卡片不會污染文章擷取。
- `runExtensionLookup`／`lookupSelection`／AI 快取／短語判定。
- `capture-ui.js` 收藏與待傳、`workspace-ui.js` 建書與文章流程、`extension/modules/*`、`shared/*`。
- `ext-inline` 佈局規則本身與 i18n 鍵（`extension.inline*` 共 9 鍵，兩語齊備）。
- popup／options 的 `lookup.html` 行為（同樣的 HTML，改動只需限縮在 `.ext-inline` 相關規則與外殼定位）。

**需要改的**

- `page-lookup.js`：iframe 的 `right/top/width/height`、按鈕與卡片的相對關係、重新定位時機（scroll／resize）、關閉時機。
- `lookup.css`：內嵌模式的尺寸假設（`body{min-width:400px}` 已被 `.ext-inline{min-width:0}` 覆蓋，但 `textarea rows=8`、表單、待傳清單仍是大塊內容）。

**技術約束（跨來源 iframe 無法自動撐高）**

iframe 與頁面不同源，內容高度無法由父頁量測。只有兩條路：固定尺寸，或由 iframe 自行量 `scrollHeight` 後 `postMessage` 給外殼（外殼需驗 `event.source === panel.contentWindow` 與 ticket——與現有 `BDC_CLOSE_INLINE` 通道同構）。

## 10. 需留意的約束清單

1. **捲動**：現在面板固定在視窗，頁面怎麼捲都不動；貼選詞的卡片若捲動就跟丟。要嘛監聽 scroll 重算（選取矩形可用，但是視窗座標），要嘛捲動即關閉。
2. **多行短語**：`getRangeAt(0).getBoundingClientRect()` 回的是整個範圍的聯集框，錨點（左下、最後一行末端、滑鼠放開點）必須先選定；含空白即判為短語、走 `articlePhraseTranslation`，回覆較長，高度需求更大。
3. **視窗邊緣**：現有夾限只保護按鈕且用硬編 100／48px；卡片需要「下方不足翻到上方、左右夾限、超長時限制高度＋內部捲動」。
4. **卡片內展開**：新增詞書表單、文章預覽（textarea rows=8＋逐段分析＋保存）、待傳清單都不是小高度；固定小卡片會擠壓內容，需明確的「展開成大面板／卡片內捲動」策略。
5. **狀態與進度**：查詞是一次往返（無串流），但文章擷取／逐段分析有 `onProgress(current,total)` 與取消（`workspace-ui.js:149-150,167-168`）；小卡的文字空間有限。
6. **未登入**：若改成自動開卡，會頻密出現「請先點擊帳戶設置登入」；目前唯一的補救路徑是跳 options 頁。
7. **事件通道**：只靠 `document` 的 `mouseup`；頁面 `stopPropagation`、鍵盤選取、觸控、子 iframe 內選取都不會觸發。卡片內若有輸入框，焦點進 iframe 會讓頁面選取消失（現流程因開卡時已抽取文字而不受影響）。
8. **佈局環境**：頁面根元素有 `transform`／`filter` 時 `position:fixed` 的參考框會改變；全螢幕元素會蓋住固定定位元素；`visualViewport`／縮放未監聽。
9. **文件與驗收**：`docs/spec/20261106141147557_網頁查詞與詞書文章聯動操作說明.md` 第 2 節仍寫「再點旁邊的查詞按鈕」，形態改了要同步；E2E 的座標點擊假設同上。
10. **本報告不涵蓋**：未執行任何瀏覽器驗證，未讀正式 Worker 或私有 `ai-config.js` 內容；`extension/modules/*`、`extension/shared/*` 為打包生成檔，與根目錄同名檔同源（`scripts/package-extension.mjs`）。

## 11. 待使用者決定的問題（不在本報告內作答）

- 選詞後是自動彈卡，或保留「先點一下查詞」。
- 卡片錨點基準與避讓方向。
- 卡片預設顯示哪些內容、尺寸策略，以及建書／文章預覽如何展開。
- 捲動、縮放、視窗大小變化時卡片如何處理。
- 關閉規則（外部點擊、Esc、新選詞、路由變化）。
- 未登入與錯誤狀態在卡片內如何呈現。
