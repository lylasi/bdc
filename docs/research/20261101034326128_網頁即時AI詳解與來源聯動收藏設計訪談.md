## 1. 使用者這次提出的目標

1. 閱讀其他網站時，對不懂的單詞或句子呼叫類似 BDC 文章詳解的翻譯／解析。
2. 能以選取內容為起點直接問 AI，並繼續追問。
3. 以網址把同一篇來源的查詞、收藏詞及文章聯繫起來。
4. 加入單詞本時，同時保存文章；可以先是先前建議的待讀網址收藏。
5. 對中英混雜或噪音較多的網頁，可回到 BDC 由 AI 整理、過濾。
6. 希望判斷整體是否合理，以及如何控制複雜度。

這會調整上一輪「僅明確收藏文章才進待讀清單」的建議：已接受的新方向是「明確加入單詞本時，一併建立／沿用該 URL 的待讀記錄」。一般查詢先作當次會話及快取，明確收藏後才成為永久學習資料。

## 2. 初步判斷

整體可行，定位是「閱讀中查懂內容，將值得保留的內容帶回 BDC 學習」。即時解釋、來源歸組及後續整理可以分別完成，不必等整篇文章抽取及清理完成才回答一個詞。

若第一版採「選取內容與附近語境 → 解釋／追問 → 點收藏時聯動網址 → 稍後在 BDC 整理」，屬中等規模功能擴充。它包含擴充套件界面、AI 接入、來源身份及持久化，不能只當成增加幾個按鈕。

若同時要求任意網頁全文快照、每次查詢永久保存、整頁 AI 清理、所有歷史會話跨裝置同步、正文改版後精確定位，工作量會明顯增加。是否需要這些保證，應由使用者體驗目標逐步決定。

已核對兩項容易誤解的邊界：

- 現有清理提示詞要求保留原始語言及用字，並不會自動刪除中文或改寫為英文學習稿；「去噪」與「僅提取英文」要分成不同任務。
- 目前文章助手通常把傳入的文章文字放進每輪上下文，並帶最近八則訊息。外部網頁不宜直接照搬整頁文字；每輪需要明確的上下文範圍及容量策略。

以上是可重用的業務規則，現有 UI、設定及儲存仍依賴網站環境。擴充套件如何沿用 BDC 模型配置與憑證，需要在使用者體驗選擇後確定，不可假設把網站模組整份匯入即可執行。

## 4. 候選的概念模型

以下為模型草案；第一輪的保存觸發及初版只保留 URL／原句等原則已確認，資料欄位與下游流程仍待澄清：

- **網頁來源：** 以帳戶及經保守處理的 URL 歸組，使用穩定的來源 ID。相同 URL 可以有多個抓取版本；網址不是正文版本。
- **查詢／會話：** 當次使用選取內容、問題、語境及回答；明確收藏後的保存範圍在後續會話設計確認。
- **收藏詞條：** 保存到使用者選定詞書，來源保留原句、quote、URL 及可選來源 ID。
- **待讀收藏：** 明確收藏單詞時一併建立或沿用；初版先保存網址、標題及原句，正文按需要導入。
- **正式文章：** 有正文之後沿用 BDC 文章儲存及同步，與來源關聯。
- **整理稿：** 由原始摘錄／正文生成的獨立結果，保存處理模式及來源版本。單詞仍可追溯原句。

「以網址為同一篇」適合作為來源歸組原則。對登入狀態、動態頁面、hash 路由及來源更新，仍須保留實際 URL 與正文版本，避免把不同文字內容視為完全同一份原文。

混合語言頁面整理之後可能刪段、改段落或重排。原始摘錄與整理稿分開保存，單詞位置以原句／quote 重新確認；不能沿用原 DOM 的 offset 當作整理稿位置。

## 6. 第一輪問題與建議（已確認 1A／2B／3A／4B／5A）

### Q1：解釋與追問是否要留在原網頁？

- A：原網頁內的擴充套件面板即可看解釋、問 AI。
- B：選取後跳到 BDC 才解釋與追問。

建議 A：它最貼近閱讀時查懂的目標。面板形態及瀏覽器選擇可下一輪細定。

### Q2：查過的內容是否全部永久保存？

- A：每次解釋／追問都永久記錄，來源也自動進待讀。
- B：查詢先作當次會話；按「加入詞書／收藏」才永久保存，收藏詞時聯動待讀來源。

建議 B：以明確收藏決定學習資料，來源關聯仍完整。查詢快取不等於永久學習記錄。

### Q3：加單詞時，「文章已保存」最低要保證甚麼？

- A：網址、標題及當次原句已保存；正文回 BDC 再取得。
- B：收藏當下的可讀正文也要保存；希望日後來源改版仍可回看。

建議第一版 A。這保留來源關聯，正文擷取失敗亦不影響加入詞書；B 可作後續增強，但其對來源回溯的價值需由使用者判斷。

### Q4：對中英混合網頁，主要想要哪種整理？

- A：保留中英文正文，清掉廣告、導覽及雜訊。
- B：提取頁面內已有的英文正文／例句，形成英文學習稿。

依目前學英語目標，建議 B；保留取得的原始文本作對照。中文自動翻成英文屬另一種改寫任務，不隱含在「過濾」內。

### Q5：首次解釋預設讀多大語境？

- A：選取文字＋附近句子／段落；需要時明確加入更大範圍。
- B：每次都把整頁可讀內容一起交給 AI。

建議 A：較快，也容易知道回答依據。分析整篇或詢問跨段問題時再擴大。
