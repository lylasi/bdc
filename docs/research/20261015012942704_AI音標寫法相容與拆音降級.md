# AI 音標寫法相容與拆音降級（/ˈʃɛltə/ 無獨立示範）

- 時間：2026-10-15
- 範圍：`phonetic-chart/word-split.js`、`features/phonetics/*`、`modules/phonetics-data.js`、`modules/prompts/dictionary.js`
- 觸發情境：單詞本點「拆音」，AI 回傳 `shelter = /ˈʃeltə/` 的讀法時，音素格出現 `/ɛ/ 暂无独立示范，可听完整单词。`，且「逐音跟读」整段中斷。

## 一、現象與影響

1. 音素格其中一個音點下去只顯示「暫無獨立示範」，無法試聽。
2. 「逐音跟讀」只要遇到一個沒有示範音的音，就整段放棄，其餘有示範的音也不唸。
3. 使用者會以為「音標庫缺錄音」，實際上是**符號寫法不同**。

## 二、根因

音標表（`phonetic-chart/data.js`）的每張卡片已經宣告「其他常見寫法」`aliases`，例如 `/ɛ/` 是 `/e/` 的另一種寫法、`/i/` 之於 `/iː/`、`/ɚ/` 之於 `/ər/`、`/ɝ/` 之於 `/ɜːr/`；音標表頁面的「其他常見寫法」折疊框就是讀這份資料。

但 `phonetic-chart/word-split.js` 的 `inventory()` 只索引 `variant.symbol`，**完全沒有索引 `aliases`**；`tokenize()` 找不到就退化成「取單個字元」，產生一個沒有卡片、沒有示範音的 token。彈窗與獨立頁看到 `token.variant?.audio` 為空，就顯示「暫無獨立示範」，逐音跟讀則直接中斷。

另外，`modules/prompts/dictionary.js` 的提示詞只要求 “dictionary-style broad IPA”，沒有任何寫法約定，所以模型用美式字典的 `/ɛ/` 是必然結果，不是偶發。

### 驗證（修復前）

以倉庫內的拆音引擎直接跑：

| 輸入 | 拆音結果 |
| --- | --- |
| `ˈʃeltə` | ʃ e l t ə，全部有示範音 |
| `ˈʃɛltə` | ʃ **ɛ（無卡片）** l t ə |
| `ˈʃɛltɚ`、`ˈʃeltər` | ɚ／ɹ 同樣無卡片 |
| `ˈveri`（本地詞庫 very 的音標） | 尾音 `i` 也是無卡片 |

補充事實：音標表**沒有任何一張卡缺錄音**（英、美兩版都有 audio）。也就是說所有「暫無獨立示範」都是寫法不匹配造成的假故障。

## 三、修復內容

### 1. 拆音器接受等價寫法（`phonetic-chart/word-split.js`）

- `inventory()` 改為同時索引卡片上的 `aliases` 與 `sourceSymbol`，且**同一張卡片的英、美兩個變體都看**（多數 aliases 只記在美音變體上），對應到目前口音的變體與示範音。
- 新增小型 `WRITINGS` 對照表，補上 `aliases` 沒涵蓋的常見記法：`ɹ→r`、`ʧ/ʤ→tʃ/dʒ`、`ɫ→l`、`ɜ→ɜː(英)/ɜːr(美)`、`oʊ→əʊ(英)`、`ɒ/ɪə/eə/ʊə→ɑː/ɪr/er/ʊr(美)`。
- 修飾符（`n̩`、`tʰ` 等，U+02B0–02FF、U+0300–036F）附在前一個音上顯示，不再自成一個查不到示範的音。
- 真的不在音標表裡的符號（例如 `ʔ`）保留原樣並標記 `unmatched: true`，不再被當成「壞掉的音」。
- 移除原本把 `i` 硬塞進符號清單、卻查不到卡片的權宜寫法（`i` 現在透過 alias 正確對應到 `iː`）。

### 2. 缺示範音不再中斷（`features/phonetics/word-sheet.js`、`page.js`）

- 沒有示範音的音素格加上 `is-unavailable` 樣式（虛線、淡化）與 tooltip，點之前就看得出不能試聽。
- 「逐音跟讀」改為跳過缺示範的音、把其餘唸完，並回報「已跳過無獨立示範的音：…」；只有全部都沒有示範音時才沿用原本的「暫無獨立示範」提示。
- 修正「所有音都是可選音」時 `skipped[0]` 會取空的邊界情況。

### 3. 約束 AI 寫法（`modules/prompts/dictionary.js`、`modules/api.js`、`modules/phonetics-data.js`）

- `dictionary.pronunciation`（v1.1.0 → v1.2.0）：注入該口音**實際可播放的符號清單**（`${symbols}`）與寫法規則（`${notation}`），要求只用這些符號。
- `dictionary.wordAnalysis`（v1.0.0 → v1.1.0）：`phonetic` 欄位同樣注入寫法規則。
- 符號清單放在 `modules/phonetics-data.js` 的 `PHONEME_SYMBOLS`，並由測試比對 `phonetic-chart/data.js` 的實際卡片，避免兩邊走樣。
- 版本號變更會使既有的 AI 音標快取失效，舊詞第一次查詢會重新打一次 AI。

### 4. 文案（`locales/zh-CN.js`、`locales/zh-HK.js`）

新增 `phonetics.unavailable`、`phonetics.skipped`（含 `{symbols}` 插值），兩份字典鍵集合一致。

## 四、驗證

- `node --test tests/phonetics.test.mjs`：11 項全過。新增三項：
  - AI 常見寫法（`ˈʃɛltə`、`ˈʃɛltɚ`、`ˈʃɛltɹ̩`、`ˈɹʌn`、`ˈbɝd`、`ˈtʃer`、`ˈsɑk`、`ˈnoʊz`、`ˈkæmərə`、`ˈstɔːri`、`ˈbʌtn̩`…）在英、美音下都能找到示範音；`ʔ` 保持 `unmatched`。
  - `PHONEME_SYMBOLS` 與音標表實際可播放的符號集合完全一致。
  - 兩個提示詞都注入了寫法規則，且 pronunciation 提示詞版本已提升。
- `node tests/phonetics.browser.cjs`（Playwright，模擬 AI／TTS）：zh-CN、zh-HK 皆 passed，`errors: []`。已擴充一則回歸：AI 回傳 `/ˈʃɛltə/` 時音素格為 `ʃ ɛ l t ə`、無 `is-unavailable`、逐音跟讀不出現「暫無獨立示範」或跳過訊息。
- 手動瀏覽器檢查：`phonetics.html?word=shelter&accent=uk&ipa=ˈʃɛltə&source=ai` 五個音素皆為可播放狀態；`ipa=ˈbʌʔn̩` 時 `ʔ` 顯示虛線不可用樣式、`n̩` 正常。

## 五、遺留

- 真的不在音標表內的音（`ʔ`、`ɐ`、`ᵻ`、`ɫ` 以外的罕見符號）仍沒有示範音，目前以「標記 + 跳過 + 提示」處理；若要補錄音，需在 `phonetic-chart/audio/` 增加對應音檔並在 `data.js` 建卡。
- 英音的 `er`／`ər` 這類「美式拼法寫進英音讀法」的情況不做自動去 r（會誤刪 `camera`、`story` 等詞的連讀 r），仍以原樣拆音並保留可播放的 `r`。
