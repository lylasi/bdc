# 免費 TTS 模型替代方案調研

- 調研日期：2026-10-28。
- 適用專案：BDC 英語學習靜態 SPA，涵蓋單字發音、聽寫、例句、文章朗讀及普通話／粵語。
- 方法：核對現有程式碼、官方原始碼倉庫、模型卡、授權條款及雲端定價頁。
- 驗證邊界：本次沒有安裝或執行模型，沒有進行音訊 A/B 盲聽、發音正確率測試或手機效能測試。下述選型為文件及架構評估，不代表已證實任何模型的音質勝過目前服務；供應商的品質及速度描述也不當作本專案實測結果。

## 一、先說建議

針對 BDC，第一個值得驗證的免費本地模型是 **Kokoro-82M**：有美式及英式英語音色、權重為 Apache 2.0、具備 CPU 與瀏覽器推理路徑，亦有社群 HTTP 服務封裝。它適合作為英語例句及文章朗讀的新增選項，但單字發音需要單獨驗證，暫不建議直接取代全部既有朗讀。

「更好」應分成發音正確、自然度、等待時間、離線能力、私隱及維護成本。BDC 現在已有微軟 Neural 聲線目錄；不能把現有服務當作只有機械式系統語音，也不能只憑某模型在網上評分較高就判斷它更適合單字教學。

免費亦要分清：

1. **模型及權重可免費本地使用**：自己提供電腦／伺服器，仍有算力、電力及維護成本。
2. **正式雲端 API 每月有免費額度**：需要帳戶，超額或切換收費級別可能收費。
3. **免 Key 的第三方／非官方線上服務**：有連線及持續可用性風險，不能視為有保證的永久免費 API。

## 二、專案目前實際使用甚麼

### 2.1 HTTP TTS 加系統語音回退

- 主應用以 `modules/audio.js:308` 及 `modules/audio.js:356` 建立 HTTP 音訊 URL，經共用 `HTMLAudioElement` 播放。
- 地址未設定、仍是示例地址或播放失敗時，`modules/audio.js:124` 的 `speechSynthesis` 分支可作回退；系統聲音是否離線，取決於裝置及所選聲線，程式沒有保證。
- 現有聲線目錄及示例設定使用微軟 Neural 命名：例如 `en-US-JennyNeural`、`zh-CN-XiaoxiaoNeural`、`zh-HK-HiuGaaiNeural`，見 `ai-config.example.js:31`。
- 全域英語偏好預設為 `en-GB`；實際聲線還受已儲存設定及首次載入聲線時自動選擇的結果影響，見 `modules/settings.js:30`、`modules/voices.js:211`。
- **未讀取本機私有 `ai-config.js`，因此不能從本次調研確認目前部署的實際上游是 Edge、Azure 或其他微軟相容服務。**

### 2.2 目前 HTTP 協議

```text
GET {baseUrl}/tts?t=<文字>&v=<聲線>&r=<語速>&api_key=<服務密鑰>
GET {baseUrl}/voices
```

這是現有服務的相容協議，並非所有 TTS 模型通用的標準。OpenAI 相容 `POST /v1/audio/speech` 也不能只換地址便直接接上，仍需服務端轉接或共用音訊層的供應商適配。

### 2.3 與新模型直接相關的限制

| 現況 | 對替代方案的影響 |
| --- | --- |
| 單字、聽寫、文章大多經 `speakText` | 適配應集中於共用層，保留播放完成、取消及狀態事件；聽寫依靠完成回調推進 |
| 文章逐句串行生成／播放，未見下一句預取 | 換較大的生成模型可能增加句與句之間的等待；分句、預取與音訊快取也會影響體驗 |
| 段落模式沒有依模型長度上限再次切分 | 需要按新模型能力切塊，不能將長段落無條件交給模型 |
| 全文下載以單次 GET 發送，超過 1,800 字符會阻止 | 要改善長篇匯出，需另處理 POST、分塊及合併；不是換模型便自動解決 |
| 未見應用層音訊 Blob／IndexedDB 快取 | 相同單字及例句可以評估生成後快取，減少重複計算與等待 |
| 聲線清單優先讀靜態 `voices.min.json`／`voices.json` | 換後端也可能繼續顯示舊微軟聲線；要按供應商區分清單，不能只修改服務 URL |
| 聲線 ID 解析及拼讀頁依賴 `en-GB-`／`en-US-` 等命名 | `af_heart`、`bf_emma` 等模型原生名稱需要映射或擴充解析 |
| 語速值目前使用 `r=-100/-50/0/50/100` 等格式 | 需明確換算為模型的倍率；現有系統語音換算與 UI 標示也存在差異 |
| 獨立 `phonetics.html` 整詞播放直接建立 URL | 不能只改主應用 `speakText`，還須兼顧獨立拼讀頁；音素示範本身使用靜態錄音 |
| 手機已有音訊互動解鎖，但未見文章 Media Session／Wake Lock | 新模型不會自動改善鎖屏／背景連續播放；仍需實機驗證 |

參考位置：`modules/audio.js:177`、`:225`、`:312`、`:362`、`:390`；`modules/voices.js:61`、`:91`、`:171`；`features/article/article.js:4998`、`:5268`、`:5470`、`:5518`；`features/phonetics/page.js:162`；`modules/phonetics-data.js:30`。

## 三、英語及輕量本地候選

### 3.1 Kokoro-82M：優先試用

- 官方模型：`hexgrad/Kokoro-82M`，82M 參數；本次模型頁顯示 v1.0，權重 Apache 2.0。
- 官方音色清單明確區分 American English 與 British English，例如 `af_heart`、`af_bella`、`bf_emma`、`bm_george`。
- 基礎模型亦列出普通話，但沒有列出粵語；`kokoro-js` 的文件及聲線主要對應英語，不應假設瀏覽器接法直接覆蓋基礎模型全部語言。
- `kokoro-js` 文件提供 WASM／WebGPU，以及 q8 等模型格式；這證明存在瀏覽器本地路徑，不等於所有手機都能順暢執行。
- ONNX 倉庫顯示 `model_quantized.onnx` 約 **92.4 MB**、FP16 約 **163 MB**、FP32 約 **326 MB**。這些是模型檔案大小，尚未計入聲線、推理引擎、字音轉換及執行時記憶體。q4 名稱也不保證檔案較小：當前 `model_q4.onnx` 頁面顯示約 305 MB。
- `kokoro-onnx` 提供 CPU 路徑；其 README 描述在 macOS M1 上接近即時，不能把該描述外推為低階手機或 BDC 實測效能。
- 社群 `Kokoro-FastAPI` 提供 CPU／GPU 部署及 OpenAI 相容 `POST /v1/audio/speech`、`GET /v1/audio/voices`。它不是模型作者的官方託管服務，也不代表有免費雲端 API。

**對 BDC 的重要限制：**官方聲線說明指出多數聲線在約 100–200 tokens 的輸入較好，少於約 10–20 tokens 時可能較弱，超過 400 tokens 時可能趕讀。因此 `cat`、`record` 等單字，以及簡短聽寫指令，必須與現有聲線直接對照；不能用文章自然度代替單字發音驗證。

**判斷：**先驗證英語例句及文章朗讀；通過單字、多音詞及低速播放驗證後，再考慮聽寫預設。

來源：[模型卡](https://huggingface.co/hexgrad/Kokoro-82M)、[官方音色及輸入長度說明](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)、[ONNX 檔案](https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX/tree/main/onnx)、[kokoro-js](https://www.npmjs.com/package/kokoro-js)、[kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx)、[Kokoro-FastAPI](https://github.com/remsky/Kokoro-FastAPI)。

### 3.2 Kitten TTS 0.8：輕量備選，須與新系列分開看

- 舊輕量系列有 15M／40M／80M 參數版本，以 CPU／ONNX 為主要賣點。
- `kitten-tts-mini-0.8` 的模型卡標示 80M、約 79 MB、8 個聲線、Apache 2.0。
- `kitten-tts-nano-0.8-int8` 的模型卡標示 15M、約 25 MB、8 個聲線、Apache 2.0。
- 本次讀取的這兩份模型卡沒有完整列出語言支援，不能把新系列的多語種宣傳套到舊 0.8；英美口音、中文及粵語需要另行核對和試聽。

**版本陷阱：**當前倉庫亦推介 **Kitten-TTS 2（約 1.7B）**。其模型卡使用 **Stellon Labs Community License**，並非舊 0.8 權重的 Apache 2.0。模型卡提及商業收入／累計融資門檻及署名要求；完整條款另有商業登記、分發及衍生模型限制。若要選用新系列，須按精確 checkpoint 重新核對授權，不能統稱「Kitten 全系列 Apache、免費商用」。

**判斷：**低配置、較小下載量可列為候選；目前沒有本專案證據證明其發音或自然度優於微軟 Neural 或 Kokoro。

來源：[官方倉庫](https://github.com/KittenML/KittenTTS)、[mini 0.8 模型卡](https://huggingface.co/KittenML/kitten-tts-mini-0.8)、[nano 0.8 int8 模型卡](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8)、[Kitten-TTS 2 模型卡](https://huggingface.co/KittenML/kitten-tts-2)、[新系列授權](https://huggingface.co/KittenML/kitten-tts-2/blob/main/LICENSE.md)。

### 3.3 Piper：偏向本地可用性及低配置需求

- 現行專案為 Open Home Foundation 的 `OHF-Voice/piper1-gpl`；官方描述為快速、本地的神經 TTS，並內建 eSpeak-ng 做字音轉換。
- 引擎程式碼是 GPL-3.0；每個聲線的模型卡另有資料／模型條款，官方明確提醒有些聲線授權較嚴格，不能一概視為 MIT 或任意商用。
- 聲線目錄可選不同語言；音質、口音和授權必須逐聲線核對。
- 本次 README 顯示基金會正徵求維護者；評估時應核對具體版本與維護狀態。

**判斷：**適合重視本地運行及資源控制的路徑；沒有依據把它當作較現有微軟 Neural 更自然的必然升級。

來源：[現行倉庫](https://github.com/OHF-Voice/piper1-gpl)、[聲線及授權提示](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/VOICES.md)。

### 3.4 Chatterbox：有特定聲音需求時再考慮

- 原版 Chatterbox 模型卡為 English、500M、MIT；Turbo 為 English、350M、MIT。
- 當前倉庫亦有 110M 的 Nano；模型卡宣稱八核心 CPU 可達約三倍即時速度，但沒有具體 CPU 型號，不視為 BDC 的效能承諾。
- Turbo／Nano 的例子需要參考音訊做聲音克隆。這會增加參考音源、口音一致性、快取和設定管理工作；對一般英語學習固定聲線未必划算。
- 專案表示輸出預設含 Perth 浮水印。官方託管產品的低於 200ms 宣傳，不能當作開源模型在自家設備上的延遲。

**判斷：**若需要特定聲音或表達控制可納入；BDC 目前以準確、穩定的固定發音為主，優先度低於 Kokoro。

來源：[官方倉庫](https://github.com/resemble-ai/chatterbox)、[原版模型卡](https://huggingface.co/ResembleAI/chatterbox)、[Turbo 模型卡](https://huggingface.co/ResembleAI/chatterbox-turbo)、[Nano 模型卡](https://huggingface.co/ResembleAI/chatterbox-nano)。

## 四、多語種及中文／粵語候選

### 4.1 CosyVoice3：中文／粵語優先驗證

- 官方可下載 checkpoint 為 **`FunAudioLLM/Fun-CosyVoice3-0.5B-2512`**，屬 0.5B 系列；當前模型卡及程式碼倉庫均宣告 Apache-2.0。未在已查文件看到額外非商用限制。
- 模型卡列出九種語言，含中英，以及 18+ 中國方言／口音；尤其官方範例以 `inference_instruct2` 傳入 **「请用广东话表达。」**，有直接的粵語控制證據。
- 官方提供 Python 推理、Gradio 及 FastAPI／gRPC 等路徑，適合作獨立推理服務，由 BDC 呼叫；所查官方 API 路徑為 `/inference_*`，沒有找到原生相容 OpenAI `/audio/speech` 的承諾。
- 已查官方 README／模型卡沒有明確最低 VRAM，不能用「0.5B」直接推算整個服務的峰值資源需求或手機可用性。

**判斷：**若希望改善中英混讀及粵語，優先與現有微軟聲線直接試聽。這是功能及授權上的候選推薦，並非本專案已證實其發音或自然度更佳。

來源：[官方倉庫](https://github.com/QwenAudio/CosyVoice)、[checkpoint 模型卡及廣東話示例](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512/blob/main/README.md)、[官方推理範例](https://github.com/QwenAudio/CosyVoice/blob/main/example.py)。

### 4.2 Qwen3-TTS：中英候選，公開權重粵語能力未明確確認

- 官方倉庫記錄 2026-01-22 發布，提供命名為 0.6B 及 1.7B 的系列：兩種大小各有 Base、CustomVoice，另有 1.7B VoiceDesign；另需 tokenizer。
- 程式碼、公開模型及 tokenizer 為 Apache-2.0；本次核對的 0.6B CustomVoice 模型卡亦列出該授權。
- 官方列十種語言，包括 Chinese、English；固定音色包括英語 Ryan、Aiden。已查的開放模型卡及音色表沒有明確確認 Cantonese。Eric 為四川口音，不能當作粵語證據。
- 雲端 **Qwen3-TTS-Flash** 的能力宣傳不能直接套到可下載的開放 checkpoint，也不代表雲端 API 免費。
- 官方範例使用 Python、CUDA、BF16；FlashAttention 2 為可選。沒有查到明確最低 VRAM，文件中的系統 RAM／編譯說明不應誤讀為 GPU 門檻。
- 本文沿用官方系列名「0.6B」；該 Hugging Face 頁面另顯示約 0.9B 的總參數 metadata，不能把系列名稱當作完整服務的實際記憶體大小。

**判斷：**如有可用推理主機，可用 0.6B CustomVoice 的固定英語音色與 Kokoro、現有聲線對照。對純前端手機直接推理，不能只根據參數較小就推薦。

來源：[官方倉庫及模型表](https://github.com/QwenLM/Qwen3-TTS)、[0.6B CustomVoice 模型卡](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice)、[技術報告](https://arxiv.org/abs/2601.15621)、[程式碼 LICENSE](https://github.com/QwenLM/Qwen3-TTS/blob/main/LICENSE)。

### 4.3 Fish Speech／Drama 3：暫不列為 BDC 免費預設後端

- 本次官方資料顯示 2026-10-13 已發布 **Drama 3** 開放權重：35B 總參數、每 token 約 3B active，不能再把上一代 S2-Pro 當作最新開放模型。
- Drama 3 權重使用 **Fish Audio Community License v1.0**。一般商用授權有過去十二個月本人／公司及關聯方總收入低於 US$500,000 的條件，並有 **“Built with Fish Audio”** 等署名要求。
- **Hosted Service 另有限制**：讓第三方自行提供文字、音訊或聲音樣本以生成語音的服務，一般需要另行書面協議；條文同時列出自有／受控制內容及免費非商業研究展示等例外。BDC 的使用者貼文章再自助朗讀流程，不能只憑「免費學習工具」就假設取得不限用途的服務授權。
- 舊 **S2-Pro** 權重仍為 Fish Audio Research License，研究及非商業用途可免費，並非任意商用許可。
- 官方安裝文件列明 **S2-Pro 的 GPU 路徑最低 24 GB GPU 記憶體**，另有 CPU 路徑；**Drama 3 FP8 最低 48 GB，要求 NVIDIA GPU，不支援 CPU／Apple MPS／AMD ROCm**。這些是文件要求，沒有在本次硬件上驗證。
- Drama 3 模型卡列出中英等語言，但沒有單獨確認 `yue`／Cantonese；未將其歸為已核實粵語模型。
- 官方服務使用 `/v1/tts`，不是本專案現有 GET `/tts` 協議。

**判斷：**授權和資源成本都較高，本案不優先。Drama 3 模型卡 metadata 與正文曾有 Research／Community 名稱不一致，本調研以隨附 LICENSE 原文及官方發布公告為準。

來源：[官方發布公告](https://fish.audio/blog/fish-audio-drama-3/)、[Drama 3 模型卡](https://huggingface.co/fishaudio/drama-3)、[Community License](https://huggingface.co/fishaudio/drama-3/blob/main/LICENSE)、[S2-Pro Research License](https://huggingface.co/fishaudio/s2-pro/blob/main/LICENSE.md)、[硬件要求](https://speech.fish.audio/install/)、[推理服務](https://speech.fish.audio/inference/)。

## 五、不自建模型時的正式免費額度

| 服務 | 本次核對的免費條件 | 對 BDC 的意義 |
| --- | --- | --- |
| Azure Speech Neural TTS | F0 每月 50 萬字符；每 60 秒最多 20 次合成請求；每次產出最多 10 分鐘 | 正式 API，但仍需開帳戶、設定資源及適配；聲線本身未必與目前微軟路徑有明顯音質差距 |
| Google Cloud Chirp 3 HD | 定價表顯示每月 100 萬字符免費 | 值得與現有聲線試聽的正式雲端候選；需啟用帳單，超額會自動收費 |
| Google Cloud Neural2 | 定價表顯示每月 100 萬字符免費 | 可作另一組正式 API 對照，同樣需要帳單及用量控制 |
| Google Cloud Standard／WaveNet | 當前定價表兩者均顯示每月 400 萬字符免費 | 勿沿用舊概覽頁的 WaveNet 100 萬說法；不同產品頁可能更新不同步，實際開通時應再核對 |

上述額度不能理解為每個聲線各自一份；應依服務帳戶、SKU 和官方計費規則計算。免費額度是服務端條件，亦不能代表 BDC 整個部署、代理及儲存成本為零。

**Google 數字的核對方式：**網頁摘要工具先後取得了截斷頁面及舊概覽，與搜尋結果有差異；本次另直接讀取官方英文定價 HTML，確認當前表格 Standard／WaveNet 的 400 萬、Neural2／Chirp 3 HD 的 100 萬，以及需啟用帳單、超額自動收費的原文。未採用部落格或舊教學的額度數字。

`edge-tts` 這類社群專案使用微軟 Edge 的線上語音服務，與正式 Azure API 不同。它可以是方便的現有來源，但不是可據其程式碼授權取得長期免費存取保證的官方服務。

## 六、建議的驗證方式

這是選型驗證建議，尚未執行或修改產品。

1. **先比固定輸入及聲線。**以目前實際聲線為基準，加入 Kokoro 的美音及英音；若主要需求為中文／粵語，加入相應多語種模型。每次記錄精確 checkpoint、聲線、文字、語速及硬件。
2. **分開測單字及文章。**單字包括 `record`、`present`、`read`、`live` 等依上下文變音的詞；有上下文的例句要逐一核對應有讀音，孤立單字則事先約定目標詞性及讀法。另測 `thought / though / through` 等易混詞、數字日期、縮寫及中英混讀。
3. **測四類文字長度。**單字、短例句、普通段落、長文；核對漏讀、重複、錯讀、句尾截斷及分句停頓。
4. **測低速聽寫。**比較原速與低速的音素清楚度、重音和自然度；聽起來悅耳不等於適合辨音教學。
5. **記錄實際等待與資源。**首次載入、冷啟動、首段開始播放、後續分句間隔、CPU／RAM／VRAM，以及手機耗電和瀏覽器記憶體。模型下載大小不可代替執行時資源數字。
6. **測完整控制流程。**取消、重播、暫停／恢復、連續聽寫、快速換詞、音訊下載、後端斷線及回退，並涵蓋 `zh-CN`、`zh-HK`、主應用與獨立拼讀頁。
7. **最後決定範圍。**可以只把新模型用於文章，單字及聽寫繼續用現有聲線；等短文本表現通過，再調整預設。

## 七、接入方向

- **先做單一可切換供應商的試驗。**共用音訊服務負責請求、取消、回調和回退；不要在各 feature 中分散加入模型專用請求。
- **服務端推理優先作初次驗證。**若有可用電腦或伺服器，可先用 Kokoro 的 CPU HTTP 服務，避免每部手機首次下載近百 MB 模型。手機可否順暢使用取決於後端是否夠快及網路是否可達。
- **瀏覽器本地模型作可選下載。**需要真離線／私隱時再加入 WASM／WebGPU；應有下載大小提示、裝置能力探測、背景推理與系統語音回退。手機負擔及 Safari／其他瀏覽器相容性須實測。
- **聲線資料必須按供應商管理。**除了替換 URL，還要處理 `voices.min.json` 的優先順序、供應商聲線 ID、英美口音對應、普通話／粵語能力及語速換算。
- **局域網服務沿用現有專案網路限制。**手機不可使用服務端的 `localhost`；HTTPS 頁面直連 HTTP 端點亦受混合內容及瀏覽器本地網路權限限制。正式雲端共享 Key 應留在服務端或適當的秘密管理邊界，不能為接 TTS 而公開到靜態檔案。
- **授權按精確版本落實。**若隨前端分發模型、採用 GPL 引擎或有限商業使用權重，需依各自條款保留聲明及履行相關義務。
