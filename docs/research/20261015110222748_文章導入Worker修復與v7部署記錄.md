# article-import-service Worker 診斷、修復與 v7 部署記錄

- 時間：2026-10-15
- 服務：`https://article-import-service.lylasi.workers.dev`（Cloudflare Worker，account `8ad18834a456194d317714785aa8475d`）
- 結論：**線上程式碼確實不是最新的** —— v1～v5 全部建於 2025-11-14，2026-10-15 的 v6 只改了變數（`ALLOW_HOSTS`）；本次推的 **v7 才是第一次動到程式碼**。

## 一、為什麼一直報 403

Worker 的 `/extract`、`/fetch`、`/feeds/:id/article` 都會先過 `requestRemote()` 的主機白名單（`src/lib/fetcher.js`）：

```
if (!isHostAllowed(normalized.hostname, allowHosts)) throw new HttpError(403, `Host ${hostname} is not allowed`);
```

而 `DEFAULT_ALLOW_HOSTS`（`src/lib/config.js`）與部署的 `ALLOW_HOSTS` 變數都是 `docs/article-import-service.md` 的模板預設值，**跟 worker 自己 feed 吐出的文章域名對不上**：

| feed | feed 給的文章域名 | 修復前 |
| --- | --- | --- |
| `/feeds/bbc` | `www.bbc.co.uk` | 403（白名單只有 `*.bbc.com`） |
| `/feeds/cnn` | `www.cnn.com` | 403（白名單只有 `edition.cnn.com`） |
| `/feeds/rt` | `rt-english.com` | 403（白名單只有 `*.rt.com`） |
| `/feeds/nyt` | `www.nytimes.com` | 過白名單，但上游 403（NYT 封鎖，見遺留） |

`/feeds` 本身能抓，是因為 feed 抓取走 `extraAllowedHosts` 把 feed 自己的域名臨時加進白名單（`src/lib/feeds.js`），所以「列表正常、一點導入就 403」。

前端顯示兩段一樣的錯誤，是因為 `fetchCuratedArticle()` 先打 `/feeds/<id>/article`、失敗再打 `/extract`（`modules/api.js:1283-1320`），兩個端點共用同一套白名單。

## 二、本次改動（v7）

以線上 bundle（esbuild 產物，未壓縮、保留 `// src/...` 模組註解）為基礎打補丁，共 4 處：

1. `src/lib/config.js` → `DEFAULT_ALLOW_HOSTS` 補上 `rt-english.com`、`www.cnn.com`、`*.cnn.com`（`*.bbc.co.uk` 原本就有）。
2. 各來源的 `allowHosts` 跟上：`rt` 加 `rt-english.com`；`cnn` 加 `www.cnn.com`、`*.cnn.com`。
3. `src/lib/content-parser.js` → 新增 `slimHtmlForParsing()`，**在 linkedom 解析前**先移除 `<!-- -->`、`script/style/noscript/template/svg/iframe`（原本只在解析後 `sanitizeDocument()` 移除，對 6MB 頁面為時已晚）。CNN 這類頁面 6.2MB 幾乎都是 inline script。
4. `MAX_BYTES` 預設 `4e6` → `8e6`，並把部署變數 `MAX_BYTES` 由 `4000000` 提到 `8000000`（CNN 文章實測 6.17MB，原本必 413 `Payload exceeded limit`）。

```diff

   "www.rt.com",
   "*.rt.com",
+  "rt-english.com",
   "feeds.bbci.co.uk",
   "*.bbc.co.uk",
   "*.bbc.com",
   "edition.cnn.com",
+  "www.cnn.com",
+  "*.cnn.com",
   "rss.cnn.com",
@@ rt source
-    allowHosts: ["www.rt.com"],
+    allowHosts: ["www.rt.com", "rt-english.com"],
@@ cnn source
-    allowHosts: ["edition.cnn.com"],
+    allowHosts: ["edition.cnn.com", "www.cnn.com", "*.cnn.com"],
@@ getConfig
-  const maxBytes = Number(env.MAX_BYTES || env.vars && env.vars.MAX_BYTES || 4e6);
+  const maxBytes = Number(env.MAX_BYTES || env.vars && env.vars.MAX_BYTES || 8e6);
@@ content-parser
+function slimHtmlForParsing(html) {
+  return String(html || "").replace(/<!--[\s\S]*?-->/g, " ").replace(/<(script|style|noscript|template|svg|iframe)\b[^>]*>[\s\S]*?<\/\1\s*>/gi, " ");
+}
 function parseArticle(html, url, options = {}) {
-  const { document } = parseHTML(html);
+  const { document } = parseHTML(slimHtmlForParsing(html));
```

## 四、部署方式（保留原變數與 KV 綁定）

用 wrangler 的 OAuth 憑證（`~/Library/Preferences/.wrangler/config/default.toml`）直接呼叫 Cloudflare API 上傳單一模組，**不經過 wrangler 打包**，並在 metadata 帶回原有綁定：

```
PUT /accounts/8ad18834a456194d317714785aa8475d/workers/scripts/article-import-service
multipart/form-data:
  metadata = {
    "main_module": "index.js",
    "compatibility_date": "2024-07-01",
    "bindings": [
      {plain_text  ALLOW_HOSTS   = www.rt.com,rt-english.com,*.rt.com,*.bbc.com,*.bbc.co.uk,edition.cnn.com,www.cnn.com,*.cnn.com,*.nytimes.com},
      {plain_text  FEED_CACHE_TTL = 300},
      {kv_namespace FEEDS_CACHE  = 2da90f96c5624b1aa980f505ea313800},
      {plain_text  MAX_BYTES     = 8000000},
      {plain_text  SOURCES_JSON  = {}}
    ],
    "annotations": {"workers/message": "..."}
  }
  index.js = <bundle>
```

下載目前線上程式碼（要再打補丁時用）：

```
GET /accounts/{acc}/workers/scripts/article-import-service/content/v2   # multipart，取 index.js
GET /accounts/{acc}/workers/scripts/article-import-service/settings     # 變數與綁定
GET /accounts/{acc}/workers/scripts/article-import-service/versions     # 版本歷史
```

回滾：把版本切回 v6（`00e87030`）即可；該版就是修復前的程式碼。

## 六、遺留

1. **NYT 仍 403**：`Upstream responded with status 403`。已用同一個 Chrome UA 從另一條網路直連 `www.nytimes.com` 也是 403，所以不是 worker 的 header 問題，是 NYT 端封鎖（IP／反爬）。要嘛撤掉 NYT 源，要嘛改走別的方式（RSS 內文、快取）。
2. **伺服器上的 `ai-config.js` 沒同步**：`bdc.eigui.cn:5000/ai-config.js` 仍是舊的 `SOURCES: guardian/techcrunch/cna/rt`，而 worker 只認 `rt/bbc/cnn/nyt`，選 guardian／techcrunch／cna 會得到 `404 Unknown source`。本機 `ai-config.js` 已是正確清單，需覆蓋到伺服器。
3. **這台機器上沒有 worker 的原始碼工程**：本倉庫只有 `docs/` 的方案文件與參考實作 `scripts/cf-worker-proxy.js`（訊息格式也跟線上不同）。本次是直接對線上 bundle 打補丁，若日後要長期維護，建議由該 bundle 還原出 `src/` 工程（模組邊界與 `// src/...` 註解都還在，可行）並改用 wrangler 部署。
