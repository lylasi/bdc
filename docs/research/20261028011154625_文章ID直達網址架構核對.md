# 文章 ID 直達網址架構核對

日期：2026-10-28（Asia/Shanghai）。依據本機目前工作樹核對，包含既有未提交變更；未核實線上部署版本。

## 結論

目前架構可以支援「每篇文章一個 ID，以 URL 直接開啟」。文章已獨立保存並具有穩定 ID，後端已有按 ID 讀取單篇的 API；前端尚未把文章 ID 接入 URL 路由。無須為私人文章直達重做儲存架構。

「自己的文章直達」與「其他人透過連結閱讀」有不同的授權範圍。現有 API 只允許擁有人讀取文章，不能僅增加網址參數就讓其他帳戶取得內容。

## 可行的補齊方向（尚未決定實作）

私人直達可採用 hash 路由，例如 `/#a/<articleId>`。此為建議格式，目前並不支援；hash 形式可沿用靜態 SPA，不要求為每篇建立 HTML 檔或新增伺服器路徑重寫。

必要工作是串接 URL 解析、文章開啟與網址更新，並處理首次載入、登入後恢復、同步端點及帳戶範圍、本機缺文時的遠端讀取或同步、已刪除／無權限／離線缺文提示，以及瀏覽器歷史導覽。遠端補取必須保留現有帳戶範圍檢查，避免切換帳戶後晚回應套到另一帳戶。

私人直達連結定位既有文章；不能把本機獨有的文章內容送到另一裝置。跨裝置開啟的前提是同一同步服務與帳戶，且該篇已成功上傳。重新分析同篇可以維持 ID；另存副本則使用新 ID。

其他人開啟則須增加分享授權及讀取流程。既有[文章獨立儲存與指定用戶分享建議](../spec/20261018184206963_文章獨立儲存與指定用戶分享建議.md)記錄了已確認的第二階段方向：指定接收者、唯讀、固定當次內容，以獨立分享記錄隔離私人學習資料；公開連結並非該階段既定範圍。這份文件是歷史決策依據，不能當成分享功能已實作的證據。
