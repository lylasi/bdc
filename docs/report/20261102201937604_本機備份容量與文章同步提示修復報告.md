# 本機備份容量與文章同步提示修復報告

日期：2026-11-02（Asia/Shanghai）。

## 證據與範圍

使用者提供兩張微信內置瀏覽器截圖：

- 建立備份報 `localStorage.setItem`／`exceeded the quota`：可以確認完整備份寫入 localStorage 失敗。舊版先寫入新完整備份，之後才裁剪自動備份；手動備份全部保留，累積後會與設定及學習資料後備路徑爭用容量。
- 齒輪顯示「文章同步失敗」：屬於文章同步階段，與上一輪閱讀逐項同步不同。原提示沒有附底層錯誤碼，不能只憑截圖判定它與備份配額是同一原因。

只讀雲端中繼資料顯示該帳戶文章數及單篇大小均未接近產品容量上限。本次沒有讀取或修改真實文章內容、筆記或憑證。實際手機的文章 outbox 及底層錯誤尚未取得；因此本報告不宣稱已重現該手機所有同步失敗。

## 實作

1. 新增 `modules/backup-store.js`，完整備份改存獨立 IndexedDB `bdc-backups`。`payloads` 與 `metadata` 同交易更新，列表只讀中繼資料。
2. 舊 `bdc:backup:v1:*` 備份逐份寫入 IndexedDB、讀回確認完全一致後，才移除 localStorage 原件；沒有舊索引的備份也會被找回。複製失敗、原件已被另一分頁改寫或讀回不一致時，原件保留。
3. 所有手動備份保留；新自動備份成功提交後保留最近兩份。新寫入或中繼資料失敗時，舊備份不會先被裁剪。相同 ID 的不同內容另存，舊手動旗標保留。
4. IndexedDB 不可用時維持 localStorage 後備；容量不足回報清楚文案並保留已有備份，仍可匯出。啟動及同步前會準備備份儲存，釋放可安全搬移的舊備份空間。登入連結片段仍在第一個 await 前同步移除。
5. `local-backup.js`、備份面板及相應測試改為 await 非同步列表、讀寫、刪除。匯入／匯出／離線還原格式維持既有 JSON payload；備份不加入雲端快照，以免遞迴膨脹。
6. 文章同步失敗、未完成及快照還原組合狀態均保留具體原因。提示區分本機容量、雲端文章容量、本機儲存讀寫、連線及逾時，原始錯誤碼仍可查看；切換語言會重新翻譯。簡體及香港繁體文案同步完成。

## 驗收界限與後續

瀏覽器測試使用隔離 context、合成資料及本機服務，沒有在微信真機上操作使用者的現有資料。新版部署後，實際手機如仍顯示文章同步失敗，需要齒輪選單的新完整錯誤文字才能繼續定位；不能以本機／模擬服務測試通過代替真實手機成功同步。
