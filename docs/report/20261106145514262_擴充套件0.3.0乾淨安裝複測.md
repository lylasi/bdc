### P3 失敗原因

腳本寫死 `/Packaged 44 files/`，那是 0.2.x 的產物數量。0.3.0 加入詞書收藏後，`scripts/package-extension.mjs` 的 `SHARED_FILES` 清單成長到 48 個共享檔，加上自動產生的 `extension/ai-config.js` 與 `_locales/{zh_CN,zh_TW}/messages.json` 共 3 個，合計 **51**，因此斷言必然失敗——打包本身是成功的。

### P4 失敗原因與 404 定位（實際 URL）

`extension/capture-ui.js` 的 `sync()` 在帳號登入後（`AUTH_EVENT SIGNED_IN`）立即呼叫 `loadBooks()` → `extension/shared/capture-client.mjs` 的 `books()`，也就是：

```
GET {syncEndpoint}/vocabulary/books
Authorization: Bearer <token>
```

這是 0.3.0 才新增的端點；舊 mock 只建模 `/login`、`/me`、`/snapshot`、`/ai-catalog`、`/ai-catalog/providers/:id/credential`、`/ai-credentials`，因此落到 `404 not_found`。擴充套件的 `responseBody()` 把 404 視為「後端太舊」，錯誤碼 `capture_server_update_required`，介面因此顯示「当前同步服务尚未支持扩展收藏，请先更新服务端。」，同時 Chromium 留下一筆 `Failed to load resource: ... 404 (Not Found)`，正好命中 P4 的 `errors.length === 0`。

**定位證據（不是推測）**：把修正後的 mock 的 `/vocabulary/books` 路由暫時關閉（`if (false && route === '/vocabulary/books' ...)`）再跑一次，P4 的診斷欄位明確指出唯一失敗請求就是它：

```
詞書端點=GET /worker/vocabulary/books → 404
未建模路由=["GET /worker/vocabulary/books (unmodeled worker route /vocabulary/books)"]
失敗請求=[{"method":"GET","path":"/worker/vocabulary/books","query":"","status":404}]
主控台錯誤=["console: Failed to load resource: the server responded with a status of 404 (Not Found)"]
請求序列=["POST /worker/login → 200","GET /worker/ai-catalog → 200","GET /worker/vocabulary/books → 404","GET /worker/snapshot → 200",...]
```

（`/worker` 是 mock 的同步端點前綴，實際 Worker 路徑就是 `GET /vocabulary/books`；正式程式碼在 `cloudflare-worker/src/captures.js` 的 `listBooks()`。）
