## 1. 本輪修正摘要（先修根因，不靠加 guard 遮掩）

### 1.1 文章同步根因：docs 與 summaries 不在同一交易

`modules/article-store.js` 舊版 `idbRequest(storeName, mode)` 只開 `db.transaction(storeName, mode)`，但 `persistDoc` / `deleteDoc` 的 callback 呼叫 `store.transaction.objectStore(STORE_ARTICLE_SUMMARIES)`。該 store 不在交易 scope，**必然同步拋出 NotFoundError**；舊程式隨後把錯誤當成「IndexedDB 不可用」，退回 localStorage 並設 `fallbackMode=true`。此後 `readSummaries` 只讀舊 localStorage 摘要，改名等更新在同步 reload 後消失。

本輪改法：
- `idbRequest` 改為接受 store 陣列（多 store 同交易），callback 支援回傳 Promise（讀改寫）。callback 同步拋錯、或回傳的 Promise reject，都會主動 `tx.abort()`，避免前一個 `put` 半提交。
- `persistDoc` / `deleteDoc` / `persistDocWithOp` / `markOpDone` / `applyRemoteDoc` / `applyRemoteTombstone` / 刪除未上傳 create 的分支，全部把 docs + `article_summaries`（必要時加 outbox）放進**同一個**交易。
- 新增 `fallbackMode` 判定：只有 `idb_unavailable` 才切換到一致的 localStorage 桶；一般 transaction／request 錯誤回報 `{ ok:false, error }` 並記錄 `persistenceError`，**不切換權威來源、不清空目前畫面**。
- `readSummaries` 失敗回傳 `null`（與「空清單」區分），`reloadScope` 遇 `null` 保留現有記憶體記錄並回報錯誤。
- 所有文章路徑（rename、touchOpened、analysis、delete、restore、duplicate、import、migration、applyRemote*、markOp*）都維護摘要。
- 已刪除所有臨時除錯輸出：`window.__opDebug`、`__pushDebug`、`__syncDebug`、`__tombDebug`、`DEBUG predelete/postdelete` 等（`rg` 已無匹配）。

### 1.2 文章保存切帳號串寫（A 正文寫進 B）

`/tmp/bdc-article-scope-review.cjs` 原始日誌：A 保存時在 `outbox.getAll` 掛起，`reloadScope(B)` 後放行，結果 B 的記憶體與永久 docs 都變成 `A NEW PRIVATE BODY.`。

根因：`persistDocWithOp` 只捕捉 scope，但 `saveArticle` 後續的 `replaceRecord` / `touchOpened` / `reanchor` 仍使用**當前** scope。

修正：
- 新增 `captureArticleContext()` / `isArticleContextActive(ctx)`（scope + generation），所有文章讀寫入口同步捕捉 ctx。
- `saveArticle`、`saveAnalysis`、`renameArticle`、`deleteArticle`、`restoreArticle`、`touchOpened`、`setBaseRevision`、`duplicateArticle`、`requeueAsCreate`、`enqueueForRetry`、`discardPending`、`importDocuments`、`importLegacyArticles`、`migrateLegacyLocalData`、`adoptGuestArticles`、`applyRemoteDoc`、`applyRemoteTombstone`、`markOpDone`、`markOpFailed`、`reconcileFullList`、`setCursor`、`markSynced`、`markSyncError`、`setConflict`、`clearConflict`、`setGatePending` 都接受並全程使用入口 ctx。
- `idbRequest` 在交易建立後、發出 request 前再次核對 ctx；交易內 callback 亦核對，失效就 abort。因此 **A→B→A** 的舊任務也會因 generation 改變而中止，回傳 `{ ok:false, error:'stale_scope' }`。
- `article-sync` 的 pull / push / ack / 錯誤 / 游標全部傳遞同一 ctx，每個網路 await 後、每次寫入前都 `assertArticleScope`；切帳戶後舊回應不會寫入新 scope，也不會把 A 的錯誤／游標寫到 B。
- 同 scope reload 不會覆蓋正在保存的新修改：`reloadScope` 以 `dataEpoch` 偵測讀取期間是否有本機提交，若是就重讀（最多 4 次）；且只有**切換 scope** 才從 `docCache` 還原已載入全文，同一 scope 重新整理仍維持摘要，避免 lazy load 退化成全量 hydrate。
- `applyRemoteDoc` / `applyRemoteTombstone` 在**交易內**重新讀取本機 docs + outbox，網路期間的新編輯（dirty/pending/有 outbox）不會被遠端覆蓋。
- `pullFull` 不再只看「缺少 ID」：逐篇比較 `revision`（本機有 pending 則跳過），並依 remote tombstone 套用刪除。
- 同步在途時的新請求不再直接回傳舊 promise，而是排一輪後續同步（`queuedSync`），避免剛產生的 outbox 被跳過。
- 修正 `markOpDone` 舊回執把已同步記錄重新標成 `pending:true` 的問題（舊 ack 只推進 revision）。

### 1.3 匯出切帳號混入另一帳戶詞書

`/tmp/bdc-reading-export-review.cjs` 原始日誌：A 匯出在 `reading_outbox.getAll` 掛起，切 B 後放行；結果標題 `ARTICLE_A`、筆記 `A_NOTE`，收藏詞書卻是 `PRIVATE_B_BOOK`。

修正：
- `reading-store.exportArticleReading(articleId, ctx)` 改為**單一 readonly 交易**同時讀取：`docs`（該篇）、`outbox`、`state`、`reading_items`、`article_documents`、`conversations`、`messages`、`vocab_books`、`vocab_entries`、`vocab_links`、`reading_outbox`、`reading_state`。回傳含文章本體、詞書／詞條／關聯與同步狀態的固定快照。
- `buildReadingNoteMarkdown` 入口 `captureReadingContext()`，格式化只用快照內的 Map／陣列，**不再呼叫 `readingStore.listVocabularyLinks` / `getVocabularyEntry` / `getVocabularyBook` / `countOutbox` / `getReadingMeta` 等可變全域**。
- 任一 await 後（含交易完成後）再核對 ctx；失效回傳 `{ ok:false, error:'stale_scope' }`，不輸出混合內容。
- 匯出去重鍵改為穩定條目 ID（fallback 為 `contentVersion|start|end|quote`），不再用 `quote|sentence|start|note`；同 quote 的不同 occurrence／版本各自保留。
- `buildFullBackup` 同樣入口捕捉 ctx，`exportAll(ctx)` + `articleStore.exportDocuments(ctx)`，並核對 `reading.scope === ctx.scope`；不一致即 `stale_scope`。`exportFullBackupFile` 失敗不再下載半套檔案。
- 修正 `reading-sync` 的「刪除 vs 修改」重複套用問題：同一遠端版本已作為 base 合併過就不再重套，避免第二次拉取同一墓碑把第一次產生的刪改衝突清掉。
- 修正 `reading-store` 刪除學習條目時 outbox 仍寫 `op:'upsert'` 的問題（改為 `delete`），墓碑才真的同步到另一裝置。

### 1.4 草稿可靠性

- `reading-panel`：`flushNoteDrafts` 改為逐一保存**所有**草稿，不限目前篩選／畫面可見的 textarea；關閉面板、Markdown 匯出、JSON 匯出、切換文章、`bdc:reading-scope-changed` 都先 flush。
- 保存失敗時**不靜默關閉**：面板保留、輸入保留、顯示可重試錯誤；`closePanel({force:true})` 只用於切帳戶（舊草稿已不屬於新 scope）。
- `phrase-picker`：`saveNote` 改為序列化 promise chain；`closePhrasePicker` 改為 async，先 `await flushPhrasePickerNote()`，失敗則維持面板與輸入並顯示錯誤；成功才清 state。JSON 匯出前亦會 flush 短語面板筆記。
- 新增測試注入：`reading-actions.__setNoteSaveInterceptorForTests()`，可實際驗證「保存失敗 → 保留草稿 → 重試成功」。

4. **前端**：`SYNC.endpoint` 指向新後端即可；舊後端會回 `server_update_required`，本機功能照常。舊 snapshot 的詞書／聊天會在 `legacyWriteBlocked=false` 時先移交到永久層，成功後才關閘。
5. **回滾**：前端可退回舊版；新表不影響舊 snapshot 讀寫，但已寫入的逐項資料不會自動回寫舊 snapshot。

## 7. 剩餘風險

- `article-store` 的 localStorage fallback 只在 IndexedDB 完全不可用時使用；此模式下多 store 交易退化為單一 bucket 寫入，仍未跨分頁原子。
- `docCache` 只保留最近 60 篇已載入全文；切回舊 scope 時未命中快取的文章會回到摘要，需再次開啟才載入（刻意維持 lazy load）。
- 實機（iOS/Android）軟鍵盤與 safe-area 仍需在真實裝置補驗；headless 量測只能證明版面不重疊。
