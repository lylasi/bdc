## 二、四項主要問題的處置

### P1：詞書名注入（合併窗口等入口）

**核查報告的判斷正確**。`features/vocabulary/vocabulary.js` 的合併窗口把 `book.name`、`book.id` 直接插進 `innerHTML`。

本輪先複現，再擴大掃描同一類入口，總共找到 **5 處**（不只合併窗口）：

| 入口 | 位置 | 原寫法 |
| --- | --- | --- |
| 合併詞書窗口 | `vocabulary.js` 書單與預覽清單 | `${book.name}`、`data-book-id="${book.id}"`、`<li>${name}</li>` |
| 補全缺失窗口 | 同檔 | `<strong>${book.name}</strong>` |
| 編輯詞書窗口 | 同檔 | `value="${book.name}"`（屬性注入）、`<textarea>${wordsText}</textarea>`（可用 `</textarea>` 跳脫） |
| 匯入詞書清單 | 同檔 | `value="${book.path}"`、`data-name="${book.name}"`、`data-id="${book.id}"`、`${book.name}` |
| 單詞篩選無結果 | 同檔 | `t('vocabulary.filterEmpty', { keyword })` 的 `keyword` 由使用者輸入 |

**修法**：全部改用 `modules/ui.js` 既有的 `escapeHtml()` / `escapeAttr()`；新增 `tHtml(key, params)`（`escapeHtml` 包裝後的 `t()`）處理「翻譯字串插進 `innerHTML`」這個模式，用於 `vocabulary.completing`、`vocabulary.analyzingProgress`、`vocabulary.filterEmpty`。

**複驗**：

```
修復前  R1-merge / R1-complete-missing / R1-edit-book / R1-import-presets 全 FAIL
        （xss=1～2，`<img src=x onerror=…>` 真的被建立）
修復後  5 個入口 xss=0、injectedImg=0
```

同時加了**反向斷言**，確認轉義沒有外洩到畫面：

- `R1-render`：詞書名 `A & B "c" <d> 'e'` 在合併清單、編輯欄位都原樣顯示。
- `R1-edit-roundtrip`：`<textarea>` 內容與原資料逐字元相同（`a<b>&"c#意<义>&@/ˈæpl/`）。
- `R1-merge-fn`：合併功能仍能正確去重合併（`apple,banana`）。

### P2：編號格式靜默丟失未完成題目

**核查報告的判斷正確**：`analyzeQAPairs()` 只要舊格式解析出一組就 `return { pairs, warnings: [] }`，繞過所有警告。

**修法**（`features/qa/qa-creator.js`）：

1. `parseLegacyFormat()` 改為回傳 `{ pairs, warnings }`，逐項追蹤：
   - 配對成功 → 進 `pairs`；
   - 有 Q 沒 A（含 `A2:` 空答案）→ `qa.numberedMissingAnswerWarning`（帶題目內容）；
   - 有 A 沒 Q → `qa.numberedEmptyQuestionWarning`；
   - 用 `regex.lastIndex` 追蹤**尾端未被消耗的內容**（`Q2: Lost?` 這種）→ `qa.orphanQuestionWarning`。
2. `analyzeQAPairs()` 在兩行格式也解析不出東西時，保留舊格式找到的警告，不再讓警告消失。
3. **採納核查報告「應在保存前處理」的建議**：`features/qa/qa.js` 兩條保存路徑（`handleSaveQASet`、編輯彈窗 submit）都先呼叫 `confirmSaveWithWarnings()`，彈出「有內容沒有被採用」的確認框，可按「返回修改」留在表單，或按「仍然保存」明確決定。原本只在存完之後用提示條說一句。

**複驗**：

| 案例 | 修復前 | 修復後 |
| --- | --- | --- |
| `Q1: One?\nA1: Yes.\nQ2: Lost?` | pairs=1、warnings=0 | pairs=1、warnings=`qa.orphanQuestionWarning` |
| `Q1: One?\nA1: Yes.\nQ2: Lost?\nA2:` | pairs=1、warnings=0 | pairs=1、warnings=`qa.numberedMissingAnswerWarning` |
| `One?\nYes.\nLost?` | 已有警告（原本就正常） | 不變 |
| `Q1: One?\nA1: Yes.\nQ2: Two?\nA2: Two.` | 無警告 | **仍然無警告**（沒有產生假陽性） |

保存路徑（端到端）：`R2-e` 確認框出現且文案正確 → `R2-f` 按「返回修改」不寫入且原輸入保留 → `R2-g` 按「仍然保存」才寫入，且只存已配對的題目。

新增雙語鍵：`qa.numberedMissingAnswerWarning`、`qa.numberedEmptyQuestionWarning`、`qa.saveWarningTitle`、`qa.saveWarningBody`、`qa.saveAnyway`、`qa.backToEdit`。

### P2：彈窗內的提示被遮罩壓住

**核查報告的判斷正確**：`#message-container` 是 `z-index: 4000`，`.modal-overlay` 是 `5000`，彈窗內發出的提示落在遮罩底下。

**修法（兩層）**：

1. **全域層級**：`styles.css` 把 `#message-container` 提到 `z-index: 6000`，並在註解寫明原因。這一改動同時覆蓋所有「在彈窗裡按鈕 → 出提示」的路徑（模型切換失敗、匯入失敗、抓取失敗…），不只文章匯入。
2. **就地驗證**：文章匯入的「未填網址」改用欄位旁的就地訊息（`#imp-url-error`，`role="alert"`、`aria-invalid`、聚焦輸入框、輸入後自動消失），新增 `.field-error` 樣式。提示條會消失、又貼在畫面底部，不適合當欄位級驗證。

**複驗**：`R3-a` 就地訊息可見、`elementFromPoint` 命中自身、`aria-invalid=true`、在彈窗內；`R3-b` 輸入後消失；`R3-c/R3-e` 提示條層級 6000 > 遮罩 5000、關閉鈕可命中；`R3-d` 用真實滑鼠點關閉鈕能關掉。

> 一點澄清：提示條**本體**仍是 `pointer-events: none`（刻意設計，避免攔截下方按鈕），所以本體位置 `elementFromPoint` 命中下層元素是正常的。核查報告關注的「看得到、關得掉」由層級與關閉鈕保證。

### P2：聽寫批改歷史「清空全部」沒有反應

**核查報告的判斷正確**。事件處理器第一句就是 `const item = e.target.closest('.dg-h-item'); if (!item) return;`，而「清空全部」在 `.dg-h-toolbar` 裡，永遠走不到清空分支。

**修法**：`features/dictation/dictation-grader.js` 的**兩個歷史入口**（右上角選單的外部入口、批改彈窗內的內部入口）都把工具列動作提到最前面處理，再處理單筆項目。

順帶修掉同一檔案裡 `renderReport()` 的 `const esc = (s) => pad(s);` —— 名字叫 `esc` 但只做了字串轉換、**完全沒有轉義**，而表格內容來自 OCR／AI 輸出。已改為真正的 `escapeHtml`。

**複驗**：`R4-a` 外部入口確認框出現、清空成功；`R4-b` 彈窗內入口同樣正常；`R4-c` 單筆「檢視／刪除」沒有被改壞。

### 次要發現：OCR 完成態按鈕文字

**核查報告的靜態判斷正確**：`setBusy(true, 完成文字)` 之後 `finally` 同步執行 `setBusy(false)`，完成文字一瞬間就被還原。

**修法**：`features/ocr/ocr.js` 改為在 `finally` 的 `setBusy(false)` **之後**才呼叫新的 `flashRunButtonLabel(text, 2200)`，並在期間若又開始新一輪就讓 `setBusy` 接管。

**複驗**：`R5` 全失敗情境下，識別一結束按鈕文字是「识别失败」（不是「识别文字」）。

## 九、如何重跑

```bash
# 1. 起站（專案根目錄）
python3 scripts/serve.py --port 8400

# 2. 這台機器沒有區域安裝 playwright，需要指定全域模組與可用的瀏覽器
export PLAYWRIGHT_MODULE="$(npm root -g)/@playwright/cli/node_modules/playwright"
export CHROME_PATH="$HOME/Library/Caches/ms-playwright/chromium_headless_shell-1234/chrome-headless-shell-mac-arm64/chrome-headless-shell"
export PORT=8400

# 3. 本輪專項複驗（28 項）
node tests/audit-review-report.cjs

# 4. 靜態掃描
node tests/audit-html-sinks.mjs --list=review
node tests/audit-i18n.mjs

# 5. 既有巡檢（全部）
for t in security data locale regression e2e flows; do node tests/audit-$t.cjs; done
```

> 注意：本機 `python3 scripts/serve.py --lan` 起站時，`/ai-config.js` 對同網段裝置同樣可讀（含 14 組金鑰）。僅供本機開發使用。
