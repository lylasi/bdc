# 擴充套件 TTS 設定、播放來源與回退診斷

擴充套件版本：0.6.6。測試日期：2026-11-07。正式發布資源版本：`8ca1454b7ffa`。本次程式碼已推送 GitHub master，149 已更新，內網與公網 208 項資源核對全部通過。

舊版擴充套件沒有 TTS 設定入口，且主站與擴充套件使用不同來源的儲存空間。擴充沒有配置服務或服務無法播放時，會用 Web Speech 裝置語音；原有挑選方式可能直接選到清單首個 English 聲音（macOS 的 Albert），產生使用者描述的機械音。無法只憑使用者截圖確認其實際回退原因，因此新版直接提供可檢查的播放來源及錯誤原因。

## 使用方式

1. 重新載入擴充套件並重新整理閱讀網頁；詞卡按設定圖示，展開「語音 / TTS」。也可直接點詞卡下方的聲音來源文字。
2. 選擇「優先 TTS 服務，失敗時使用裝置語音」，填入 BDC 主站使用的 TTS **基礎地址**及可選 Key；不填 `/tts` 或查詢參數。
3. 選英語朗讀首選；按「讀取服務聲音」或直接填入服務支援的聲音 ID。可另外選擇裝置英語後備聲音。
4. 按「試播並檢查」。只有實際開始播放服務音訊，才顯示「TTS 服務播放成功 · 服務主機 · 所選聲音」。成功讀取聲音清單本身不會顯示播放成功。
5. 服務失敗時會顯示回退原因及實際裝置聲音；也可明確選擇「只用裝置語音」。所有設定會自動儲存，不設額外儲存按鈕。

詞卡保留一行小型聲音來源提示，詳細設定按需開啟。來源文字及詳細狀態不包含 API Key、URL 私人路徑或查詢字串。擴充內的 Key 輸入欄會遮蔽內容，設定只儲存在擴充套件的本機設定／secrets，不會打包到安裝檔。

## 實作與判定

- 沿用共用 `modules/audio.js`、`modules/settings.js` 及聲音清單正規化，不新增另一套播放引擎。`tts.extensionMode` 只控制擴充套件，既有主站 `tts.use` 保持原來的 remote/local/custom 行為。
- 設定表單與播放引擎共用基礎地址解析，兼容舊 remote/local/custom 選項。清空自訂地址後不會偷偷使用別個服務。
- 裝置聲音優先考慮英語地區、系統預設及自然音色，降低趣味機械音色的自動順位；使用者明確手選的聲音仍會使用。沒有英語聲音時不會把中文預設聲音冒充已選的英語聲音。
- 播放狀態回傳安全的來源、主機、所選服務聲音／實際指定裝置聲音及回退原因。服務的音色 ID 表示請求傳送的聲音參數；服務端是否自行換音色仍由服務實作決定。
- `canplay` 只代表媒體可播放，不視為已開始。服務播放的 `playing` 事件或成功的 `play()` Promise 才確認開始播放；裝置語音使用 utterance 的 start/end/error。
- 擴充套件服務首次等待限時 10 秒。停止、關閉、換頁或換設定會使舊請求失效，遲到的拒絕不會再觸發後備語音。共用引擎的其他呼叫預設等待限時為 15 秒。
- 服務清單只讀取當前服務的 `/voices`，不以靜態檔案或其他服務快取冒充連線成功。清單 401 能顯示 HTTP 狀態；媒體元素沒有暴露 HTTP 狀態時只回報音訊載入失敗，不臆測為某個狀態碼。
- 自動儲存的提示放在試播按鈕下方，避免 blur/change 更新狀態時移動按鈕而丟失點擊。
- 所有新增介面文字同時完成 zh-CN 及 zh-HK；未增加擴充套件權限。
