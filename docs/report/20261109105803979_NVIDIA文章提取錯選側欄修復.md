# NVIDIA 文章提取錯選側欄修復

- 日期：2026-11-09
- 來源：[Statement from NVIDIA Board of Directors](https://nvidianews.nvidia.com/news/statement-from-nvidia-board-of-directors)
- 修改：`extension/page-extractor.js`
- 回歸測試：`tests/extension-page-extractor.cjs`

## 原因與重現

來源頁面以 `div.article > div.article-body` 放置正文；右側「More News」以 `article.index-item` 放置相關新聞卡片。

舊提取器只搜尋 `article`、`main`、`[role="main"]` 和 `[itemprop="articleBody"]`，然後按 `innerText` 長度選出一個容器。這頁沒有符合舊選擇器的正文容器，五個候選全部是右側新聞卡片。最長的 Oracle 新聞標題因此成為唯一的提取結果；六段正文在呼叫 AI 前已經遺失。這與使用者截圖完全一致。

已在實際來源頁面比較修改前後結果，見 [live-extraction.json](assets/20261109105803979_nvidia-extraction/live-extraction.json)。

## 修正

1. 在頁面副本中先移除導覽、側欄、相關新聞區、隱藏內容、表單及擴充套件介面，再選正文，避免干擾候選評分。
2. 加入 `.article`、`.article-body`、`.entry-content` 等常見正文容器，並支援多值 `itemprop`；同時考慮主標題的祖先容器。
3. 依段落內容、連結比例及主標題關聯評分。只有標題／連結的新聞卡片不會因標題較長而勝出；分數相同時優先較小的正文容器。
4. 保留純文字後備路徑、段落及列表格式、來源網址／標題，以及 100,000 Unicode 碼點的上限。操作不改動來源 DOM。

函式仍完全自包含，適用於 `chrome.scripting.executeScript({ func })`，沒有加入外部依賴或新的 UI 文案。

## 使用方式

修正位於工作區的 `extension/` 目錄，共享檔已重新打包。瀏覽器載入這個更新後的目錄並重新載入擴充套件後，在來源頁面再次按「AI 提取本頁文章」，即可重新產生完整正文預覽。舊預覽需要重新提取。
