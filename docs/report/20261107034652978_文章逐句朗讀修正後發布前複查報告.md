## 三、問題清單

**無阻擋問題（P0／P1／P2 皆無）。**

以下四點為 **非阻擋觀察**，不影響發布，可列入後續：

1. **P4／ARIA 結構**：`index.html:1649` 的提示節點是 `<p role="status">`，位於 `role="menu"`（`index.html:1648`）之內。ARIA 規範中 `menu` 的子節點應為 `menuitem`／`group`／`separator`；部分螢幕閱讀器可能不按預期朗讀，或把提示當成菜單項。建議改放 `role="none"`，或把提示移出菜單並以 `aria-describedby` 關聯。功能與鍵盤操作不受影響（我實測方向鍵僅在按鈕間移動）。
2. **P4／zh-HK 用詞並存**：修改後 `readSelection`（`locales/zh-HK.js:901`）用「選取」，但同檔既有 `analyzeSelection`「解析選中內容」、`addSelectedToWordbook`「加入生字簿（選中）」仍用「選中」。非本次退步，僅為一致性議題。
3. **P4／防禦性分支**：`article.sentenceNotReadable`（`features/article/article.js:5145`）在現行渲染路徑下不易經 UI 觸發（純圖片段不產生入口、表格與一般段落都會進入 chunk），屬保險用；兩份字典皆有鍵，無缺鍵風險。
4. **P4／健壯性**：`features/article/sentence-actions.js:53` 直接假設 `.article-sentence-menu-hint` 存在（目前只有 `index.html` 提供）。若日後有頁面沿用菜單 markup 而漏掉提示節點，`refreshSentenceActions()` 會拋錯；可順手加 null 防護（非本次必要）。
