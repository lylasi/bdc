## 3. 環境與方法

- Playwright + 系統 Chrome，headless，**每個案例獨立 context**（不共用使用者設定檔／登入態）。
- `context.route` 只放行 `127.0.0.1` / `localhost`，其餘外站（TTS、同步、AI）一律 `abort`；`serviceWorkers: 'block'`。
- 資料以 `addInitScript` 寫入隔離 context 的 `localStorage`（`vocabularyBooks`、`activeBookId`、`pen_global_settings`），**不改寫已儲存的教材原文或使用者詞書名稱**；四種標題字串原樣使用（含使用者截圖中的英文段落）。
- 未呼叫 `ai-config.js` 內任何端點；`SYNC` 因外站封鎖無法連出，等同空同步。
- 每案例量測：標題行數／寬高、`scrollWidth vs clientWidth`（水平截斷）、`scrollHeight vs clientHeight`（垂直截斷）、`title`／`aria-label` 是否保留全文、標題列內元素兩兩重疊面積、chip 是否被擠出面板內容盒、chip 排成幾列、頁面與面板水平溢位、清單列水平溢位、來源橫幅與篩選列是否互相重疊、`.word-sources-btn` 圓形比例、所有 SVG 圖示寬高比。

## 6. 發現與（可選）最小修改建議

### 6.1 v1 → v2 已修：平板雙欄的 chip 落單

- 視口 1024／1080、面板內容寬 404–460px，五顆 chip 合計 432px（含 gap）→ 折成兩列，「刪除」單獨落單。
- v2 以 `@container vocabulary-words (max-width: 480px)` 收合成「更多」選單，實測 900/960（面板較寬）仍顯示 5 chip 一列，1024/1080 走選單，無任何折行。**判定：通過，無需再改。**

### 6.2 觀察（非阻斷）：寬螢幕短標題多佔 39px 高

- `≥720px` 時操作 chip 一律獨立一列：短標題標題列 77px（修正前 38px）。
- 這是「標題與 chip 不再爭同一列」的必然代價，換來的是任何長度標題都不會錯位；不建議為短標題回到同排（會重新引入擠壓風險）。若在意密度，可只在面板內容寬 ≥ 640px 且標題單行時才同排，但需再驗一輪。

### 6.3 觀察：文章閱讀記錄的標題截斷後沒有全文入口

- `styles.css:3675 .ar-history-title` 為 `nowrap + ellipsis`，由 `features/article/article.js:4258` 產生，**未設 `title`／`aria-label`**；滑鼠使用者無法取得被截斷的完整文章標題（螢幕閱讀器仍可讀到按鈕名稱）。
- 最小修改：在該 `<span>` 加上 `title="${escapeAttr(title)}"`。
- 本次未實測（閱讀記錄需真實分析文章，離線 headless 不可達），此為靜態碼檢視結論。

### 6.4 觀察：QA 卡片長名稱在手機變很高

- 使用者自建問答集名稱若是整段文章，320px 下 `.qa-set-name` 為 8 行（160px 高）、390px 為 6 行；無水平溢位、不與「題數」重疊、卡片不溢位。
- 屬既有行為（本次未改），可選最小修改：`.qa-set-name` 加 2 行 clamp + `title` 屬性。

### 6.5 觀察：文章庫卡片標題不設行數上限

- 預置 30 篇文章的真實標題皆不截斷；注入 247 字元長標題後 320px 變成 8 行（卡片變高，但無溢位、無遮擋）。是否需要 clamp 由產品決定，非本次問題。

### 6.6 測試環境現象（非本次 UI 修正造成）

- 隔離環境以 `localStorage` 種入 legacy 詞書時，主控台會出現 `[bdc] 閱讀資料遷移失敗: verify_vocabulary_failed`，畫面同時彈出「閱讀資料遷移失敗，舊資料仍保留」提示（`reading-store.js:3403`）。
- 此現象只在「有 legacy 資料 + 無同步後端」的種子情境出現，不影響本次版面結論（畫面其餘部分正常），但建議另案確認 `verify_vocabulary_failed` 的觸發條件是否需要更精確的錯誤說明。
