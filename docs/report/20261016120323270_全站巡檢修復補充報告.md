## 一、本輪新增修復

### N1. 引導彈窗正文是硬編碼繁體，在簡體介面下顯示錯誤

**位置**：`features/vocabulary/vocabulary.js` → `showNoBookOnboarding()`

開啟頁面第一眼就會看到：標題「开始之前」、按鈕「稍后 / 登录 / 导入单词本」都是簡體，但**正文兩行是繁體**：

```
目前還沒有任何單詞本。
建議先「導入單詞本」或「新建單詞本」，之後就可以在學習 / 默寫 / 測驗等功能中使用。
```

原因是這兩行直接寫死在 `dom.modalBody.innerHTML` 的樣板字串裡，沒有走 `t()`。

**修法**：改用 `t('vocabulary.onboardingEmpty')` / `t('vocabulary.onboardingSuggestion')`，兩份字典都補齊。

### N2. 同一類問題還有 7 處（合併彈窗、聽寫批改彈窗、QA 報告）

| 檔案 | 原本寫死的文案 |
| --- | --- |
| `features/vocabulary/vocabulary.js` | `選擇要合併的單詞本 (至少2個)`、`合併預覽`、`已選單詞本:`、`去重後總詞數:`、`合併後刪除已選單詞本` |
| `features/dictation/dictation-grader.js` | `上傳相片：`、`選項：`、`批改方式：`、`OCR 模型：`、`AI 提示詞：` |
| `features/qa/qa.js` | `AI 正在校對本題...`、`問題:`、`標準答案:` |

全部改為 `t()`，並補上對應雙語鍵（`vocabulary.merge*`／`dictationGrader.*Label`／`qa.checkingThisQuestion`／`qa.standardAnswerLabel`）。

複驗（同一份頁面分別以 zh-CN / zh-HK 開啟）：

```
zh-CN 合併彈窗: 选择要合并的单词本（至少 2 个） … 合并预览 … 已选单词本： 0 去重后总词数： 0 …
zh-HK 合併彈窗: 選擇要合併的生字簿（至少 2 個） … 合併預覽 … 已選生字簿： 0 去重後總詞數： 0 …
zh-CN 批改彈窗: 上传相片： … 选项： … 批改方式： … OCR 模型： …
zh-HK 批改彈窗: 上傳相片： … 選項： … 批改方式： … OCR 模型： …
```

### N3. 舊掃描器漏報這整類問題（工具已補強）

`tests/audit-i18n.mjs` 原本是**逐行**掃描，而且只挑「整行都是中文」的字面值。上述文案有兩個特徵讓它全部漏掉：
1. 內容在**跨行的樣板字串**裡；
2. 字串同時含 HTML 標籤，不符合「純中文」的判斷。

**修法**：新增一項檢查「HTML 標籤內直接寫死中文」（對整個檔案內容做匹配，不逐行）。加上這項後，主應用回報 0 處；剩下 8 處都在獨立頁面 `phonetic-chart/`（該頁本來就只有簡中介面，與 SPA 的 i18n 體系無關，對應首份報告的 L8）。

### N4. 本機伺服器連線佇列過小，造成間歇性模組載入失敗

**位置**：`scripts/serve.py`

巡檢期間出現間歇性的 `net::ERR_CONNECTION_RESET` / `ERR_SOCKET_NOT_CONNECTED`，每次命中的模組都不同，症狀是「偶爾有模組沒載入、初始化只完成一半」。

`socketserver.TCPServer.request_queue_size` **預設只有 5**，而這個頁面一開場就會平行抓大約 60 個 ES module；佇列一滿，核心直接丟掉多餘連線。

**修法**：新增 `DevHTTPServer(ThreadingHTTPServer)`，把 `request_queue_size` 提到 128，並設 `daemon_threads` / `allow_reuse_address`。

> 附帶更正：首份報告提到「8313 埠的 preview.py 併發時會 ERR_CONNECTION_RESET」——同樣的症狀在 `serve.py` 上也存在，根因是這個 backlog，不是那個伺服器獨有。

## 二、巡檢腳本自身的缺陷（一併修正）

本輪也修掉幾個讓結果失真的測試問題，否則會持續產生假陽性或無謂耗時：

| 問題 | 影響 | 處置 |
| --- | --- | --- |
| `addInitScript` 每次導覽都執行，會把測試剛寫入的狀態清掉 | 把真實的持久化缺陷掩蓋成「正常」 | 加 sessionStorage 哨兵，只播種一次 |
| 同一頁註冊兩個 `dialog` handler（一個 accept、一個 dismiss）互相搶答 | 「按取消」被誤判成「按確定」 | `makeCollector` 支援 `dialogMode`，同頁只留一個 |
| 假 `speechSynthesis` 在 `speak()` 內同步觸發 `onend` | 文章朗讀流程誤判為已播完，浮動朗讀列「不出現」的假陽性 | 改為可選（`stubTts`），預設不裝 |
| `--only=corrupt` 沒設 `vocabImportPromptShown` | 引導彈窗蓋住導覽列，每次點擊都等 Playwright 的 30 秒逾時 | 補上該旗標；`clickModule` 改短逾時並先關閉站內彈窗 |
| 上述逾時拖慢整體 | `audit-e2e` 單次執行 **4 分 24 秒** | 修好後 **54 秒**（已加入分階段計時輸出） |

另外把「OCR 失敗細節要讀 textarea 的 `.value` 而非 `textContent`」、「完成訓練要處理站內確認框」、「訓練預設是『一次列出全部』，驗證逐題需先選 `layout=single`」等斷言同步到新行為。
