## 量測方法與範圍

- 每個情境在全新的 browser context 開啟 `?perf=1`（以既有 module 路由進入文章模組），以 route mock 回應段落翻譯／查詞／助手，不連真實 AI／TTS／同步端點。
- `analyze` 量的是「按下分析 → 所有段落 render 完成」；包含既有 400ms 段落間隔與併發上限（產品現行行為），不是純渲染時間。
- 點詞延遲量的是「點擊 → tooltip 外殼可見（含下一個動畫框）」；查詞本身仍是非同步請求，但 tooltip 載入殼會先顯示，因此不是 AI 回應時間。
- long task 由瀏覽器 Long Tasks API 取得（`PerformanceObserver({type:'longtask'})`）；不支援時標示 `unavailable`，不當成 0。
- DOM 數以 `document.querySelectorAll('*').length` 計算，`.interactive-word` 以 querySelectorAll 計數；皆為該情境最終畫面。
- 助手 context 以「實際放進 messages 的字元長度」計；每輪請求數在真正送出 provider 請求時累加。
- 報告只寫字數／段數／耗時／數量，不寫入文章內容、句子或助手訊息。

## 限制

- 只量測前端成本（DOM、分詞包字、tooltip 顯示、context 組裝），不代表供應商網路或模型延遲。
- 測試使用 route mock 固定回應；mock 延遲與真實供應商差異很大，數字不可用來推論線上等待時間。
- long task 由瀏覽器 Long Tasks API 提供，Safari／Firefox 支援不一致；不支援時標示 unavailable，不當成 0。
- 單一機器、單一瀏覽器、單一視窗大小的結果；不可宣稱代表所有裝置或所有長文。
- 點詞延遲量的是「點擊到 tooltip 外殼可見」（含下一個動畫框），不是 AI 回應時間。
- analyze 量測含既有 400ms 段落間隔與併發上限（產品現行行為），不是純渲染時間。
