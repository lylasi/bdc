# 文章私人網址與刷新恢復驗收報告

日期：2026-10-28（Asia/Shanghai）。依據：[已確認範圍](../decision/20261028012124668_文章私人直達與刷新恢復範圍.md)。

## 完成行為

- 已保存文章可用 `/#a/<encodedArticleId>` 直達；開啟閱讀記錄或保存分析後自動更新網址，沿用既有 ID，包括 `local:`、`url:` 等舊身份。
- 刷新、書籤、瀏覽器返回／前進會恢復指定文章的原文及已保存詳解。一般 `/#a` 入口提供「繼續閱讀〈上次標題〉」，由使用者選擇續讀。
- 輸入時先同步寫入本分頁的 sessionStorage 備援，再以 600ms debounce 寫入本機文章草稿；換篇、切到背景及 pagehide 也會嘗試保存。每篇草稿分開保存，恢復後保留原文章 ID，包括刻意清空正文的草稿。
- 草稿恢復會明確提示「文章內容仍未保存，已有詳解對應保存時的原文」；輸入與保存原文不一致時，沿用既有「原文已修改，畫面仍是舊版分析」提示。
- 本機缺少指定文章時，只補讀該篇私人文章；不推進一般同步游標、不覆蓋本機待同步修改、不復活待刪除文章。登出、帳戶／同步端點切換及較晚返回的請求均有範圍與世代檢查。
- 無效 ID、未登入、未設定同步服務、文章不存在、離線、網絡及儲存失敗均有對應狀態與恢復入口。手機上的續讀／錯誤提示放在編輯器上方。

## 使用界限

私人網址跨裝置開啟需要相同同步服務、相同帳戶，以及文章已同步到服務端。只有本機保存的文章可在原裝置離線恢復；草稿與最近閱讀指標不跨裝置同步。

恢復文章不會自動重跑 AI、延續音訊或恢復精確捲動位置。清除瀏覽器資料會移除本機草稿；分頁備援也受瀏覽器儲存可用性限制。持久草稿寫入失敗會顯示錯誤，不宣稱已完成保存。

首次驗收時未修改私人 `ai-config.js`，亦未提交或部署；後續按使用者「提交並更新 149」的指示進行隔離發佈。工作區同時進行的閱讀記錄側欄修改及其文件保持原狀，本報告的驗收範圍為文章私人網址與刷新／草稿恢復。

## 隔離發佈驗收

使用 `c9c4d1b` 建立獨立 worktree，只合入本輪文章私人網址與草稿恢復，不包含正在修改的閱讀記錄側欄。重新產生資源版本 `d03f41ce94d5`（88 個模組）並通過 `--check`。隔離版本的 `tests/release-asset-versioning.cjs` 18 項全部通過，包含筆記編輯與 scope 重載；文章 scope 4 項與刷新 scope 10 項亦通過。

發佈驗證時修正新導航測試的等待方式：Playwright `waitForFunction` 會將非同步 predicate 的 Promise 物件視為 truthy，改為等待 `page.evaluate` 結果後輪詢，確實等到文章／身份／草稿條件成立。修正後 19 個場景全部通過。此項只修改測試，不修改功能實作。測試另支援 `BASE_URL`，可在正式靜態站以隔離資料和 mock 服務重跑。

簡繁字典各 2054 鍵一致；13 個 JavaScript／測試語法、差異檢查通過，原有 i18n 警告如前述。正式更新結果見[149 部署記錄](../release/20261028072011245_文章私人網址與草稿恢復149部署記錄.md)。
