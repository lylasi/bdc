# 舊網址文章同步失敗修復報告

## 問題與證據

使用者手機顯示 `文章同步失败：legacy_verify_missing`（2026-11-02 20:55:32，快照 v280）。本機備份的 localStorage quota 問題已由 `741e4c9` 另行修復；這次是文章身份對應錯誤。

正式 D1 的唯讀彙總：該帳戶共 21 篇文章，8 篇的內部 ID 不同於 legacy_article_id，亦有 8 篇舊 ID 含嚴格 ID 格式不接受的字元。刪除筆數 0，最長舊 ID 139 字元，最大文章 40,846 bytes。未讀取／輸出文章內容、登入憑證或筆記內容。

舊版以 `url:` 加 encodeURIComponent(網址) 作 ID。Worker 匯入時為含百分號的 ID 產生新儲存 ID，但原本的 batch 只查新 ID，前端核對使用舊 ID，導致文章已寫入仍回報缺失；重試被 skipped 後再次核對缺失，形成永久失敗。舊 mock 永遠保留輸入 ID，沒有覆蓋實際後端的轉換。

## 修復

- 對外文章身份保留 legacy_article_id；SQL 寫入、版本與 change log 維持既有儲存 ID。API 接受兩者查詢並在批次去重，所有查詢維持 owner_user_id 隔離。
- 全量與增量列表提供相同公開身份，並附 storageId，後續修改、刪除、還原先解析到原儲存列，不複製文章。
- 前端在後端宣告 identityVersion=1 後做一次完整核對。已下載新 ID 的裝置保留待上傳修改，完成後再清理已同步副本。
- storageId 對應存入文章文件與摘要；閱讀條目、文件、會話、詞書來源及匯出同時識別兩個 ID。既有閱讀實體不可變的 articleId 保留，不重寫筆記內容。
- 舊 URL 私人書籤可開啟；既有內部 ID 書籤也可找到同一原文章。

## 驗證

新增真實 Worker + SQLite + 前端儲存／outbox 的回歸，覆蓋首次匯入、已匯入跳過、回應遺失後修改、同步期間修改、舊 ID／內部 ID 書籤、舊裝置升級與筆記關聯、尚未上傳文章的保護及跨帳戶隔離。Worker／selfhost 共用協議測試另驗證讀取、增量、修改、刪除、還原與隔離。

部署與完整測試結果另記於 docs/release 發布記錄。真機重新同步結果仍須由原手機原網域確認，不能以測試帳戶或資源雜湊代替。

已完成的測試：Node 綜合測試 222 通過、0 失敗、6 項 PostgreSQL 因未設定連線略過；最後修正後的身份／匯入／代際測試 62 通過。真實 selfhost 瀏覽器文章同步、閱讀同步、備份還原、lazy load、雙語導覽 21 情境與 release asset versioning 均通過。i18n 兩份字典各 2189 鍵，單邊缺鍵與插值差異均為 0；整庫掃描含既有 worktree 的動態鍵提示，並非本次新增 UI 文案。
