## 一、根因

### P2-T6：播放與下載共用同一個「可用」假設

- 朗讀（`audio.speakText`）在未設定遠端 TTS 時有本機語音後備；下載（`audio.downloadTextAsAudio`）沒有後備，但 UI 仍把它當成和播放同等可用：
  - `#download-audio-btn` 的 `title`／`aria-label` 只由靜態 `data-i18n-*` 決定，未反映「需要遠端 TTS」。
  - `downloadAudio()` 直接組 URL 並以 `<a target="_blank">` 開連結，沒有能力檢查、沒有範圍說明、沒有長度上限，也不區分「已開啟連結」與「已下載完成」。
  - `downloadTextAsAudio()` 沒有回傳值，呼叫端無法得知是否真的把連結交給瀏覽器；錯誤只能靠 try/catch，且沒有避免把含 `api_key` 的 URL 帶進訊息。
- 結果：未設定 TTS 時按「下載語音」會開空白／失敗分頁；全文長文沒有事前阻擋；使用者不知道下載的是全文、本段還是本句，也不知道會連到哪個服務。

### P2-T7：兩個匯出入口行為不一致

- 頂部 `#article-reading-export-btn` 直接匯出 note-only Markdown，沒有任何預覽。
- 面板 `#reading-export-md` 讀取面板 checkbox（`#reading-export-fulltext`、`#reading-export-chat`）後直接匯出；面板 `#reading-export-json` 直接完整備份。
- 兩個入口的預設與可選項不同，使用者在按下按鈕前無法知道會匯出多少記錄、哪個原文版本、是否包含全文與對話。
- 缺少「只描述範圍、不產生檔案」的查詢：`reading-export.js` 只有真正產生 Markdown／備份的函式，UI 只能先匯出才知道內容。

## 二、改法

### P2-T6

1. `modules/audio.js`
   - 新增 `describeTtsTarget()`：以 `getEffectiveBaseUrl()` 取得有效 TTS base URL，回傳 `{ configured, host }`；`host` 只取 `URL.host`（含 port），不含 path、query 或 `api_key`。`configured` 直接沿用 `isRemoteTtsConfigured()`，避免 UI 與播放判定分歧。
   - `downloadTextAsAudio()` 不改 GET 協定（D4 既有決策），改為回傳 `{ ok: true, url }` 或 `{ ok: false, error }`；錯誤訊息只帶例外交付錯誤，不記錄、不回傳到 UI 的可見文字。
2. `features/article/article.js`
   - 新增 `updateDownloadAvailability()`：依 `describeTtsTarget().configured` 設定 `#download-audio-btn` 的 `title`／`aria-label`（可用＝`article.downloadAudio`，不可用＝`article.downloadNeedsRemote`），並以 `data-download-unavailable` 標記；**不隱藏按鈕**。
   - `initArticle()`、`bdc:locale-change` listener 都呼叫 `updateDownloadAvailability()`；另監聽 `bdc:settings-change`，使用者改 TTS 設定後立即反映。
   - 重寫 `downloadAudio()`：
     1. 先檢查 `describeTtsTarget().configured`，未設定只顯示 `article.downloadNeedsRemote`，不開分頁。
     2. 以 `buildReadingChunks()` 決定全文／本段／本句的文字。
     3. 以 `audio.buildTTSUrl(...)` 的 `t` 參數長度估算（`estimateDownloadCharCount()`）；全文超過 `DOWNLOAD_FULL_TEXT_LIMIT = 1800` 字元時，以 `article.downloadLongText` 阻擋，建議改用段落／句子。
     4. 以 `ui.confirmAction()` 顯示 `article.downloadScope`（插值範圍）＋ `describeTtsTarget().host`；取消即返回。
     5. 確認後才呼叫 `downloadTextAsAudio()`；成功只提示 `article.downloadLinkOpened`（「已開啟下載連結；是否完成由瀏覽器及服務決定」），失敗提示既有 `article.downloadAudioFailed`。`console.error` 只記錄錯誤名稱，不記錄 URL。
   - 說明：長度檢查刻意放在確認框之前（計劃文字列在確認之後），否則全文長文會先彈確認再被拒，與驗收「全文被阻擋、句子模式可進確認」不一致；行為與驗收一致。

### P2-T7

1. `modules/reading-export.js`
   - 新增 `describeReadingScope(articleId)`：與 `buildReadingNoteMarkdown` 一樣在入口捕捉 `readingStore.captureReadingContext()`，呼叫 `readingStore.exportArticleReading(articleId, ctx)` 取得**同一交易快照**，只回傳摘要：
     `{ ok, title, contentVersion, itemCount, noteCount, documentCount, conversationCount, messageCount, pending, conflictCount }`。
   - 不產生 Markdown、不寫檔；交易前後都檢查 context，切 scope 回 `stale_scope`；沒有文章回 `article_not_found`。
   - `noteCount` = 有筆記文字的學習條目 + `kind === 'note'` 的文件；`messageCount` = 此文章會話下的訊息數。
2. `features/article/reading-panel.js`
   - 新增 module 變數 `exportSelection = { fullText, chat }` 作為兩個入口共用的「上次選擇」；面板 checkbox 只同步這個變數，不直接決定匯出內容。
   - 新增 `openExportDialog({ source })`：
     - 先 `readingExport.describeReadingScope(currentArticleId)`；讀取期間切文章／帳戶則不開對話框。
     - 使用 `ui.showOptionsModal()`（已確認 `getOptionsResult()` 對 checkbox 回傳 `{ key: boolean }`）：
       - 標題 `article.exportScopeTitle`。
       - 摘要：文章標題、`article.readingExportVersion`＋版本短碼、`article.exportScopeSummary`（items／notes／messages 插值）；note-only 時附加 `article.exportNoteOnly`。
       - checkbox `fullText` → `article.exportIncludeFullText`；`chat` → `article.exportIncludeChat`；`fullBackup` → `article.exportFullBackup`（文案已含「目前帳戶／端點；檔案較大」）。
       - 預設沿用共用記憶（首次為 note-only，fullText／chat 未勾）。
     - 對話框內變更勾選時即時更新摘要（勾選全文／對話／完整備份後移除 note-only 說明）。
     - 確認後：一般匯出呼叫 `exportReadingNoteFile({ articleId, includeFullText, includeChat })`；完整備份呼叫 `exportFullBackupFile()`。兩者都先 flush 面板筆記草稿與片語草稿，失敗即不匯出；flush 後若 `currentArticleId` 已變更則不寫檔。
   - 頂部 `#article-reading-export-btn` 與面板 `#reading-export-md` 都改呼叫 `openExportDialog()`；面板 `#reading-export-json` 保留既有直接完整備份（P2-T7 未要求變更，避免擴大改動）。
   - 無文章時顯示 `article.readingNoArticle`，不建立對話框。
   - 保留面板 checkbox 作為「上次選擇」的視覺記憶，面板重建（locale 切換）後由 `syncExportSelectionUI()` 重套。
3. 翻譯鍵（zh-CN／zh-HK 同步新增，插值參數一致）
   - `article.downloadNeedsRemote`、`article.downloadScope`（`scope`）、`article.downloadLongText`、`article.downloadLinkOpened`
   - `article.exportScopeTitle`、`article.exportScopeSummary`（`items`／`notes`／`messages`）、`article.exportNoteOnly`、`article.exportIncludeFullText`、`article.exportIncludeChat`、`article.exportFullBackup`

## 五、殘留風險與後續

1. **GET + `api_key` 仍在 URL**：本期依 D4 只避免在 UI／console 顯示；要根本移除需服務端支援 POST／header 或短時效下載票證。
2. **1800 字元門檻是常數**：不同 TTS 代理的長度上限不同；若實測過嚴／過鬆，調整 `DOWNLOAD_FULL_TEXT_LIMIT` 即可，無需改流程。
3. **面板 `#reading-export-json` 仍直接完整備份**：P2-T7 只要求統一頂部與面板 Markdown 兩個入口；JSON 直接入口保留既有行為，未加範圍預覽。若要求「所有匯出都先預覽」，下一步可讓它呼叫 `openExportDialog({ source: 'json' })` 並預勾 `fullBackup`。
4. **版本文案重用既有鍵**：對話框的版本行使用既有 `article.readingExportVersion`，未新增 `exportScopeVersion` 鍵；`article.exportFullBackup` 文案內含「檔案／文件較大」，未新增額外說明鍵。
5. **額外回歸觀察（非本次要求）**：
   - `tests/reading-panel-scope-refresh.cjs`：34/36。失敗的兩個是同一情境（desktop／mobile）在等 `#word-analysis-tooltip .btn-note-item` 可見；P2-T2 已把「寫筆記」收進預設收起的「更多」，且該測試未 mock AI，屬其他會話 WIP 的既有測試落差，與本次下載／匯出改動無關。
   - `tests/floating-player-and-icons.cjs`：未 mock AI，句子譯文為空、句卡等待逾時；同屬環境／既有測試條件問題，未列入本次驗收結論。
6. `describeReadingScope()` 與真正匯出各自捕捉 context；正常情況下中間切帳戶會由後續 `buildReadingNoteMarkdown()`／`buildFullBackup()` 回 `stale_scope`，不會寫錯帳戶；但「摘要」與「實際匯出」之間若資料被同步更新，數量可能與最終檔案有微小時間差，屬快照語義的預期行為。
