## 已修復的行為

| 原問題 | 修復後行為 |
| --- | --- |
| 重複單詞總是取第一句 | 以真實 DOM Range 的字元位置定位句子；純函式及注入版共用同一套邏輯，支援巢狀文字及輸入框選區 |
| 改 word 後查詢按鈕卡住，其他輸入顯示舊答案 | word、原句、context、語言、提取新選區、帳戶及端點改變均取消舊查詢、清除當前結果及恢復按鈕 |
| 舊擴充頁把新端點的 token 送往舊端點 | 既有認證及 AI profile 都即時讀取同一份擴充套件端點，切換時先退出原會話，其他頁面跟隨 storage 訊號 |
| 內容腳本可讀 chrome.storage.local 的會話備份 | 刪除可重放 token 的備份；會話只保存在擴充套件 origin 的 localStorage，chrome.storage.local 另限制為 TRUSTED_CONTEXTS |
| 同 provider id 換上游命中舊快取 | 結構化查詞快取加入上游 apiUrl、協議、認證模式及 managed catalog 版本，另保留帳戶、同步端點、模型、原句、context、語言、提示及 thinking |
| 備援模型回答卻標成主模型 | 正常結果及快取均保留實際回答者的 provider/model |
| 無效回應被當釋義及快取 | 擴充套件共用入口要求結構化有效釋義；非 JSON、空義及錯誤型別不寫快取，錯誤使用雙語文案。主站既有非嚴格文字後備流程仍可使用 |
| 下載個人 Key 失敗仍宣稱同步完成 | 每個供應商保存下載錯誤，整體狀態如實反映失敗，保留既有 Key，可重試恢復；介面不再推斷密鑰一定只在網站本機 |
| 提交共享副本後可能漏 ai-config.js | extension/modules、locales、shared、_locales 及生成的 ai-config.js 均為產物；安裝前執行打包，唯一源碼仍在原 modules/locales/shared |

## 安裝及連接

在此工作樹根目錄執行：

```bash
node scripts/package-extension.mjs
```

然後在 Chrome／Edge 的擴充套件管理頁開啟開發人員模式，選擇「載入未封裝項目」，載入 `/Users/linus/CODE/bdc-extension-ai-proof-20261105/extension`。

同步服務地址由使用者輸入。介面提供帳戶密碼、通行碼及一次性登入碼，沿用既有 Worker API；連接後取得 snapshot 的 AI 設定、managed catalog 及可同步的個人憑證。只存在網站本機的個人 Key 需明確手動匯入，按服務地址及帳戶隔離。managed Key 只留在記憶體。

選詞後打開擴充套件 popup 並提取當前選區，或在擴充頁直接輸入詞、原句及附近語境。只有詞時使用 wordAnalysis；有原句時使用文章單詞語境任務；短語使用文章短語任務。請求仍走 modules/api.js、共用 prompts、thinking 與 ai-protocols，沒有另外複製供應商 HTTP 實作。

打包只讀 ai-config.example.js；不讀私有 ai-config.js。生成檔以原子寫入產生，避免多個測試同時打包讀到不完整副本。Node 測試亦從生成的擴充套件模組載入，所以不需要本機私有配置。Chrome 的 manifest 繁體 locale 使用其支援的 zh_TW 槽位，但文案取自 zh-HK 字典；頁面仍明確提供 zh-CN／zh-HK，沒有教材轉換。[Chrome i18n 官方文件](https://developer.chrome.com/docs/extensions/reference/api/i18n)

## 真實驗證界線

本輪使用隔離 mock Worker／供應商、隨機本機連接埠及臨時 Chromium profile，未使用真實帳戶或 Key，未部署、合併或推送。真實 Worker 若採嚴格 ALLOWED_ORIGINS，需要管理員加入實際 chrome-extension://<id>；本輪沒有變更生產設定。原型 host_permissions 為 http/https，以連接使用者指定端點，沒有常駐內容腳本。

自建 selfhost 的學習資料同步不提供本方案所需的 AI catalog／憑證接口，不能據此宣稱相同的 AI 接入支援。正式 Chrome／Edge 手動安裝、工具列 popup 生命週期及真實供應商連線仍須另外實測；現有自動化覆蓋 Chromium 真實擴充套件 origin 的頁面。
