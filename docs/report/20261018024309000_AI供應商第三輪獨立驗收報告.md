## 尚餘 P2：部署命令的錯誤碼被掩蓋

位置：`docs/release/20261017174843744_AI供應商設定同步部署與遷移指南.md:159`、`:166`、`:171`。

1. 暫存目錄版本執行檢查或下載失敗後，繼續執行最後的 `rm -rf "$tmp"`。普通 Bash 執行整段命令時，最後的清理成功導致整段 exit 0，違反同節「只有 exit 0 才算通過」的說明。
2. 管道版本沒有設定 `pipefail`。若 curl 已輸出一部分看似乾淨的內容後以非零碼退出，Node 仍可掃描成功；整段管道只返回 Node 的 0，忽略下載未完成。

重現方式：從指南抽取原始 Bash 區塊，以同名 shell 函式替代 curl，只產生假設定或模擬下載失敗；未連線任何網站，未使用真實密鑰。

| 場景 | 模擬輸入／狀態 | 實測整段退出碼 |
| --- | --- | --- |
| 暫存版，掃描發現遺留匯出 | 假內容 `export const API_KEY = "test-placeholder-only";`；Node 印出 1 項發現 | 0（錯誤） |
| 暫存版，下載失敗 | curl 回傳 22；印出下載失敗提示 | 0（錯誤） |
| 管道版，部分內容後下載失敗 | 輸出 `export const SYNC = {};` 後 curl 回傳 18；Node 判定乾淨 | 0（錯誤） |

修正方向：以子 shell 包住暫存版，檢查 mktemp 結果，以 EXIT trap 清理，明確保留下載／掃描的退出碼；管道版在子 shell 啟用 `set -o pipefail`。驗收須執行指南中的完整命令，覆蓋乾淨輸入、掃描發現、下載立即失敗及部分下載失敗，不能僅測 checker 本體。
