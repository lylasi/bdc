# 文章分享網址與刪除記錄驗證

日期：2026-10-28（Asia/Shanghai）
驗證版本：本機 `master`，`048d07b`。本次只驗證行為，未修改應用程式碼、提交或部署。

## 結論

**「閱讀記錄 → 刪除記錄」確實會刪除目前帳戶保存的整篇文章，並同步到同一帳戶的其他裝置；本次未重現另一個帳戶刪掉原擁有人文章的情況。**

目前 `/#a/<文章ID>` 是按登入帳戶查找文章的私人網址，沒有跨帳戶授權能力。A 將網址傳給 B，若 B 沒有自己的同 ID 文章，B 會看到「目前帳戶下找不到這篇文章」。即使 B 保存了完全相同 ID 的個人副本，刪除也只作用於 B 的副本。

「指定用戶分享」仍是[第二階段規格](../spec/20261018184206963_文章獨立儲存與指定用戶分享建議.md:3)，目前程式沒有分享／接收者關係表及相應入口。本次不能把建立 B 的獨立副本當成已完成跨用戶分享流程的驗收。

## 實際瀏覽器復現

啟動 `python3 scripts/serve.py --port 8313`，測試腳本另外啟動真實 selfhost SQLite 後端；使用合成帳戶 A（alice）、B（bob）及三個獨立 Chromium context。B 的第二個 context 代表同帳戶的另一裝置。測試路由攔截私有配置，瀏覽器刪除／復原只操作臨時資料庫，結束後清理。

以下流程分別以 `zh-CN`、`zh-HK` 完成，共 **18／18 通過，沒有頁面執行錯誤**。

| 步驟 | 結果 |
| --- | --- |
| A 建立文章並開啟私人網址 | 成功，原文及保存的分析可顯示 |
| B 開啟 A 的同一網址 | 單篇讀取回 404，頁面顯示目前帳戶找不到文章 |
| B 直接要求刪除 A 的 ID | 回 404，A 的文章仍存在 |
| B 建立完全相同 ID 的獨立文章 | 成功；A、B 分別取得自己的標題與文件 |
| B 點閱讀記錄內的「刪除記錄」 | B 的清單項消失；實際發出 `DELETE /articles/:id`，B 的文章產生 `deletedAt`，revision 由 1 變 2 |
| 刪除後重查 A | HTTP 200，原文未變、`deletedAt` 為空、revision 仍為 1；刷新私人網址仍能開啟 |
| B 的另一裝置同步 | 收到 B 的文章刪除標記 |
| B 點撤銷 | 文章恢復，A 的 revision 仍為 1 |
| B 再以私人網址開啟並刷新 | 原文與分析可再次開啟 |

重跑指令：

```bash
PORT=8313 PLAYWRIGHT_MODULE=<path-to-playwright> \
    node docs/report/assets/20261028113306106/verify-article-delete.cjs
```

腳本使用 Node 24、內建 `node:sqlite`，預設 Chrome 位於 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；可用 `CHROME_PATH` 指定。前端伺服器需預先啟動。

## 兩個刪除入口的差異

| 入口 | 實際範圍 | 同步 |
| --- | --- | --- |
| 閱讀記錄清單的「刪除記錄」 | 刪除目前帳戶的整篇保存文章；不是只清除最近閱讀時間 | 文章刪除同步到同帳戶其他裝置 |
| 「本文學習記錄」側欄的單條刪除 | 刪除該條單字／短語／句子學習記錄及個人筆記，或選中的整理文件；不刪文章原文 | 走個人閱讀資料的同步接口 |

閱讀記錄的撤銷提示目前顯示 12 秒；此次已實際驗證提示可復原。若兩個人使用的是同一登入身份，系統會視為同一帳戶，其刪除會同步到彼此的裝置。

## 程式證據

- [deleteReadingRecord](../../features/article/article.js:4377) 呼叫 `articleStore.deleteArticle(recordId)`，並保存復原快照。
- [articleStore.deleteArticle](../../modules/article-store.js:1878) 建立文章刪除標記與 outbox；尚未上傳的新建操作可能直接取消，不一定發 HTTP DELETE。
- [article-sync.js](../../modules/article-sync.js:561) 送 `DELETE /articles/:id`，附 revision 及 mutation ID。
- [Worker readRow](../../cloudflare-worker/src/articles.js:88) 同時以 `owner_user_id` 與文章 ID 查詢；[handleDelete](../../cloudflare-worker/src/articles.js:555) 也以 owner、ID、revision 作原子更新。selfhost 重用同一 handler。
- [學習側欄 deleteRecord](../../features/article/reading-panel.js:792) 呼叫閱讀實體的刪除方法，經 `POST /reading/mutations` 同步，不呼叫文章 DELETE。

建議將閱讀記錄內的整篇刪除文案明確標為「刪除我的文章」，提示會同步至同帳戶裝置；若產品需要只隱藏閱讀歷史，應另外設計移除歷史操作。正式跨用戶分享應區分接收者移除分享與擁有人刪除原文。

本次驗證覆蓋本機 checkout 及同源後端邏輯，沒有使用正式帳戶重現刪除，也未核對使用者當時實際分享的網址或雙方 `user_id`。因此可以確認目前程式的刪除語義與帳戶隔離，無法斷言那次實際操作屬於哪一種登入／網址情境。
