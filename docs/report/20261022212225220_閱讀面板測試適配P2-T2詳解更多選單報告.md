## 1. 失敗根因

P2-T2 把單詞詳解的次要操作（寫筆記、選短語、解析短語、解析其他短語）收進
`<details class="tooltip-more">`，預設 `open === false`。依瀏覽器預設行為，
關閉的 `<details>` 之內容不會產生 layout，因此 `.btn-note-item` 的可見性為 false。

受影響測試原本直接：

```
await page.waitForSelector('#word-analysis-tooltip .btn-note-item', { timeout: 5000 });
await page.locator('#word-analysis-tooltip .btn-note-item').click();
```

Playwright 的 `waitForSelector`（預設 `state: 'visible'`）與 `locator.click()`
都會等待元素可見，故在元素位於關閉的 `details` 內時逾時失敗：

- `waitForSelector`：note-draft-refresh 情境在兩個 viewport 各失敗 1 項。
- `locator.click()`：實測 30 秒逾時，log 明示 `element is not visible`
  （見下方 `tests/reading-marks.cjs` 修正前基線）。

根因純屬測試腳本與新資訊層級不一致，產品行為（主要操作 ≤ 3）為既定設計，未改動。

## 2. 修正方式（同一個 helper，避免重複）

在每個受影響測試檔加入同一個 helper，於操作 `.btn-note-item` 前先展開：

```js
// P2-T2：「寫筆記」收進 details.tooltip-more（預設收起），直接操作前必須先展開。
async function openTooltipMore(page) {
    await page.waitForSelector('#word-analysis-tooltip details.tooltip-more', { timeout: 5000 });
    await page.evaluate(() => {
        const details = document.querySelector('#word-analysis-tooltip details.tooltip-more');
        if (details && !details.open) details.open = true;
    });
    await page.waitForSelector('#word-analysis-tooltip details.tooltip-more[open] .btn-note-item', { state: 'visible', timeout: 5000 });
}
```

設計取捨：

- 直接設 `details.open = true`，不點擊 `summary`、不模擬滑鼠軌跡，避免在
  兩個 viewport（桌面／行動底部 sheet）下引入額外的滾動與點擊位置不穩定。
- 展開後仍以 `waitForSelector(..., { state: 'visible' })` 明確驗證按鈕真的可見，
  不降低覆蓋。
- 未修改既有 `waitForSelector('#article-reading-panel:not(.hidden) textarea.reading-note')`
  之類的後續等待與全部斷言。
