## 一、被測差異（唯一正式改動）

`features/vocabulary/vocabulary.js:206`

```js
// 舊（V4 / V3）
if (trigger.top < viewportTop || trigger.bottom > viewportBottom) {

// 新（V5）
if (trigger.bottom <= viewportTop || trigger.top >= viewportBottom) {
```

語意：舊守衛要求按鈕「完整」落在操作帶（`viewportTop..viewportBottom`，即 appBar 底緣到 appNav 頂緣）內；新守衛只要求「按鈕與操作帶有交集」。按鈕完全離開操作帶（含整支被底部導覽列蓋住）時仍收合。`window.scroll → closeWordPanelMenu` 與選單的 `maxHeight` / `top` 夾限邏輯均未改動。

## 三、判定原則（本輪唯一改動的判讀方式）

原 V3 腳本的 `fullTriggerInsideBand` 只是量測欄位（要求按鈕完整落在帶內），**不再**當作判準。本輪改為：

```
overlapBand = max(0, min(trigger.bottom, viewportBottom) - max(trigger.top, viewportTop))
預期開啟 ⟺ overlapBand > 0        （按鈕與操作帶有交集，含只有 11.2px 可見）
預期收合 ⟺ overlapBand = 0        （完全離開操作帶／整支沒入底欄）
```

因此「完全藏在底欄下的按鈕」不再被要求開啟。
