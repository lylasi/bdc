# 快速模型切換與完整思考模式入口完成報告

日期：2026-11-02。狀態：已實作、通過快速 sol61 複核、已提交推送並部署 149。部署記錄見[快速模型切換與完整思考模式入口 149 部署記錄](../release/20261102194507153_快速模型切換與完整思考模式入口149部署記錄.md)。

## 一、使用者問題的回答

### 為什麼之前只有幾個任務能選思考強度？

第一版只把 `wordAnalysis`、`articleParagraphTranslation`、`articleSentenceTranslation`、`assistant` 四個群組開放到介面，其餘任務仍使用應用程式預設。這是為了避免設定面板一次出現太多供應商相關旋鈕，不是那些任務不能設定。

本次已把思考模式下拉擴到所有任務列：查詞、造句檢查、問答 AI 校對、文章詳解、文章段落翻譯、句子詳解、文章 AI 清洗、例句生成、OCR、AI 助手。

### 全文翻譯能不能選？

可以。全文翻譯與逐段翻譯共用 `articleParagraphTranslation`，都走 `features/article/paragraph-pipeline.js` → `api.analyzeParagraph()`。因此不需要另立「全文翻譯」任務；為了讓介面更清楚，這次把該列文案改為：

- zh-CN：文章翻译（段落 / 全文）
- zh-HK：文章翻譯（段落／全文）

設定該列的思考模式即同時套用到逐段與整篇翻譯。

## 二、快速模型圖示

新增共用模組 `modules/quick-model-picker.js`，提供輕量模型選單：

- 文章閱讀頁工具列新增晶片圖示 `#article-ai-model-btn`，可切換：
  - 文章翻譯 `articleParagraphTranslation`
  - 句子詳解 `articleSentenceTranslation`
  - 文章詳解 `articleAnalysis`
  - 文章 AI 清洗 `articleCleanup`
- 單詞／短語查詞彈窗的標題列新增模型圖示，開啟 `wordAnalysis` 模型清單。
- 選單選項包含「跟隨全局預設」；選擇後確認會清除該任務的明確覆寫，否則寫入所選模型。
- 選單內另有一行緊湊的「思考」下拉，預設顯示「跟隨應用預設（目前檔位）」；可選跟隨服務端、關閉思考、低／中／高強度。
- 確認時模型與思考模式在同一個 profile revision 寫入；選擇「跟隨應用預設」會清除該任務的 `taskThinking` 覆寫。桌面與 390px 手機版都已檢查。
- 無可用模型時顯示說明並停用確認；目前模型不可用時保留原設定，不會誤清。
- 支援帳戶切換保護、模型在開啟期間被移除的重新驗證、Esc／背景／取消關閉、焦點還原、Shift+Tab 焦點圈限。
- 助手面板已有模型下拉，本次未重複加入圖示。

## 四、複核與修正

快速 sol61 第一輪提出 6 項問題，均已修正並補測試：

1. 帳戶切換後舊選單可能寫入新帳戶 → 加入 auth 事件關閉與確認前 scope guard。
2. 目前模型不可用時直接確認會清除原設定 → 顯示不可用但目前選取項目，直接確認保留原值。
3. 模型在選單開啟期間被移除仍可儲存 → 確認時重新驗證可用清單，顯示錯誤且不寫入。
4. 單任務已選模型時 Shift+Tab 會離開彈窗 → radio group 只把已選項視為 Tab 邊界。
5. tooltip 非同步重繪後焦點無法還原 → 新增 `returnFocus` callback，聚焦重繪後的新圖示。
6. 單任務且無模型時焦點留在背景 → 以取消鈕作為備援焦點。

第二輪複核結論：**可合併**，六項功能修正均實測通過；另指出測試未等待 radio 焦點、未模擬非同步重繪，本次已補強為 58 項 quick-model 檢查。

### 2026-11-03 追加：快速選單加入思考強度

- 在快速模型選單加入一行原生「思考」下拉，選項為應用預設（顯示目前檔位）、跟隨服務端、關閉思考、低／中／高強度。
- 模型與思考模式以 `saveTaskModelAndThinking()` 在同一次 profile revision 寫入；只有實際改動的欄位會寫入，避免選單開啟期間另一個分頁的更新被覆蓋。
- 修正下拉箭頭被 `background` 簡寫清除的問題。
- quick-model 測試增至 72 項，包含只改模型、只改思考、並行更新、未改動確認、預設清除與箭頭樣式。
