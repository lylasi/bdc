# AI 思考強度按任務設定完成報告

日期：2026-11-02。狀態：已實作，經快速 sol61 三輪複核，最終結論為可合併。未 commit、未 push。

## 一、原問題的回答

目前（實作前）BDC 對查詞、文章翻譯、句子分析與 AI 助手都沒有傳送任何思考強度參數：

- `requestAI()`／`streamAIResponse()` 只送 `temperature`、`maxTokens`。
- 三個協議適配器都沒有輸出 `reasoning_effort`、`thinking` 或 `thinkingConfig`。
- 因此實際思考程度完全由供應商／模型／網關預設決定，不能稱為「低／中／高」，也不能視為已關閉。
- 依先前實測，Magpie 的 `workbuddy/deepseek-v4.1-flash` 省略參數仍有推理用量；明確送 `reasoning_effort: "none"` 才驗證為 0。

結論：可以調整，而且有必要按任務分開。查詞與普通翻譯應優先速度，助手保留較高推理空間；但必須依渠道能力處理，不能對所有模型假設同一組參數。

## 二、實作後的行為

設定位置：設定 → AI 供應商 → 按功能指定模型 → 思考模式。

每個任務可選：

| 選項 | 含義 |
| --- | --- |
| 跟隨服務端 | 完全省略思考參數 |
| 關閉思考 | 盡量明確關閉；部分渠道會降為最低強度 |
| 低強度 | 最低可用推理檔位 |
| 中強度 | 中等推理檔位 |
| 高強度 | 最高推理檔位 |

應用程式任務預設：

| 任務 | 預設 |
| --- | --- |
| 查詞／一般釋義（`wordAnalysis`，含文章查詞與片語） | 關閉思考 |
| 文章段落翻譯（`articleParagraphTranslation`） | 關閉思考 |
| 句子詳解（`articleSentenceTranslation`） | 低強度 |
| AI 助手（`assistant`） | 中強度 |
| 其他任務 | 跟隨服務端 |

助手面板另有本次提問的思考模式下拉，可選跟隨設定／關閉／低／中／高；首次送出時會凍結有效的思考等級與模型，重試沿用同一組，不會因中途改設定而換模型或換檔位。

優先次序：本次覆寫 → 個人任務設定 → 應用程式任務預設。

## 三、協議映射

| 協議 | 映射 |
| --- | --- |
| Chat Completions | 非 `auto` 時送 `reasoning_effort` |
| Anthropic Messages | `low/medium/high` 送 `thinking: { type: "enabled", budget_tokens }`；`temperature` 設為 1；`max_tokens` 保證大於 budget；`auto/none` 省略 |
| Gemini 2.5 | `thinkingConfig.thinkingBudget`；Flash 的 `none` 為 0，Pro 的 `none` 映射最低值 128 |
| Gemini 3 | `thinkingConfig.thinkingLevel`：`none/low` → `low`，`medium/high` → `high` |

生成預算：

- 非 `auto` 模式在呼叫端已給 `maxTokens` 時套用最低預算（low 1200／medium 2500／high 5000）。
- Anthropic 與 Gemini 2.5 由適配器把思考預算與答案保留量相加，避免思考耗盡總輸出。
- 截斷重試可辨識 OpenAI `length`、Anthropic `max_tokens`、Gemini `MAX_TOKENS`，並依實際出站額度增加，不再被舊的 4000 上限卡住。

## 四、失敗與能力處理

- 供應商以 400／422 拒絕思考參數時，自動重試一次不含思考參數的請求，功能不中斷。
- 支援 `detail`／`errors` 等結構化錯誤；不會因 `[object Object]` 而漏判。
- 同一 provider／format／endpoint／model／level 的拒絕結果會在本次頁面生命週期內記住，後續直接使用 `auto`，避免每次重複踩同一個錯誤。
- 帳戶切換、工作階段失效、catalog 變更時會清空能力記憶；並以世代計數避免舊回應污染新狀態。
- 降級重試固定在原本解析出的 endpoint，不會因中途改設定而把請求送到另一個目標。
- 成功降級後發出 `bdc:ai-thinking-fallback` 事件（同一目標只發一次），供 UI 或除錯觀測。

## 五、同步與快取

- AI profile 新增 `taskThinking`，沿用帳戶範圍 profile 與現有同步流程。
- 舊 snapshot 沒有 `thinking` 時不會清空本機設定；空映射也不會被推送。
- `lwwMerge()` 在群組 LWW 之外補上 thinking 鍵級合併；勝出方同名鍵優先，落敗方獨有鍵保留。若真的新增了鍵，會推進合併時間戳，確保能套回本機；沒有新增時不推進，避免同步迴圈。
- 字典查詞、發音、文章段落／句子／片語／單詞分析快取鍵都納入有效思考模式與 `provider:model`，避免快速／深入或不同供應商互相命中。
- 快取讀取時捕獲的思考模式會一路傳給實際請求，避免「出站用 high、寫入 none 快取鍵」的競態。

## 九、剩餘風險

- 未對真實 Anthropic／Gemini／各網關做 live 配額與錯誤格式驗證，全部協議測試為 mock fetch。
- 「關閉思考」能否真正關閉取決於渠道；Gemini 2.5 Pro 的 `none` 是最低強度 128，Gemini 3 的 `none` 是最低檔 `low`，UI 已提示部分渠道會降級。
- 能力記憶只在單一頁面生命週期內有效；重新載入後會重新探測。
- 少數模型／網關的輸出上限較小，放大後的思考預算可能被拒絕；此時會觸發一次不含思考參數的降級重試。
- LWW 的 thinking 合併是鍵級復活語意，無法用單一 snapshot 表達「刪除某任務的思考設定」。
