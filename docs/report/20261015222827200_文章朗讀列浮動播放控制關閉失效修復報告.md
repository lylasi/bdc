# 文章朗讀列（浮動播放控制）關閉失效修復報告

- 時間：2026-10-15 22:28
- 範圍：`index.html?module=article`（文章詳解）右下角／底部置中的浮動朗讀列 `.floating-reader`
- 相關檔案：`features/article/article.js`、`styles.css`
- 對應回報：「播放的懸浮有點問題，點關閉沒反應」

## 一、結論（一句話）

浮動朗讀列的「關閉」與「結束朗讀」其實一直有被點到，但**CSS 沒有任何隱藏狀態**，
`hideFloatingReader()` 只切換 `.is-visible`，而 `.floating-reader` 本身寫死 `display:flex`，
所以控制條永遠留在畫面上（連切到別的功能頁也還在）；另外手機上底部訊息提示的
`z-index`（4000）比朗讀列（1500）高且可點擊，整條播放控制會被提示蓋住，
點「關閉」只會關掉提示。兩者疊加就是「按了沒反應」。

## 二、重現與證據（Playwright + Chrome headless，`scripts/serve.py` 起站）

| 觀察 | 修復前 | 修復後 |
| --- | --- | --- |
| 朗讀後 `.floating-reader` 計算樣式 | `display:flex` | `display:flex` |
| 點 `.fr-close` 後 | `display:flex`（`is-visible` 已移除但無效） | `display:none` |
| 點 `.fr-stop` 後 | `display:flex` | `display:none` |
| `styles.css` 內與 `floating-reader` 有關的規則 | 只有 7 條按鈕樣式，**沒有 `.is-visible`** | 新增 `.floating-reader.is-visible { display:flex }` |
| 手機（390×844）朗讀列 7 顆按鈕 `elementFromPoint` | 7/7 被 `message-toast` 蓋住 | 0/7 被蓋住 |
| 切到「學習模式」頁後的固定定位元素 | 仍含 `.floating-reader` | 只在朗讀進行中出現 |

## 三、修復內容

### 1. 讓朗讀列真的能消失（核心）

- `styles.css`：`.floating-reader` 基底改為 `display:none`，新增 `.floating-reader.is-visible { display:flex }`。
  JS 端本來就是切 `.is-visible`，補上這條規則即可，無需改動狀態機。

### 2. 訊息提示不再蓋住播放控制

- `styles.css`：新增權杖 `--float-reader-h: 70px`，並在「底部懸浮元件避讓」區塊加入
  `body.has-floating-reader #message-container { bottom: … + var(--float-reader-h) }`。
- `features/article/article.js`：`showFloatingReader()` / `hideFloatingReader()` 同步切換
  `body.has-floating-reader`（與聽寫播放器的 `body.has-floating-player` 同一套做法）。

### 3. 關掉之後還能叫回來

「關閉」的語意是**收起控制條、不停止朗讀**（要停止請按「結束朗讀」），
但原本只有 `readArticle()` 會顯示朗讀列，關掉後就再也叫不回來（重新按「朗讀文章」是暫停／繼續，
而且停止後重讀會從第一句開始）。因此 `togglePauseResume()`、`playNextChunk()`、`playPrevChunk()`
在朗讀進行中會重新顯示朗讀列——使用者只要再操作一次播放控制，控制條就回來。

### 4. 順手修掉檢查到的其他問題

- **雙語標籤不會更新**：朗讀列只在第一次朗讀時建立，標題／`aria-label` 是建立當下 `t()` 的結果，
  切到香港繁體後仍顯示簡體。改為抽出 `applyFloatingReaderTexts()`，建立時與
  `bdc:locale-change` 時都重新套用（切換語言後實測為「關閉／上一句／朗讀控制」）。
- **無障礙**：朗讀列補上 `role="toolbar"` 與 `aria-label`（`article.readingControls`）。
- **「跟隨朗讀滾動」被覆寫**：`applySentenceHighlight()` 在朗讀中開啟句子詳解時會無條件加上
  `dim-others`，把使用者剛關掉的淡化又打開。已改為一併判斷 `_followScroll`。

## 四、驗證

### 自建驗證腳本（桌面 1100×850 與手機 390×844 各 10 項，共 20 項全過）

涵蓋：朗讀前不建立元素 → 朗讀後顯示 → 提示出現時按鈕不被遮 → 關閉後 `display:none` 且 body 類別移除
→ 再次操作播放控制可重新顯示 → 結束朗讀後消失 → 切換 zh-HK 標籤同步 → 無 JS 例外。

### 專案既有回歸 `tests/ui-regression.cjs`

- 本次修改後：**91/92**，唯一失敗項與修改前（乾淨副本）完全相同：
  「原始碼沒有寫死的中文 UI 字串」指向 `features/phonetics/word-sheet.js:29`、
  `features/qa/qa-pdf.js:441/461/510/525` 的內部 `Error` 訊息（非 UI 文案，屬既有問題）。
- 朗讀列相關檢查（7 顆 sprite 圖標、標籤已本地化、不遮擋底部導覽、寬度未溢出、切換有狀態回饋、
  無 JS 例外）在 zh-CN／zh-HK 兩種語系下全數通過。

## 五、未動但值得留意的點

1. **桌機上朗讀列位置偏高**：`bottom` 仍以 `--tabbar-h`（62px）為基準，但桌機（≥768px）沒有底部標籤列，
   訊息提示的基準是 `safe + 20px`，兩者不在同一條線上；目前不影響操作，僅是視覺上略高。
2. **跨頁常駐**：朗讀進行中切到其他功能頁時，朗讀列仍會顯示在該頁（與聽寫播放器行為一致）。
   若希望它只出現在「文章詳解」頁，可再加一個 section 判斷。
3. `applySentenceDim()`（片語詳解）仍會單獨淡化句子，不受「跟隨朗讀滾動」控制。
