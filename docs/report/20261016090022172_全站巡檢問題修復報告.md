### H3 + M9：啟動路徑韌性（`index.html`、`main.js`、`features/qa/*`）

- `main.js` 的 `DOMContentLoaded` 改為分步 `step(name, fn)`：任一步失敗只記錄並印 `console.error`，**其餘模組、主導覽與 URL 路由照常運作**；最後若有失敗步驟，用站內提示告知使用者哪些模組未載入。

複驗：`qa-sets` 設為 `'null'` / `{}` / `42` 皆不再有未捕捉例外；阻斷 `ai-config.js` 時出現可讀說明頁；阻斷 `qa-sets/manifest.json`、`wordlists/manifest.json` 時其餘功能正常。

### M1：提示條遮擋（`modules/ui.js`、`styles.css`）

- `#message-container` 原本整條 `.message-toast` 都是 `pointer-events: auto`，等於在畫面底部中央放一塊可點攔截區；加上 `mouseenter` 會無限期暫停自動消失，使用者的滑鼠為了點下方按鈕一停上去就再也關不掉。
- 改為：提示條本體 `pointer-events: none`，只有新增的 `.message-toast__close`（24×24，帶 `aria-label` 使用 `common.dismiss`）可點；移除無限期 hover 暫停。
- 過程中曾嘗試「顯示時探測遮擋再自適應抬升」，但在 1280×800 會把提示推到畫面中央，體感更差，已回退並改採上述方案。

複驗：1440 / 1280 / 1024 / 834 / 390 五種寬度下，被提示實際遮擋而點不到的按鈕數皆為 0，且提示仍固定在底部。

### M2：失敗提示語意（`features/ocr/ocr.js`）

- `runOCR()` 依 `counters` 決定提示型別：成功 0 且失敗 >0 → `error`；部分失敗／取消 → `warning`；全成功才 `success`，並延長非成功提示的顯示時間。
- 按鈕文字在全失敗時顯示新增的 `ocr.allFailed`（识别失败／識別失敗），而不是「完成」。
- 9 處原生 `alert` 全部改為 `ui.displayMessage`（含「请先上传图片或拍照」）。

複驗：阻斷 AI 服務後，結果區保留逐圖失敗原因，提示為 `message-toast message-error`。

> 說明：巡檢報告中「聽寫 AI 批改按下沒反應」經複查為**測試誤判** —— 該按鈕是開啟批改彈窗，且無圖時會明確顯示「請先上傳或拍照」。已修正測試腳本而非產品程式碼。

### M3：模型選擇器（`modules/ai-models.js`）

- 根因：`getTaskModelSelection()` 只把 provider 的 `allowedModels` 當成選項來源，而 `ai-config.js` 的 `AI_PROVIDERS` 未定義該欄位，於是所有模型下拉都是空且停用。同一個 `imageOCR` 任務在「AI 批改手寫」彈窗卻有模型可選，因為那裡直接讀 `OCR_CONFIG.MODELS`。
- 修法：provider 未設定 `allowedModels` 時，改用 `getTaskSpecificDefaultCandidates(taskName)`（即 `ai-config.js` 為該任務宣告的模型）作為選項來源，並讓 `disabled` 依實際選項數決定。

複驗：`#ocr-model-select` 由 0 個選項變為 `bohe:gemini-2.5-flash` / `grok-4.2-fast`；`#qa-model-select`、`#qa-model-select-report` 皆為 `grok-4.2-fast` 且可選。
