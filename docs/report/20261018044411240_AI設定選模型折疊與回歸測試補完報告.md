# AI 設定「選模型自動折疊」修復與未完成回歸測試補齊報告

日期：2026-10-18（Asia/Shanghai）
範圍：AI 供應商設定（個人／管理員）模型選擇器、設定面板折疊狀態、AI 回歸測試、本機區域網（LAN）驗證。

## 1. 這次補完的是什麼

上一次工作階段（Session 387，本地區域網支持與 AI 設定）把「模型選擇」從逐列 checkbox 改成 chip 選擇器，但收尾沒有完成，留下兩類問題：

1. **互動 bug**：在設定面板選模型（任務模型、預設模型、管理員卡片模型）之後，整個面板會重建 DOM，使用者正在看的折疊區塊（「按功能指定模型」、「進階設定」）會自己折回去，回報為「選模型選一下窗口會自動折疊」。
2. **回歸測試失效**：`tests/ai-review-regressions.mjs` 仍指向舊版 UI 的 `[data-admin-form-model]`、`[data-admin-model]`、`[data-admin-candidate]` checkbox，改版後實測 11/27 通過，其餘 16 項逾時或斷言失敗。

本次把上述兩件事補完，並重新驗證 LAN 啟動路徑。

## 2. 折疊問題的根因

兩個面板（`features/sync/ai-provider-settings.js`、`features/ai-admin/ai-admin.js`）的設計都是「每次互動 → `host.innerHTML = ...` 整塊重繪」：

- `<details>` 的 `open` 狀態只存在 DOM 上，重繪後回到標記預設值（關閉），所以「按功能指定模型」一選就折回；管理員卡片的「進階設定」同理。
- 模型晶片清單 `.ai-model-picker-list` 的 `scrollTop` 也在重繪後歸零，長清單每次勾選都跳回頂部。
- 個人表單的「測試／預設模型」`<select>` 不會觸發重繪，導致勾選模型後「設為我的預設模型」不會即時出現。

## 3. 修改內容

### 3.1 新增共享模組 `modules/detail-state.js`

以 `data-keep-open="<唯一鍵>"` 為鍵，重繪前 `captureDetailState()`、重繪後 `restoreDetailState()`。只需 20 餘行、無外部依賴，兩個面板共用。

### 3.2 `features/sync/ai-provider-settings.js`

- 「按功能指定模型」加上 `data-keep-open="ai-tasks"`，並以 mount 範圍的 `taskDetailsOpen` 記憶展開狀態。
- 「進階設定」加上 `data-keep-open="ai-advanced-<表單 id>"`；鍵含表單 id，切換到另一個供應商時不會誤帶舊狀態。
- 新增 `captureViewState()`：重繪前把 `<details>` 的 `open`、模型清單 `scrollTop` 寫回 `form`；並用 `data-ai-form-id` 確認 DOM 與目前表單是同一份，避免舊表單狀態污染新表單。
- 新增 `activeFocusKey()` / `restoreFocus()`：任務下拉與預設模型下拉加上 `data-focus-key`，重繪後焦點回到原本的欄位（鍵盤操作不再中斷）。
- 移除 `renderTaskSection()` 裡沒有作用的 `${profile.defaultModel ? '' : ''}` 死碼與未使用的 `registry`。
- 「測試／預設模型」改為 `change` 後重繪（折疊已有保護），勾選模型後「設為我的預設模型」立即出現。

### 3.3 `features/ai-admin/ai-admin.js`

- 供應商卡片「進階設定」與新增表單「進階設定」加上 `data-keep-open`，`render()` 前後保存／還原展開狀態。管理員勾選模型時不再折回。

### 3.4 `modules/ai-model-picker.js`

- `redraw()` 支援 `keepScroll`：勾選／取消模型、批次操作保留清單捲動位置；切換「全部模型／只看已選」與搜尋則回到頂部。
- 清單捲動位置寫入 `state.scrollTop`，外層整塊重繪後由新實例接回同一位置。

### 3.5 個人供應商「取得模型後不預選」（與管理員發布規則一致）

`doConnect()` 原本在取得模型後自動把整份清單加入 `allowedModels`，並自動選第一個為預設模型。這與檔案開頭「connect → pick a model → save」的設計、以及管理員「候選不自動開放」的規則不一致，也讓 `settings.aiNeedModel` 的錯誤路徑永遠不會觸發。

現在：

- 取得模型只填入候選（`form.models`），`allowedModels` 只保留使用者已手動加入的模型。
- 沒有勾選任何模型時按「儲存」會明確提示（`settings.aiNeedModel`），不會默默存成空清單。
- `model_not_selected` 補上 `describeDetectionError` 對應文案，未選模型按「測試模型」時顯示「尚未選擇模型」，不再是「連線失敗」。

### 3.6 其他

- `tests/ai-units.test.mjs` 新增 `<details>` 狀態保存的單元測試。
- `scripts/serve.py` 的拒絕清單加入 `/.playwright-cli`（瀏覽器巡檢快照與 console 記錄），`.gitignore` 同步忽略。
- `AGENTS.md`、`CLAUDE.md`、`README.md` 的驗證指令補上 `tests/ai-sync-regressions.test.mjs` 與 `tests/ai-review-regressions.mjs`。

## 4. 回歸測試改寫（原本 11/27 → 29/29）

`tests/ai-review-regressions.mjs` 全面對齊 chip 選擇器，新增 `modelChips()` / `pickedModels()` / `clickModel()` 三個小工具：

| 項目 | 改寫後 |
| --- | --- |
| 管理員新增表單偵測協議後不預先批准 | 檢查 `admin-add` 選擇器內 `aria-pressed="true"` 的數量為 0 |
| 只發布勾選的模型 | 點擊 `claude-a` 後加入草稿；卡片選擇器批准 `claude-a`，`claude-b` 仍在候選但未勾選 |
| 無金鑰 LAN 供應商 | 點擊 `lan-model` 後加入；金鑰動作維持 `preserve` |
| F5 模型發現不擴大批准清單 | 發現後仍只有 `allowed-model`；`expensive-new-model` 為未勾選候選 |
| 明確勾選候選才發布 | 點擊 `expensive-new-model` 後發布內容包含兩個模型 |
| 單一供應商失敗不阻塞 | 失敗卡片維持 `kept-model`，健康卡片維持 2 個批准模型 |
| 新增：選模型不折疊（管理員） | 展開卡片進階設定 → 勾選模型 → `details.open` 仍為 `true` |
| 個人表單流程 | 連線後 0/2 已選、預設模型為空、未勾選儲存會被阻止；勾選 `model-b` 後儲存，`allowedModels=["model-b"]`、`discoveredModels` 仍保留 2 個候選 |
| 新增：任務區選模型不折疊（個人） | 展開「按功能指定模型」→ 改預設模型 → 區塊仍展開 |

zh-CN 與 zh-HK 各跑一輪。
