# AI 思考強度按任務設定：第二輪收尾修正報告

日期：2026-11-02
範圍：`docs/plan/20261102151815409_AI思考強度按任務設定實施計劃.md` 之後的收尾修正；未 commit、未 push。

## 一、修正內容

### 1. 記憶不支援思考參數的供應商

`modules/api.js` 新增模組層級 `Set`：

- key 為 `provider|model|format`，避免把同一模型在不同協議／供應商下的能力混為一談。
- `requestAI()` 與 `streamAIResponse()` 解析出 `resolved` 後，若要求的等級不是 `auto` 且該 key 已被標記，直接改用 `auto`，不再先送一次必定失敗的請求。
- 只有實際送出思考參數、收到 400／422，且錯誤文字符合思考參數問題時才標記；`auto` 請求不會被標記。
- 額外加入 `requestCarriesThinkingParameter()` 防護：像 Anthropic `none` 這種「省略欄位」的模式，若請求根本沒帶思考參數，不會因為其他 400 被誤標記。
- `bdc:ai-thinking-fallback` 事件保留；同一 key 只在第一次成功降級時提示一次。

### 2. 降級重試恢復原始 maxTokens

- 兩個入口都保留呼叫端原始預算（`baseMaxTokens`），思考等級每次變動時都用 `applyThinkingTokenFloor(baseMaxTokens, level)` 重新計算。
- 思考降級為 `auto` 後，重試不再帶著 `5000` 之類的 thinking token floor。

### 3. 擴大思考參數錯誤辨識

- `isThinkingParameterError()` 仍只接受 400／422。
- 關鍵字新增 `max_tokens`、`max_completion_tokens`，涵蓋 Anthropic 因 extended thinking 抬高 `max_tokens` 而被舊模型拒絕的情況。
- 新增測試：Anthropic 回 `max_tokens ... exceeds` 時，會降級重試一次且第二次不含 `thinking`。

### 4. 空思考映射不再清空其他裝置設定

- `getAIViewFromProfile()`：`taskThinking` 為空時不再輸出 `thinking` 欄位。
- `modules/ai-settings-sanitize.js`、`cloudflare-worker/src/snapshot-sanitize.js`、`selfhost/snapshot-sanitize.js`：只有至少一個合法任務／等級時才輸出 `thinking`。
- `applyRemoteAISettings()` 仍保留「明確收到 `thinking: {}` 可清空」的語意。
- 新增測試：
  - 空的本機 profile 不會在 view／sanitizer 產生 `thinking`。
  - 有值的 profile 會保留。
  - 舊 snapshot 不會清空本機值（既有測試）。

### 5. 文章分析快取 key 補上 provider

- `modules/api.js` 新增 `cacheModelKey()`，文章段落、句中詞義、句子詳解、選取短語分析快取改用 `${provider}:${model}`。
- 字典查詞與發音快取原本使用 `modelSpec`；因 profile 允許裸模型名，這次也改為 `cacheModelKey(normalizeModelSpec(modelSpec))`，確保 key 含 provider。
- 副作用：舊字典快取 key 不再命中，會自然過期；不影響正確性。

### 6. 助手底部排版

- `styles.css`：`.assistant-switch` 改為 `flex: 0 0 auto`；只有 `.assistant-switch:has(select)` 才伸展（`flex: 1 1 150px`）。
- `.assistant-sub` 維持 `flex-wrap: wrap`，窄螢幕仍可換行。
- 以 Chromium 實際量測 700px 寬面板：`流式响应` label 寬度 87px（面板 698px），模型／思考兩個 select 各 247.5px，未溢出，`flex-wrap` 為 `wrap`。

### 7. 測試

- `tests/ai-units.test.mjs`
  - 新增「空 thinking 不會被 view／sanitizer 輸出」。
  - 擴充既有 profile／snapshot 測試與舊 snapshot 不清空測試。
- `tests/ai-protocol-integration.test.mjs`
  - 新增 requestAI：400 降級、第二次請求直接跳過、`maxTokens` 由 5000 恢復為 300、事件只發一次。
  - 新增 Anthropic `max_tokens` 錯誤降級重試。
  - 新增 streaming：422 降級、記憶生效、`maxTokens` 恢復、第二次串流不再帶思考參數。

## 三、未處理風險

1. **清空思考設定無法透過一般同步傳播**：依本次要求，sanitizer 會省略空的 `thinking`，因此使用者把所有任務思考值清空後，其他裝置仍保留舊值；只有直接呼叫 `applyRemoteAISettings({ thinking: {} })` 才會清空。這是刻意取捨。
2. **降級記憶只在單一頁面生命週期內有效**：重新載入後，每個 provider／model／format 仍會先嘗試一次思考參數。記憶 key 也不含實際 endpoint URL，若同一個 provider id 在 session 內換到不同網關，可能誤用舊記憶。
3. **`max_tokens` 關鍵字較寬**：若思考參數確實已送出，但 400／422 其實是其他 token 上限問題，仍會觸發一次不含思考的重試；結果通常安全，但該次請求可能失去推理能力。
4. **未對真實 Anthropic／其他供應商做 live 驗證**：目前只有 mock 的協議整合測試。
5. **助手排版只以注入 markup + 真實 styles.css 量測**：未開啟真實助手會話逐個 panel mode 驗證；CSS 與寬度無關，但仍建議日後在實際寬／窄面板各看一次。
6. **`applyAISettingsPatch()` 對 `thinking: {}` 採合併語意**，不能用空物件清除單一 patch；本次未改動，僅全量 snapshot 套用可清空。
7. 專案仍無 build／lint／typecheck；本次驗證依賴 `node:test`、i18n audit 與一次 Chromium DOM 量測。
