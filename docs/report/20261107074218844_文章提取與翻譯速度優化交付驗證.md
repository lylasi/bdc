# BDC 0.6.4：文章提取與翻譯速度優化

日期：2026-11-07 07:44:43 CST。先完成高級後端與 Pi 的獨立分析，再實作、複核及驗證。

## 結果

提取仍先開獨立視窗供檢查及修改，按確認後才翻譯及保存。確認前不會產生新的段落翻譯、文章寫入或 page-link 寫入；之前已確認的待傳可按原規則重試。

| 固定本地 mock 工作負載 | 改前 | 改後 | 耗時減少 |
|---|---:|---:|---:|
| 8 段首次翻譯 | 9.08s | 5.56s | 38.8% |
| 3 塊正文清洗 | 3.52s | 1.86s | 47.0% |

兩者均由 1 個變成最多 2 個在途請求，保留既有 API 的限流；沒有降低思考設定、縮短原文、刪除譯文欄位或更換模型。基準及改後使用同一份腳本、同一組輸入與固定供應商延遲。時間量測涵蓋該 runtime 操作，沒有把帳戶視窗開啟或正式網絡耗時混入。這些是本機模擬比較，不能當成正式供應商的速度承諾。

相同文章再處理時，成功段落命中快取：6.9ms、0 次新增 AI 請求。停止在途／排隊工作約 5.5ms；429 退避中停止約 3.7ms。以上均為同一測試環境量測。

## 採納並完成

- 翻譯及清洗都以最多兩個 worker 處理，按原索引組合結果；相同翻譯段落單次任務只請求一次。進度從 0 起，完成後才增加，不提早顯示全部完成。
- 內容層失敗讓其他段繼續完成；整篇有失敗就不保存半份分析，傳回失敗索引及原因。再次確認復用成功快取，只補未完成段落。提供者／設定／會話錯誤則中止整批。
- 段落成功快取加入擴充帳戶、端點及公開 AI 設定上下文；固定本次語言、模型偏好及思考設定。語言／實際設定／帳戶改變會中止舊任務，預覽可保留。舊的無帳戶標記段落快取不作擴充新任務的依據，需要建立一次新快取；既有查詞快取格式保留。
- 純文字 fallback 成功也會快取；連續截斷或空譯文不作成功快取及完整分析保存。清洗若空白、失敗或截斷，使用該塊完整原文並顯示警告；不把截斷內容當完整正文。
- queue 等待及 HTTP 退避可取消，不在取消後另送 fallback。並行開始時間先預訂，避免同批 waiter 在同一時間醒來而繞過間隔。
- 移除 catalogGeneration 作為內容快照的條件，同版本同內容刷新不誤停分析；版本及公開模型設定仍受檢查。
- 文章啟動不等待無關的詞書清單，避免強制重刷剛取得的 catalog；仍等待已確認的待傳，保留最新 snapshot／憑證同步與真正 AI 請求的授權驗證。
- 提取已存在文章預設只 GET。明確開啟原文章時才補 page-link，確認保存時沿用既有關聯。保存成功後詞書 metadata 讀取在背景更新，不阻塞完成狀態。
- 翻譯與保存使用不同提示；保存階段隱藏不會生效的停止按鈕。已凍結待傳內容維持不可編輯，但主按鈕可以重試原操作。重新提取若會取代使用者的編輯，先明確確認。

## 保留與後續空間

沒有採用「刪掉保存前 sourceUrl GET」：穩定 ID 無法取代舊版隨機／url: ID 的查重，也要處理預覽期間由別處建立的文章。移除此 GET 會造成舊文章重複，收益不足以抵銷相容性風險。

仍可進一步評估長段按句界內部分批、跨視窗共用供應商限額、只以實際任務使用到的供應商 metadata 建快取身份，以及更大幅度的冷啟同步合併。這些涉及現有儲存、模型、對齊或登入新鮮度，沒有在本輪為求速度而改寫。正常 stop 卻語義上刪文的模型輸出仍需使用者檢查；本輪不聲稱能自動證明翻譯品質或全文等價。
