## 4. 逐項覆驗

### 4.1 修改重點 1：兩行上限、標題獨佔行、被截斷才顯示詳情

- 標題元素：`display:-webkit-box; -webkit-box-orient:vertical; -webkit-line-clamp:2; overflow:hidden; overflow-wrap:anywhere; flex:1 1 auto; min-width:0`，字級 18px（窄版 16px），行高 1.5。
- 所有案例 `title.lines ≤ 2`、`title.clientHeight ≤ 2 × lineHeight`、`scrollWidth == clientWidth`（無橫向裁切）；`title` 屬性與 DOM `textContent` 皆等於**已儲存的完整名稱**（無改寫、無 `…` 寫入 DOM）。
- 詳情彈窗（`details` 階段，34 例實際開啟）：
  - 標題為 `单词本名称` / `生字簿名稱`（1 行）；
  - `.book-name-full` 文字**逐字等於**原始名稱（247 字英文、49 字中文、154 字網址皆完全一致）；
  - `pageOverflow = 0`、內文 `scrollWidth == clientWidth`、全文未超出彈窗內文右緣；
  - **關閉（Esc）後焦點 34/34 回到 `#book-name-details-btn`**，`#modal-body` 已清空。
- 短名稱：8 個主畫面案例（2 語言 × 8 寬度中的每組 short）`#book-name-details-btn` 恆為 `display:none`，未截斷時一律隱藏（唯一例外見 L1 的 1 幀閃現）。
- `ResizeObserver`：`resize` 階段同一頁面連續改寬 10 次，每一次「入口模式／標題行數／截斷狀態／詳情圖示」都與當前面板寬度一致（例如 1440→chips、1024→更多、834→chips、720→chips、719→更多、320→更多），沒有殘留舊狀態。

### 4.2 修改重點 2：container query 取代「只看視窗寬度」

- `.vocab-words-panel { container-name: vocabulary-words; container-type: inline-size }` 實測生效（`getComputedStyle` 回報正確值）。
- 臨界值實測：面板寬 **436px → 更多選單**；面板寬 **692px → chips**；門檻 480px 行為正確。
- **1024px（桌面寬視窗、面板 436px）走更多選單 → 這是預期結果**，且五個操作在選單內**全部可達、沒有漏失**：
  - 選單項目數 = 5（`补全资料 / 合并 / 导出 / 编辑 / 删除`，zh-HK 為 `補全資料 / 合併 / 匯出 / 編輯 / 刪除`），文案與 chips 完全一致；
  - 逐項點擊並攔截原按鈕 `click`：**觸發序列 = 預期的五個 source btn**（32/32 案例，0 漏接、0 誤接）；
  - 禁用狀態鏡射：`chip.disabled == menuItem.disabled`（32/32）；
  - Esc 關閉且 `aria-expanded=false`、焦點回到 `#word-panel-more-btn`（32/32）；點選單外部也會關閉；
  - 選單幾何：寬 188px、每個項目 44px 高、文字 1 行、`menu.rect` 在面板與視窗內（32/32，除 L2 的空狀態 320px）。
- **選單 top 依實際 header 高度**：inline `top` 實測值 `54px / 58px / 64px / 68px` 四種，對應 1 行標題與 2 行標題的 header 高度；`menu.rect.y` 一律 = `header.bottom + 4`（誤差 < 0.5px），**沒有任何案例的選單壓到兩行標題**（`overlapsTitle = 0`）。
- 選單開著把視窗放大（320→1280）：320 時 `aria-expanded=true`，放大後 `hidden=true`、`aria-expanded=false`、⋯ 按鈕 `display:none`，**浮層沒有殘留**。

### 4.3 修改重點 3：編輯彈窗與來源彈窗的標題

- 編輯詞書彈窗（56 案例）：標題固定 `编辑单词本` / `編輯生字簿`（1 行，長度 5/5 字），完整名稱在 `#modal-book-name` 輸入框內且**與原名稱逐字相同**（247 / 49 / 154 / 13 字），輸入框 `scrollWidth` 可橫向捲動取得全名（例如 247 字時 `scrollWidth 1799 > clientWidth 278`）；`pageOverflow = 0`，Esc 可關閉。
- 詞條來源彈窗（48 案例）：標題 `单词来源（1）` / `单词来源（3）`、`單字來源（1）` / `單字來源（3）`（全部 1 行，長度 ≤ 9 字），不再被詞條本身撐長；長詞放在 `.word-source-term`（`overflow-wrap:anywhere; white-space:pre-wrap`）：
  - 100 字無斷點網址（來源彈窗的長詞）在 320px → 折成 4 行（118.8px 高）仍 `term.right ≤ 內文右緣`；
  - 526 字無斷點詞在 320px → 折行且不溢位（`stress` 案例）；
  - 內容超出時由 `#modal-body`（`overflow-y:auto`）在彈窗內捲動，**固定 header 不被撐滿**、不超出視窗高度。

### 4.4 修改重點 4：簡繁同步、切換語言不改教材／名稱

- 32 案例（8 寬度 × 4 標題）實測 `setLocale('zh-HK')` → 再切回 `zh-CN`：
  - `#current-book-name` 的 DOM 文字與 `title` 屬性**始終等於原名稱**（切換前後一致，含簡體字詞書名）；
  - `localStorage.vocabularyBooks` 的名稱未被改寫；
  - 截斷狀態、行數、水平溢位在切換前後完全相同；
  - UI 文案正確切換：詳情 `查看完整名称`→`查看完整名稱`、⋯ `更多操作`、選單 `补全资料/合并/导出/编辑/删除`→`補全資料/合併/匯出/編輯/刪除`、來源彈窗 `单词来源（n）`→`單字來源（n）`、編輯彈窗 `编辑单词本`→`編輯生字簿`；

## 5. 問題列表

> 嚴重度：**high** = 版面破損／內容遺失；**medium** = 互動或無障礙缺陷；**low** = 單幀或邊界情境。本輪 **0 high、0 medium（版面）、1 medium（無障礙）、2 low**。

### M1（medium，建議修）⋯ 選單開啟的彈窗，關閉後焦點掉到 `body`

| 項目 | 內容 |
|---|---|
| selector / 位置 | `#word-panel-menu .menu-item` → `features/vocabulary/vocabulary.js` `buildWordPanelMenuItem()`（約 163–166 行） |

### 範圍外觀察（本輪量測到，但**不建議在長標題這次改動內修**，請裁決）

#### O1（P3）帶未知 query 參數時，`#v/<bookId>` 深連結會被忽略

```
#v/book-b                        → 顯示 BOOK B           ✔
?utm_source=x#v/book-b           → 顯示 BOOK A（上一個）   ✘ 無任何提示
?flash=1#v/book-b                → 顯示 BOOK A（上一個）   ✘
?module=vocabulary#v/book-b      → 顯示 BOOK B           ✔
```

- 原因：`main.js` `extractModuleAliasFromUrl()` 的「`?/模組`」後備分支把**任意** query 片段當成模組別名（`HEAD` 已存在），`resolveButtonIdFromAlias` 找不到就 `return`，連帶不執行 `applyVocabularyRoute()`。
- 影響：使用者分享帶追蹤參數的連結時，新做的詞書深連結會靜默失效。
- 最小建議：只在 query 片段**確實是已知模組別名**時才採用；或 `location.hash` 命中 `#v/...` 時優先走 hash 路由。
- 證據：`routing-query-deeplink-check.txt`

#### O2（P3，既有樣式，不在本次 diff）編輯彈窗的名稱輸入框被拉成 220px 高

- `styles.css:5306 #app-modal .input-group { flex-direction: column; align-items: stretch }` × `styles.css:1010 .input-group > input { flex: 1 1 220px }` → `#modal-book-name` 實測 520×**220px**（1024px 視窗），文字垂直居中在大框內，視覺上像多行文字框。
- 這組規則在 `git diff` 中**未被本次改動**（本次 styles.css 只新增 `.modal-content:has(.word-sources) #modal-title`），屬既有樣式。
- 若在意：`#app-modal .input-group > input { flex: 0 0 auto; }`

#### O3（P2，資料層）詞書名稱超過 300 字會被永久層靜默截斷

- 實測：以「編輯單詞本」把名稱存成 400 字 → 面板標題／詳情彈窗只剩 **300** 字；`localStorage.vocabularyBooks` 仍是 400 字，永久層（`readingStore.vocabularyBooksForUi()`）是 300 字，重新載入後兩層仍不一致。
- 來源：`shared/reading-protocol.mjs:38 maxTitleChars: 300` + `cleanString()`（`case 'name'`），而 `#modal-book-name` 沒有 `maxlength`。
- 影響：>300 字的名稱會**失去尾段且無法從 UI 取回**（違反「全文可取得」的邊界）；使用者的實際案例是 247 字，未觸發。
- 最小建議：`#modal-book-name` 加 `maxlength="300"` 並提示（或把 `maxTitleChars` 提高）；存檔成功後把清理後的名稱寫回 `state` 與 localStorage，避免兩層不一致。
- 證據：`long-rename-truncation-check.txt`

### 設計確認（不是缺陷，供你決策）

1. **719px 仍收成「更多」、720px 才一次顯示五個 chips**：719px 時面板其實有 691px 寬，chips 放得下，但 `@media (max-width:719px)` 仍會隱藏 chips。這符合「手機 ≤719 用更多選單」的規格，只是 719→720 有明顯視覺跳變。若希望完全以面板寬度決定，可移除該 media query 那組規則，統一交給 `@container vocabulary-words (max-width:480px)`。
