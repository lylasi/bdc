## 問題與根因

舊版 `modules/reading-export.js` 的 `buildFullBackup()` 只捕捉 `readingStore.captureReadingContext()`，再把同一個 ctx 傳給 `articleStore.exportDocuments(ctx)`。兩個模組各自維護獨立的 generation，正常情況下數值本來就不同；文章層把它視為 stale 並回傳空陣列，外層只檢查閱讀 ctx 仍有效，於是把 `payload.articleDocuments=[]` 當成成功備份。

已用實際備份檔確認：`docs/report/assets/20261019230030000/full-backup-sample.json` 曾為 `ok:true`，閱讀資料有 3 條目／2 文件／70 消息，但頂層文章文件為空，缺少 `art_reading_preview` 的原文與分析。

## 修正內容

### `modules/article-store.js`

- 新增 `exportDocumentsResult(ctx)`：明確回傳 `{ ok, scope, generation, documents }`；stale scope、讀取失敗都回 `ok:false`，不再讓呼叫方把失敗誤判為空備份成功。
- 保留既有 `exportDocuments(ctx)` 入口與回傳陣列行為，不改動現有呼叫者（例如 `modules/local-backup.js`）。
- 把文件讀取拆成 `readDocsDetailed()`：IndexedDB 交易失敗不再只回空陣列，會帶回 `ok:false` 與錯誤；`exportDocumentsResult()` 與 `loadAllRecordsDetailed()` 會把失敗往上傳。
- `loadAllRecords()` 對既有呼叫者仍維持回傳陣列，但內部已能區分讀取失敗。

### `modules/reading-export.js`

- `buildFullBackup()` 在入口分別捕捉：
  - `readingStore.captureReadingContext()`
  - `articleStore.captureArticleContext()`
- 入口即核對兩個 ctx 都有效且 scope 相同；任一無效回 `stale_scope`，scope 不同回 `scope_mismatch`。
- 每次 await（快照、閱讀匯出、文章匯出）前後都重新核對兩個模組自己的 ctx 與相同 scope。
- 文章匯出改用 `articleStore.exportDocumentsResult(articleCtx)`；`ok:false` 直接讓整個備份失敗，不會輸出成功但缺文章的空備份。
- 保留 generation 守衛，沒有取消 stale 檢查，也沒有把讀取失敗當成空資料。
