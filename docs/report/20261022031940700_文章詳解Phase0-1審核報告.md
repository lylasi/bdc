## 二、最嚴重的五項發現

### 1. P1｜批次保存失敗後，失敗段數變成 0，批次重試入口消失

對 IndexedDB 寫入注入交易失敗後，實際得到：

- 兩段均顯示 `failed／未能保存`；
- 摘要卻是「已重試 0 段，仍失敗 0 段」；
- 批次按鈕隱藏且停用；
- 重載後仍是兩段失敗。

證據：

- `features/article/article.js:5031` 只回退畫面，隨後 `features/article/article.js:2191` 從記憶體記錄重算失敗數。
- `modules/article-store.js:1060` 在持久化失敗時仍更新記憶體結果。此 store 行為在 HEAD 已存在，不能歸咎於其他工作階段。

建議：讓「未保存狀態、失敗數、重試入口」使用一致來源，並以真正的交易失敗驗證。

### 2. P1｜單段重試會被其他段落提前解鎖，舊回應可覆寫新結果並落盤

同時重試兩段時，第一段完成後，第二段仍在請求中，但按鈕已重新啟用。再次重試第二段，讓新版先完成、舊版後完成，最終記錄及重載畫面都變成舊版。

證據：

- `features/article/article.js:2175` 在版本一致時無條件啟用所有重試按鈕。
- `features/article/article.js:4631` 每次單段完成都觸發它。
- `features/article/article.js:129` 的 `isJobWriteTarget` 沒有同一段落的請求世代判斷。

建議：由段落工作持有忙碌狀態及寫入權，拒絕重複工作或淘汰舊工作。

### 3. P1｜助手忙碌鎖設得太晚，初始化期間連送會產生兩個請求

同步觸發兩次送出，獨立探測得到：

- `requests: 2`
- 兩個停止按鈕
- 兩條使用者訊息
- 第二題輸入亦被清空

證據：

- `features/assistant/assistant.js:543` 檢查忙碌後，經過多次 `await`，直到 `features/assistant/assistant.js:626` 才設定 `activeAsk`。
- `features/assistant/assistant.js:734` 又無條件清除它。

建議：在首個 `await` 前取得忙碌權，並只允許持有者解除。現有測試等停止按鈕出現後才送第二題，漏掉這個窗口。

### 4. P2｜未分析文章被標成已分析；切換歷史時殘留錯誤版本提示

已重現兩個情境：

- `analysis: null` 的文章，助手 chip 為 `analyzed`；
- 從已分析 A 開啟未分析 B，畫面同時出現「尚未分析」及「畫面仍是舊版分析」。

證據：

- `features/assistant/assistant.js:282` 只比較正文，沒有確認分析存在。
- `features/article/article.js:2965` 的無分析分支沒有重設版本狀態。

建議：以實際分析來源判斷 chip，並完整重設無分析歷史記錄的版本狀態。

### 5. P2｜切換介面語言後，動態失敗狀態及摘要沒有更新

已重現 `zh-CN → zh-HK`：locale 已是 `zh-HK`，摘要仍為「已重試 0 段，仍失敗 2 段」，失敗原因及重試文字亦保留簡體。

證據：

- `features/article/article.js:387` 的 locale listener 沒有刷新這些動態節點。
- 摘要建立處 `features/article/article.js:2232` 只在建立時翻譯。

建議：保留狀態及插值資料，在語言切換時重新套用文案。

### 6. P2｜音訊驗收載具不可用

- `tests/audio-owner.test.mjs:45` 的事件註冊與派送都是空操作。
- 但 `tests/audio-owner.test.mjs:89` 註冊監聽後要求收到事件。

因此正常實作 owner 功能後，這個 stub 仍無法驗證成功；目前只是被 gate 跳過。建議使用可實際派送事件的 stub。

## 五、i18n、同步、安全與偏差

- 新增翻譯鍵兩語對齊，香港用詞未見明顯問題；動態語言切換仍因發現 5 未達標。
- 全域稽核列出 454 個疑似中文硬編碼及 `phonetics.` 動態鍵候選，不能直接歸為本次新增問題。
- 未見資料庫 schema migration，但段落旗標及 `message.status='cancelled'` **會改變持久化內容**。實施報告「無新增持久化欄位」的概括不準確。
- 現有同步合約 `shared/reading-protocol.mjs:243` 接受 status 字串，匯出 `modules/reading-export.js:269` 亦標示 cancelled；這只是程式碼相容證據，沒有完成實際跨端往返驗證。
- 回滾舊助手後，cancelled 半段內容可能失去不完整標示，並重新出現保存為文件入口。回滾不能把 cancelled 改寫成 complete。
- 正式驗收亦須固定 article-store／reading-store 等依賴版本，避免混合工作區的通過結果被誤當成可獨立交付證據。
- 新增摘要、chip、錯誤註記使用 `textContent` 或轉義；本次範圍未發現新增 XSS 或敏感資料外洩。
- 未見 Phase 2／3 產品功能提前實作；續作入口延至 Phase 3 有依賴理由，但不能把相關驗收概括為全部完成。
