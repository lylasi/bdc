## 5. 發現的問題與風險（按嚴重度）

1. **（測試基建／真缺陷邊界）詞卡外殼在彈窗關閉後會移動並縮放 iframe，約 500 ms 內座標不穩**
   實測同一輪內：`{x:12,y:16,w:296,h:618}` → `{x:8,y:163,w:304,h:128}`。若在這個窗口用舊座標點擊 `#ext-inline-retry`，點擊會落到 iframe 之外的網頁上：詞卡端**完全沒有任何 JS 反應**（trace 只有 `arm`，`aiAttempts` 增量 0，也無錯誤提示）。
   這與「Codex 自測 `tests/extension-lookup-cache.cjs` 末尾 locale 階段 timeout」的症狀完全一致（該測試在 `#ext-settings-close` 之後立刻點重查）。建議該測試在關閉設定彈窗後等待外殼尺寸穩定再點，或改點 iframe 內的元素時先等 `frameElement().boundingBox()` 連續穩定。
   真實使用者此情境下會被「點空」，但看到的是最終版面，影響有限；屬**可改善的互動時序**，不是快取邏輯缺陷。
   （本次測試以 `settleFrame()`＋「trace 無反應則重量測重點」處理，之後連續 3 次全綠。）
2. **401 時詞卡本身沒有錯誤提示**：`managed_login_required` 的錯誤 notice 會被 `SIGNED_OUT` 觸發的 `invalidateLookup()` 清掉，使用者只看到空白詞卡 + `#ext-inline-status` 的登入提示。資訊足夠但不夠明確（建議在 401 路徑保留 `showLookupNotice('error', ...)`）。
3. **結果剛渲染時外殼高度會落後內容約 33 px**（`innerHeight=126` vs `body=159`），實測 24–116 ms 內追上；期間收藏列可能被裁切一瞬。屬視覺閃動，不影響可點性（追上後量測全部在框內）。
4. **既有測試的期望與 0.6.3 文案不一致**：`tests/extension-capture.cjs:522/528` 仍斷言收藏鍵文字為 `加入詞書` / `加入词书`，但產品現在渲染短版 `加入`（aria 才是完整文案）。依指示未執行該套件，但該斷言在目前程式下必然失敗，需維護者更新（未修改他人測試）。
5. **失敗重試策略**：單次強制查詞在供應商持續失敗時最多發出 3 次傳輸嘗試才回報錯誤。對「AI 計數」而言，成功查詞仍是 1 次；但若以「請求次數」計費，需留意此重試放大。

- 針對使用者回報的「同詞重開仍等網絡」，在真 MV3 + 真同步後端 + 網絡被按住的條件下**已不復現**：本機命中在詞卡出現後 0.1–0.85 秒內顯示（全新 iframe 載入模組的固定成本），期間共享 Key 下載 0 次、AI 次數不增。
- 「短『加入』按鈕 + 常駐重查圖示」在 zh-CN／zh-HK、320 px 下幾何與語意（aria）皆符合；重查為一次性 `noCache`，不改寫後續預設（`#ext-force-refresh` 保持未勾選）。
- 隔離與帳戶邊界（語境、思考、模型、上游、語系、帳戶、登出、401、遲到回應）皆符合預期；`cacheOnly` 只用於讀取本機成功答案，不授權任何新請求，也不持久化共享 Key。
