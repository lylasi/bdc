## 1. 初始問題

首次登入後同步資料需要很久才完成。初判與修復集中於：

1. 匯入後的逐篇核對造成大量重複讀取。
2. IndexedDB 讀取存在 N+1 模式。
3. snapshot 拉取缺少條件式讀取，重複搬運未變更資料。
4. 多筆 IndexedDB 寫入未合併交易。
5. 備份在同步鎖內執行，拉長「同步中」時間。

## 2. 效能修復

- 匯入核對改為批次處理，避免逐篇重讀。
- 文章／閱讀清單與摘要改為一次批次讀取，移除 N+1。
- snapshot 依游標與版本條件讀取，未變更群組不重複載入。
- 多筆文件、摘要、outbox、代際帳本寫入合併至同一交易。
- 備份移出同步鎖，改為本輪結束後排程執行，並以資料簽章去重。

## 3. 正確性加固（隨複審逐步收斂）

為避免效能修正放大既有的競態與資料遺失風險，最終形成以下機制：

- **每篇文章 generation 帳本**（IndexedDB v4 `article_generations`）：rebuild、遠端 tombstone、全量拉取移除、同 ID 備份還原都會退休舊代際，遲到回執不得再修改 revision／updatedAt／outbox。
- **`restore_update` outbox 型別**：備份還原覆蓋墓碑時先 restore 再 PUT，並以 `advanceOperationBase()` 落地已確認 revision；同代際的新操作接手時只交接 revision／expectedRevision。
- **全量拉取 `onlyIfClean`**：不得刪除其他分頁尚未同步的本機內容。
- **嚴格後備讀取**：所有 localStorage 桶的讀改寫入口改用 `fallbackReadStrict()`；讀取失敗／JSON 損壞時不寫入、保留原資料並回報錯誤。涵蓋同步收尾、回執、墓碑、全量移除、備份匯入、outbox、草稿等路徑。
- **備份匯出 fail closed**：文章與閱讀匯出失敗時不保存備份、不裁剪舊備份、不更新自動備份簽章。
- **閱讀還原部分失敗回報**：`restoreAll()` 累積寫入失敗與核對錯誤，`allowPartial:true` 仍繼續處理其餘項目，但最終回 `ok:false`；備份還原 UI 因而顯示失敗而非假成功。
- **同步狀態誠實化**：文章階段頂層失敗、單篇失敗／衝突、雲端還原與文章失敗／未完成同時發生時，都不再顯示「同步完成」，並使用 zh-CN／zh-HK 雙語組合訊息。

## 7. 剩餘風險

- 後備模式（localStorage）的讀改寫沒有跨分頁原子性；嚴格讀取只能防止損壞桶被覆寫，不能提供交易隔離。
- 儲存長期不可讀時，同步每輪都會失敗並顯示錯誤，沒有自癒機制，需使用者處理儲存空間／瀏覽器資料。
- 閱讀還原核對只比對消息的 `content`／`role` 等主要欄位，不是完整 metadata 校驗。
- `partial_restore_failed` 在 UI 上呈現為整體還原失敗（保守策略），未區分「部分成功」。
- `tests/phonetics.test.mjs:47` 為既有失敗，未在本工作範圍內處理。
