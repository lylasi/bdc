## 六、新發現（本輪，皆為 P3）

### F1（P3，打包／安裝健壯性）`scripts/package-extension.mjs:142` 的 CLI 守衛在含符號連結的路徑下靜默不執行

- **程式**：`if (import.meta.url === \`file://${process.argv[1]}\`) { ... }`
- **重現**（`F1-packager-symlink.txt`，全程只動 `/tmp` 臨時目錄）：

```bash
cd /Users/linus/CODE/bdc-extension-ai-proof-20261105
rm -rf /tmp/f1probe && mkdir -p /tmp/f1probe
env -u GIT_CONFIG_COUNT -u GIT_CONFIG_VALUE_0 git archive --format=tar -o /tmp/f1probe/src.tar HEAD
mkdir -p /tmp/f1probe/src && tar -x -C /tmp/f1probe/src -f /tmp/f1probe/src.tar
cd /tmp/f1probe/src && node scripts/package-extension.mjs        # → Packaged 44 files（相對路徑，正常）
rm -rf extension/modules extension/locales extension/shared extension/_locales extension/ai-config.js
node /tmp/f1probe/src/scripts/package-extension.mjs              # → 無任何輸出、退出碼 0、extension/ 仍只有 6 個原檔
```

- **成因**：`import.meta.url` 為 `file:///private/tmp/...`，而 `process.argv[1]` 為 `/tmp/...`（macOS `/tmp` 是符號連結），字串比較不成立 → 模組只被當成「被 import」而**什麼都沒做，退出碼仍 0**。
- **影響**：只要 checkout 路徑含任一符號連結元件（`/tmp`、被 symlink 的家目錄、部分 CI workspace），文件記載的安裝步驟會**假成功**，之後載入的擴充套件缺 `_locales`／`modules`（本輪 `P2` 觀察到 Chromium 直接不載入該擴充套件）。
- **建議**：改用 `pathToFileURL(fs.realpathSync(process.argv[1])).href === import.meta.url`（或在 `packageExtension()` 外層加 `--check`／缺產物即以非 0 退出）。**我未修改產品程式碼。**

### F2（P3，文案／診斷）憑證 binding 不符仍被說成「下載失敗，請重試同步」

- **程式**：`modules/extension-ai-runtime.js:367` `credentialState: keyStatus.lastError ? 'download-failed' : (...)`；`extension/lookup.js:230` 只判斷 `lastError` 是否存在就套用下載失敗文案。

- **實際**：`credentialSync={"status":"error","error":"binding_mismatch"}`、`credentialState:"download-failed"`、橫幅「個人供應商金鑰下載失敗，請重試同步。已儲存的本機金鑰仍會保留。」、任務列「尚未解析到可用查詞模型（尚未配置此供應商的 API Key）」。

- **影響**：只誤導使用者操作，不影響安全邊界（此狀態下 `resolveAIRequestConfig` 仍會拒絕使用該 Key，`C3` 已證明不會發出任何上游請求）。
