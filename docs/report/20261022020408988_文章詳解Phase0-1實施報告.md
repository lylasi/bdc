## 五、與計劃的偏差

1. **文字判定與清理的位置**：計劃把 Markdown 清理放進 `paragraph-pipeline.js`。實作上把 `prepareParagraphForTranslation`、`stripMarkdownImagesFromText` 移到 pipeline（供 article.js 匯入，維持單一來源）；中文原文／Markdown 圖片判定則集中在 `analysis-state.js`（顯示、朗讀、統計都使用），避免三個地方各有一套。`runParagraphRequest` 由 `article.js` 提供 `aiText`／`sentences`（分句器仍留在 article.js，避免搬動 50 行渲染用分句器）。
2. **新增錯誤碼與鍵**：新增 `save_failed`、`stale_version` 對應文案，以及計劃 8.2 未列的 `article.retryNeedsReanalyze`、`article.paragraphStatusCancelled`、`article.emptyTranslation`。兩語同步補齊。
3. **`assistant.newAnswer` 未落地**：屬 P2-T4（捲動跟隨），本期未實作；`tests/assistant-state.cjs` 的「向上閱讀」案例以 `PHASE2=1` gated，預設不執行並在輸出註明。
4. **timeout 矩陣**：以 `route.abort('connectionaborted')` 代表網路／逾時類失敗（同一 `network_or_cors` 分類路徑）；真實 30–45 秒 timeout 會讓測試超過 1 分鐘且易 flaky，未納入自動化。
5. **P1-T3 的「繼續未完成分析」**：計劃標明「有 `analysis_run` 但缺結果」顯示「待分析＋繼續」；`analysis_run` 屬 Phase 3，本期只顯示「待分析」，沒有續作按鈕。

## 七、風險與審核重點

1. **`article.js` 仍是大型單檔**：本次只在既有邊界內抽離純函式與管線，沒有拆檔；請優先 review「重試／狀態列／版本」三個區塊，以及 `isJobWriteTarget` 的歸屬條件。
2. **版本狀態只在記憶體**：`viewVersion`／`analyzedVersion` 重新整理後由記錄重建；若使用者在分析後改字但未重新整理，banner 依 250ms debounce 出現，這是刻意的取捨（不自動清空舊譯文）。
3. **`status: 'cancelled'` 進入同步／匯出**：`reading-store.appendMessage` 目前不限制 status，Worker／selfhost 未拒絕；已在對話匯出加標記。若舊版客戶端把 `cancelled` 當完整答案顯示，屬跨版本風險，回滾方式是停止寫入 cancelled（改為不保存半段），但**不得**改回 `complete`。
4. **批次保存失敗會把成功段退回 failed**：使用者需再重試一次，但避免「畫面成功、記錄失敗」的假象；`article_too_large` 使用者在容量未清出前會持續失敗。
5. **主分析仍使用原有的併發 2／間隔 400ms**：段落管線化沒有改動成本曲線；Phase 3 的長文量測尚未開始。
6. **`analyzeWordInSentence` 的持久快取** 仍以 word+sentence+locale+promptVersion+model 為身份；本次只補「空 meaning 不進快取、頁內 Promise 去重」，未改 API 快取 TTL／容量（P3-T2）。
7. **`api.js` 的網路錯誤分類**：把 fetch 的 `TypeError` 標成 `network_or_cors`，會讓所有 AI 任務的錯誤訊息更精確；`ai-*` 測試 70 項通過，但其他模組若依賴舊的 `provider_error` 文案，需留意。
8. **i18n unused 鍵**：新增 4 個 map 鍵被稽核腳本視為未引用（與既有 `errors.*` 相同情況），不是缺鍵；兩語鍵集合與插值一致。
9. **並發工作區**：見偏差 12；提交前務必只挑本次檔案，否則會把另一個工作階段的 WIP 一起帶入。
10. **`#article-version-notice` 的 `role="status"`**：切換語言時文字會原位更新；未使用 modal，符合 D11（不保留舊版閱讀入口）。
