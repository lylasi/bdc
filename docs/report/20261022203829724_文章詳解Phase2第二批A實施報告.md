## 一、根因

### P2-T2 單詞詳解

1. `.tooltip` 沒有高度上限與內捲：長 `meaning/role` 會把面板撐到 1000px 以上，超出視窗；實測 375×667 時高度 1126px、`overflow-y: visible`。
2. 沒有關閉鈕；唯一的收起方式是點擊頁面其他位置或再點別的字，鍵盤使用者沒有可見出口。
3. 內容順序是「作用（role）→ 意思（meaning）」，句子角色比詞義更先出現；六個操作（加入詞書、標記、筆記、選短語、解析短語、自訂短語）全部攤平，沒有主次。
4. 載入中只顯示一行 `article.loading` 與部分操作，沒有發音、沒有關閉，也沒有固定標題。
5. 焦點完全沒有管理：滑鼠關閉後焦點留在 body；鍵盤開啟時焦點不會進面板，locale 切換重畫後焦點也會遺失。
6. `ui.initTooltip()` 直接 `display:none`，article 模組的 `wordTooltipSession`、觸發詞與焦點狀態不會被同步清除；晚到的查詞回應有機會重新打開面板。
7. 定位只用 `rect + window.scrollY`。文章載入後有平滑捲動；捲動中 `rect` 與 `scrollY` 可能不同步，長面板會被定位到離觸發詞很遠的位置（橫屏實測 top ≈ -771px）。

### P2-T3 句級鍵盤入口與逐詞模式

1. `.interactive-sentence` 只是 `<span>`，沒有 `tabindex`、`role`、`aria-expanded`、`aria-label`；用鍵盤完全無法把焦點放到句子上（測試紅燈：`document.activeElement` 仍是 `BODY`）。
2. 句卡沒有鍵盤焦點管理：開卡後焦點留在背景，卡片內按鈕要用滑鼠找；關閉後焦點遺失。
3. 沒有「逐詞檢視」入口；詞的 `.interactive-word` 永遠不可聚焦，也沒有方向鍵導覽。
4. 100 段文章若把每個詞都放進 Tab 順序會爆炸；需求是只讓目前這一句的詞可聚焦，且句卡關閉／換句時要清乾淨。
5. `.sent-analyze-btn` 的實際點擊區只有 16×16、預設 opacity 0.3，手機與低視力使用者難以命中。

## 二、改法

### 1. `index.html`

`#word-analysis-tooltip` 加上：

```html
role="dialog" aria-modal="false" aria-labelledby="word-tooltip-title" tabindex="-1"
```

不鎖背景（沒有 focus trap、沒有遮罩），只提供可讀標題與程式聚焦點。

### 2. `styles.css`

- `.tooltip`：`max-height: min(70vh, 520px)`、`overflow-y: auto`、`overscroll-behavior: contain`，`padding-bottom` 計入 `--safe-bottom`。
- `.tooltip.tooltip-sheet` 與 `@media (max-width: 640px)`：固定在底部、左右 8px、`bottom: calc(var(--safe-bottom, 0px) + 8px)`、`max-height: 60vh`。
- 新增 `.tooltip-head`、`.tooltip-close`（28×28）、`.tooltip-primary-actions`、`.tooltip-more`／`.tooltip-more-body`、`.tooltip-role`（次要層級）。
- `.sent-analyze-btn.icon-only`：圖示維持 16px，`opacity: 0.55`，hover／focus-visible 為 1；用 `::after` 把可點區擴到 28×28，`@media (pointer: coarse)` 為 32×32，不撐高行距。
- 新增 `.interactive-sentence:focus-visible`、`.interactive-word:focus-visible`、`.sentence-card:focus-within`、`.word-mode-hint`；未改滑鼠 hover 行為。

### 3. `modules/ui.js`（最小兼容修改）

- `repositionTooltip()`：偵測 `.tooltip-sheet` 時只設 `visibility`，不寫 `top/left`；其餘情況改為「先算視窗座標，再換算 offsetParent 座標」，並把面板夾在視窗內。這修掉平滑捲動期間 `rect`／`scrollY` 不同步造成的錯位，屬 P2-T2「長詳解不越界」的必要修正。
- 新增 `hideTooltip(source)`：Escape、關閉鈕、外部點擊共用；收起時 dispatch `bdc:tooltip-hidden`，讓 article 清 session／焦點狀態。
- `initTooltip()` 改呼叫 `hideTooltip('outside-click')`；沒有改變其他模組行為（全站只有 article 使用 `repositionTooltip`）。

### 4. `features/article/article.js`

#### 單詞詳解

- 新增 `wordTooltipTrigger`、`wordTooltipReturnFocus`、`wordTooltipLastPayload`、`wordTooltipRender`、`wordTooltipKeyboardOpen`。
- `renderTooltipShell()` 統一輸出：
  - 標題列：`#word-tooltip-title`（`tabindex="-1"`）＋ `.tooltip-close`（`article.close`）。
  - 內容：**意思 → 句中角色（次要 `.tooltip-role`）**。
  - 操作：`.tooltip-primary-actions` 只放 `btn-play-word`、`btn-add-to-book`、`btn-toggle-mark`。
  - `<details class="tooltip-more">` 內放 `btn-note-item`、`btn-pick-phrase`、`btn-analyze-phrase`、`btn-analyze-phrase-custom`。
- 載入中使用 `showLoading()`：保留標題、發音、加入詞書、標記、關閉與 `article.loading`。
- 失敗使用 `showError()`：保留重試與主要操作，locale 切換可重畫。
- 鍵盤開啟判定：`options.keyboard === true`、`event.detail === 0`，或 `document.activeElement` 是觸發詞／句子節點；第一次與非同步重畫時把焦點放在標題。
- Escape／關閉鈕：`dismissWordTooltip({ restoreFocus: true })`，焦點回觸發詞（若仍在 DOM）；若詞原本不可聚焦，暫時 `tabindex="-1"`，blur 後移除。
- 外部點擊：`ui.hideTooltip` dispatch `bdc:tooltip-hidden`，article 清 session、觸發詞與焦點狀態；晚到的回應因 `stillShowing()`（含 `clickedElement.isConnected`）不會重開。
- locale listener：可見時用 `wordTooltipLastPayload` 重畫；觸發詞不在 DOM 則關閉並清除。
- `repositionTooltip` 在 `scroll`（rAF 節流）與 `resize` 時重新對位，詳解跟著觸發詞走。

#### 句級鍵盤與逐詞

- `sentenceWrapHtml()`：`.interactive-sentence` 加 `tabindex="0"`、`role="button"`、`aria-expanded="false"`、`aria-label="句首 40 字 · article.sentenceAnalysis"`。
- `sentenceAnalyzeButtonHtml()`：`aria-label` 同樣含句首片段，並同步 `aria-expanded`。
- `handleArticleAnalysisKeydown()`：
  - 句子上 Enter／Space → 開關句卡；Escape 收起。
  - 逐詞模式中左右方向鍵移動、Enter 查詞、Escape 離開逐詞模式（若詳解仍開著，第一次 Escape 先關詳解）。
- `toggleSentenceCard(sentenceEl, { keyboard })`：
  - Modal 開卡時 `aria-expanded="true"`，記錄 `articleSentenceCard`。
  - 僅鍵盤開啟時先把焦點放進卡片；`renderSentenceCard()` 完成後再移到第一個可操作元素（`.sent-word-mode`）。
  - 關閉（Escape、背景、關閉鈕、換文章）由 `bdc:modal-closed` / `resetSentenceCardState()` 還原 `aria-expanded`、清逐詞 `tabindex`、必要時把焦點還給句子。
- 句卡頂部新增 `.sent-word-mode`（`article.wordMode`）。按下後：
  - Modal 句卡先收起，再對「該句」的 `.interactive-word` 設 `tabindex="0"`，焦點移到第一個詞；其他句子保持不可聚焦。
  - 顯示 `article.wordModeHint`（`role="status"`）。
  - 句卡關閉／換句／重繪時清除全部逐詞 `tabindex`。
- locale listener 重套句子與解析鍵的 `aria-label`、逐詞提示與句卡「逐詞檢視」文案。

> 設計取捨：目前 `USE_SENTENCE_MODAL = true`，句卡是模態層。若保持句卡開啟卻把焦點移到遮罩後的詞，會造成焦點落在不可見內容。因此「逐詞檢視」會先收起句卡、回到文章本體再進入逐詞模式；這也讓「開句卡 → 逐詞 → 查詞 → 關閉 → 回句」的 Escape 層級自然成立。

## 六、殘留風險與未覆蓋

1. **真實裝置／輔助技術**：未實跑 iOS Safari＋VoiceOver、Android Chrome＋TalkBack。`role="dialog"`＋`aria-modal="false"` 對非模態浮層可能過度宣告；若實機干擾，計劃允許改 `role="group"` 並保留 `aria-labelledby`。
2. **軟鍵盤**：sheet 以 `bottom: safe-area + 8px` 定位，未在真實 iOS 軟鍵盤上量測；若鍵盤遮住底部，計劃的降級是可拖曳高度或回到上方浮層＋max-height。
3. **200% 縮放**：測試以 `html { font-size: 32px }` 模擬文字放大，不是瀏覽器頁面縮放（pinch／Ctrl+加號）。版面結果偏向保守（文字變高），但未覆蓋所有瀏覽器的 zoom 行為。
4. **逐詞模式與句卡的關係**：因句卡是 modal，按「逐詞檢視」會先收起句卡；若產品要求句卡保持開啟，需要另外設計非模態句卡或卡內逐詞介面。
5. **locale 重畫**：詳解與逐詞提示會即時更新；句卡內其他動態內容（譯文、chunks、按鈕忙碌狀態）仍沿用既有行為，完整保留面板狀態屬 P3-T3。
6. **測試載具**：文章清單目前只讀 `article_summaries`，新測試在 `seedDocs` 後呼叫 `articleStore.reloadScope()` 重建摘要；未改共用 `tests/helpers/article-mock.cjs`。既有 `article-reliability.cjs` 在本樹仍可通過。
7. **定位依賴 offsetParent**：`repositionTooltip` 現在以 offsetParent 換算座標；若未來把 tooltip 移到有 `transform` 的新容器，需重新確認。
