# 擴充套件 0.6.3：本機快取直讀與常駐重查圖示

## 問題及修正

查詞的成功結果原本已存在本機，但詞卡每次開啟會先等待詞書／工作區初始化、`/snapshot`、catalog 和個人憑證同步；共用查詞又先解析可能下載共享 Key 的連線設定，才嘗試快取。因此「有本機快取」仍會出現網絡等待。

現在由共用 `getCachedLookupSelection` 先只讀取本機成功結果。沿用原有 IndexedDB／localStorage、30 天有效期及鍵格式；原句、語境、供應商、上游網址、模型、思考、語言、帳戶／端點、catalog 及 prompt 版本仍分區。未命中才等待正常 AI 設定及傳輸。詞書／耐久待傳初始化不阻擋命中結果；命中後帳戶同步在背景進行。

`cacheOnly` 僅用公開 metadata 讀取過去答案，回傳的連線中不含 Key。實際 AI 的 `resolveAIRequestConfigAsync` 強制使用 `cacheOnly:false`，仍驗證 session、provider、model、catalog 及 credential binding。擴充讀取前後檢查帳戶 scope 與 signal，登出或帳戶切換不接受遲到結果。

收藏列改為「加入＋詞書圖示＋重查圖示」，加入按鈕固定約 64px，不再撐滿整行；短文字保留完整 aria label。重查只略過當次快取，成功後更新原快取，成功及失敗後圖示都保留；詞書規則、來源及當前釋義保存語意延用既有流程。命中時加上「本機快取」小標記。

另修正詞卡錯誤提示最初帶 `hidden` 屬性、僅移除 CSS class 仍不會顯示的問題；現在顯隱屬性一致。重查失敗會顯示原因，不把失敗覆蓋為成功快取，恢復後可再按圖示。

快取瀏覽器測試不是只驗證同一個 iframe 的記憶體：關窗後重開、刷新來源網頁、在另一網站開同一詞句語境，均刻意按住同步請求，確認結果在放行前出現且 AI 次數不增加。重查以真實輸出版本區分新舊結果；再開後命中新版本。供應商持續回 503 時顯示錯誤與可用重查圖示，恢復後能查詢及更新快取。

窄窗高度同時補足 iframe 的兩條 1px 邊線，避免 body 底部少 2px 可見空間。兩語 320px 測試等待外層 iframe 完成縮放，檢查三個按鈕仍在同一行、完整位於可見區域且可命中。較早腳本只等待 dialog 關閉，可能在外層 iframe 尚未完成非同步移動時點擊錯誤位置；現已補上幾何穩定條件，未放寬請求計數或保存斷言。

所有 AI transport 為本機 mock，Worker 與 SQLite 路由實際執行。未使用正式帳戶或正式 AI 呼叫作成功證據。快取的讀取不意味著新的 AI 呼叫可以離線執行；收藏同步仍需服務連線。

## 最後審核

DeepSeek 的 37 項驗收均通過，涵蓋無記憶體共享 Key 時讀本機、傳輸仍需原有 binding 驗證、共享 Key 未持久化、語境／模型／上游／帳戶／語言隔離、登出與 401、遲到回應、重查恢復及兩語收藏。

其指出的既有 `extension-capture.cjs` 文字期望已改為短標題，同時斷言完整 aria label；忙碌等待亦識別「加入中」，完整 31 項已重跑通過。401 清除舊結果並改為登入提示，屬本輪接受的會話失效恢復方式。供應商持續失敗仍沿用既有 fallback／重試策略，可能嘗試多次傳輸；一次按重查的語意是略過當次快取，不保證失敗時只送一個 HTTP 請求。

外殼以跨情境訊息更新尺寸，首次結果出現仍可能有 24–116ms 的高度追趕；穩定後三個控制項完整可見，2px 邊線差已補足。這不會再次等待同步網絡，也不影響最終快取或詞條資料。
