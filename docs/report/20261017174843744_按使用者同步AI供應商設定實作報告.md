## 2. 後端（Cloudflare Worker / D1）

### 新增檔案

- `cloudflare-worker/src/credential-crypto.js`：AES-256-GCM、版本化主密鑰、canonical binding、personal/managed 分離 AAD、HMAC 發布摘要、binding URL 驗證。
- `cloudflare-worker/src/http.js`：CORS origin 白名單、`Cache-Control: no-store`、大小限制 JSON body、單 isolate 限流。
- `cloudflare-worker/src/ai-credentials.js`：個人憑證 CRUD、`user_id + provider_id + version` 條件更新、首次建立主鍵衝突、mutationId 冪等、刪除 tombstone、上限（200 個 / 單次 32 KiB / Key 8 KiB）。
- `cloudflare-worker/src/ai-catalog.js`：預設列表讀取、共享 Key 按需解密、管理員完整草稿／歷史、原子發布、`baseVersion` 衝突、mutation 冪等、preserve/replace/clear Key 操作、10 版歷史、憑證 revision。
- `cloudflare-worker/src/snapshot-sanitize.js`：伺服器端過濾普通 snapshot 的 AI 群組（不得含 Key、managed 定義、任務層網址／Key 覆寫、帶憑證 URL）。
- `cloudflare-worker/migrations/001_ai_provider_sync.sql`：`users.role`、`user_ai_credentials`、`ai_default_catalog_releases`。

### 修改檔案

- `cloudflare-worker/src/worker.js`：路由整合、角色檢查、舊通行碼在 AI 路由回 `403 passcode_upgrade_required`、Origin 檢查、`/me` 回角色、no-store、錯誤碼、snapshot 讀寫過濾。
- `cloudflare-worker/schema.sql`：新資料表與 `role`。
- `cloudflare-worker/add-user.mjs`：自動產生 43 字元通行碼、最低 32 字元、`--admin` 僅在 INSERT 設定角色、既有帳號角色不被覆蓋。
- `cloudflare-worker/wrangler.toml.example`、`README.md`：秘密、migration、角色、接口、輪換與安全邊界。

### 行為重點

- 個人與共享 Key 使用不同 AAD 領域，互換解密必失敗。
- 共享 Key 只在已登入且 `catalogVersion` 等於當前版本時回傳；停用或不存在回 404。
- 發布以 `INSERT ... ON CONFLICT(version) DO NOTHING` 保證只有一位管理員成功；`baseVersion` 不符回 409。
- 同 `mutationId` 且內容相同回原結果；同 ID 不同內容或版本已前進回 409。
- 缺少主密鑰只讓憑證路由回 503，不影響學習資料同步。
- Worker 不代理任何 AI 生成請求。

## 4. 行為與安全

- 未登入：預設供應商鎖定；可新增／使用「此裝置」供應商；不下載共享 Key。
- 已登入：以 `/me` 與 `/ai-catalog` 在線驗證；共享 Key 只進入記憶體，最長 60 分鐘；每次 AI 請求只檢查本機有效期、供應商狀態與 binding，不逐次查 D1。
- 個人供應商：不逐次驗證登入；401 後仍可用本機 Key，直到使用者明確登出（清除帳戶 profile）。
- 明確登出：清除該帳戶 profile／個人 Key／共享 Key／預設列表快取／管理中草稿，取消相關請求；其他分頁透過 storage 事件失效。
- 端點或認證方式變更後，保留舊 Key 需要重新確認；未重新輸入前 resolver 拒絕請求。
- 進階設定可明確允許跨來源模型列表（預設關閉）；否則模型探索拒絕把 Key 送到不同 origin。
- 一般 snapshot 只允許個人定義與選擇引用，managed 定義、Key、`discoveryError`、任務層網址／Key 覆寫都會被前後端丟棄。
- 共享 Key 複製風險、60 分鐘有效期與「非供應商端強制登入」已在 UI 與文件中明示。

## 5. 介面

- 預設供應商：只讀列表、登入／驗證狀態、剩餘時間、管理員入口；不顯示 Key。
- 我的供應商：精簡列（名稱、協議、模型數、來源／同步狀態、啟用、編輯、刪除）；「新增供應商」在空列表與未登入時仍可見。
- 新增表單預設只有「服務網址 + API Key」；名稱／協議／認證／端點／手動模型在「進階設定」；連接成功才顯示模型；單模型預選，多模型要求選擇。
- 測試模型需第二次確認並提示可能產生費用；只發一次短請求。
- 逐任務模型在「按功能指定模型」收合區；明確選擇 > 個人預設 > 管理員任務預設；不可用時提示重選，不自動改用其他供應商。
- 金鑰同步：同步／只在本機／移除雲端；待同步、同步失敗、版本衝突（雲端／本機／稍後）。
- 管理員：版本、發布人／時間、供應商草稿、Key 保留／替換／清除、模型、任務預設、測試、歷史還原、發布；明確警告共享 Key 可被已登入使用者複製。

## 7. 未完成事項與環境阻礙

1. **未部署、未修改正式 D1、未建立或撤銷任何真實 Key。** 部署與 migration 指令見 release 指南。
2. **本機 `ai-config.js` 仍含靜態 AI 設定與秘密。** 依照「不讀出／輸出秘密、不提交秘密」的約束，本次沒有改寫該私有檔；已提供 `scripts/migrate-ai-config.mjs`（不列印秘密、備份與匯入檔放網站根目錄外）與管理員 JSON 匯入。部署前必須執行，並在供應商端撤銷舊 Key；靜態主機也應避免公開此檔。
3. 既有 `audit-flows` 全量跑完的 AI 功能會因未配置供應商而記錄 console error（low）；這是新架構下的預期提示，不是不可用。實際 AI 呼叫已用 mock 三協議驗證。
4. 既有 Playwright 測試需外部 `PLAYWRIGHT_MODULE`；專案仍未新增 npm 工作流。
5. 憑證同步使用 Web Locks 序列化；Provider 編輯／任務選擇等同步 UI 寫入仍是最後寫入者勝（本機 profile 以 revision 讀回驗證，雲端以版本 CAS 防止無聲覆寫）。尚未加入「Web Locks 不可用時停止多分頁自動寫入」的專用提示。
6. 共享 Key 的 60 分鐘到期以模組邏輯實作；自動測試未模擬 60 分鐘等待，屬程式碼審查與短時效邏輯驗證範圍。
