# 閱讀面板同 Scope 重載標記恢復修復

## 任務範圍

- 只處理「文章開啟後執行 `refreshScope()` + `reloadReadingScope()`，已有劃線消失」。
- 未修改 `modules/reading-store.js`、`modules/article-store.js`、`tests/article-refresh-scope.cjs`、`tests/reading-lazy-load.cjs`。
- 未部署；只提交本次修復、獨立回歸與本報告，保留工作區內其他任務與主代理的 release 文件／assets。

## 根因

`reading-store.reloadReadingScope()` 在同一 scope 下會走 `loadScopeIntoMemory()`，清空 `itemsById`、`documentsById` 與 `loadedArticleIds`，再發出 `bdc:reading-change`（`reason: 'scope-reloaded'`）。

`reading-panel.js` 原本對所有 `bdc:reading-change` 直接 `applyMarks(currentArticleId)`，但沒有先按需補讀目前文章，因此：

- 記憶體中的學習條目已清空；
- `applyMarks()` 找不到既有 `marked: true` 條目；
- 正文劃線被清掉，面板也可能顯示空資料；
- 直到重新點詞、重新載入文章後才恢復。

## 修復內容

檔案：`features/article/reading-panel.js`

1. `reason === 'scope-reloaded'` 不再直接套用空資料，改為只對目前文章呼叫 `ensureArticleReadingLoaded()` 補讀。
2. 補讀完成後才重畫目前文章的正文標記與面板；冷文章仍維持未載入。
3. 以 `scopeRefreshToken`、目前 `articleId` 與 `readingStore.isReadingContextActive(ctx)` 三重檢查，避免非同步結果在切換文章／帳戶後回畫。
4. `loadArticle()` 與 `bdc:articles-scope-changed` 會使舊補讀失效。
5. 一般 `bdc:reading-change`（標記、筆記等）只同步目前記憶體狀態，不觸發補讀，避免遞迴或全量載入。
6. 面板重繪沿用「筆記輸入中不整份 render」保護；scope 重載時只更新同步狀態，保留 textarea 焦點與草稿。

## 新增回歸測試

檔案：`tests/reading-panel-scope-refresh.cjs`

獨立 Playwright 回歸，使用桌面 `zh-CN` 1440×960 與手機 `zh-HK` 390×844，涵蓋：

1. 主動標記第二個重複詞 → refresh → 精確劃線、版本／錨點與面板項目仍在。
2. 重載只按需讀目前文章；以 IDB `scope_article` 讀取探針確認沒有讀入冷文章。
3. 正常 mark 事件不觸發 `scope_article` 補讀。
4. 筆記輸入中 refresh：焦點、未保存草稿、面板內容均保留，之後仍可保存。
5. 補讀期間切換文章：舊文章結果不得畫到新文章。
6. 補讀期間切換帳戶 scope：舊 scope 的條目與劃線不得回畫到新 scope。

測試以 IndexedDB request 明確暫停補讀，不使用 sleep 假裝競態。

## 風險與注意事項

- 同一 scope 重載後會多一次「目前文章」的 IndexedDB 按需讀取；不影響冷文章 lazy load。
- 一般 mark 事件不新增任何讀取，不會遞迴觸發 scope 補讀。
- 若補讀失敗，維持現有畫面（不主動清空），等待下一次閱讀變更或文章載入重試；不顯示誤導性的成功狀態。
- 筆記輸入中只更新面板同步狀態，不重繪列表；使用者離開輸入框後再由既有事件／操作刷新完整列表。
