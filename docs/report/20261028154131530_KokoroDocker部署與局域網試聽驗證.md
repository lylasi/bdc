# Kokoro Docker 部署與局域網試聽驗證

- 日期：2026-10-28。
- 目標：在現有 Mac 部署 Kokoro Docker，提供實際可用的試聽頁，並按使用者後續要求開放 `10.10.10.5` 局域網存取。
- 結果：容器持續運行，Docker 健康檢查為 `healthy`；本機及局域網位址的試聽頁、聲線 API、語音合成均已驗證。

## 使用入口

- 局域網試聽：<http://10.10.10.5:8880/web/>。
- 本機試聽：<http://127.0.0.1:8880/web/>。
- 局域網 API 文件：<http://10.10.10.5:8880/docs>。
- 健康檢查：<http://10.10.10.5:8880/health>。

同一局域網裝置應使用 `10.10.10.5`；`127.0.0.1` 只指向開啟網頁的裝置自身。此次檢查由部署主機透過 LAN 位址完成，尚未由另一部實體手機驗證網絡／防火牆可達性。

## 部署設定

設定檔：[selfhost/kokoro/compose.yaml](../../selfhost/kokoro/compose.yaml)。

- 容器：`bdc-kokoro`。
- 映像：`ghcr.io/remsky/kokoro-fastapi-cpu`，固定 digest：

```text
sha256:ee3111d6a2c903ed62f3b4fa19543c6901205ed39fce3c177e895b34a8386b9c
```

- Apple Silicon 使用原生 Linux ARM64 映像，CPU 推理。
- 服務端 API 版本：`0.9.0`，啟動時載入 72 個聲線。
- CPU 上限：4 核；記憶體上限：6 GiB；單一 worker。
- 綁定：`127.0.0.1:8880` 及 `10.10.10.5:8880`。
- 重啟策略：`unless-stopped`。
- 每 30 秒以容器內 `/health` 執行健康檢查，起動寬限 60 秒。
- API 日誌等級 `INFO`；Docker 日誌每檔上限 10 MB、保留 3 檔。

最初僅綁定 loopback；使用者指出局域網需要存取後，已核對 `10.10.10.5` 確實為本機 `en0` 位址，再新增該位址並重建容器。未改為所有網絡介面通用監聽，亦未建立公網 Tunnel。

## 實際驗證

### 服務及 API

以下兩個 base URL 的 `/health`、`/web/`、`/v1/audio/voices` 均回應 HTTP 200：

- `http://127.0.0.1:8880`
- `http://10.10.10.5:8880`

`/health` 回傳 `{"status":"healthy"}`，聲線列表含 72 個項目；OpenAPI 的語音端點為 `POST /v1/audio/speech`。

### 生成及音訊檔驗證

以實際 API 生成 MP3，使用 ffprobe 解析規格，並以 ffmpeg 完整解碼，沒有解碼錯誤。

| 測試 | 聲線 | 字符數 | 生成完成時間 | 音訊長度 |
| --- | --- | ---: | ---: | ---: |
| 英語三句短文 | `bf_emma`，英式 | 130 | 5.409 秒 | 7.128 秒 |
| 單詞 `pronunciation` | `af_heart`，美式 | 13 | 1.571 秒 | 1.392 秒 |

兩者均為 HTTP 200、`audio/mpeg`、24 kHz、單聲道。時間是本次完整回應耗時，不是首段播放延遲或正式效能基準；發音正確性及自然度仍由使用者試聽評估。

### 真實試聽頁互動

使用 `run` 及 `playwright-cli` 技能啟動與驅動上游試聽介面：

1. 開啟本機 `/web/`，填入 130 字符英語短文，使用預設 `af_heart` 按下 Generate Speech。
2. 頁面顯示 `Generation complete in 4.9s`，自動播放流程推進到片段末尾，可重播及下載。
3. 改以 `http://10.10.10.5:8880/web/` 開啟，填入 71 字符試驗文字，關閉自動播放後生成。
4. LAN 網址的頁面顯示 `Generation complete in 3.3s`，Play 可按、Download 可見。
5. 兩次查看瀏覽器 console，均為 0 errors、0 warnings。

畫面已截圖並檢視，確認文字、播放器、生成完成狀態正常：

- [LAN 試聽完成畫面](assets/20261028154131530/kokoro-lan-player.png)。

API 生成完成後曾觀察容器約 1.343 GiB；重新建立並完成 LAN 合成後觀察約 1.079 GiB。這是離散時間點的 Docker 統計，不是峰值記憶體上限測試。

## 操作與維護

從任意目錄執行：

```bash
# 啟動／套用設定
docker compose -f /Users/linus/CODE/bdc/selfhost/kokoro/compose.yaml up -d

# 查看服務
docker compose -f /Users/linus/CODE/bdc/selfhost/kokoro/compose.yaml ps

# 查看最近日誌
docker logs --tail 80 bdc-kokoro

# 暫停試用服務
docker compose -f /Users/linus/CODE/bdc/selfhost/kokoro/compose.yaml stop
```

若主機 LAN IP 日後不再是 `10.10.10.5`，需更新 Compose 對應 port binding，再執行 `up -d`。同一局域網仍需允許裝置互通及 TCP 8880 連線。

本次部署供獨立試聽；BDC 正式朗讀路徑的 `/tts` 協議轉接及聲線映射屬後續接入工作。本次沒有執行模型訓練或音質評分。
