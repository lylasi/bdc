## 3. 分詞與 skip 規則

### 3.1 `segmentWords(text, { locale = 'en' } = {})`

- 優先 `new Intl.Segmenter(locale, { granularity: 'word' })`；建構失敗時退回 `'en'`；仍失敗或 API 缺失時走 fallback。
- 只取 `isWordLike === true` 且「含字母」（`\p{L}`）的片段；純數字（`2020`、`3.14`）不成為查詞 token。
- 連字號合併：Segmenter 會把 `co-operate` 切成 `co`／`operate`、`COVID-19` 切成 `COVID`／`19`；本模組把「只隔一個連字號（`-`、`‐`、`‑`）」的相鄰 word-like 片段合併回同一個詞，合併後才做含字母檢查。因此 `COVID-19`、`B2B-commerce`、`3D-printed`、`state-of-the-art` 都是一個 token。
- 回傳 `{ word, start, end }[]`：`word` 是原文切片，`start`／`end` 是原文 code unit offset；呼叫端只包 DOM，不改文字，錨點／朗讀定位不受影響。
- fallback regex：`/(?=[\p{L}\p{M}\p{N}.'’\-‐‑]*\p{L})[\p{L}\p{M}\p{N}][\p{L}\p{M}\p{N}'’.\-‐‑]*/gu`
  - 以規格 regex 為基礎，額外允許 `3D`（數字開頭但整串含字母）與非斷行連字號；
  - 尾端標點交由 `trimTokenEdge` 去除，所以 `U.S.A.` → `U.S.A`、網址尾點不會留在詞內；
  - `3.14`、`2020` 不會產生 token，不會在小數點切錯。
- `trimTokenEdge` 只去詞兩端標點，保留詞內 `'`、`’`、`.`、`-`。
- `isTokenizableChar` 接受字母、組合符號（`\p{M}`）、數字；標點、空白、emoji 不接受。

### 3.2 `shouldSkipNode(node)`

- `node` 可為元素或文字節點；文字節點以其 `parentElement` 判定，統一用 `closest`。
- skip selector：`a, code, pre, kbd, samp, script, style, textarea, .sent-analyze-btn, .interactive-word, .md-image, [data-no-word-wrap]`。
- 無 DOM／`closest` 不可用時回 `false`，呼叫端不需防禦；不會拋錯。

### 3.3 `article.js` 的落地方式

- `wrapWordsInElement`：TreeWalker 只收「非 skip」文字節點，逐 token 建立 `span.interactive-word`，`data-word` 寫原文（含大小寫與重音），文字切片原樣保留。
- `wrapWordsInTextHTML`：HTML 字串版本同樣以 `segmentWords` + escapeHtml 組字，只包 token、不改文字。
- 文章查詞以拉丁字詞為主：包字前額外過濾 `\p{Script=Latin}`，純 CJK 原文沿用舊行為（不把每個漢字變成查詞入口）；`segmentWords` 本身仍回傳 CJK token（單元測試涵蓋中文混排）。
- 點擊：`handleArticleWordAnalysisClick` 與 container click 都在最前面檢查 `rawTarget.closest('a, code, pre, kbd, samp')`，命中直接 `return`（不 `stopPropagation`、不 `preventDefault`），連結照常開、code 不開 tooltip、不開句卡。
- `bindAnalyzeButtonToLastWord` 尾詞 regex 改為 `[\p{L}\p{M}\p{N}][\p{L}\p{M}\p{N}'’.-]*[^\s\p{L}\p{M}\p{N}]*\s*$`，避免帶重音詞被尾詞擷取拆開；`while (node && guard < 3)` 等既有邏輯未動。

## 6. 殘留風險

1. **舊版瀏覽器無 `Intl.Segmenter`**：fallback 已用同一批 29 組樣本驗證；但 fallback 對 CJK 的分詞粒度與 Segmenter 不同（會被當成一整串），文章端有拉丁字過濾，CJK 不會生成 token，影響限於 `segmentWords` 的呼叫端若直接把 CJK token 拿去查詞。
2. **HTML 字串預先包字路徑**：`replaceOutsideTags`（表格、預先比對 `detailed_analysis`／`word_alignment`）仍用舊 ASCII regex；連字號／重音詞若剛好命中既有分析資料，可能先由字串路徑包成 token（例如 `COVID-` 與 `19` 分開），之後不會再被 DOM 路徑修正。未在本次改動範圍；目前不影響驗收（測試以空 `detailed_analysis` 驗證 DOM 路徑）。
3. **文字內 `data-word` 與舊記錄比對**：`data-word` 保留原文，`showArticleWordAnalysis` 的 `item.word` 比對仍大小寫不敏感，未改比對邏輯；但若舊 `detailed_analysis` 以 ASCII 片段（`Caf`／`na`）存過，新的完整詞不會命中舊條目，會走一次懶載，屬預期。
4. **CJK 原文**：文章端以 `\p{Script=Latin}` 過濾，純中文段落維持不包 token；若未來要做中文查詞，需另開入口，不要直接放開此過濾。
5. **未量測效能**：P3-T5 尚未實作；`Intl.Segmenter` 對長文的成本未量測，本次未宣稱任何效能數字。
6. **未新增翻譯鍵**：本次沒有新增使用者可見文案，`zh-CN`／`zh-HK` 鍵集合未變（`audit-i18n` 通過）。
