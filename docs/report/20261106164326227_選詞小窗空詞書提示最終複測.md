## 七、一個需要知道、但**不是**本輪造成的既有行為

**緊湊卡剛開好時，提示列（`#ext-capture-notice`）是空的**，空詞書的引導只出現在**下拉佔位文字**上；按「更多」展開再按「刷新」後，提示列才出現同一條文字（I12／I14 實測）。

原因（讀碼，`b7cc464` 內容）：

- `extension/lookup.js:577` `await captureUI.sync()` → `extension/capture-ui.js:157` 在書單為 0 時 `setNotice('extension.captureNoBooks')`（此時提示列有字）；
- 接著 `extension/lookup.js:584` `await handleLookup()` → `extension/lookup.js:442` `clearDisplayedResult()` → `extension/capture-ui.js:254–263` 的 `clearResult()` 把 `notice` 設回 `null`，**清掉了剛設好的提示**；之後 `showResult()` 不會補回來。

這是**既有程式路徑**：本輪只換了兩條字串，`capture-ui.js` 一行未改，改動前後行為相同。使用者在卡上看到的引導仍然是正確的新文字（下拉佔位 ＋ 一鍵建書按鈕），所以**不影響放行**。若之後想讓提示列在緊湊卡也穩定可見，可考慮「查詞完成後重設空詞書提示」或「`clearResult` 不清 notice」——屬打磨項，建議另開票。
