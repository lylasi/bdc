## 缺陷與根因

重現流程：

1. 開第一處重複句卡並完成初次分析。
2. 原卡仍開著時，`articleStore.saveArticle` 把同一 article ID 的正文改版（模擬其他分頁／同步）。
3. 點舊卡的「重新取得」。
4. 舊行為在點擊當下才 `captureActionContext()` 與 `readingActions.articleVersion()`，忽略卡片自己的 `dataset.contentVersion`／anchor；於是新版正文重新解析重複句得到 `start=-1`，並把 `stale-card-refresh` 寫進新版 `result.sentence_analysis`。

修復前獨立覆核（`/tmp/bdc-stale-sentence-review.cjs`）實際輸出：

- `originalVersion cv1_7019bacf_64`
- items `[{version:cv1_503634f7_81,start:-1},{version:cv1_7019bacf_64,start:0}]`
- legacy analysis `[stale-card-refresh]`
- 2 項失敗、page error 0
- 證據：`docs/report/assets/20261021002319652/stale-sentence-before-fix.json`

另一個同源問題：`toggleSentenceCard` 首次 `await` 回來後，`canUpdateView` 只比對帳戶與 article ID，正文改版後仍會把遲到的首次句子回應重繪進舊卡。

## 精確變更

### 1. 句卡凍結歸屬（`features/article/article.js`）

新增模組層 `WeakMap` 與輔助函式，位置在 `stampSentenceCardTarget` 一帶：

- `sentenceCardTargets`：卡片 → 凍結歸屬。
- `stampSentenceCardTarget(card, articleId, contentVersion, anchor, extra)`：
  - 建立時保存 `articleId`、`contentVersion`、精確 `anchor`（start／end／quote）、`sentence`、`context`、`paraIdx`、`sentIdx`、`articleContext`、`actionContext`。
  - 同一張卡已有凍結值時直接沿用，重新渲染不會覆寫。
  - 仍同步寫入原本的 `dataset.articleId/contentVersion/anchorStart/anchorEnd`，維持既有測試與相容性。
- `sentenceCardTarget(card)`：讀回凍結值；沒有 WeakMap 記錄時用 dataset 重建。
- `sentenceCardTargetStale(target)`：帳戶失效、正文版本不符，或凍結 anchor 已無法在目前正文對上時回傳 true。
- `sentencePhraseAnchor(target, phrase)`：以凍結的整句 anchor 起點加上短語在句內的 offset，定位句內短語；不再用最新正文重算第一處。

`toggleSentenceCard` 建立 modal／inline 卡片時，額外傳入句境、文章 context 與 action context；`canUpdateView` 改為 `canUpdateView(card)`，條件加入：

- `card.isConnected`
- 帳戶 action context 仍有效
- 仍是目前文章
- `readingActions.articleVersion(articleId) === contentVersion`

因此首次句子回應延遲跨版本時不再重繪，也不再把結果併入新版 legacy `result`。

### 2. 句卡動作入口全部沿用凍結值

- **refresh**：點擊當下先檢查 `sentenceCardTargetStale`；過期卡直接顯示提示並返回，不發新請求、不建立任何條目。通過檢查後，文章、article context、action context、版本與 anchor 全部取自凍結值；`await` 後仍以同一份 target 判斷 `stillValid`。
- **句卡 chunk「詳解」**（inline 與 modal 兩個委派處理）：沿用卡片的 article／version／action context／article context；以 `sentencePhraseAnchor` 定位句內短語；過期卡阻擋，回應回來後若卡片已失效則不顯示。
- **原生選區「分析選中內容」**：改用卡片凍結版本與帳戶；以句內 offset 定位短語；過期卡阻擋，`await` 後失效則不附加結果。
- **「加入單詞本（選中）」**：過期卡阻擋；呼叫 `addWordToCurrentArticleBook` 時帶入凍結的 `articleId`、`contentVersion`、`anchor` 與 kind。
- **「選短語」**：過期卡阻擋；`sentenceStart` 優先用凍結 anchor，而不是目前 DOM 重算。
- **inline 錯誤卡「重試」**：沿用凍結 target，過期卡阻擋，`await` 後失效則不重繪。

### 4. 永久回歸測試（`tests/article-version-ownership.cjs`）

保留原有 1–5 段，新增：

- 第 6 段「正文已改版後點舊句卡 refresh 必須被阻止」：
  - 改版後點 refresh 不得新增 pending 請求；
  - 不得在新版本建立 `start=-1` 條目；
  - 不得污染新版 `result.sentence_analysis`。
- 第 7 段「首次句子回應延遲跨版本不得重繪新正文」：
  - 首次分析等待期間改版，遲到回應不得寫入新版 `sentence_analysis`；
  - 不得重繪新版本卡片；
  - 只保留原版本條目。

測試檔頭部覆蓋說明同步更新；未加入任何 DBG 日誌，也未削弱既有斷言。
