# 擴充套件 beforeunload 離開確認修復

- 日期：2026-11-09
- 問題：文章獨立視窗的 Chrome 擴充套件錯誤頁出現 `Blocked attempt to show a 'beforeunload' confirmation panel…`。
- 修改檔案：`extension/lookup.js`、`extension/inline-panel.js`。
- 新增測試：`tests/extension-beforeunload.cjs`。

## 原因

右鍵文章入口會自動開啟 `lookup.html?windowTicket=…&view=article&import=1`，並自動產生正文預覽。預覽使 `workspaceState.hasDraft` 成為 true；即使使用者還未在新視窗操作，原有 `beforeunload` 處理器也會要求顯示離開確認。

Chrome 要求該文件已收到使用者操作才允許這類原生確認。舊處理器未檢查這項條件，因此直接關閉／導向離開時，Chrome 會阻止確認並記錄警告。內嵌面板從本機恢復助手草稿時也能觸發相同問題。

參考：[Chrome Page Lifecycle API 的 beforeunload 說明](https://developer.chrome.com/docs/web-platform/page-lifecycle-api#the-beforeunload-event)、[HTML 使用者啟用狀態](https://html.spec.whatwg.org/multipage/interaction.html#sticky-activation)。

## 修正

兩個會取消 `beforeunload` 的處理器均先檢查 `navigator.userActivation?.hasBeenActive`。視窗／frame 沒有收到操作時直接返回，避免向 Chrome 要求無法顯示的確認。

使用歷史操作狀態 `hasBeenActive`，不使用會過期的短期狀態 `isActive`；使用者編輯草稿後，即使隔一段時間才離開，原有離開保護仍保留。內嵌面板自己的保留／放棄確認及既有草稿儲存流程維持原有行為。沒有新增使用者可見文字。

## 重現與驗證

新增測試載入真實 MV3 擴充套件，使用隔離 Worker／SQLite 和 mock AI 傳輸，不連正式帳戶或 AI 服務。

一般 Playwright DOM 讀取會啟用使用者操作狀態，不能用它驗證這個情境。新測試在真正點擊之前，一律使用 `Runtime.evaluate` 並設定 `userGesture: false`，明確確認新視窗／frame 的 `hasBeenActive === false`，再透過真正的瀏覽器導向觸發離開。透過 CDP `Log.entryAdded` 收集 Chrome 警告；另設故意要求不合法確認的正向對照，確保測試確實能捕捉原始錯誤。

同一測試在修正前，已於 zh-CN、zh-HK 各重現文章視窗及恢復草稿內嵌面板的警告；修正後九組情境通過：正向對照能捕捉警告、兩語自動預覽離開沒有警告、兩語編輯後離開會確認且取消會保留正文、兩語無草稿視窗不會確認、兩語未操作的恢復草稿面板離開沒有警告。

## 使用

本機 `extension/` 目錄已更新並重新打包。重新載入使用這個更新目錄的擴充套件，再清除 Chrome 錯誤頁的舊記錄，重新測試右鍵提取文章及關閉視窗。既有錯誤記錄不會因程式修正而自動消失。
