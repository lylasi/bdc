## 2. 代碼修改

### 共用契約與儲存

- `shared/reading-protocol.mjs`
  - `learningItem` patch 白名單加入 `marked`。
  - `marked` 只接受明確布林：`true` 保存 true、`false` 保存 false。
  - `mergeReadingEntity` 將 `marked` 納入內容欄位與刪改衝突判斷。
  - 遠端缺 `marked` 時不覆寫本機明確布林值，避免舊後端／舊備份令取消標記復活。
- `modules/reading-store.js`
  - `learningEntityFrom` 保留既有 `marked`，新條目預設 false；查閱、AI 回應、補寫解釋不會改標記。
  - 新增 `stableLearningItemId()`，供加入詞書入口在交易前算出同一 occurrence ID。
  - 新增交易內冪等遷移：只對缺少 `marked` 的舊記錄，按舊 `needs_review`／`understood`／有效詞書關聯補 true；僅查閱、僅筆記補 false；已有 boolean 不動。兩個分頁同時載入時，後到交易會看到布林值而跳過。
  - `addVocabularyEntryWithLink` 改為單一 IDB 交易：
    - 同交易讀取最新學習條目／詞書／詞條／關聯／outbox；
    - 加入詞書一律設定 `marked: true`；
    - 只補缺少的精確 anchor、句子與解釋；
    - 不覆蓋其他分頁剛寫入的 note／understanding；
    - 詞書條目來源合併、重複收藏不同 occurrence 建立各自關聯；
    - 任一寫入失敗整批回滾。
  - 舊詞書遷移產生的條目標記 true；舊文章解析按舊狀態遷移 marked。
  - `restoreAll` 支援舊備份缺 `marked` 的遷移與新備份布林值原樣還原，驗證同時比對 marked。
  - `persistRemoteEntity` 在遠端缺 `marked` 時保留本機明確值。
- `modules/reading-actions.js`
  - 新增 `setMarked(itemId, marked, actionContext)`、`toggleMarked`。
  - `ensureItem` 可明確傳入 marked，但查閱／收藏／筆記預設不改。
  - `addItemToVocabulary` 傳遞精確 anchor／articleId／contentVersion／itemId，加入詞書自動標記。
  - AI 整理記錄改傳 `marked: yes/no` 與個人筆記，不再傳 understanding。
- `modules/vocab.js`
  - 使用穩定 occurrence ID。
  - 加入詞書傳入只含定義欄位的 item payload；筆記／標記狀態以交易內最新版本為準。
  - 詞書已有同詞時仍按本次 occurrence 補來源、關聯與標記。
  - 使用交易回傳的實際詞條更新記憶體，避免用舊資料覆蓋。

## 3. 資料遷移與同步細節

- 遷移只在文章閱讀資料按需載入時進行，維持啟動 lazy load；每筆在交易內重新確認是否仍缺 `marked`，可重試、冪等。
- 明確 `marked: false` 優先：即使舊 `understanding` 是 `needs_review`／`understood`，也不會重新標記。
- 缺失欄位不視為取消：舊後端／舊備份缺 `marked` 時，本機 boolean 保留。
- 新備份完整包含 `marked`；舊備份依舊狀態與有效關聯補齊；還原後回讀比對 marked。
- 後端能力閘門在 migration 之後、任何 push／pull 之前；不支援時 outbox 保留，後端更新後同一筆可正常補送（測試已驗證）。
- 未執行正式後端部署；Cloudflare D1 與 selfhost 共用路由測試使用記憶體 SQLite／本機 selfhost。
