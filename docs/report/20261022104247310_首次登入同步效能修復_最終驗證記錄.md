### 靜態審查（本次獨立抽查）

1. **importSnapshot 與舊回執**
   - `recordImportSubmission()` 在送出 `/articles/import` 前，把實際送出的內容與 mutation ID 寫入 outbox。
   - `verifySubmittedSnapshots()` 以快照比對遠端內容；`markOpsDone()` 只清除 mutation ID 相符的操作，其他操作透過 `rebasePendingOutbox()` 保留並推進 revision。
   - 未發現會用「目前本機內容」誤確認舊回執的路徑。

2. **文章 metadata 原子性**
   - `persistDocWithMeta()` 將文章、摘要、state 放入同一個 IndexedDB 交易。
   - `markOpDone()`／`markOpsDone()` 的衝突移除也同一交易；失敗會回傳錯誤。

3. **配額原子性**
   - `quotaLockStatements()` 只在 PostgreSQL 加上 `SELECT … FOR UPDATE`；SQLite／D1 為 no-op。
   - 建立／更新／還原／匯入都使用交易內 `INSERT … SELECT … WHERE` 或等價條件。
   - `ensureState()` 先讀後寫，寫入路徑在使用者 state 列存在後才取鎖。
   - `writeStatements()`／`advanceStatements()` 以本次 insert 的唯一 token 綁定，避免替其他請求的文章記變更。

4. **skipped 用量刷新**
   - 重試前、全部跳過、部分跳過三條返回路徑都會重讀 `readUsage()`，不會保留被跳過項目的預占額度。

5. **fake IndexedDB**
   - 交易使用快照，commit 才寫回；abort／request 執行期錯誤會丟棄全部寫入；重疊交易依建立順序序列化。
   - 新增 `tests/fake-indexeddb.test.mjs` 驗證上述語意。
