**本機開發及隔離驗證已完成，版本 0.2.0。尚未執行本輪正式 D1 migration、Worker 發布或 149 主站更新。**

## 可用流程

擴充套件保留帳戶連接及語境查詞，新增詞書選擇、加入詞書、來源連結、本機待傳及逐筆重試／取消。收藏直接使用已展示的有效意思、音標與詞性，不再呼叫 AI。單詞和短語都可保存；無來源網址的手動查詞亦可加入。

首次由使用者明確選書，按網頁記住選擇，不以中文書名或排序猜測預設。換網頁時重新確認目標詞書，未改動帳戶的全站設定。目標被刪除會保留待傳並報錯，不改存另一個詞書。

來源保存原句、附近語境、原網址、標題、當次意思、選詞定位及時間。主站詞條可展開來源，開啟原網頁；返回前景可依 reading cursor 發現新收藏，更新畫面不依賴快照版本變動。備份還原至空白瀏覽器後仍保留來源。

## 本輪新增後端能力

| 接口／資料 | 用途 |
| --- | --- |
| `GET /vocabulary/books` | 本帳戶仍存在的詞書列表；無明確帳戶預設時回空 defaultBookId，由使用者選擇 |
| `GET /captures/capabilities` | 收藏協議版本與來源上限 |
| `POST /captures` | 冪等收藏已查出的詞與來源 |
| `vocabulary_captures` | 按 owner／requestId 保存操作指紋及成功回執，新增 migration 007 |

詞條仍寫入既有 reading_entities，change／cursor 仍走 reading_changes／reading_state。詞條與回執同一交易提交，沒有整份覆寫 snapshot、另建 AI 代理或新增獨立後端服務。selfhost SQLite 使用同一 handler，亦有實際 HTTP 測試。

同書同詞追加來源並保留已編輯釋義；同一位置不同「當次意思」另外保留來源。相同 requestId 重送只回原回執，改內容回衝突；後來刪除資料再重播不會復活。來源最多 100 筆，且收藏接口遵守累積詞條 1MB 上限，超量明確失敗，不靜默裁切。

本機待傳逐筆保存並依 endpoint／user 分區，不含登入 token 或 AI Key。先持久化再請求，只有內容相符的成功回執才能清除。重新開啟、恢復連接或手動重試可續傳；損壞項目可見且可取消，不阻擋健康項目。沒有新增常駐背景 token 副本或擴充套件權限。

## 獨立審核與修正

[初次獨立報告](20261106104838931_擴充套件加入詞書_後端與擷取client獨立測試及審核報告.md) 發現 5 個 P2 邊界問題，均已修正：

1. 收藏中換詞書時 busy 卡住：改以獨立 attempt token 管理，完成提示標明原詞書；舊 finally 不影響新的收藏。
2. 一筆壞 outbox 阻擋整批：改為保留可見的無效項目，跳過並續送其他操作；可以明確取消，外帳戶 payload 不顯示。
3. 同位置新釋義被去重丟棄：來源身份加入當次意思，保留不同釋義版本；使用者原釋義不覆蓋。
4. 猜測預設詞書：移除按中文名／排序預選，首次須明確選擇，舊 cache 不冒充已確認預設。
5. 主站來源第 101 筆靜默裁切：資料表示保留完整內容，寫入及交易合併明確拒絕，並顯示雙語提示。

[修復後獨立複測](20261106111036151_擴充套件加入詞書_修復後定向複測報告.md) **115/115 通過**，5 項 P2 均關閉；獨立測試於暫存副本做 21 項突變驗證，全部能識別。之後本代理又檢查了完整主站畫面的遠端更新通知及累積 1MB 界線，最終總套件包含獨立測試重新執行。
