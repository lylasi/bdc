# 句尾朗讀懸停浮層修復與驗證

## 問題與成因

使用者回報：英文長句換行、句尾靠左時，小喇叭被獨立定位到譯文提示框右側；鼠標移向按鈕時，原句尾的 mouseout 立即清除提示框，造成看得到卻無法點到。

原有測試只檢查圖示不壓住提示框，並使用 locator.click 直接點擊；沒有覆蓋從句尾經過空隙、提示文字再移向喇叭的真實鼠標動線。

## 修正

- 喇叭與譯文提示共用一個浮層，按鈕移入標題列、緊貼標題，不再以固定定位放到框外右邊。
- 浮層可以接收指標事件，句尾與浮層之間加入 8px 透明移入區。
- 懸停生命週期統一由 sentence-actions 管理，移入提示文字或按鈕均保持，離開整組後延遲收起；鍵盤焦點可保持浮層，Escape 可退出。
- 原有詞語詳解的 Escape 優先處理不被單純懸停攔截；手機仍只有句尾 ⋯，沒有新增常駐圖示。
- 繼續使用既有 zh-CN／zh-HK 文案，沒有轉換教材或增加持久化設定。

## 驗證

已在隔離瀏覽器與合成文章中檢查簡繁兩語、1280／960 像素桌面長句換行：鼠標在間隙停留 350ms、提示文字停留 500ms、按鈕停留 350ms，然後透過 mouse.down／mouse.up 真實點擊；每次均只讀正確英文句一次。另檢查離開收起、焦點與 Escape、切換相鄰句，以及視窗底部向上顯示的動線。

發布副本排除了原工作區另一項未提交的句卡原文複製修改，基於 origin/master 建立，僅包含本次懸停修復及測試。

使用者已明確指示「DSH 有問題了，不用等它了你自己審查」，因此本次由主代理自行完成驗收；不把 DSH 的失敗任務記作通過審查。
