## 三、仍存在的風險

1. **Gemini 重試額度可能偏大**：為確保實際出站額度增加，第二次
   `effectiveMaxTokens` 會從已含 thinking budget 的實際值再放大；Gemini 會變成
   `budget + 放大後答案額度`，可能超過部分模型／網關上限，需靠供應商錯誤回報。
2. **能力記憶仍只在 session 內有效**：重新載入頁面後會重新探測；若供應商在同一個
   session 內改變行為且沒有 auth／catalog 事件，記憶仍可能暫時過期。
3. **世代隔離只保護記憶寫入與事件**：舊世代請求本身仍會完成既有的一次 fallback
   retry；若該 retry 對新 endpoint 有副作用，仍需靠 abort／呼叫端取消。
4. **LWW thinking 仍是鍵級復活**：勝出方刻意清空某任務、落敗方仍有舊值時會保留舊值；
   單一 snapshot 無法表達「刪除」。
5. **時間戳推進依賴本機時鐘**：若本機時鐘大幅落後，會用原時間戳 + 1ms 保證可套用；
   若多裝置時鐘差異大，群組 LWW 的其他欄位仍可能出現既有時間排序問題。
6. **測試皆為 mock fetch**：未對真實 Anthropic／Gemini 供應商做 live 驗證；實際配額、
   錯誤格式與串流截斷行為仍建議抽樣確認。
