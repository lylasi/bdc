## 三、驗收方法（三層證據，不鏡像實作）

1. **真環境**：真 Chromium 載入 `extension/`（MV3、真 service worker）＋真 `worker.fetch`＋`node:sqlite`＋`cloudflare-worker/schema.sql`＋`selfhost/d1-adapter.js`；帳號與詞書由測試自建（alice／bob）。**只有 AI transport 是 mock**（`tests/helpers/extension-mv3.cjs` 的 `/mock-ai/*`）。
2. **幾何量測**（使用者指定方式）：卡片是 closed shadow root 內的 iframe，沒有 DOM 選擇器可用，因此用 `frame.frameElement().boundingBox()` 讀**實際 iframe 框**；浮動「查詞」按鈕同樣在 closed shadow 內，用 CDP `DOM.getDocument({depth:-1, pierce:true})` + `DOM.getBoxModel` 取得真實框後**真滑鼠點擊**（不是合成事件）。選詞用真滑鼠拖曳，再以 `Range.getClientRects()` 取實際矩形。
3. **資料面**：收藏成功以**伺服器回執**為準（`vocabulary_captures` 的 request_id／fingerprint），事後用 SQLite 核對 `reading_entities`（`vocabularyBook`／`vocabularyEntry`）的實際內容；請求體取自 `env.state.captureCalls`，AI 是否重跑以 `/mock-ai/*` 請求數與 `aiCalls` 計數比對。
4. **頁面世界稽核**：以 `addInitScript` 攔截 `window.postMessage`（送出）與 `message`（收到）並記錄；偽造訊息一律附上**真 ticket**，以證明「即使票據洩漏到網頁，也無法經 window message 驅動卡片」。

## 七、觀察（不是故障，但值得留意）

1. **自動高度是非同步收斂**：結果文字出現的那一幀量到 `179px`，之後 iframe 回報（`BDC_INLINE_STATE.height`）經背景中繼、外殼設高才到 `216px`。測試因此改為「等待收斂（≤5s）再判定」，實測在 1 秒內收斂、且內容從不裁切。使用者在極快的情況下可能看到一次高度跳動，屬視覺打磨項，不影響功能。
2. **展開後不再跟隨選區**：完整面板固定在右側滿高（`420×876`），與 Q7「展開為完整面板並固定」一致；返回小窗後立即恢復貼近選區（G6/G7 已驗）。
3. **兩個收藏入口並存**：`#ext-quick-capture` 只在「沒有可用目標詞書」時顯示（同時隱藏一般「加入詞書」），有目標時用 `#ext-capture-save`。我的測試對兩者都支援，並在 I1/I8/I9/I10 分別驗到。
4. **偽造測試的票據是「已知洩漏假設」**：我刻意把真 ticket 放進 12 則偽造 window message，產品零反應；同時頁面世界在偽造前收到 0 則來自卡片的訊息（`productPosted 0 / productInbound 0`），證明 0.4.0 已把尺寸／模式／關閉改走 `chrome.runtime` 中繼，不再用 `parent.postMessage`。
5. **帳戶切換後的一鍵收藏**會為新帳戶建立自己的本頁詞書（`webbook_7c48…`），alice 的詞書與詞條 0 變動。
