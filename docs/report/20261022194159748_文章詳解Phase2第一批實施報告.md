## 3. P2-T1 音訊 owner／中斷／暫停語義

### 3.1 根因

- `modules/audio.js` 的 `speakText` 沒有 owner 概念：任何模組呼叫都會直接 `stopCurrentAudio()`，舊的播放者不會收到通知，因此文章朗讀只能靠自己的 `onEnd`／`_playToken` 猜測，容易出現「UI 顯示播放中但沒有聲音」或單詞發音結束後文章自行跳下一句。
- 遠端音訊把 `onloadstart` 當成「已開始」，loading 與 playing 沒有分開；本機 fallback 失敗時只回傳 false，沒有 status／error 回呼，文章 UI 會卡在播放中。
- `#read-article-btn` 只更新 `title`，沒有同步 `aria-label`；且 HTML 仍有 `data-i18n-aria-label`，locale 套用時會蓋掉動態狀態。
- 文章沒有監聽音訊中斷事件，也沒有「被單詞發音打斷後只能重播本句」的狀態。

### 3.2 改法

`modules/audio.js`：

- 新增 module 級 `activeAudioOwner`、`getActiveAudioOwner()`。
- `speakText(..., options = {})` 支援 `{ owner, onStatus, onError }`：
  - `owner` 預設 `'default'`。
  - 開始前記錄 `previousOwner`，停止目前音訊，設定新 owner。
  - `previousOwner` 存在且不同 owner 時 dispatch `bdc:audio-interrupted`，detail 為 `{ owner: previousOwner, by: owner }`。
- `stopCurrentAudio(options = {})`：清除 owner，不主動 dispatch 中斷事件；同時清掉遠端音訊所有事件 handler。
- 遠端 HTMLAudio：
  - `onloadstart` → `loading`。
  - `onplaying`／`oncanplay` → `playing` 並觸發一次 `onStart`；`play()` resolve 後再保底觸發一次。
  - `onwaiting` → `loading`。
  - `onended` → `ended` 後才走 `onEnd`。
  - `onerror`／`play()` reject → 既有 local fallback；fallback 也失敗時呼叫 `onStatus({ state: 'error' })` 與 `onError`。
- 本機語音：
  - `onstart`／`onend`／`onerror` 對應 status。
  - `speakWithLocalVoice` 失敗回傳 `false`。
  - 有 status／error 回呼的呼叫端（文章朗讀）失敗時不再走 `onEnd`，避免自動跳下一句；沒有回呼的舊呼叫端（聽寫）保留原本 `onEnd` 相容行為。

`features/article/article.js`：

- `playCurrentChunk` 傳 `{ owner: 'article-reading', onStatus }`，並用 `_playToken` 過濾舊音訊的 status。
- 新增 `bdc:audio-interrupted` listener：中斷 owner 是 `article-reading` 且有朗讀 chunks 時，`_playToken++`、`setIsReadingChunkPaused(true)`、`_interruptedByOtherAudio = true`、更新按鈕與浮動列；不自動恢復。
- `btn-play-word` 改傳 `{ owner: 'word-pronunciation' }`。
- `togglePauseResume`：被中斷後恢復時顯示一次 `article.playbackPausedByPronunciation`，按鈕 title／aria 用 `article.replayChunk`，從目前句開頭重播。
- `playNextChunk`／`playPrevChunk`／`stopReadArticle`／`readArticle`／模式切換清除 `_interruptedByOtherAudio`。
- `updatePlaybackStatus` 處理 `loading`／`playing`／`error`；error 顯示 `article.audioFailed` 並停止朗讀，按鈕可再按。
- `updateReadButtonUI` 同步 `title` 與 `aria-label`；`index.html` 移除 `#read-article-btn` 的 `data-i18n-aria-label`；locale listener 依目前播放狀態重呼叫。
- `updateFloatingToggle` 在被打斷的暫停狀態顯示「重播本句」。

## 4. P2-T4 助手輸入、序列化與捲動

### 4.1 根因

- 助手輸入是單行 `<input>`；`keydown` 對所有 Enter 直接 `doSend()`，沒有判斷 Shift、`isComposing` 或 `keyCode === 229`，中文輸入法選字會被誤送出。
- 沒有 textarea 自動高度，長問題只能單行捲動。
- 串流每個 delta 都 `box.scrollTop = box.scrollHeight`，使用者向上閱讀會被強拉回底部。
- 送出失敗／停止後問題已被清空，沒有草稿恢復；忙碌時雖有 `assistant.busy`，但輸入生命週期沒有和錯誤／取消路徑對齊。
- M1 已有 context chip 與 `activeAsk`，本批保留，不回退。

### 4.2 改法

`features/assistant/assistant.js`：

- `#assistant-input` 改為 `<textarea rows="1">`，新增 `#assistant-input-hint`（`assistant.inputHint`）。
- `wirePanel`：
  - `compositionstart`／`compositionend` 維護 `isComposing`。
  - keydown：只有 Enter、非 Shift、`!isComposing && !e.isComposing && e.keyCode !== 229` 才 `preventDefault()`＋`doSend()`；Shift+Enter 保留換行。
  - `input` 自動長高 1–5 行（`min-height: 44px`、`max-height: 140px`，超過內捲）。
  - 送出時清空並重設高度；忙碌時保留輸入並提示 `assistant.busy`。
- 新增 `isNearBottom(box, 48)`、`showNewAnswerHint(panel)`、`hideNewAnswerHint(panel)`。
  - 串流每個 delta 先判斷是否接近底部；接近才自動捲動，否則顯示 `.assistant-new-answer`（`assistant.newAnswer`）。
  - 點提示或手動捲到底會收起提示。
  - `restoreConversation` 還原後捲到底。
- `askOwned`：
  - 送出前記錄 `shouldFollow`；只有接近底部才在 append 後捲動。
  - `finally` 重新套用 markdown 前記錄 `followBeforeRender`，避免重繪把正在看舊訊息的人拉回。
  - 錯誤／取消後若輸入框為空，`restoreDraft(panel, userText)` 放回本次問題；使用者已輸入新內容則不覆蓋。
- 移除只加提示的 `#assistant-refresh`，避免與 context chip 重複；`activeAsk` 與 chip 三態邏輯不變。
- `compose` 預填引用後同步重算高度。

`styles.css`：

- `.assistant-row textarea.assistant-input`：44–140px、`resize: none`、自動內捲。
- `.assistant-input-hint` 小字提示。
- `.assistant-new-answer`：messages 容器底部的 sticky 浮動提示。

## 5. P2-T5 例句點詞與延遲結果歸屬

### 5.1 根因

- `generateExamples` 在 `await` 後無條件 `displayExamples(word)`；A 詞請求較慢、使用者已切到 B 時，A 回來會覆蓋 B 的例句區。
- 例句中的 `.interactive-word` 點擊只 `console.log`，沒有中文 gloss、沒有發音、沒有 `aria-expanded`、沒有鍵盤操作。
- 沒有 alignment 的例句完全沒有可點詞，無法顯示「沒有對應解釋」。
- 更關鍵的是：`shared/reading-protocol.mjs` 的 `vocabularyEntry.examples` 白名單只保留 `{en, zh}`，學習例句的 `english`／`chinese`／`alignment` 在保存進 permanent store 時被削掉；即使畫面正確，換詞或重載後也無法保留。此為本批唯一觸及的共享 WIP，屬 P2-T5 絕對必要。

### 5.2 改法

`features/learning/learning.js`：

- 新增 `exampleRequestSeq`。
- `generateExamples`：
  - `const requestId = ++exampleRequestSeq; const targetWordId = selectedId;`
  - 結果一律寫入原 `word.examples` 並 `saveVocabularyBooks()`。
  - 只有 `requestId === exampleRequestSeq && dom.wordSelect.value === targetWordId` 才 `displayExamples(word)`。
  - `finally` 只有最新請求才解除按鈕忙碌，避免舊請求解除新請求的 disabled。
- `displayExamples` 改用 DOM fragment，不再把 AI 文字拼進 `innerHTML`：
  - `.interactive-word` 加 `role="button"`、`tabindex="0"`、`aria-expanded="false"`。
  - 英文句所有單詞都可點；alignment 命中的詞／片語共用 `pairId`，中英同步 hover 高亮。
  - 無 alignment 的詞仍可點，但不發任何請求。
- 新增 `toggleExampleWordGloss`／`openExampleWordGloss`／`closeExampleWordGloss`：
  - 展開 `.example-word-gloss`，內容 `learning.exampleGloss` + alignment 的 `zh`。
  - 同一例句只保留一個 gloss；再點同詞收起。
  - 無 alignment 顯示 `learning.exampleNoGloss`。
  - 提供發音鈕，`audio.speakText(..., { owner: 'learning-example' })`。
  - gloss 文字用 `textContent`，不進 innerHTML。
- `handleWordAnalysisClick` 移除 `console.log`，改呼叫 `toggleExampleWordGloss`；保留 hover 高亮。
- 新增 `handleExampleWordKeydown`：Enter／Space 展開或收起，Escape 收起。

`shared/reading-protocol.mjs`（最小 additive）：

- `normalizeReadingPatch` 的 `examples` 除既有 `en`／`zh` 外，保留 `english`、`chinese`、`alignment`（皆有字數與數量上限）。
- 原本讀寫／同步格式不變；Worker／selfhost 共用此檔，兩邊測試通過。

`styles.css`：

## 9. 殘留風險

1. **Shared protocol 尚未部署**：`shared/reading-protocol.mjs` 已保留學習例句欄位，Worker／selfhost 共用此檔。依指示未部署；本機保存正常，但跨裝置同步要用新版 Worker／selfhost 才會保留 `english`／`chinese`／`alignment`。舊後端仍可能把新欄位削掉。
2. **真實裝置未測**：P2-T1 只用 node stub＋Chromium DOM 驗證，沒有在 iOS Safari／Android Chrome 測真實 TTS、藍牙、來電中斷、SpeechSynthesis 行為；P2-T4 的 IME 是用合成 composition 事件＋真實鍵盤事件混合模擬，未涵蓋所有輸入法。
3. **locale-change 的助手面板狀態**：本批確保 locale 重繪不會把正在看舊訊息的人拉回底部（目前 locale 會重建面板），但「保留面板開啟、草稿、焦點、訊息捲動位置」屬 P3-T3，本批未提前實作。
4. **例句 gloss 位置**：gloss 統一插在英文例句段落之後（同一例句只一個），不是字面緊貼被點詞的行內位置；優點是不造成版面大幅跳動，缺點是中文側點詞時 gloss 會出現在英文與中文之間。若產品要求嚴格「詞下方」，需再調整。
5. **例句所有英文詞都可點**：這讓無 alignment 的詞也能顯示 `exampleNoGloss`，代價是例句的 Tab 停留點變多；文章區的逐詞鍵盤模式（P2-T3）未受影響。
6. **移除 `#assistant-refresh`**：`assistant.refreshContext`／`assistant.contextRefreshed` 變成未使用鍵；若產品仍要手動刷新入口，可再以 chip 點擊方式補回。
7. **`assistant-new-answer` 的 sticky 樣式**：已在 1280×900 驗證；手機窄面板／軟鍵盤遮擋仍需人工巡檢。
8. **P2-T1 自然結束後 owner 保留**：目前 owner 只由 `stopCurrentAudio()` 清除，自然播完不會清；這是計畫指定語義，下一次不同 owner 播放仍會發中斷事件（文章 listener 只認 `article-reading`，不會誤暫停其他模組）。若後續要更精確，可在 `onended` 清 owner，但需另評估相容性。
