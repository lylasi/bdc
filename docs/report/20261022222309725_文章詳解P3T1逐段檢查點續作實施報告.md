## 二、analysis_run 與流程摘要

### 2.1 資料形狀（additive）

```js
result.analysis_run = {
  schemaVersion: 1,
  runId: 'run_<time>_<seq>',
  contentVersion: '<contentVersionOf(article)>',
  status: 'running' | 'complete' | 'partial' | 'cancelled' | 'failed',
  total, completed, failed,
  startedAt, updatedAt,
  lastErrorCode
}
```

- 段落仍存 `result.paragraph_analysis[i]`；checkpoint 保留 `total` 長度陣列，未完成段為 `null`。
- `analysisRunStats` 只把非 null 段落算 `completed`（含 skipped），`failed === true` 另計。
- `displayArticleAnalysis` 對 null 段顯示「待分析」（`.analysis-pending-inline`），不再顯示「分析失敗」；失敗統計也不把 null 算失敗。

### 2.2 主分析

1. 初始 `saveArticle` 即寫入 `analysis_run(status: running, total, contentVersion)`，並把段落陣列初始化為 total 長度 null，讓第一段回來前重新載入也能辨識未完成。
2. 每段成功／失敗後 `scheduleAnalysisCheckpoint()`：debounce 1200ms。
3. `flushAnalysisCheckpoint()` 以 chain 序列化，同一 checkpoint 同時最多一個寫入；內容為「目前完整段落結果＋analysis_run」，透過 `queueAnalysisSave` → `articleStore.saveAnalysis(..., { expectContentVersion, ctx, silent: true })`。
4. 寫入失敗只設 `lastCheckpointError`、顯示 `article.analysisCheckpointFailed`，分析繼續；`article_too_large` 會停止後續 checkpoint 但不刪已完成段。
5. `visibilitychange(hidden)` 與 `pagehide` 嘗試 flush（best effort，不宣稱保證關頁前最後一刻寫入）。
6. 全部完成：最後一次保存不 silent，`status = complete（無失敗）／partial（有失敗）`，並清除 checkpoint 失敗提示。
7. `settings.reading.analysisCheckpoint === false`：不建立 analysis_run、不排程 checkpoint、不顯示續作 banner，完全回到只在最後保存的舊行為。

### 2.3 取消

- `cancelActiveRun` 會對目前 run 的 checkpoint 先 flush，再以 `status: 'cancelled'` 寫入已完成段；取消後不清除既有段落。
- 取消寫入透過 `checkpointEpoch` 防止舊回合蓋掉新回合；清除／切換文章時仍可寫回原文章。
- 取消當下仍是同一篇時，checkpoint 寫入成功後顯示 `article.analysisCancelledKept`；本輪沿用既有清除／切換入口，沒有新增取消按鈕。
- `finalSaved` 後不再接受取消 flush：分析完成後再按清除／切換文章，不會把 `complete` 蓋成 `cancelled`（測試 b 已覆蓋）。

### 2.4 重新載入與續作

- `applyRecordToView`：`analysis_run` 為 running／partial／cancelled 且 `contentVersion` 與記錄正文一致 → 顯示「已保存 N/M」＋續作提示＋「繼續未完成分析」。
- 版本不一致 → 不顯示續作，沿用既有舊版分析提示／重新分析入口。
- `resumeAnalysis()`：以 `resumeIndicesFromResult` 選段（跳過已完成、null、純圖片、原文中文），沿用 `requestParagraphAnalysis` 管線與既有 claim／版本守門；成功段不重做，完成後合併最新記錄並保存 analysis_run（complete／partial）。若沒有可續作段，只把 analysis_run 收成 complete，不送任何請求。
- `recordStatusText`：running → `article.analysisRunningStatus`；partial／cancelled → `article.analysisPartialStatus`（N/M）；無 analysis_run 或格式不符時完全回到 Phase 1 失敗段顯示。

### 2.5 翻譯鍵

沿用並驗證兩語系既有鍵（鍵集合與插值一致）：

`article.analysisCheckpointFailed`、`article.analysisCancelledKept`、`article.analysisPartial`（`done`／`total`）、`article.checkpointResumeHint`、`article.resumeAnalysis`、`article.analysisRunningStatus`、`article.analysisPartialStatus`（`done`／`total`）。

## 四、剩餘風險

1. **寫入放大**：每 1.2 秒 checkpoint 會寫整份分析 JSON；`silent` 只減少 UI 事件，不減少 IDB／outbox 工作。目前以 debounce、`disabledByLimit` 與 total 長度 null 陣列控制，尚未量測 10k／50k 字成本。
2. **多裝置／版本競態**：checkpoint 依賴 `expectContentVersion`；舊回合以 `checkpointEpoch` 與版本比對丟棄，不做自動合併。若別臺修改正文，本機未完成分析不會被續作。
3. **關頁保存不保證**：visibilitychange／pagehide 只做 best effort；瀏覽器直接終止程序時，最後 1.2 秒內的段落可能不在 checkpoint 中。
4. **續作中斷**：resumeAnalysis 只在最後保存；續作途中重新載入會回到原本的 analysis_run（已完成段仍在），續作期間新完成的段不會逐段 checkpoint（plan 只要求最後保存 analysis_run）。
5. **partial 顯示語義**：最終 partial（有失敗段）在歷史列顯示「已保存 total/total」，失敗數仍由重試入口呈現；若產品希望顯示「成功段／總段」，需另調文案與統計。
6. **設定未同步**：`settings.reading.analysisCheckpoint` 僅裝置本地預設，未進同步快照；目前也沒有設定面板 UI 開關，符合 plan 建議先維持本地設定。
7. **測試穩定性**：新腳本依賴 Playwright route mock、固定段落 marker 與 IDB `put` 注入；若 mock 載具或 onboarding modal 行為變更，需同步調整。測試已用獨立 browser context 避免污染。
