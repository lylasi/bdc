## 三、疑點與嚴重程度

未發現阻擋（Blocker）或高風險問題。以下為低嚴重度觀察，屬建議性質，不影響本次發布有效性：

1. **【低】`ALLOW_ORIGIN="*"` 使跨域呼叫全面開放**
   `OPTIONS` 與所有回應皆回 `Access-Control-Allow-Origin: *`，任意網站可發起跨域請求。由於授權採 Bearer token（非 cookie）且未登入一律 401，實際風險有限；若要收斂，需同時把 `chrome-extension://<id>` 納入白名單，建議另案評估，勿在無測試下急改。

2. **【Codex 覆核：原觀察不成立】詞書載入錯誤提示**
   DeepSeek 原先認為 `extension/capture-ui.js:149-154` 對 <500 的錯誤沒有提示。Codex 對照實際程式：`loadBooks` 的 catch 在仍屬當前會話時，已有詞書且屬網路／5xx 錯誤才顯示離線；其他錯誤走 `else showError(error)`，會呈現本地化錯誤。過期會話或過期請求會被忽略，避免干擾新帳戶。介面亦已有「更新詞書並重試」入口。首輪缺少足夠診斷，無法歸因於 4xx；加入初始化等待後最終通過。本項不列為產品缺陷。

3. **【低】主站未引用 `modules/extension-capture.js`**
   `index.html`／`main.js` 未引用該模組（僅 `scripts/package-extension.mjs` 打包進擴充套件、`extension/capture-ui.js` 使用）。屬打包來源的合理冗餘，非缺陷；可考慮於文件註明避免誤判為死碼。

4. **【資訊】migration 證據的 pragma 輸出未含表名**
   `migration-007-schema-verified.json` 的 `pragma table_info` 結果本身不含表名，單看 JSON 無法自證是哪張表；我已用 `sqlite_master` 獨立確認 `vocabulary_captures` 存在，證據缺口已補。

5. **【資訊】三輪 smoke 證據並存**
   建議後續報告一律引用最終 20/20 那份，並保留 `initial-smoke-attempt/`、`second-smoke-attempt/` 作為失敗診斷軌跡，避免以首輪結果誤判發布品質。
