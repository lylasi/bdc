## 2. 六項修正的程式位置與行為

### F1 新裝置下載已同步的個人 Key（`modules/ai-credential-sync.js`）

- 新增 `addDownloadTargets()`：同步在讀取 `/ai-credentials` 清單後，對「遠端有記錄、本機完全沒有憑證列、且本機已知該供應商定義」的項目建立 `syncMode: 'cloud'`、`version: 0` 的可下載狀態，交給原本的決策表下載。這正是「新裝置從 snapshot 拿到定義、本機 credentials 為空」的情況。
- 本機既有的憑證列一律不動：明確 `local-only` 的記錄仍被跳過（優先權保留）。
- `processCredential` 的 `download` 分支在下載**之前**先比對遠端 `binding` 與本機供應商定義；不符時不發出下載請求，記錄 `lastError: 'binding_mismatch'` 並把 `bindingVerified` 設為 false（不會把別人的 Key 綁到新端點）。
- 遠端 tombstone（`deleted: true`）不會建立本機 Key；`authMode: 'none'` 的供應商不建立憑證列。
- UI 補充：`features/sync/ai-provider-settings.js` 對「cloud 模式但本機仍無 Key」顯示「等待从账号下载密钥／等待從帳戶下載金鑰」，不再顯示「已同步」。

### F2 同步不再覆寫等待期間的本機修改（`modules/ai-credential-sync.js`）

- 同步改為在記憶體副本上作業：讀取清單後只載入一次 base profile，處理過程只改副本。
- 新增 `commitCredentialChanges()`：提交時以 `updateAIProfile()`（同步讀取最新 localStorage、單執行緒讀改寫）重新讀取現況，只提交「本次真的改變」的憑證列，且只有當該列的**使用者欄位指紋**（`apiKey`、`syncMode`、`binding`、`pending` 的 type/mutationId/expectedVersion）仍等於同步開始時的值才寫入；被使用者改過的列原樣保留（連同其新的待同步操作）。
- 供應商定義與 `taskModels` 完全不由同步寫入，因此等待期間新增供應商、改 Key、刪除、改任務模型都不會被回滾。
- `advanceConfirmedBase()`：若使用者在等待期間又改了一次同一供應商，而本次同步剛好確認了**自己**先前那個 mutation（遠端版本前進且 `pending` 已清空），只把新 `pending.expectedVersion` 接到剛確認的版本，避免立刻產生假衝突；別台裝置造成的遠端變更不會被這樣推進，仍走衝突流程。
- 新增 `stopCredentialSync()`，登出時清除同步／重試計時器（也是測試用的確定性入口）。

### F3 舊請求的 401 不得改動新工作階段

- `modules/sync-cloudflare.js` 新增 `captureAuthSession()` / `isAuthSessionCurrent()`（endpoint + userId + token + auth generation 四項比對）；`apiRequest` 在回應上附 `__bdcSession`；`verifySession()` 在寫入 role 前先比對工作階段，並新增 `stale_session` 錯誤碼。
- `modules/ai-catalog.js`：`getManagedCredential()` 的 401／403／404／409／其他錯誤、下載後的寫入、`refreshInternal()` 的 401／403／錯誤、`refreshAICatalog()` 的 catch、`initAICatalog()` 的 `/me` 回調，全部先以 `captureCatalogSession()` / `catalogSessionStale()` 檢查；屬於舊工作階段的回應只拋 `stale_session`，不呼叫 `invalidateSession()`、不改 `state`。
- `modules/ai-credential-sync.js`：`createSessionGuard()` 取代舊的 `scopeStillActive()`（加入 token 比對）；清單請求、每次下載／上傳、提交前、結果處理前都檢查；401 只有在工作階段仍是原本那一個時才 `invalidateSession()`。
- `features/sync/sync.js`：學習資料快照同步的 `unauthorized` 分支先看 `guard.stale()`，避免舊帳戶快照的 401 登出新帳戶。
- `features/ai-admin/ai-admin.js`：`loadDraft()` / `publish()` / `loadMetadataOnly()` / `loadHistory()` 都先捕獲工作階段並在回應後比對。

### F4 帳戶／端點切換立即鎖定共享 Key

- `modules/ai-catalog.js` 新增 `sessionIdentityChanged()` / `resetForIdentityChange()`：`ACCOUNT_CHANGED`、或任何一次 refresh 發現 userId／endpoint 變了，就清空 catalog 版本與供應商清單、丟棄記憶體共享 Key（`clearManagedKeys()` 一併推進 `state.generation` 使舊請求失效）、`verifiedAt`／`expiresAt` 歸零、狀態改為 `offline`（已登入但未驗證）；只有新帳戶重新驗證成功才會回到 `verified`。`SIGNED_OUT` 另外清除該帳戶的非秘密列表快取。
- `modules/sync-cloudflare.js` 的 `storage` 監聽改為追蹤 `(token, userId)` 身份：其他分頁換帳戶時遞增 generation 並發出 `ACCOUNT_CHANGED`；同帳戶換通行碼時發出 `SIGNED_IN`（不清帳戶 profile）。
- `modules/ai-credential-sync.js` 的 `ACCOUNT_CHANGED` 只在 profile 範圍真的改變時才清除舊帳戶 profile（避免同帳戶 token 更新時誤刪）。

### F5 管理員模型發現不再擴大全站開放清單（`features/ai-admin/ai-admin.js`）

- 草稿供應商新增 `candidates`（發現結果）與 `modelMeta`（每個模型的已知能力），`models` 仍是唯一會被發布的白名單。
- 「取得模型」只寫入 `candidates`（合併、去重）；`models` 完全不動，已開放模型的能力標記得以保留。
- 卡片改為「已開放的模型」勾選清單 +「候選模型」未勾選清單 + 手動加入模型；勾選候選才會加入白名單，取消勾選只移出白名單（能力標記留在 `modelMeta`，重新勾選可還原）。
- `providerToConfig()` 只送 `models`，`candidates`／`modelMeta` 不出 page、不發布。
- 單一供應商取得模型／測試失敗只顯示該卡片錯誤，不影響其他卡片與發布按鈕。

### F6 遷移保留舊任務模型選擇（`modules/ai-profile-storage.js`）

- 新增 `migrateLegacyTaskModels()`：讀取舊 `settings.ai.models` 與 `settings.ai.tasks`（合併，`models` 優先，與解析器一致），只保留「provider 存在於新 profile、且不是 `managed-…`／`default`」的引用；無法歸屬的單一模型名與 managed 引用記入隔離紀錄（`skippedTaskModels`），不匯入。
- 舊 `settings.ai.defaultModel` / `models.default` / `tasks.default` 若指向已遷移的個人供應商，且 profile 尚無個人預設，會一併還原。
- 移除舊欄位前先重新讀回 profile 核對每個已遷移任務映射都存在；若沒寫進去（或寫入失敗），回傳 `task-models-not-persisted` / `save-failed`，**不刪除**舊欄位。

## 3. 管理員維護 UI 補齊（原方案第 16 節）

- 「新增預設供應商」改為與個人供應商相同的兩欄流程：**服務地址 + API Key → 連接 → 勾選模型 → 加入草稿**。初始表單只有這兩個輸入（已由測試斷言 `input:visible === 2`）。
- 協議自動辨識共用 `modules/ai-protocols/index.js` 的 `detectProvider()`（同一份有限候選規則），成功後顯示「已識別協議：…」；「進階設定」可手動覆寫協議、認證方式、API／模型端點，無需金鑰的局域網服務可留空 Key。
- 連接成功後模型只是候選、**全部預設不勾選**，加入草稿按鈕在未勾選時停用；無法辨識時仍可手動加入模型名稱（明確回退提示 `aiAdminManualFallback`），並保留 URL 與已填內容。
- 「從我的供應商預填」只複製服務地址、協議與模型候選，**不複製金鑰**（避免未經確認把個人金鑰發布成共享金鑰），並在提示中說明。
- 每張卡片在進階設定提供「臨時測試密鑰（只在本頁記憶體，不會發布）」，讓保留舊 Key 的供應商也能取得模型／測試。
- 卡片同時顯示供應商名稱與協議徽章；樣式補充 `.ai-admin-models`、`.ai-admin-model-row`、`.ai-admin-inline`、`.ai-admin-newform` 與 checkbox 寬度修正。
- 既有能力保留：個人自建供應商 UI 未改動；離線／局域網與多協議手動覆寫仍可用；不宣稱無法辨識的協議一定成功（連接失敗會顯示分類錯誤與手動回退說明）。

## 7. 已知限制與未驗證項

- 三個協議的驗證是 mock 層面的協議正確性（請求編碼、回應／SSE 解析、取消、錯誤碼），**不代表**任何真實供應商服務已完整驗收，也沒有做真實費用請求。
- 瀏覽器回歸是功能測試：頁面只載入模組與（截圖時）`styles.css`，未做完整站點與窄屏視覺驗收；管理員面板的 1100px／390px 佈局只做過人工目視確認。
- 未執行既有 `tests/audit-flows.cjs` / `audit-e2e.cjs` / `audit-security.cjs`：它們需要工作區靜態伺服器，會對外提供私有 `ai-config.js`（本工作階段的驗收約束禁止），因此沿用 route 白名單方式。
- 多分頁同時編輯仍是「後寫入者勝」；本修正只保證同步不會覆蓋 UI 寫入、以及伺服器版本 CAS 生效。Web Locks 不可用時的專用提示仍未加入。
- 共享 Key 60 分鐘有效期以模組邏輯實作，未以真實等待時間測試。
