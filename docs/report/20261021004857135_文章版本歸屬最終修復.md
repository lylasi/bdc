## 3. 實際修改

### 3.1 `modules/article-store.js`：`saveAnalysis` 增加版本守門

`saveAnalysis(articleId, result, options)` 新增 `options.expectContentVersion`：在補全文後、寫入前以 `contentVersionOf(record.article)` 比對請求開始時的版本；不符即回

```js
{ ok: false, error: 'stale_version', staleVersion: true, record }
```

不寫入、不改 `updatedAt`。這保護所有 legacy `result` 合併（詞／句／片語）在「檢查後、寫入前」才改版的競態；帳戶切換仍由既有 `isArticleContextActive(ctx)` 攔截並回 `stale_scope`。

### 3.2 `features/article/article.js`：統一的寫回前檢查

- 新增 `analysisWriteTargetCurrent(articleId, articleCtx, contentVersion, actionContext)`：
  - 文章 scope／generation 仍有效；
  - reading scope（帳戶）仍有效；
  - record 仍存在且有 `result`；
  - 目前正文 `articleVersion` 等於請求時凍結的版本。
- 新增 `reportAnalysisSaveFailure(result)`：`staleScope`／`staleVersion` 不顯示「儲存失敗」 toast，避免延遲或切換時多餘錯誤訊息。
- `persistSentenceAnalysis(...)`、`persistPhraseAnalysis(...)` 增加 `options = { contentVersion, actionContext }`，先通過上述檢查，再以 `expectContentVersion` 呼叫 `saveAnalysis`。
- 按需查詞（`showArticleWordAnalysis` 懶載回應）：
  - 寫回 `result.detailed_analysis` 前先通過 `analysisWriteTargetCurrent`，並帶 `expectContentVersion`；
  - 舊版 readingItem 解釋仍以凍結的 `contentVersion`／`anchor` 保存（符合「舊版解釋可依已凍結版本保存」）。
- 句卡 refresh：
  - 卡片建立時以 `stampSentenceCardTarget` 寫入 `data-article-id`、`data-content-version`、`data-anchor-start`、`data-anchor-end`；
  - refresh 點擊時（`await` 前）凍結 `articleId`、文章 context、reading context、`refreshVersion`，並用卡片自己的 offsets 經 `anchorFromOffsets` 重建錨點（僅在 offsets 對不上時才 fallback `resolveAnchor`）；
  - `await` 後只在 `card.isConnected && actionContextActive && isCurrentArticle && articleVersion === refreshVersion` 時更新原卡片；
  - legacy `sentence_analysis` 寫回帶 `contentVersion`／`actionContext`；`recordExplanation` 使用凍結的 `refreshAnchor`。
- 句卡 chunk 片語詳解（inline 與 modal 兩個入口）與句卡「分析選中內容」：
  - 在請求前凍結 `articleId`／版本／action context，`analyzePhraseWithSaved` 與 `persistPhraseAnalysis` 都沿用同一組值。
- `stillShowing()`（詞彈窗）增加：
  - `readingActions.articleVersion(targetArticleId) === contentVersion`：改文後舊回應不得重新顯示；
  - `dom.analysisTooltip.style.display !== 'none'`：使用者已點擊別處收起彈窗時，舊請求不得自動重開。
- 未新增任何 UI 文案，因此 `zh-CN`／`zh-HK` 字典不需變更。

### 3.3 新增永久回歸測試 `tests/article-version-ownership.cjs`

沿用父助手 `/tmp/bdc-mark-async-extended-review.cjs` 的隔離 fixture（真 Chrome、獨立 context、route mock `analyzeWordInSentence`／`analyzeSentence`／`analyzeSelection`），新增 12 項檢查：

1. 收起後遲到回應不重開彈窗；
2. 第一處句卡凍結自己的 occurrence（`anchor-start=0`）；
3. refresh 保存到卡片自己的 occurrence（不是 `-1`／另一處）；
4. refresh 更新原卡片與 `sentence_analysis`；
5. 舊版片語回應未併入目前正文（走句卡 chunk → `persistPhraseAnalysis`）；
6. 舊版查詞不污染目前 `result.detailed_analysis`（含 `sentence`）；
7. 查詞解釋仍只保存成原版本；
8. 改版後舊回應不重新顯示彈窗；
9. 改版後 refresh 不寫入 legacy `sentence_analysis`；
10. 改版後 refresh 不更新原卡片；
11. 競態不顯示多餘的儲存失敗訊息；
12. 流程沒有 page error。

測試刻意使用兩個相同句子（重複 occurrence），並要求 mock 回應包含 `sentence`，避免假通過。

## 6. 限制與未擴張項

1. `retrySingleParagraph` 既有的 `articleStore.saveAnalysis(targetArticleId, updated)`（段重試）仍只檢查 `isCurrentArticle`，未帶版本；本輪依指示只修按需詞／句／短語與句卡 refresh，未擴張重構。若段重試期間正文改版，仍可能把該段結果寫回新正文，建議後續以同一 `expectContentVersion` 模式補齊。
2. 句卡 refresh 的版本在「點擊 refresh 前」凍結（滿足請求前凍結）；卡片建立時另存 `data-content-version` 供除錯／後續使用。若使用者在卡片建立後、點 refresh 前改文，錨點會先以卡片 offsets 對當前正文驗證，對不上才 fallback，不會在 `await` 後重算。
3. `analysisWriteTargetCurrent` 需要 record 已有 `result`；若文章只載入摘要（summaryOnly）而尚未補全文，舊回應會被丟棄（與修補前行為一致）。
4. 舊版 readingItem 解釋仍會以凍結版本保存（產品允許），測試只要求它不得記成新版本；若使用者期待「舊回應完全不落地」，需另立產品決策。
5. 驗證全部使用 mock AI 與合成文章，未連真實供應商／同步端點；未重跑前一輪已完成的廣泛 AI 70/70 測試（依指示）。
