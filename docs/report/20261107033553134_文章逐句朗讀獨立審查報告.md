## 三、問題清單

### F1（P2／建議本次修掉）原文已是中文的段落仍顯示朗讀入口，按下後完全沒有反應

- 嚴重度：中（P2）。無聲、無提示的死入口；不影響英文句流程，不造成資料或播放錯誤。
- 重現步驟：
  1. 匯入含「以中文為主的段落」的文章（例如英文段落與中文筆記交錯），完成分析。
  2. 在中文段落的句子尾端點 `⋯` → 選單正常開啟，「朗讀本句／從這裏開始讀／循環讀本句」皆為可點狀態。
  3. 點任一朗讀項：沒有任何語音，也沒有任何提示訊息或 UI 變化；桌面懸停的浮動小喇叭同樣是死入口。
- 實測證據：`audit-suite-5.log`、`J-chinese-source-sentence.png`（`{"menuOpen":true,"before":0,"after":0,"feedback":[]}`）。
- 成因（檔案行號）：
  - `features/article/article.js:5153`：`buildReadingChunks` 以 `isChineseSourcePara` 跳過中文原文段，因此該句不會產生 chunk。
  - `features/article/article.js:5239-5240`：`startSentenceReading` 找不到 chunk 時 `if (index < 0) return;` 靜默返回。
  - `features/article/sentence-actions.js:57`（選單停用判斷）與 `:123`（懸停入口判斷）：`canRead` 只檢查 `isConnected && !isArticleViewStale()`，沒有考慮「這一句其實無法朗讀」。
  - `features/article/article.js:7233`／`:7303`（呼叫 `sentenceWrapHtml`，定義於 `:2541`）對中文原文段仍照常渲染句尾入口，所以入口存在。
- 修正建議（任一即可，約 5 行）：
  1. 首選：把 `canRead` 收緊為「該句所屬段落不是 `data-source-language="zh"`」（或 `buildReadingChunks('sentence')` 中存在對應 chunk），使三項朗讀 disabled 並沿用既有 `article.staleSentenceCard` 之外的新提示鍵（例如「本段原文已是中文，略過朗讀」），同時也讓懸停小喇叭不出現；或
  2. 在 `index < 0` 時顯示一則 warning（可重用既有鍵，避免新增翻譯負擔）。

### F2（P3／後續改善）選單會被 App 自身的平滑自動捲動關掉

- 嚴重度：低。行動裝置上「剛點開選單就被關閉」，使用者需再點一次。
- 重現步驟：
  1. 在長文章中把頁面捲到下方，從遠方句子啟動「朗讀本句」（播放器會 `scrollIntoView({block:'center',behavior:'smooth'})` 自動捲動）。
  2. 捲動動畫尚未結束時（約 300ms 內）點另一句的 `⋯`：選單會開啟後立即消失。
  3. 同理，任何 1px 的平滑捲動（含行動瀏覽器網址列收合）都會立即關閉選單。
- 實測證據：`audit-suite-1.log` 的 `C29 menu vs app auto-scroll :: {"openedNow":true,"stillOpen":false}` 與 `A16 menu after 1px smooth scroll :: {"stillOpen":false}`；此現象也曾讓我的自動化點擊在 320 情境下間歇失敗，證實可穩定重現。
- 成因（檔案行號）：`features/article/sentence-actions.js:169`（任何 scroll 就 `closeSentenceActions()`）搭配 `features/article/article.js:5657`／`:5664`（每個 chunk 開始都平滑捲動）。
- 修正建議：開啟後 200–250ms 內忽略 scroll 事件；或改為「錨點（入口）仍在視窗內就重新定位、離開視窗才關閉」，避免自捲與選單互斥。

### F3（P3／後續改善）在選單內按 Tab 後，焦點跳到頁尾的 AI 懸浮鈕

- 嚴重度：低（鍵盤可及性）。
- 重現步驟：以鍵盤 Enter 開選單 → 按 Tab → 選單關閉，焦點落到 `#assistant-fab`（頁面層級、遠離該句）。
- 實測證據：`audit-suite-1.log` 的 `B9 Tab from menu :: {"closed":true,"tag":"BUTTON","id":"assistant-fab","inArticle":false}`。
- 成因（檔案行號）：`index.html:1656` 將選單放在 `<main>` 之後的 body 層級；`features/article/sentence-actions.js:110` 在 Tab 時只關閉、不處理後續焦點。
- 修正建議：把選單節點移到對應 `.sentence-wrap` 內（`position: fixed` 定位不受影響），或在 Tab 關閉後把焦點交給入口的下一個可聚焦控制；亦可考慮在選單內做 focus trap。

### F4（P3／後續改善）循環播放會跨模組繼續，且只有懸浮播放列可停

- 嚴重度：低。與既有「離開文章 route 不會自動停止朗讀」策略一致（設計定稿 `:179` 已明言本輪不改），且懸浮播放列仍可見、停止鈕可正常停止（我實測在單詞本頁成功停止）。但「無限循環」是本功能新增能力，離開文章後仍持續屬於較高風險。
- 重現步驟：啟動「循環讀本句」→ 等一次朗讀結束（進入 0.5 秒間隔）→ 立刻切到「單詞本」：語音會在單詞本頁繼續；畫面左下懸浮播放列仍在，可停止。
- 實測證據：`audit-suite-2.log` 的 `G1 pending loop at module change :: {"before":1,"after":2,"lateCalls":1}`；`audit-suite-4.log` 的 `I1`／`I2`（單詞本頁 `readerVisible:true`、`stopHit:"fr-stop"`、點擊後不再出聲）；截圖 `I-module-switch-loop.png`。
- 成因（檔案行號）：`features/article/article.js:5475-5481` 的循環計時器只由 `invalidateArticlePlayback()` 取消，而 `leaveArticleRoute()`（`features/article/article.js:4355`，由 `main.js:137` 在切換模組時呼叫）不會呼叫 `stopReadArticle()`。
- 修正建議：在 `leaveArticleRoute()` 內加一行「若 `sentencePlaybackMode === 'loop'` 則 `stopReadArticle()`」；不改動全文／段落朗讀的既有跨模組行為。

### F5（P4／文案）zh-HK 用詞「選中」非香港慣用語

- 嚴重度：極低（文案）。
- 位置：`locales/zh-HK.js:905` `readSelection: '朗讀選中內容'`；簡體 `locales/zh-CN.js:905`「朗读选中内容」正確。香港書面語一般用「選取」。
- 建議：`readSelection: '朗讀選取內容'`（並確認與 `article.lookupPhrase`／`addToWordbook` 等既有香港用詞一致）。

## 四、非阻擋的觀察（已確認屬設計或既有行為，不需修）

1. **「從這裏開始讀」中途前進後，原句選單不再是停止態**：逐句前進到下一句後，重開原句選單會顯示「從這裏開始讀」（非停止），再點是「由該句重新開始」而非停止。與設計定稿「對正在播放的該句才顯示停止」一致，但若日後使用者回饋混淆，可考慮對「本次連續朗讀」整體顯示停止。實測 `H15`。
2. **全文朗讀需先停止才能重新開始**：句尾朗讀使側欄朗讀鈕進入暫停態，這是共用播放列的既有行為，非本次新增。
3. **開啟選單不移動焦點（滑鼠／觸控）**：以鍵盤開啟才聚焦首項；與現有站內選單一致。
4. **選區朗讀會高亮整句**：只播片段但沿用句子高亮與淡化，屬視覺取捨，無功能影響。
5. **中文原文段的「從這裏開始讀」會正確跳過該段**（實測 `J5`：讀出 3 句英文、略過中文段），與 F1 只差在「單獨對該句操作時沒有回饋」。
