# AI 模型选择跨浏览器未保存排查报告

> 状态：已于 2026-07-13 完成修复。以下“当前行为”描述的是修复前行为；实施结果见 `docs/release/20260713010046304_AI模型非敏感配置同步记录.md`。

## 结论

问题可以稳定由现有设计解释，并非模型接口抓取失败：

1. 模型地址、已抓取模型、允许模型和任务模型映射，只有点击全局设置弹窗底部的“保存”后，才会写入当前浏览器的 `localStorage`。
2. 这些设置写入 `pen_global_settings`；API Key 写入 `pen_global_secrets`。两个键都被明确标记为“仅本机、永不同步”。
3. 云端同步快照不包含 AI Provider、模型清单或任务模型映射。因此换用另一个浏览器、浏览器配置文件、无痕窗口或另一台设备时，新环境无法恢复原选择，必须重新抓取和选择。

## 代码证据

- `modules/settings.js:3-6`：全局设置与密钥被定义为 local-only，分别使用 `pen_global_settings` 和 `pen_global_secrets`。
- `modules/settings.js:94-137`：设置和密钥仅通过 `localStorage` 读写。
- `features/sync/sync.js:393-418`：打开设置弹窗时，从当前浏览器已持久化设置初始化 `aiState`。
- `features/sync/sync.js:714-760`：抓取、勾选允许模型及任务模型选择只修改弹窗内的 `aiState`。
- `features/sync/sync.js:919-931`：只有点击“保存”后，才调用 `saveGlobalSettings()` / `saveGlobalSecrets()`。
- `modules/sync-core.js:375-406`：同步快照仅包含听写、词书、文章、QA 和助手对话，不包含全局 AI 设置。

## 场景判断

| 场景 | 当前行为 |
| --- | --- |
| 同一浏览器，点击保存后刷新或重新打开 | 应能恢复 |
| 同一浏览器，抓取/勾选后直接关闭弹窗或页面 | 不会保存 |
| 新浏览器、无痕窗口、新浏览器配置文件或新设备 | 不会恢复，即使原浏览器已点击保存 |

## 建议修复方向

建议将非敏感 AI 配置加入同步快照，包括 Provider 的名称、启用状态、Base/API/Models URL、允许模型、已抓取模型元数据和各任务模型映射；API Key 继续只保存在本机，避免把密钥写入云端快照。

同时建议在“抓取模型”和勾选模型后增加明确的“尚未保存”状态，或直接安全地自动保存非敏感配置，避免用户误以为抓取完成即已持久化。

## 风险提示

- Provider URL 可能属于内部服务地址。若纳入同步，应在产品层确认其是否可视为非敏感信息。
- 不应同步 `pen_global_secrets` 或 API Key。
- 若只同步允许模型而不保存已抓取模型，任务映射仍可工作，但新浏览器的设置页可能只显示已允许的模型，完整清单仍需重新抓取。
