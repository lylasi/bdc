## 二、逐項說明

### M5 無障礙

分兩部分：**工具誤報**與**真的缺名稱**。

巡檢腳本原本只用「元素自身 textContent / aria-label / title / placeholder」判斷可訪問名稱，於是所有靠 `<label for>` 或外層 `<label>` 標註的控制項（單選框、文字輸入、開關）都被誤報。已改為依無障礙演算法取值：`aria-label` → `aria-labelledby` → `<label for>` → 外層 `<label>` → 自身文字 → `title`/`placeholder`，並略過 `aria-hidden="true"` 與 `sr-only`（渲染成 1px）的節點。

修正後真的有問題、已修的：

| 位置 | 問題 | 修法 |
| --- | --- | --- |
| `#loop-mode` / `#shuffle-mode`（聽寫） | 開關右側的 checkbox 只有 `<span class="slider">`，文字在**兄弟節點**，沒有 `for` 也沒有 `aria-label` | 補 `aria-label` + `data-i18n-aria-label`（沿用既有鍵） |
| `#read-chinese-mandarin` / `#read-chinese-cantonese` | 外層 `<label>` 內只有「普」「粵」兩個字，可訪問名稱過於簡略 | 補 `aria-label`（朗讀中文意思時使用普通話／粵語），新增 `dictation.mandarinAria` / `cantoneseAria` |
| `.stepper-arrow`（兩組數字階梯的上/下箭頭） | 34×21，小於 24px 最小點擊高度，手機上容易誤觸旁邊那顆 | `min-height: 21px → 24px`（現為 34×24） |
| App Bar 副標題「纸上听写 · 单词 · 学习」 | `--ink-400` 在淺色底上對比度 3.18:1，未達 4.5:1 | 改用 `--ink-500`（5.15:1） |

複驗：`audit-flows` 的 a11y 段落回報 **0 項 medium、0 項對比度問題**。

### M6 大量詞條效能（增量渲染）

原況：12000 詞（單本 4000）時一次渲染全部節點——40878 個 DOM 節點、清單高 263994px、渲染約 3 秒。

改法（`features/vocabulary/vocabulary.js`）：抽出 `buildWordItem()`，把「一次 forEach 全部」改成**分批渲染**：

- 首屏渲染 150 筆，清單底部放一個哨兵列，顯示「已載入 150 / 共 4000 個，繼續滾動查看更多」；
- `IntersectionObserver`（`rootMargin: 600px`）在哨兵進入視窗時再補 150 筆；
- 換書、換關鍵字、清空篩選都會 `stopIncrementalWordRender()` 重來，observer 一併斷開；
- 沒有 `IntersectionObserver` 的環境自動退回一次渲染全部，功能不受影響。

複驗（`audit-data`）：

```
修復前  節點 40878、清單高 263994px、首屏渲染 4000 筆
修復後  首屏 151 筆、節點 6229、清單高 9945px
        捲到底 151 → 450 筆，哨兵文字「已加载 300 / 共 4000 个，继续滚动查看更多」
```

> 過程中一度把哨兵 `appendChild` 放在 `appendWordChunk()` 之後，導致 `insertBefore` 找不到參考節點、清單整片空白。
> 這個錯誤沒有被 `node --check` 抓到，是瀏覽器實測時 console 出現 `[bdc] 初始化步驟「vocabulary」失敗` 才發現——
> 順帶印證了 `main.js` 分步 try/catch（H3/M9）的價值：單一模組初始化失敗不會拖垮整個應用。**語法檢查不等於功能可用。**

### M11 詞書可重名

詞書選擇器只顯示名稱，重名後無法區分，且 `activeBookId` 只認 id，切換時容易誤操作。

`saveBookWithAICompletion()` 在寫入前擋查（排除自己，所以「只改內容不改名」不受影響），提示 `vocabulary.duplicateName` 並聚焦、選取名稱欄位。匯入路徑原本就會問「要覆寫嗎」，維持不變。

複驗：建立同名詞書後 `localStorage` 仍只有一本，畫面出現「已经存在名为「巡檢詞書」的单词本，请使用其他名称。」

### L2 學習頁「上一個」的環繞行為

原況：未選取單詞時按「上一個」直接跳到**最後一個**；在第一個單詞按「上一個」也會跳到最後一個，且沒有任何提示。

改法（`features/learning/learning.js`）：**取消環繞**，改為

- 尚未選取：兩個方向都從第一個單詞開始；
- 已經在最前／最後：停在原地，並借用「第 n / 共 m」那一行顯示「已经是第一个单词／已经是最后一个单词」，1.8 秒後還原。

新增鍵：`learning.alreadyFirst`、`learning.alreadyLast`。

複驗：`audit-flows` 的「前後切換」段落現在驗證三件事——未選取時從第一個開始、在首項按「上一個」停在原地、邊界有提示。

## 三、巡檢工具自身的修正

改完產品碼之後，還有 3 項是**工具誤報**，一併修掉（否則會持續產生假陽性，也會掩蓋真問題）：

| 腳本 | 問題 | 處置 |
| --- | --- | --- |
| `audit-flows.cjs` | 可訪問名稱計算不解析 `<label for>` / 外層 `<label>` / `aria-labelledby`，也不排除 `aria-hidden` 與 `sr-only` | 改為依無障礙演算法取值 |
| `audit-flows.cjs` | 簡體殘留偵測的字元集誤收「制」——它在簡繁同形（控制、制度），於是 zh-HK 的「朗讀控制」被報成殘留簡體 | 從字元集移除「制」，並在註解寫明收錄條件 |
| `audit-data.cjs` | 效能斷言只判斷「節點數 > 20000」 | 改為驗證增量渲染：首屏筆數要遠小於總數、要有「已載入 n / 共 m」、捲到底要真的載入更多 |

`audit-flows.cjs` 另外兩處斷言同步到新行為（詞書重名、學習頁前後切換）。
